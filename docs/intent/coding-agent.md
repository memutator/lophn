# coding-agent

## 왜
내가 쓰던 coding agent로 앱을 만들고 고치면서도, 매번 자료와 플랫폼 규칙을 설명하고 결과를 확인하는 일을 반복하고 싶지 않다. lophn은 필요한 근거와 작업 통로를 열고, 내 권한과 실제 확인을 지킨다.

## 무엇을 약속하나

- **[I1]** 내가 쓰던 coding agent를 MCP나 CLI로 붙여 lophn의 일을 시킬 수 있다.
- **[I2]** 연결마다 내가 정한 범위(전체 또는 앱 하나)만 쓰고, 거두면 바로 끊긴다.
- **[I3]** coding agent는 필요한 근거만 적게 읽고, 문서·테스트·release 준비를 할 수 있다.
- **[I4]** 구현과 수리는 검사 가능한 ticket으로 맡기고, 내가 시킨 ticket만 처리한다.
- **[I5]** 완료 주장, 실제 테스트, release, 문제 닫힘을 따로 확인한다.
- **[I6]** Claude Code, Codex 등 일곱 제품을 지원한다.
- **[I7]** 수리할 때 필요한 자료를 작은 한 묶음으로 받는다.
- **[I8]** ticket은 버려진 세션에 오래 붙잡혀 있지 않는다.

## 하지 않는 것
- coding agent 자체나 코드 생성 loop를 만들거나 외부 세션을 자동으로 시작하지 않는다.
- 연결·claim을 사람 권한으로 바꾸거나 운영 데이터·secret의 직접 접근을 열지 않는다.
- 외부 파일 편집이나 프로세스를 lophn이 강제로 멈췄다고 보장하지 않는다.

## 잘되고 있다는 신호
- 익숙한 도구에서 필요한 자료를 적게 읽고, 내 앱과 설정을 망가뜨리지 않고 계속 작업한다.
- 고친 결과와 미실행 확인을 원래 문제나 ticket에서 찾고, 내게 다시 설명을 요구하는 일이 줄어든다.
