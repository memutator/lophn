# lophn-agent/extensions

lophn agent가 읽을 로컬 skill의 발견·목록·읽기와 사람이 연결한 외부 MCP 서버의 설정·수명·인증·도구 이름을 맡고, skill과 MCP를 등록하는 두 층(전역 Workspace, 자리 project·app)과 agent 정의가 그 가운데 무엇을 쓸지 고르는 규칙을 정한다; agent 정의의 나머지는 agent 정의의 concern이, `/` 메뉴에 skill을 올리는 일은 lophn-agent/commands가, 호출 허용 여부는 lophn-agent/harness/tool-judgment가 정한다.

## 요구

### skill

**[R1]** harness는 그 agent의 자리(project나 app)에 둔 skill 폴더를 먼저 찾고 사람이 전역(Workspace)에 등록한 skill 폴더를 등록 순서대로, 사용자 개인 skill 보관소와 lophn에 동봉된 skill을 차례로 찾으며, 각 폴더 자체와 바로 아래 skill 꾸러미만 살피고 앱 소스·상위 폴더·다른 harness의 보관소는 자동으로 찾지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 자리 폴더, 등록 순서가 다른 전역 폴더 둘, 개인 보관소, 동봉 skill, 앱 소스와 상위 폴더에 서로 다른 skill을 놓으면 앞의 다섯 범위만 정한 순서로 발견되고 꾸러미 아래의 중첩 꾸러미는 발견되지 않으며 다른 자리의 폴더는 발견되지 않는다.
- 의도: lophn-agent#I5

**[R2]** skill은 UTF-8 Markdown과 YAML 머리로 된 Agent Skills 형식으로 받으며 이름은 영문 소문자·숫자·하이픈으로 된 1~64자이고 처음·끝·연속 하이픈은 금지하며 설명은 공백만으로 되지 않은 1~1,024자로 제한하고 잘못된 형식은 목록에서 제외해 이유를 알린다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 이름·설명이 빠진 것, 이름 65자, 설명 1,025자, 잘못된 YAML, 금지된 하이픈을 각각 제외하고 경계값 64자·1,024자는 받아들이며 이름이나 원문을 고쳐 성공시키지 않는다.
- 의도: lophn-agent#I5

**[R3]** 같은 이름의 skill은 탐색 순서에서 먼저 발견한 것 하나만 사용하고 같은 범위에서는 꾸러미 이름의 영문 사전순으로 먼저인 것을 사용하며, 중복으로 제외된 skill과 선택된 출처는 사람에게 함께 알린다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 같은 이름에 본문이 다른 skill을 네 범위와 한 범위의 꾸러미 둘에 놓고 탐색을 반복하면 선택과 충돌 설명이 늘 같고 등록 폴더의 순서를 바꾼 뒤 새 run에서는 선택이 바뀐다.
- 의도: lophn-agent#I5

**[R4]** 제공할 skill은 그 agent가 발견한 유효한 목록에서 그 agent 정의가 끈 정확한 이름을 뺀 것이며, 정의가 기본으로 전부 켜 두므로 새로 발견된 skill은 다음 run부터 제공되고 끈 skill의 읽기는 거절한다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 서로 다른 skill을 끈 agent 둘에는 각자 끄지 않은 것만 제공되고 끈 skill의 읽기는 거절되며 새로 놓은 skill은 다음 run에 두 agent 모두 받고 없는 이름은 빈 본문으로 돌아오지 않는다.
- 의도: lophn-agent#I5

**[R5]** 역할의 프롬프트에는 사용할 skill의 이름과 설명만 이름의 영문 사전순으로 넣고 본문·보조 자료·설치 명령·로컬 주소는 넣지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: skill 세 개의 목록을 반복 조립하면 이름·설명과 순서가 같고 본문에만 있는 문장, 보조 자료와 로컬 주소는 읽기 전 프롬프트에 나타나지 않는다.
- 의도: lophn-agent#I5

**[R6]** 역할이 목록의 이름으로 skill을 읽으면 선택된 skill의 본문 전체와 보조 자료의 제목 목록만 돌려주고 다른 skill의 본문은 함께 읽지 않으며, 본문 전체를 제공하지 못하면 일부를 성공한 읽기로 돌려주지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 본문 뒤에만 있는 주의 문장까지 읽기 결과에 포함되고 보조 자료 본문과 다른 skill 본문은 없으며 문맥의 수용 한도를 넘긴 본문은 읽지 못한 것으로 돌아온다.
- 의도: lophn-agent#I5

**[R7]** skill의 보조 자료는 역할이 제목으로 따로 고른 UTF-8 문서만 읽고 skill 꾸러미 밖으로 나가는 상대 주소·절대 주소·심볼릭 링크는 거절하며 스크립트와 실행 파일은 실행하지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 꾸러미 안 문서는 고른 것만 읽히고 상위 폴더 문서, 절대 주소 문서, 밖을 가리키는 링크는 내용 없이 거절되며 실행 파일을 보조 자료로 골라도 프로세스가 생기지 않는다.
- 의도: lophn-agent#I5

**[R8]** skill의 선택·이름·설명은 run을 시작할 때 고정하고 읽기 전에 그 skill이 변경되거나 사라졌으면 읽기를 실패시키며 새로 발견된 skill과 변경된 skill은 다음 run부터 적용한다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: run 중 이름·설명·본문을 바꾸거나 skill을 삭제하면 기존 목록은 바뀌지 않고 그 skill의 새 읽기는 실패하며 다음 run의 목록과 읽기는 새 내용에 맞는다.
- 의도: lophn-agent#I5

**[R9]** skill을 목록에 넣거나 읽는 일은 도구 추가·권한 부여·바깥 MCP 연결·인증을 실행하지 않고 본문의 지시는 역할 정의·권한·안전의 경계를 바꾸지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 본문에 새 서버 연결, 도구 설치, 권한 허용을 지시하는 skill을 읽어도 연결·도구·권한이 바뀌지 않고 이후 호출은 기존 판정을 받는다.
- 의도: lophn-agent#I5, lophn-agent#I6

**[R10]** skill의 원격 검색·다운로드·설치·자동 작성은 확장의 자동 기능으로 제공하지 않고 사람이 로컬 꾸러미를 준비해 등록한 뒤에만 발견한다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 원격 주소나 “skill을 설치하라”는 역할 요청만으로 다운로드·파일 쓰기·목록 추가가 일어나지 않고 사람이 등록한 로컬 꾸러미는 다음 run에 발견된다.
- 의도: lophn-agent#I5

### 외부 MCP

**[R11]** 외부 MCP 서버의 추가·삭제·enabled·목적지·인증 설정은 사람만 정하고 어느 agent가 어떤 서버/tool을 쓰는지는 agent 정의로 고르며 문서·skill·agent 요청·server 응답과 다른 harness의 설정 보관소에서 설정을 자동 수입하지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 같은 서버를 agent 하나의 정의에서만 켜 두면 다른 agent에는 제공되지 않고 문서나 서버 응답에 연결 주소와 실행 명령을 넣거나 다른 harness의 MCP 설정 파일을 놓아도 연결이 늘지 않는다.
- 의도: lophn-agent#I5, lophn-agent#I6

**[R12]** 바깥 MCP 연결 설정은 사람이 구별하는 서버 이름·전송 방식·활성 여부와 함께 stdio에는 실행 파일·인자·작업 폴더·환경 값·platform/secrets가 관리하는 비밀 참조를, HTTP에는 서버 URL·추가 요청 헤더·인증 방식을 받고 누락·상충·잘못된 값이 있으면 그 서버만 연결하지 않고 고칠 항목을 알린다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 실행 파일이 없는 stdio, URL이 없는 HTTP, 두 전송의 설정이 섞인 연결을 각각 거절하고 정상 서버와 lophn 자체 도구는 계속 사용할 수 있다.
- 의도: lophn-agent#I5

**[R13]** 바깥 MCP 전송은 로컬 stdio와 원격 Streamable HTTP 두 가지를 지원하고 전송 방식을 명시적으로 선택하며 SSE로 자동 전환하지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: stdio 서버와 Streamable HTTP 서버가 각각 연결되고 Streamable HTTP가 실패해도 SSE 주소로 두 번째 연결을 시도하지 않는다.
- 의도: lophn-agent#I5

**[R14]** stdio 서버는 harness가 지정된 실행 파일과 인자를 셸 해석 없이 시작하고 환경은 실행 파일 탐색·홈·임시 폴더·문자 인코딩에 필요한 값과 사람이 그 서버에 지정한 값만 전달하며 다른 연결이나 provider의 비밀은 상속하지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 셸 메타문자가 들어간 인자가 그대로 전달되고 데몬 환경에만 있는 테스트용 비밀은 자식에게 없으며 그 서버에 지정한 테스트용 비밀만 자식에게 전달된다.
- 의도: lophn-agent#I5

**[R15]** HTTP 연결은 HTTPS를 기본으로 하고 평문 HTTP는 사용자의 머신 안 loopback 주소에만 허용하며 다른 호스트로의 리다이렉트에는 인증 헤더를 보내지 않고 TLS 검증을 끄는 설정은 제공하지 않는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: loopback HTTP와 정상 HTTPS는 연결되고 원격 HTTP와 잘못된 인증서의 HTTPS는 실패하며 다른 호스트로 보내는 테스트용 리다이렉트 요청에는 인증 헤더가 없다.
- 의도: lophn-agent#I5

**[R16]** HTTP 인증은 인증 없음·사람이 지정한 Bearer 토큰 또는 API 키 헤더·OAuth 2.1 Authorization Code와 PKCE를 지원하고 OAuth는 사람이 시작한 브라우저 인증과 loopback 반환으로 진행하며 동적 클라이언트 등록을 지원하지 않는 서버에는 사람이 등록된 클라이언트 정보를 넣는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 세 인증 방식이 각각 연결되고 OAuth가 필요한 서버는 로그인 전 도구 호출이 막히며 잘못된 반환 검증 값은 거절되고 등록을 지원하지 않는 서버는 등록 정보를 받은 뒤 연결된다.
- 의도: lophn-agent#I5

**[R17]** 인증 비밀은 platform/secrets의 비밀 보관 방식으로 서버 연결 대상과 OAuth 발급자에 묶고 URL·발급자·사용 계정이 바뀌면 이전 비밀을 재사용하지 않으며 만료 토큰은 같은 연결에서 한 번에 하나만 갱신하고 갱신 실패는 재인증 필요로 알린다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 같은 이름으로 URL·발급자·계정을 바꾼 서버에는 옛 토큰이 전달되지 않고 만료 직후 동시 호출 둘의 갱신 요청은 하나이며 실패 후에는 인증 필요가 연결 실패와 구별된다.
- 의도: lophn-agent#I5

**[R18]** 바깥 MCP 연결은 assignment와 사람이 등록하고 그 agent가 켠 서버의 조합마다 하나씩 유지하고 그 역할의 여러 run은 같은 연결을 쓰되 다른 assignment와는 공유하지 않으며 assignment 사용이 끝나거나 서버를 떼거나 데몬이 종료되면 닫는다.
- 이유: 필요한 절차와 의존성을 명시적으로 골라 오래 쓰면서도 정보 범위와 안전 경계를 넓히지 않아야 한다.
- 확인: 같은 assignment의 연속 run 둘은 stdio 프로세스 하나를 재사용하고 같은 서버를 쓰는 다른 assignment에는 별도 연결이 생기며 assignment 하나의 사용을 끝내도 다른 assignment의 연결은 유지된다.
- 의도: lophn-agent#I5

**[R32]** skill과 MCP 서버는 두 층에 등록한다: 전역(Workspace: skill 등록 폴더·개인 보관소·동봉 skill, MCP 서버 목록)과 자리(project나 app의 data 폴더에 둔 skill 폴더와 MCP 서버)이며, 자리 층의 것은 그 자리에서 여는 agent에만 보이고 다른 자리의 agent에는 보이지 않는다.

- 확인: 전역에 등록한 skill과 서버는 모든 자리의 agent에 후보로 보이고 phroner project에만 둔 skill은 phroner에서 여는 agent에만 보이며 다른 project의 agent에는 보이지 않는다.

**[R30]** agent 정의는 끈 skill을 정확한 이름으로만 저장하고 생략·빈 목록은 끈 것이 없다는 뜻이며 중복 이름과 와일드카드·패턴은 거절하고, 지금 발견되지 않는 이름도 거절하지 않고 그대로 두어 그 skill이 다시 나타나도 끈 채로 둔다.

## 버린 것

- subagent 확장과 기본 수량 — 유지 결정 9가 모든 역할의 subagent를 제외한다.
- 미분류 바깥 MCP 도구를 쓰기로 취급 — 되돌림을 모르면 external로 보고 묻고, agent 정의의 안전 표시가 있을 때만 묻지 않는다.
- preset이 skill과 MCP를 고른다는 요구 — preset을 없애고 agent 정의가 고른다. 고르기는 기본 전부 켜고 끈 것만 저장하는 모양으로 R4·R30·R31에 옮겼다.
- 새로 발견된 skill이 기존 역할에 자동으로 추가되지 않아야 한다는 이유(옛 R30) — 사람이 기본 전부 켬으로 정했다. 켜졌다고 권한이 넓어지지 않는다는 경계는 R9·R31에 남긴다.
