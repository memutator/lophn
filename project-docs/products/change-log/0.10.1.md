# 0.10.1

## OAuth MCP server를 붙이고 sign-in한다. 앱 secret을 지우고 sign-out한다. 일시 오류로 sign-in이 끊기지 않는다

```yaml
modules: [packages/core/lophn-agent, packages/core/apps, packages/core/secrets, packages/core/main, packages/protocol, packages/shell/main, packages/shell/renderer, packages/design, tools]
checked: []
```

- 전:
  - MCP server form은 인증으로 None, Bearer, API key만 골랐다. 설정 file에 `oauth2`를 손으로 써도 sign-in 단추가 없어 그 server는 늘 Needs sign-in이었다. 끝점은 `${issuer}/authorize|token`으로만 만들었고 `client_credential`은 읽는 곳이 없어 client secret 없이 교환했다.
  - MCP OAuth는 refresh 응답이 400 이상이면 모두 거절로 보고 token을 지웠다. 발급자가 잠깐 503을 내도 사람이 다시 sign-in해야 했다.
  - 앱 Access 탭은 값을 넣기만 했다. 넣은 API key를 지우거나 OAuth sign-in을 끝낼 길이 없었다.
- 후:
  - Settings › Tools and skills와 project 층의 server form이 OAuth 2.1(issuer, client ID, scopes)을 받는다. client secret은 더한 뒤 보호 입력으로 `mcp.<scope>.<server>.client`에 넣고, 넣지 않으면 public client다. OAuth 줄은 로그인 전 [Sign in], 기다리는 동안 [Cancel]이다.
  - MCP sign-in은 발급자의 `/.well-known/oauth-authorization-server`를 먼저 읽어 https 끝점을 쓰고, 없으면 `${issuer}/authorize|token`이다. client secret은 교환과 refresh 본문에만 실린다.
  - 앱 OAuth와 MCP OAuth의 refresh가 같은 규칙이다: 400·401·`invalid_grant`만 거절이고, 그 밖에는 만료 전 token을 그대로 쓴다.
  - 앱 Access 탭의 plain secret 줄은 값이 있으면 [Remove value], OAuth 줄은 `signed_in`·`failed`일 때 [Sign out]이 있다. Sign out은 access·refresh·meta를 지우고 client id·secret은 남긴다.
  - `secrets/put`과 shell의 secret 제출이 byte 배열을 0으로 덮던 코드를 지웠다. 같은 값이 이미 JS 문자열로 있어 효과가 없었다.
- 계약:
  - 생긴 것: memory route `apps.oauth_sign_out`(`{app, name}` → `{signed_out: true}`), `McpOAuth.signOut`, `createMcpAuthControl` deps의 `secrets`, MCP runtime oauth2 auth의 `client_secret`(secret 이름).
  - 지운 것: `McpOAuthServer.refreshRejected`, `refreshToken` 입력의 `rejected`, `createMcpOAuth`의 `keepValidOnUnavailable`.

왜: hosted MCP server 대부분이 OAuth인데 사람이 붙일 길이 없었고, 앱에 넣은 key와 refresh token은 lophn 안에서 지울 수 없었다. 발급자의 잠깐 오류로 sign-in을 잃는 일은 앱 OAuth에서 이미 막았는데 MCP만 남아 있었다.

결정:
- dynamic client registration은 하지 않는다. 사람이 그 서비스에 만든 client를 넣는다(앱 OAuth와 같다). (agent)
- agent 정의 층 server는 OAuth를 고르지 않게 둔다. core에 그 층의 sign-in 길이 없어서다. 남은 일은 `issues/agent-definition.md`다. (agent)
- grant [Revoke]는 앱 secret 값을 지우지 않는다. 이름이 전역이라 다른 앱이 같은 값을 쓴다. (agent)
- 과하다고 본 secret 장치 가운데 앱 log를 읽을 때의 redaction, supervisor의 60초 보관과 redirect 뒤 다시 붙이지 않기는 남긴다. 앞의 것은 core만 아는 값을 지우고, 뒤의 둘은 invocation 끝을 모르는 supervisor와 바깥 서버의 redirect를 막는다. (agent)

후속: `issues/agent-definition.md`의 "agent 정의 층의 OAuth MCP server는 sign-in할 길이 없다".

## core에 구조화 log·trace·metric, `/healthz`·`/readyz`, 오류 hint·trace_id, `npm run doctor`

```yaml
modules: [packages/base, packages/protocol, packages/core/diagnostics, packages/core/server, packages/core/main, packages/core/jobs, packages/core/workflows, packages/core/storage, packages/core/apps, tools]
checked: [architecture-observability, tool-doctor]
```

- 전: core daemon의 운영 출력은 `console.error` 평문이었다. 요청을 잇는 id가 없었고 metric이 없었다. 상태는 `diagnostics/status`(구성 요소 available)뿐이었다. 오류 body는 `code`, `message`(, `details`)였다. 개발 환경을 점검하는 명령이 없었고 `.env.example`은 git에 없었다.
- 후:
  - core의 log는 stderr 한 줄 JSON(`LOPHN_LOG_FORMAT=pretty`면 사람이 읽는 줄)이다. 칸: `timestamp`, `level`, `service_name`, `trace_id`, `span_id`, `component`, `event`, `message`, `fields`. credential pattern, 알려진 secret, secret 모양의 key 이름(password, token, api_key …)의 값은 `*`로 나간다.
  - API 요청마다 server span이 생기고, ledger writer command와 reader read가 그 아래 span이다. 받은 `traceparent`를 잇고, 모든 응답에 `traceparent`와 `x-trace-id`가 붙는다. RED metric: `http.server.requests`, `http.server.errors`(5xx), `http.server.request.duration`(ms).
  - `LOPHN_TELEMETRY=console`이면 span을 debug log로, `otlp`면 span·metric·log를 `OTEL_EXPORTER_OTLP_ENDPOINT`(loopback http만)로 10초마다와 종료 때 보낸다. 기본 `off`.
  - `GET /healthz`(uptime, pid, memory)와 `GET /readyz`(구성 요소 점검과 점검별 지연, reader 상태, event loop 지연, memory. `ready`·`degraded` 200, `not_ready` 503). 둘 다 Bearer가 있어야 한다.
  - 오류 body에 `hint`(code마다 고정 문장)와 `trace_id`가 더해진다. handler가 던진 것은 `api handler_threw` error log에 종류와 저장소 안 첫 frame만 남는다.
  - `kill -USR2 <core pid>`가 `<data root>/diagnostics/`에 자원 요약 JSON과 5초 CPU profile을 남긴다(`LOPHN_HEAP_SNAPSHOT=1`이면 heap snapshot도).
  - `npm run doctor`(`tools/doctor/`)가 runtime·도구 판, Electron과 sandbox, `.env` 대 `.env.example`, telemetry env, lock 파일과 설치본, 필수 binary, dev data root, port 7431·7499, 떠 있는 core, 바깥 TCP 연결을 보고 `fix:` 명령을 보인다. `--fix`는 `.env` 복사, chmod, `.cache` 만들기를 한다. `.env.example`을 git에 넣는다.
- 계약:
  - 생긴 것: `errorBodySchema.error.hint`, `errorBodySchema.error.trace_id`, HTTP `GET /healthz`·`GET /readyz`, 응답 header `traceparent`·`x-trace-id`, env `LOPHN_TELEMETRY`·`LOPHN_LOG_LEVEL`·`LOPHN_LOG_FORMAT`·`OTEL_EXPORTER_OTLP_ENDPOINT`·`LOPHN_HEAP_SNAPSHOT`, `CoreOptions.telemetry`, `WiringContext.telemetry`, `packages/base/telemetry/`.
  - 바뀐 것: `JobSchedulerDeps.logger`, `createWorkflowService`의 `logger`, `withAfterCommit(writer, apply, logger)`, `confirmStartup(root, logger)`, `ReaderPoolOptions.logger`, `openRuntime`의 `logger`.

왜: 장애 때 log, 요청, ledger 호출을 한 id로 묶어 원인을 좁히고, 새 개발자가 명령 하나로 환경 문제를 찾게 한다.

결정:
- OpenTelemetry SDK를 들이지 않고 W3C Trace Context·OTLP JSON 모양을 직접 만든다. core는 `node:http` loopback API와 SQLite Worker라 auto-instrumentation이 거의 걸리지 않고, base는 바깥 import를 못 한다. 버린 길: `@opentelemetry/*` 6~8개 의존. (agent)
- `/healthz`·`/readyz`도 Bearer를 요구한다. 같은 컴퓨터의 사용자 앱이나 agent가 띄운 명령이 token 없이 core 내부 상태를 읽지 않게 한다. 버린 길: `/healthz` 무인증. (agent)
- OTLP는 loopback 수집기에만 보낸다. core의 network는 loopback뿐이라는 규칙을 telemetry가 깨지 않는다. 바깥 backend는 수집기가 내보낸다. (agent)
- 바깥 provider·MCP로 가는 요청에는 `traceparent`를 붙이지 않는다(`tracedFetch`는 loopback에만). (agent)

후속: 없음.

## agent 정의 층에 둔 OAuth MCP server도 sign-in한다

```yaml
modules: [packages/core/lophn-agent, packages/core/apps, packages/core/main, packages/protocol, packages/shell/renderer, tools]
checked: []
```

- 전: agent 편집 화면의 server form은 OAuth 2.1을 고르지 못했다. 정의 파일에 손으로 `oauth2`를 써도 core의 sign-in이 그 server를 찾지 못했고(`registeredMcpServers`에 없었다), token 이름이 place에서만 정해져 같은 이름의 전역 server와 겹쳤다.
- 후:
  - agent 편집 화면에서 OAuth 2.1 server를 더하고, 정의를 저장한 뒤 그 줄의 [Sign in]으로 로그인한다. 그 agent의 turn만 그 token을 붙인다.
  - agent 층 server의 token은 `mcp-oauth.<agent id>.<server>.*`에 둔다. 사람이 넣는 credential 이름 `mcp.<agent id>.<server>`와 같은 규칙이다.
- 계약:
  - 바뀐 것: `BeginMcpAuth`·`CompleteMcpAuth`·`CancelMcpAuth` 입력과 `ReadMcpAuthState`의 `servers[]` 입력·출력에 `agent`(agent id 또는 null, 필수)가 생겼다. place와 agent가 둘 다 있으면 `invalid_input`이다. `McpAuthKey`는 `{place, agent, name}`, `runtimeServerOfLayer`는 셋째 인자 `agent`, `RegisteredMcpServer`는 `agent`, `McpSourceOptions.agent`는 `id`를 받는다. renderer `McpLogin`에 `agent`, `AgentDetail`에 `agentMcpLogins`가 생겼다.
  - 이 판 첫 항목의 결정 "agent 정의 층 server는 OAuth를 고르지 않게 둔다"를 바로잡는다.

왜: OAuth MCP server를 한 agent에만 붙일 길이 없었다. 전역이나 project 층에 두면 그 범위의 모든 agent가 그 tool을 받는다.

결정:
- 자리(`placeSchema`)에 agent를 넣지 않고 `agent` 칸을 따로 둔다. 자리는 session·skill·권한이 같이 쓰는 값이라 MCP 소유자 때문에 넓히지 않는다. (agent)
- agent 층 server의 로그인은 저장된 정의의 server에만 연다. core가 읽는 것은 정의 파일이다. (agent)

후속: 없음.
