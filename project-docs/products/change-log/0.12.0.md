# 0.12.0

## 대화 화면 다듬기: 편집 카드 한 줄, composer 아래 줄 정리, `/status` 위로 띄우기, 머리 시각·Retry·사람 글 Fork 제거

```yaml
modules: [packages/shell/renderer, packages/design, tools]
checked: [architecture-agent-chat]
```

- 전:
  - 편집 카드는 글 한 줄 아래에 chevron과 `[Open]`이 따로 한 줄 더 있었다.
  - composer 오른쪽 끝에 `[Stop]`과 보내기 단추가 따로 있었다.
  - composer에 model 단추와 별도로 `Effort: Default` 같은 축 단추가 있었다. 사용량(창·token·금액)은 place·권한 아래 별도 줄이었고 금액은 `About 2.064708 USD`였다.
  - `/status` panel이 대화 위쪽을 덮어 대화가 가렸다.
  - agent 답 머리에 이름 옆 시각이 있었고, 마지막 끝난 turn에 `[Retry]`(`AgentTabSource.repeatTurn`)가 있었다. 쓰는 중인 글 끝에 caret이 깜빡였다. 내 메시지에도 `[Fork]`가 있었다.
- 후:
  - 편집 카드가 한 줄이다: 앞에 chevron, `Edited <path> +n −m`, 오른쪽 끝 `[Open]`.
  - 쓰는 중인 글 끝의 caret을 없앴다(코드 block 아래 막대로 보였다).
  - composer의 축 단추를 지웠다. effort·speed는 model menu 안에서만 고른다(좁은 폭에서만 모으던 규칙이 항상이 됐다). 사용량은 place·권한과 같은 줄의 오른쪽 끝이다.
  - composer의 동작 단추가 하나다(둥근 단추). 글이 없고 쉬는 중이면 옅은 보내기, 글이 있으면 채워진 보내기, 도는 중이고 글이 없으면 채워진 네모 `Stop`, 도는 중에 글이 있으면 보내기(다음 turn 줄)다. Esc의 멈추기는 그대로다.
  - 금액은 `$2.06`처럼 통화 기호와 소수 둘이다(`status-summary.ts`의 `costText` 하나, footer와 `/status`가 같이 쓴다). 추정과 보고는 가르지 않는다. 값을 모르는 묶음(`Unknown`)은 `/status`에만 보이고 footer는 아는 금액만 둔다.
  - `/status`의 Tokens 줄은 입력(cache 뺀 것)·cache에서 읽은 입력·출력의 비율 띠와 개수 legend다. 전에는 `7,473,839 in (7,473,679 cached) · 182,676 out` 한 줄이었다.
  - `/status`는 composer 윗변에 붙어 위로 뜨는 overlay라 대화가 보인다.
  - agent 답 머리의 시각을 없앴다(아래 줄의 시각은 그대로). `[Retry]`와 `repeatTurn`을 지웠다. 오류 줄의 `[Retry]`(`retryTurn`)는 그대로다. `[Fork from here]`는 agent 답에만 있다.
- 계약:
  - 지운 것: `AgentTabSource.repeatTurn`, `ModelAxisMenus`, i18n `conversation.label.model-axis*`·`status-cost-estimated`·`status-cost-reported`. `AgentComposer`에 `usage` slot이 생겼다.
  - Fork 명령(`forkSession`, `through_seq`)은 그대로다. 고른 메시지의 `created_seq`까지 복사하므로 agent 답에서 갈라도 그 답까지 들어간다. 저장 모양은 바뀌지 않아 migration이 없다.

왜: 사람이 쓰면서 고른 화면 정리다. 중복(effort 단추, 시각, 별도 사용량 줄)과 가리는 것(`/status`), 쓰이지 않는 것(Retry, 사람 글 Fork)을 줄였다.

결정:
- 금액에서 `About`(추정)을 뺐다. 사람이 구별을 원하지 않았다. (사람)
- 통화는 `Intl.NumberFormat("en-US", currency)`로 그려 USD는 `$`, 그 밖은 그 통화 기호다. 통화 코드를 몰라 던지면 `2.06 XXX`로 둔다. (agent)

후속: 없음.

## 대화: [Send now]·[x]가 줄에 바로 보이고, steer 표시가 남고, 잠깐 끊긴 뒤에도 놓친 줄을 다시 맞춘다

```yaml
modules: [packages/protocol/events, packages/core/main/daemon/wiring, packages/core/lophn-agent/session, packages/shell/main, packages/shell/renderer]
checked: [architecture-agent-chat, architecture-event]
```

- 전:
  - 다음 turn 줄의 [Send now]·[x]는 core 입력함(메모리)만 바꾸고 event를 내지 않아 줄이 그대로 남았다. 다시 누르면 이미 빠진 메시지라 "That didn't work"이 떴다. 올린 메시지는 turn이 정해져도 `delivery`가 `next_turn`이라 대화에 steer 표시가 붙지 않았다.
  - 큐 글 고치기·순서 바꾸기(`session_inputs/edit`·`move`)는 shell main allowlist에 없어 늘 forbidden이었다.
  - 조건이 다시 걸려 `ready`가 오는 동안 쌓인 event는 앞선 snapshot 읽기가 안 끝났으면 버려졌고 대화는 다시 읽지 않았다. 읽기가 reject되면 `syncing`이 풀리지 않아 event가 영영 쌓이기만 했다.
  - 쓰는 중인 글이 저장되는 순간(특히 reasoning뿐인 응답) 묶음 전체가 key가 바뀌어 다시 mount되고 본문을 읽는 동안 줄이 비었다.
- 후:
  - agent event `MessageSteered`·`MessageRemoved`가 생겼다(core가 `steer_now`·`remove` 성공 뒤 낸다). 화면은 줄을 대화의 steer 줄로 옮기거나 뺀다. session snapshot에 `steering`(아직 model 요청에 싣지 않은 steer)이 생겨 다시 읽어도 줄이 되살아나지 않는다. 화면은 turn을 연 입력이 아닌데 turn이 정해진 사람 메시지를 steer로 그린다.
  - `takeSteering`이 올린 메시지의 checkpoint를 지운다(steer는 rewind 시점이 아니다).
  - allowlist에 `session_inputs/edit`·`move`를 더했다. [Send now]·[x] 성공 뒤 대화를 다시 읽는다.
  - `syncOnReady`는 겹친 `ready`에서도 모은 event를 버리지 않고 읽기 실패에도 풀린다. 맞춘 횟수(`synced`)가 늘면 대화를 다시 읽는다. 묶음의 key를 앞 구분 줄 id로 하고, 저장되기 전 live reasoning을 본문을 읽기 전 자리로 쓴다.
- 계약:
  - 바뀐 것: `SessionSnapshot.steering`(선택).
  - 생긴 것: agent event `MessageSteered {message}`, `MessageRemoved {message}`.
