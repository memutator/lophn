# lophn-agent/observability

원본 run·호출·변경을 한 trace로 되짚는 범위, trace 화면에서 확인할 근거, 파일·네트워크 export와 보존 정책을 맡는다; 사용량 합계는 lophn-agent/harness/usage, 실제 삭제는 platform/ledger와 platform/blob-store가 맡는다.

## 요구

### trace

**[R1]** trace 하나는 run 하나의 시작 조건·상태 변경·model 및 도구 호출의 원본 참조를 묶으며 관측용 별도 원본이나 이력 사본을 만들지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 같은 run의 변경 이력과 호출을 한 묶음으로 읽으며, 관측을 꺼도 상태 변경의 원본이 사라지지 않고 별도의 trace 원본 저장소가 생기지 않는다.
- 의도: lophn-agent#I7

**[R2]** trace는 시작 당시 주체·일·대상 고정 판·역할 정의 및 지시 판·선택한 model·허용 도구를 원본 근거로 조회하며 시작 조건 안에 지시 본문 사본을 넣지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: run 뒤 역할 정의·model·도구·대상을 바꿔도 이전 시작 조건은 변하지 않으며 지시 본문은 당시 보호된 원본으로 열리고 시작 조건에 중복 사본이 없다.
- 의도: lophn-agent#I7

**[R3]** handoff 수신 run은 별도 trace로 조회하고 보낸 run과 받은 run을 양방향으로 연결하며 실제 주체와 비용 귀속을 발신 주체로 바꾸지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: handoff 양쪽 trace에서 상대 run으로 이동하며 같은 실제 호출을 두 주체의 것으로 복제하지 않는다.
- 의도: lophn-agent#I7

**[R4]** run에 속하지 않는 model 호출은 호출 하나의 독립 trace로 조회하고 실제 연결된 세션만 가리키며 가짜 run·세션을 만들지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 대화 제목 생성과 대화 없는 배경 호출을 각각 조회할 수 있으며, 대화 없는 호출에는 새 대화가 생기지 않는다.
- 의도: lophn-agent#I7

**[R5]** trace는 lophn-agent/harness/usage의 모든 실제 model 시도와 lophn-agent/harness/tools의 모든 도구 판정을 샘플링 없이 연결하고 retry·실패·취소·미실행·불명확한 결과를 구별한다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: model 실패 뒤 retry와 거절된 도구 호출을 각각 따로 찾고 기록이 없으면 누락을 표시한다.
- 의도: lophn-agent#I7

**[R6]** trace는 UTC 시작·종료 시각을 밀리초 정밀도로 남기고 경과 시간은 단조 시계로 재며, run 전체 경과 시간, 모델 호출 경과 시간, 첫 응답까지의 시간, 도구 실행 시간과 사람의 답을 기다린 시간을 각각 구별한다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 10초 동안 사람의 답을 기다리고 2초 동안 모델을 호출한 run에서 기다림과 호출 시간이 서로 다른 값으로 나오며, 시스템 시계를 뒤로 바꾸어도 측정한 경과 시간이 음수가 되지 않는다.
- 의도: lophn-agent#I7

**[R7]** trace는 machine이 확인한 정상 종료, 모델 오류, 도구 오류, 권한 거절, 안전에 의한 차단, 사용자 중단을 구별하고 종료 확인 없이 끊긴 run을 정상 종료로 간주하지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 모델이 완료했다고 말한 뒤 변경이 실패한 경우 실패 사실이 남고, 데몬이 중간에 종료된 경우 종료 확인이 없음을 볼 수 있다.
- 의도: lophn-agent#I7

**[R8]** trace는 실제 model 입력·응답·사용한 자료의 고정 판과 구간·요약 근거·생략·크기·압축·cache 경계를 소유 원본에서 조회하고 문맥 본문 사본이나 별도 영구 조립 이력을 만들지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 압축 전후의 호출에서 원래 자료 판·범위·생략을 찾으며 관측을 위해 복제한 원문은 없다.
- 의도: lophn-agent#I7

**[R9]** trace의 본문은 lophn-agent/conversation·lophn-agent/harness/usage·lophn-agent/harness/tools의 보호된 원본으로만 열고 자유 형식 오류 원문·비밀·내부 추론을 관측용 사본으로 저장하지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 보존된 실제 입력·응답은 원본으로 열리고 비밀·내부 추론과 관측용 중복 본문은 없으며 redaction은 platform/redaction을 따른다.
- 의도: lophn-agent#I7

- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 한글 내용의 export가 UTF-8 경계를 지키고 잘림을 별도 표시하며 긴 복구 원본의 뒷부분은 그대로 읽힌다.
- 의도: lophn-agent#I7

**[R11]** 확정 전 스트리밍 조각과 진행 말은 영구 trace·재생·export에 넣지 않고 확정 본문은 소유 원본을 참조한다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 스트림 종료 뒤 조각 재생이 없으며 확정된 메시지와 호출의 원본 링크만 조회된다.
- 의도: lophn-agent#I7

### export와 범위

**[R12]** 관측 기록은 platform/ledger·platform/blob-store가 관리하는 로컬 원본을 이용하며 네트워크 export와 제삼자 사용량 분석 전송은 기본으로 꺼져 있다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 기본 설정으로 실행할 때 관측용 외부 요청은 없으며, 인터넷 없이도 trace와 비용을 조회할 수 있다.
- 의도: lophn-agent#I7

**[R13]** 네트워크 내보내기는 사용자가 대상 세션·실행과 목적지를 직접 지정했을 때만 켜고, 목적지는 HTTPS 또는 루프백 주소의 HTTP로 제한하며 프로젝트 설정과 역할은 수집 범위 확대나 목적지 변경을 하지 못한다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 목적지 없이 켜기, 비루프백 HTTP, 프로젝트 설정을 통한 목적지 바꾸기는 거절되며 사용자가 지정한 루프백 수집기에는 선택 범위만 간다.
- 의도: lophn-agent#I7

**[R14]** 로컬 파일 내보내기는 UTF-8 NDJSON으로 문서 형식 버전 1과 trace별 기록을 남기고, 네트워크 내보내기는 OpenTelemetry OTLP/HTTP의 Protobuf 형식만 지원한다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 파일의 각 줄을 독립된 JSON으로 읽어 형식 버전과 기록 관계를 복원할 수 있으며, 표준 OTLP/HTTP 수집기가 Protobuf 요청을 받아 실행·모델·도구 단위를 구별한다.
- 의도: lophn-agent#I7

**[R15]** OpenTelemetry 내보내기는 실행을 agent 수행 단위로, 모델 호출과 도구 호출을 그 안의 작업 단위로 변환하고 handoff의 별도 trace는 링크로 연결하며, 적용한 GenAI Semantic Conventions 버전을 명시하고 원본 기록의 의미를 바꾸지 않는다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 같은 원본을 두 규약 버전으로 내보내도 run의 호출 수, 수행 주체와 비용은 같고, 버전과 협업 연결을 수집기에서 찾을 수 있다.
- 의도: lophn-agent#I7

**[R16]** 파일·네트워크 export는 메타데이터만 기본으로 보내고 사용자는 export마다 메시지·model 입력·model 출력·도구 입력·도구 출력 중 포함할 종류를 다시 고른다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 보호된 원본에 도구 결과가 있어도 기본 export에는 본문이 없고 해당 종류를 선택한 export에만 redaction과 내용 상한을 적용한 본문이 포함된다.
- 의도: lophn-agent#I7

**[R17]** 내보내기 실패는 로컬 원본과 실행 결과를 바꾸거나 모델 호출을 재시도시키지 않으며, 보낸 기록 수와 보내지 못한 기록 수를 구별하여 반환한다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 수집기를 중단한 채 내보내기를 실행해도 로컬 조회와 원래 작업 결과가 유지되고, 실패 수가 0인 성공으로 표시되지 않으며 유료 모델 호출이 추가되지 않는다.
- 의도: lophn-agent#I7

**[R18]** trace 조회는 호출 수·차단 수·오류·시간·근거의 사실만 계산하고 사용량·비용은 lophn-agent/harness/usage, 품질 점수·통과 기준은 lophn-agent/evaluation을 가리킨다.
- 이유: 과거 판단과 실제 동작을 당시 근거로 되짚되 원본을 중복하거나 성공을 추정하지 않는다.
- 확인: 평가 기준을 바꾸어도 trace의 실패 사실, 호출 수와 비용은 같고, 관측 기록만으로 run에 품질 점수나 합격 표시가 붙지 않는다.
- 의도: lophn-agent#I7

### trace 화면

**[R19]** 외부 MCP 호출은 서버 응답의 기록 유무와 무관하게 실제 주체·서버·원래 도구·효과 분류·최종 판정과 근거·approval 및 결정한 사람·실행 여부·성공·거절·실패·결과 불명을 연결하여 조회한다.
- 이유: 외부 서버가 감사 기록을 제공하지 않아도 책임과 결과를 구별해야 한다.
- 확인: 기록 없는 MCP 테스트 서버에서 성공·거절·실패·응답 전 단절이 각각 추적된다.
- 의도: lophn-agent#I7

**[R20]** trace 화면은 기본으로 대상·결과·필요한 다음 행동만 보여 주고 상세에서 시각·나·역할 이름·자동 확인의 구별·이유·근거·영향 문서와 앱 링크를 확인하게 하며 근거 또는 본문이 없으면 없다는 사실과 읽을 수 있는 범위를 표시하고 화면 말은 shell/wording을 따른다.
- 이유: 변경의 주체와 판단 근거를 혼동하거나 삭제된 자료를 존재하는 것처럼 보여서는 안 된다.
- 확인: 세 주체와 삭제된 원문을 함께 조회하면 구별되고 없는 링크를 성공한 읽기로 꾸미지 않는다.
- 의도: lophn-agent#I7

**[R21]** 도구 활동은 단계 개수로 접어 실패·거절 요약을 남기고 펼치면 시작 순서의 대상·한 일·상태를 보이며 도구 이름·입력·원문 결과는 추가 자세히에서 열게 한다.
- 이유: 원문이 기본 결과를 밀어내지 않으면서 원인 추적은 가능해야 한다.
- 확인: 성공 10단계와 실패 1단계를 접어도 실패가 보이고 끝났다는 사실만으로 성공 표시가 붙지 않는다.
- 의도: lophn-agent#I7

**[R22]** agent 판단은 검토 가능한 요약으로만 설명하고 model의 내부 사고 과정은 trace로 요구하지 않는다.
- 이유: 설명 가능한 근거와 내부 추론은 다르다.
- 확인: 요약과 근거를 확인할 수 있으나 내부 추론 원문은 제공하지 않는다.
- 의도: lophn-agent#I7

- 확인: 181일 된 상세와 15일 된 본문이 자동 만료 기본값 때문에 없어지지 않는다.

**[R24]** 유한 보존 정책을 적용할 때도 진행 run·미반영 입력·답 및 approval 대기·revert 근거는 삭제 대상으로 넘기지 않는다.
- 이유: 진행과 복구에 필요한 근거가 수명 정리 때문에 사라져서는 안 된다.
- 확인: 만료 후보에 대기·revert 근거가 섞이면 보호 대상으로 구별된다.
- 의도: lophn-agent#I7

**[R25]** 본문이 보존 종료로 사라지면 그 원문을 담은 derived index·cache의 제거와 부재 표시를 platform/blob-store·platform/ledger에 요청하며 다른 store의 정리를 한 transaction으로 약속하지 않는다.
- 이유: 삭제된 내용이 다른 파생 경로로 다시 보이면 삭제 의미가 깨진다.
- 확인: 원문 제거 뒤 trace는 부재를 표시하고 derived 경로에서도 원문이 돌아오지 않는다.
- 의도: lophn-agent#I7

**[R26]** run·호출·세션의 보존 종료를 그 과정에서 만든 문서·release의 삭제로 전파하지 않고 변경 주체의 최소 식별과 남은 근거의 부재를 유지한다.
- 이유: 오래 쓸 산출물은 일시적인 작업 기록과 수명이 다르다.
- 확인: 호출 본문이 없어진 뒤 문서·release와 저자 구별이 남는다.
- 의도: lophn-agent#I7

## 버린 것

- 다섯 종류별 local 본문 기록 opt-in — 복구·이어가기에 필요한 세션·호출 본문을 보호 처리하여 기본 저장하므로 export 선택만 유지한다.
- subagent trace와 자동 대체 model trace 예시 — subagent와 자동 model 대체를 새 설계에서 제공하지 않는다.
