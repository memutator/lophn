# 0.10.2

## 쓰던 data root가 새 판으로 이어진다: schema step은 id로 적용하고, data root 파일에도 migration step이 있다. 제품 판은 하나다

```yaml
modules: [packages/core/storage, packages/core/main, packages/coding-agent, packages/shell/main, tools]
checked: []
```

- 전:
  - ledger 적용기는 step의 목록 위치를 판 번호로 썼다. 앞쪽 module에 step을 하나 더하면 뒤 step의 번호가 밀려 기존 ledger가 `history_mismatch`로 열리지 않았다.
  - ledger 밖 파일(`agents/*.md`, `settings.json`, `secrets.json` 등)의 모양을 바꿀 길이 없었다. 개발 data는 schema가 바뀌면 지웠다.
  - 제품 판이 `packages/shell/main/package.json`과 CLI의 상수 `VERSION` 두 곳에 있었다.
- 후:
  - 적용기는 `schema_migrations.step_id`로 적용 여부를 본다. 기록에 없는 id만 차례로 적용하고, 같은 id의 SQL hash가 다르면 `history_mismatch`, 지금 목록에 없는 id가 적용돼 있으면 `newer_schema`다. 복구본은 전처럼 미적용 step이 있을 때 먼저 만든다.
  - wiring이 `dataSteps`(`{id, run(root)}`)를 낸다. core가 ledger migration 뒤에 `<data root>/data-migrations.json`에 없는 step만 돌리고 하나 끝날 때마다 기록한다. 새 data root는 돌리지 않고 모두 적용한 것으로 적는다. 기록에 모르는 id가 있으면 `newer_schema`로 거절한다.
  - 제품 판은 root `package.json`의 `version` 하나다. CLI `lophn version`이 그것을 읽고, `.deb` 이름과 Electron 앱 판도 같은 값이다.
- 계약:
  - 생긴 것: `Wiring.dataSteps`, `applyDataSteps`, data root 파일 `data-migrations.json`.

왜: 사람이 lophn을 실제로 쓰기 시작해 `~/.lophn`을 지울 수 없다. 새 판을 깔아도 쓰던 data가 그대로 열려야 한다.

결정:
- package마다 판을 두지 않는다. `.deb` 하나가 모든 package를 같은 commit에서 싣는다. 버린 길: package별 판. 맞춰 볼 상대가 없다. (사람)
- 앱 SDK 판은 이번에 다루지 않는다. 앱 SDK를 덜 써 봤다. (사람)
- SDK 설치 사본, 앱 template, node shim은 전처럼 기동마다 설치본과 byte를 맞춰 다시 쓴다. harness hook은 PATH의 `lophn`을 부르므로 판이 바뀌어도 다시 놓지 않는다. 그래서 data step에 넣지 않았다. (agent)
- 자동 업데이트는 두지 않는다. 배포 서버가 없고 `.deb` 설치는 root가 필요하다. 새 `.deb`을 `apt install`로 덮어 깐다. (사람, agent)

후속: 없음. 이미 낸 step의 SQL을 고치면 쓰던 ledger가 열리지 않으므로, 앞으로 표를 바꿀 때는 새 step을 더한다(AGENTS.md "호환성").

## 끊김을 hook으로 알리는 harness는 Esc·Ctrl-C로 탭 점을 내리지 않는다

```yaml
modules: [packages/protocol, packages/shell/main]
checked: []
```

- 전:
  - 도는 turn 중에 Esc나 Ctrl-C를 한 번 치면 tracker가 상태를 unknown으로 내렸다. omp·pi 등은 입력을 지우거나 팝업을 닫는 데도 이 key를 써서, turn이 도는데 점만 사라졌다.
  - unknown은 다음 TurnStarted까지 안 풀린다. `wait`·subagent로 이어지는 turn은 몇 시간이고 점이 없었다.
- 후:
  - 끊김을 hook으로 알리는 harness(opencode·kilo·mimocode, pi, omp, amp, grok, droid, cline, cursor, kimi, codex)는 `interrupt_keys`가 비어 있고, 끊김은 TurnEnded(interrupted)로만 안다. cursor는 `stop`의 `status: aborted`, kimi와 codex는 `Interrupt` hook, 나머지는 plugin 본문이 알린다.
  - 그 밖의 harness(claude, copilot, kiro, antigravity, devin, qwen, qoder, muse, codebuddy, command-code, letta, hermes)는 전처럼 key로 내린다. hermes는 `on_session_end`의 `extra.interrupted`를 읽는 코드는 있지만 실제로 오는지 확인하지 못해 남겼다.
  - 키 판정이 남은 harness는 키로 내린 것을 짐작으로 기억한다. 그 뒤 PermissionResolved(PostToolUse 계열)가 오면 turn이 안 끊긴 것이라 running으로 되돌린다.
- 계약:
  - 바뀐 것: `HARNESS_ADAPTERS[id].interrupt_keys`가 위 harness에서 `[]`.

왜: 점은 도는 turn 동안 보여야 한다. 끊김을 hook이 알려 주는데 key로도 내리면 오판만 늘고 되돌릴 길이 없다.

결정:
- key 판정은 끊김 신호가 없는 harness에만 남긴다. 버린 길: 모든 harness에서 key 판정 삭제. Claude Code는 Esc로 끊어도 Stop을 안 보낸다. (agent)
- 키 판정이 남은 harness의 같은 증상(입력 지우기로 점이 사라짐)은 tool이 끝나는 hook으로 되돌린다. tool이 없는 turn(긴 생성)에서는 되돌리지 못한다. 진짜 끊긴 turn에 동시에 끝난 tool의 늦은 hook이 오면 running에 남을 수 있어 감수한다. (agent)
- 각 harness가 실제로 끊김 hook을 내는지는 표와 payload를 읽는 코드, 공식 문서(cursor `stop.status`)로 가렸다. 실행해서 확인한 것은 omp뿐이다. (agent)
- Codex 0.150 미만은 `Interrupt` hook이 없어 끊어도 running에 남는다. 설치본이 0.165이고 표가 판을 가르지 못해 감수한다. (agent)

후속: 이미 떠 있는 탭의 unknown은 다음 turn이 시작해야 풀린다. 앱을 다시 켜면 이 변경이 적용된다.

## wording 검사·생성 체계를 지우고 `@lophn/i18n`(@formatjs/intl)만 남긴다. 생성 앱은 문구를 화면 코드에 그대로 쓴다

```yaml
modules: [packages/design, packages/sdk, packages/core/apps, packages/shell/main, tools]
checked: [architecture-ui-kit, architecture-appearance, skill-ui-design, tool-check]
```

- 전:
  - `@lophn/wording`이 en catalog와 `t()`를 갖고, 직접 만든 placeholder 생성기(`npm run wording`, `*.placeholders.ts`)와 문구 검사(`tools/check-wording.ts`: 직접 쓴 문구, key 이름·마침표 규칙, 안쪽 말 경고)를 `npm run check`가 돌렸다.
  - 생성 앱 template도 `src/wording/`(en catalog, 생성 placeholders, `t`), `scripts/generate-wording.ts`, `tests/wording_test.ts`를 가졌다.
  - `@lophn/app-ui`의 `ToolButton`·`AppErrorBoundary` 문구는 늘 en이었다.
- 후:
  - package 이름은 `@lophn/i18n`(`packages/design/i18n`)이다. `t(key, values?)`와 `translator(locale)`는 `@formatjs/intl` 위의 얇은 층이고, 없는 locale·key는 en 문장이다. catalog 값과 key는 그대로다. 생성기, `*.placeholders.ts`, `check-wording`, wording skill은 없다.
  - placeholder 이름·종류는 type이 보지 않는다. 틀리면 실행할 때 formatjs가 오류를 console에 낸다.
  - main이 dom-ready마다 앱 view(`lophn-app://`) 문서에 `<html data-lophn-locale>`을 적고, `@lophn/app-ui`가 그 locale로 자기 문구를 고른다.
  - 앱 template과 test sample 앱은 catalog 없이 화면·선언 문구를 코드에 그대로 쓴다.
- 계약:
  - 바뀐 것: 내장 SDK `@lophn/ui` 1.1.0, `@lophn/app-ui` 1.1.0(둘 다 `@lophn/i18n` 1.0.0에 기댄다). `FIXED_UI_DEPENDENCIES`의 `@lophn/wording` → `@lophn/i18n`.
  - 없어진 것: 새 template의 `@lophn/wording` 의존, `npm run wording`(repo와 앱).

왜: en 하나뿐인 catalog에 생성기와 검사기가 붙어 문구 하나 고치는 데 단계가 많았고 사고가 났다. 번역 틀은 표준 library로 두고, 사용자 한 사람이 쓰는 생성 앱에는 번역이 필요 없다.

결정:
- 직접 만든 i18n 대신 `@formatjs/intl`을 쓴다. 이미 쓰던 `intl-messageformat`과 같은 계열이라 catalog와 `t()` 호출 250곳을 고치지 않는다. 판은 쓰던 `intl-messageformat` 12.1.2에 맞춰 6.1.2다. (사람, agent)
- 이미 만든 앱은 옮기지 않는다. data root의 `sdk/wording/1.0.0`, `sdk/ui/1.0.0`, `sdk/app-ui/1.0.0` 사본은 기동이 지우지 않으므로 그 앱은 고정한 판으로 계속 build된다. 새 판은 새 폴더(1.1.0)에 깔린다. 같은 판 번호의 byte를 바꾸면 lock이 있는 기존 앱의 `npm ci`가 실패해서 판을 올렸다. (사람, agent)
- `@lophn/app-ui`의 locale은 appearance가 이미 앱 view에 닿는 dom-ready 길로 보낸다. 새 preload API를 만들지 않는다. (사람)

후속: 없음.

## ChatGPT 구독을 Codex client로 로그인하고 Codex backend로 보낸다

```yaml
modules: [packages/core/lophn-agent, packages/protocol, packages/shell/renderer, packages/design]
checked: []
```

- 전:
  - ChatGPT 구독은 OpenAI 공식 Sign in with ChatGPT(`dynamic_agent_client` 등록, id_token JWKS 검증)로 로그인하고 `api.openai.com/v1/responses`로 보냈다. 요청에 `prompt_cache_key`나 session header가 없어 앞부분이 같은 요청도 cache를 거의 못 읽었다(한 session의 cache 읽기 9.8%, 49번 중 34번 0).
  - `max_output_tokens`를 보냈고, encrypted reasoning을 요청하지 않았다. `cache_write_tokens`를 엉뚱한 칸에서 읽어 늘 null이었다.
  - 설정 화면의 단추는 "Continue with ChatGPT"였다.
- 후:
  - ChatGPT 로그인은 Codex CLI의 공개 client와 고정 callback `localhost:1455/auth/callback`이다. 계정 id·email·plan은 token claim에서 읽는다.
  - ChatGPT 로그인 연결의 endpoint는 `https://chatgpt.com/backend-api/codex`다. `providers/adapters/codex.ts`가 Responses body를 `/responses`로 보내면서 session에서 만든 같은 값을 `prompt_cache_key`와 `session_id`·`conversation_id`·`session-id` header에 싣고, `chatgpt-account-id`를 붙이고, `max_output_tokens`를 빼고, `include`에 `reasoning.encrypted_content`를 넣는다.
  - 계정 model 목록은 Codex backend `GET /models?client_version=…`의 `models[].slug`다.
  - Responses usage의 `cache_write`는 `input_tokens_details.cache_write_tokens`에서 읽고, `input`은 cache 읽기·쓰기를 뺀 값이다.
  - 한도 code는 Codex의 `usage_limit_reached`(quota)·`usage_not_included`(plan_access)다.
  - 단추는 다른 구독처럼 "Sign in with ChatGPT"다.
- 계약:
  - 바뀐 것: provider 정의 `oauth`의 chatgpt 모양(`client_id`, `redirect_uri`, `inference_endpoint`를 더하고 `issuer`·`jwks_uri`·`resource`를 뺐다). token meta에서 `client_id`를 뺐다.
  - 없앤 것: `hostIdOf`와 secret `provider-oauth.host-id`, 화면 문구 `settings.label.method-continue`.
  - ledger step `lophn-agent.harness-provider.chatgpt-codex-login`: 저장한 ChatGPT 연결의 정의와 endpoint를 새 것으로 바꾸고 credential을 `revoked`(`refresh_revoked`)로 둔다. 사람은 Disconnect 뒤 다시 로그인한다.

왜: 같은 일에 Codex보다 ChatGPT 사용량이 훨씬 빨리 닳았다. 원인 1순위가 cache routing이 없는 것이었고, omp·opencode는 이 길로 해결했다.

결정:
- omp 방식대로 Codex client로 로그인한다. 버린 길: 공식 Sign in with ChatGPT 유지. 그 흐름은 `api.openai.com/v1`만 받아 cache affinity를 줄 수 없다. Codex backend는 OpenAI가 제3자에게 공개 보장한 API가 아니다. (사람)
- 옛 token은 옮기지 않는다. 다른 client가 발급해 Codex backend가 받지 않는다. (agent)

후속: 실제 ChatGPT 호출로 `cached_tokens`가 오르는지 아직 확인하지 않았다(`npm run test:live:login` 뒤 `test:live`).

## Claude 구독 cache를 1시간으로 두고 대화 쪽 cache 경계를 둘로, Gemini thought signature를 돌려보낸다

```yaml
modules: [packages/core/lophn-agent, tests]
checked: []
```

- 전:
  - Anthropic 요청의 cache 표시는 system 층 셋(place 종류, 지침, place 정보)과 대화 끝 하나였다. 표시는 모두 5분 수명이었다.
  - Antigravity(Gemini) 요청은 thought signature를 버리고 첫 functionCall에 서명 검사를 건너뛰는 표시만 실었다.
- 후:
  - system 표시는 place 종류와 place 정보 둘이고, 대화 쪽은 마지막 message와 그 앞 user message 둘이다. 넷을 넘지 않도록 system·tools가 쓴 표시를 뺀 남은 자리만 쓴다.
  - Claude 구독(Claude Code profile)은 모든 표시를 1시간 수명으로 보낸다. API key 요청은 5분 그대로다.
  - Gemini functionCall의 thought signature를 tool call에 실어 같은 turn의 다음 요청에 그대로 돌려보낸다. 앞 turn의 functionCall에는 전처럼 건너뛰는 표시를 단다.
- 계약:
  - 바뀐 것: `HistoryPart`의 `tool_use`에 `signature?`, adapter `ToolCall`에 `signature?`. 저장한 이력과 model call blob 모양은 그대로다.
  - 바뀐 것: `assembleTurnPrompt`의 `cache_boundaries`가 둘(place_kind, place)이다.

왜: Anthropic은 표시마다 앞쪽 20 block까지만 찾는다. 대화 쪽 표시가 하나면 한 call에 tool 결과가 많이 늘었을 때 앞 call의 cache를 못 찾는다. 5분 수명은 긴 tool 실행이나 사람의 답을 기다리는 사이에 끝난다. omp와 Claude Code가 이 둘을 같은 방식으로 다룬다.

결정:
- omp를 따라 system 하나·tool 하나 대신 system 둘을 둔다. lophn의 tools는 session 동안 고정이라 place 종류 표시가 함께 덮는다. (agent)
- Gemini 서명은 저장하지 않는다. 같은 turn의 model은 고정이라 그 안에서만 돌려보내면 다른 model의 서명을 보낼 일이 없다. (agent)
- 1시간 수명은 구독 요청에만 둔다. API key는 쓰기 요금이 2배라 Claude Code도 5분이다. (사람이 omp 방식을 골랐다, agent)

후속: 실제 Claude·Antigravity 호출로 cache 읽기가 오르는지 아직 확인하지 않았다.
