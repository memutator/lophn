# lophn 0.6.0

This release moves app building to the App Engineer, reworks how approvals work, and adds headless agent runs, workflows, and desks.

## New
- The App Engineer designs a new app or feature before building it: reuse, data model, journeys, screens, and tools. It asks you only plain questions about what you will see.
- Settings › Shell rules sets allow, ask, or deny rules for shell commands, for all projects or for one project. Choosing "always" on an approval adds an allow rule for that command's first two words.
- A "Skip permissions" line under the chat box lets one session run without asking.
- `lophn agent run` and `lophn tool call` run an agent or an app tool from a terminal, without a window. `lophn run wait`, `show`, and `cancel` follow the result. Runs appear under Background in the sidebar.
- Workflows: a project can define workflows. The Workflows panel lists them, and a workflow tab shows each run and its steps, with Start and Stop. `lophn workflow start`, `stop`, and `show` do the same from a terminal.
- Desks: each project window has a Main desk and one desk per workflow. Switch with the `project ▾ / desk ▾` menu at the top left. Each desk keeps its own tabs and layout.
- App logs are kept in a file per app, so they survive restarts. The App Engineer can read an app's status, logs, and failed calls.

## Changed
- Tools an agent is assigned run without asking again, including tools that reach outside. Shell commands ask only when no rule covers them. The question offers once, always, or reject. The "this session" choice is gone.
- The App Engineer builds apps itself. Tickets, the test runner, and the hand-off to a coding agent are gone. The App Engineer runs the app's tests, prepares a release, previews it, and activates it.
- New apps start empty. The sample item list is gone.
- A release that cannot be prepared says why: the migration step and database error, the first lines of the build output, or the tools that have no handler.
- lophn no longer opens an App Engineer session on its own when an app reports an error. The Issues tab and the Report a problem button are gone. Use an annotation on the app screen to tell the App Engineer about a problem.
- Settings › Reactions is gone.
- The `/` menu lists Commands and Skills. The role commands `new-app`, `repair-app`, and `check-kinds` are now built-in skills, and `/recap` is gone. Text typed after `/skill-name` is sent along with the skill.
- `repair-app` reads the app's status, logs, and failed calls, tells you what it finds, and asks that app's App Engineer to fix it.
- The sidebar is an icon bar: Explorer, Agents, Artifacts, Domains, and Workflows. Click an icon to open its panel, and click it again to collapse the panel.
- An agent can make up to 150 model calls in one turn (was 30).

## Fixed
- Opening another project no longer overwrites the layout of the project you left, and a new project no longer shows the previous project's tabs.
- The shell safety rule against deleting the root or home folder now catches any order of `rm` flags and a `sudo` prefix. Before, only one exact spelling was caught.
- The Instructions card in the Agents tab now shows the contents of LOPHN.md. It was always empty.
- A turn that fails to start is written to the diagnostic log once, instead of failing silently.
- When an app's data migration is rolled back during activation, the failure names the step that failed and the database error.

## Action needed
- If your settings file still has the `reactions.release_activation_failed` line, delete it. lophn refuses the whole settings file while that line is there.
- Run `lophn harness install` once to remove the old `lophn-build-app` and `lophn-repair` skill copies that lophn left in your home folder.
