# 0.10.2

## 쓰던 data root가 새 판으로 이어진다: schema step은 id로 적용하고, data root 파일에도 migration step이 있다. 제품 판은 하나다

```yaml
modules: [packages/core/storage, packages/core/main, packages/coding-agent, packages/shell/main, tools]
checked: []
```

- 전:
  - ledger 적용기는 step의 목록 위치를 판 번호로 썼다. 앞쪽 module에 step을 하나 더하면 뒤 step의 번호가 밀려 기존 ledger가 `history_mismatch`로 열리지 않았다.
  - ledger 밖 파일(`agents/*.md`, `settings.json`, `secrets.json` 등)의 모양을 바꿀 길이 없었다. 개발 data는 schema가 바뀌면 지웠다.
  - 제품 판이 `packages/shell/main/package.json`과 CLI의 상수 `VERSION` 두 곳에 있었다.
- 후:
  - 적용기는 `schema_migrations.step_id`로 적용 여부를 본다. 기록에 없는 id만 차례로 적용하고, 같은 id의 SQL hash가 다르면 `history_mismatch`, 지금 목록에 없는 id가 적용돼 있으면 `newer_schema`다. 복구본은 전처럼 미적용 step이 있을 때 먼저 만든다.
  - wiring이 `dataSteps`(`{id, run(root)}`)를 낸다. core가 ledger migration 뒤에 `<data root>/data-migrations.json`에 없는 step만 돌리고 하나 끝날 때마다 기록한다. 새 data root는 돌리지 않고 모두 적용한 것으로 적는다. 기록에 모르는 id가 있으면 `newer_schema`로 거절한다.
  - 제품 판은 root `package.json`의 `version` 하나다. CLI `lophn version`이 그것을 읽고, `.deb` 이름과 Electron 앱 판도 같은 값이다.
- 계약:
  - 생긴 것: `Wiring.dataSteps`, `applyDataSteps`, data root 파일 `data-migrations.json`.

왜: 사람이 lophn을 실제로 쓰기 시작해 `~/.lophn`을 지울 수 없다. 새 판을 깔아도 쓰던 data가 그대로 열려야 한다.

결정:
- package마다 판을 두지 않는다. `.deb` 하나가 모든 package를 같은 commit에서 싣는다. 버린 길: package별 판. 맞춰 볼 상대가 없다. (사람)
- 앱 SDK 판은 이번에 다루지 않는다. 앱 SDK를 덜 써 봤다. (사람)
- SDK 설치 사본, 앱 template, node shim은 전처럼 기동마다 설치본과 byte를 맞춰 다시 쓴다. harness hook은 PATH의 `lophn`을 부르므로 판이 바뀌어도 다시 놓지 않는다. 그래서 data step에 넣지 않았다. (agent)
- 자동 업데이트는 두지 않는다. 배포 서버가 없고 `.deb` 설치는 root가 필요하다. 새 `.deb`을 `apt install`로 덮어 깐다. (사람, agent)

후속: 없음. 이미 낸 step의 SQL을 고치면 쓰던 ledger가 열리지 않으므로, 앞으로 표를 바꿀 때는 새 step을 더한다(AGENTS.md "호환성").

## 끊김을 hook으로 알리는 harness는 Esc·Ctrl-C로 탭 점을 내리지 않는다

```yaml
modules: [packages/protocol, packages/shell/main]
checked: []
```

- 전:
  - 도는 turn 중에 Esc나 Ctrl-C를 한 번 치면 tracker가 상태를 unknown으로 내렸다. omp·pi 등은 입력을 지우거나 팝업을 닫는 데도 이 key를 써서, turn이 도는데 점만 사라졌다.
  - unknown은 다음 TurnStarted까지 안 풀린다. `wait`·subagent로 이어지는 turn은 몇 시간이고 점이 없었다.
- 후:
  - 끊김을 hook으로 알리는 harness(opencode·kilo·mimocode, pi, omp, amp, grok, droid, cline, cursor, kimi, codex)는 `interrupt_keys`가 비어 있고, 끊김은 TurnEnded(interrupted)로만 안다. cursor는 `stop`의 `status: aborted`, kimi와 codex는 `Interrupt` hook, 나머지는 plugin 본문이 알린다.
  - 그 밖의 harness(claude, copilot, kiro, antigravity, devin, qwen, qoder, muse, codebuddy, command-code, letta, hermes)는 전처럼 key로 내린다. hermes는 `on_session_end`의 `extra.interrupted`를 읽는 코드는 있지만 실제로 오는지 확인하지 못해 남겼다.
  - 키 판정이 남은 harness는 키로 내린 것을 짐작으로 기억한다. 그 뒤 PermissionResolved(PostToolUse 계열)가 오면 turn이 안 끊긴 것이라 running으로 되돌린다.
- 계약:
  - 바뀐 것: `HARNESS_ADAPTERS[id].interrupt_keys`가 위 harness에서 `[]`.

왜: 점은 도는 turn 동안 보여야 한다. 끊김을 hook이 알려 주는데 key로도 내리면 오판만 늘고 되돌릴 길이 없다.

결정:
- key 판정은 끊김 신호가 없는 harness에만 남긴다. 버린 길: 모든 harness에서 key 판정 삭제. Claude Code는 Esc로 끊어도 Stop을 안 보낸다. (agent)
- 키 판정이 남은 harness의 같은 증상(입력 지우기로 점이 사라짐)은 tool이 끝나는 hook으로 되돌린다. tool이 없는 turn(긴 생성)에서는 되돌리지 못한다. 진짜 끊긴 turn에 동시에 끝난 tool의 늦은 hook이 오면 running에 남을 수 있어 감수한다. (agent)
- 각 harness가 실제로 끊김 hook을 내는지는 표와 payload를 읽는 코드, 공식 문서(cursor `stop.status`)로 가렸다. 실행해서 확인한 것은 omp뿐이다. (agent)
- Codex 0.150 미만은 `Interrupt` hook이 없어 끊어도 running에 남는다. 설치본이 0.165이고 표가 판을 가르지 못해 감수한다. (agent)

후속: 이미 떠 있는 탭의 unknown은 다음 turn이 시작해야 풀린다. 앱을 다시 켜면 이 변경이 적용된다.
