# 0.10.0

## model은 켠 것만 보이고, 처음 고른 model이 기본이 된다. effort 저장 고침, 실패 이유를 사람 말로

```yaml
modules: [packages/core/lophn-agent, packages/protocol, packages/shell/renderer, packages/design, tools]
checked: []
```

- 전:
  - provider를 붙이면 그 provider의 model이 모두 picker에 켜져 나왔다(OpenAI는 47개). 사람이 끈 model 목록을 저장했다.
  - Settings → Agents에서 models.dev 갱신으로만 들어온 model(예: `gpt-6.1-terra`)의 effort를 고르면 저장 검사가 동봉 snapshot만 봐서 `invalid_input`으로 거절했다. 화면은 Effort 칸과 떨어진 맨 위에 색 없는 "That didn't work. Nothing changed. Try again." 한 줄을 보였다.
  - 어느 층에도 model이 없을 때 보내면 turn이 `configuration_unavailable`로 끝나 대화에 "configuration unavailable"이 그대로 보였다. 대화 안 실패는 모두 이유 enum을 밑줄만 바꿔 보였다.
- 후:
  - 새 provider의 model은 모두 꺼져 나온다. 저장하는 것은 켠 model 목록이다(`ChangeShownModels`, `ReadShownModels`, 표 `model_shown`). 고른 model(전역 기본, project, session)은 같은 transaction에서 켠 목록에 더해진다. 지금 쓰는 model은 꺼져 있어도 picker에 보인다. 연결 직후의 "Choose a default model" 창은 켠 목록과 상관없이 모든 model을 보인다.
  - Manage models: provider의 model을 하나도 켜지 않았으면 모두 펼쳐 보인다. 하나라도 켰으면 켠 model만 남고 꺼진 model은 "N models off" 한 줄로 접힌다. 누르면 펼친다. 검색 중에는 접지 않는다.
  - `ChangeShownModels`는 끊은 provider의 줄을 거절하지 않고 버린다. 거절하면 그 줄이 남은 뒤로 모든 켜고 끄기가 `not_found`였다.
  - 전역 기본이 없을 때 session이나 project에서 고른 model이 전역 기본이 된다.
  - 기본·project·session model 저장 검사가 화면이 읽는 catalog와 같은 바탕(derived catalog, 없으면 동봉 snapshot)을 본다.
  - model 칸의 저장 실패는 option 축 바로 아래 빨간 한 줄(아이콘, `role="alert"`)이다. 지침 열기 실패는 지침 칸 아래에 보인다.
  - 고른 model이 없으면 composer가 보내기를 막고 입력칸 안에 이유를 보인다. 그래도 끝난 turn은 새 이유 `model_required`다. 대화 안 실패는 이유마다 문구가 있다.
- 계약:
  - 지운 것: `ChangeHiddenModels`, `ReadHiddenModels`(resource `hidden-models`), `HiddenModels`, `setHidden`, 표 `model_hidden`·`model_hidden_seq`, `snapshotCatalogEntry`.
  - 생긴 것: `ChangeShownModels`, `ReadShownModels`(resource `shown-models`), `ShownModels`, `setShown`, 표 `model_shown`·`model_shown_seq`, turn 실패 이유 `model_required`, `TURN_FAILED_REASONS`, `catalogBase`.
  - 바뀐 것: `orderPicker`가 `shown`을 받는다. `checkEntryOf`가 catalog 바탕을 받는다. conversation commands deps에 `catalog`가 생겼다.
  - schema step을 그 자리에서 고쳤고 migration은 없다.

왜: provider 하나를 붙이면 고를 수 없을 만큼 model이 쏟아졌고, effort 저장과 model 없는 보내기는 실패해도 사람이 무엇을 할지 알 수 없었다. omp는 per-model 끄기 없이 첫 실행 마법사에서 기본 model을 고르게 하고, model이 없으면 보내기 전에 "No model selected"로 막는다.

결정:
- 켠 것만 보이는 opt-in으로 바꾼다. 버린 길: catalog로 거른 기본값(tool 미지원·deprecated·날짜 판 끔), omp처럼 숨김 없이 최근 사용순. (사람)
- 처음 고른 model을 전역 기본으로 삼는 것은 전역 기본이 비어 있을 때만이다. 이미 있으면 바꾸지 않는다. (agent)
- agent 정의 파일의 model 저장은 command를 거치지 않아 켠 목록에 더하지 않는다. (agent)
- 연결 직후 실패 이유(`configuration_unavailable`)는 provider·credential 문제에 남기고, model을 아무 데서도 고르지 않은 경우만 `model_required`로 나눈다. (agent)

후속: schema가 바뀌어 개발 data(`.dev-data/`)를 지우고 새로 만든다. 지금까지 켜져 있던 model은 모두 꺼진 상태로 시작한다.

## 터미널 복사·붙여 넣기와 파일 경로 link, 대화 코드 블록 실행, 탭 안에서 연 것의 자리 정책 하나

```yaml
modules: [packages/shell/renderer, packages/shell/main, packages/shell/ipc, packages/design]
checked: [architecture-browser-tab]
```

- 전:
  - Linux·Windows 터미널에는 복사·붙여 넣기 키가 없었다(Ctrl+C는 SIGINT).
  - 터미널 출력의 링크는 http/https만 Ctrl/Cmd-click으로 열렸다. 파일 경로는 글 그대로였다.
  - 대화의 코드 블록에는 복사 단추만 있었다.
  - 새 탭의 자리를 여는 쪽마다 정했다. 터미널 URL은 `bridgeAfter`(반대쪽 pane), 검색 결과와 대화의 파일 link는 focus pane 끝이었다.
- 후:
  - 터미널 Ctrl+Shift+C는 고른 글을 복사하고 Ctrl+Shift+V는 bracketed paste로 붙여 넣는다(Linux·Windows). macOS는 그대로 Cmd+C/V다.
  - 터미널 출력의 파일 경로(확장자가 있는 것, `:line[:col]`)가 shell 시작 폴더 기준으로 디스크에 있으면 link가 되고 Ctrl/Cmd-click하면 그 줄로 문서 탭을 연다.
  - 대화의 bash·sh·zsh 코드 블록에 [Run in terminal] 단추가 생겼다. floated 새 터미널을 열고 한 줄이면 실행, 여러 줄이면 붙여 넣기만 한다(Enter는 사람). 줄바꿈·tab 밖의 제어 문자가 있으면 단추가 없다. detached 창에는 없다.
  - 탭 안에서 연 새 탭의 자리를 `workspace/open-policy.ts`의 `openAt` 하나가 정한다. source가 pane에 있고 pane이 둘이면 반대쪽 pane 끝, 하나면 source 바로 뒤, floated·minimized·detached면 focus pane 끝이다. 검색 결과와 대화의 파일 link도 이 규칙을 따른다.
  - 터미널 아래 여백이 4px에서 8px이 됐다.
- 계약:
  - `TerminalOpen`·`terminalOpenSchema`에 `command`(8192자, 줄바꿈·tab 밖 제어 문자 거절)가 생겼다. main은 shell의 첫 prompt 뒤에 친다(resume 명령도 같다).
  - terminal IPC에 `shell:terminal-copy {text}`·`shell:terminal-paste`(`TerminalApi.copy`·`paste`)가 생겼다. shell 창 session이 web clipboard permission을 거절해 main의 Electron `clipboard`를 쓴다.
  - `CodeBlock`에 `action`, `Markdown`에 `codeAction`이 생겼다.
  - `bridgeAfter`를 지웠다.

왜: lophn은 floated·minimized·detached 자리가 있고 탭을 여는 source(터미널, coding agent, lophn agent)가 여럿이라, 여는 쪽마다 자리를 정하면 규칙이 갈라진다.

결정:
- pane이 하나면 자동으로 나누지 않고 source 뒤에 연다. 버린 길: 자동 split(layout이 바뀐다). (사람)
- 실행 단추는 bash·sh·zsh만, 한 줄만 바로 실행한다. 버린 길: 여러 줄도 바로 실행(줄마다 실행되어 중간 실패를 못 본다). (사람)
- 파일 경로의 상대 기준은 shell 시작 폴더다. 버린 길: OSC 7로 지금 폴더 받기(shell 시작 층을 고쳐야 한다). (agent)

후속: 없음.

## 단축키가 창의 command registry와 keybinding service를 거친다

```yaml
modules: [packages/shell/renderer, packages/shell/ipc]
checked: [architecture-workspace-layout]
```

- 전: Workspace가 `workspace/use-keybindings.ts`(document keydown)와 `useMainCommand`(main이 보낸 command)로 키를 직접 받아 `runCommand` switch를 불렀다. 키 판정과 기능의 일이 한 component에 묶였다.
- 후:
  - 창마다 command registry(`renderer/commands/registry.ts`, id → handler)와 keybinding service(`renderer/commands/keybinding-service.ts`, chord → id, document capture listener 하나)가 있다. `Desktop`이 만들고 React 밖의 값으로 쓴다.
  - Workspace는 표의 command를 `useCommands`로 올리고 unmount에서 푼다. main이 먼저 받은 키(`shell:shortcut`)도 `registry.execute(id)`로 간다.
  - 키는 그 command를 지금 부를 수 있을 때만 삼킨다. 런처·Settings에서는 Ctrl+B·Ctrl+P·Alt+숫자를 page로 넘긴다(예전에는 작업대 밖에서도 renderer가 삼켰다).
  - 같은 id는 나중 주인이 받고, 같은 키는 나중 바인딩부터 본다. handler가 던지면 log에 남기고 `internal`을 돌린다.
  - 단축키 표와 chord 판정은 그대로 `ipc/keybindings.ts`다. 키·조합 중·터미널의 Ctrl+글자·반복 규칙은 바뀌지 않았다.

왜: 사람이 VS Code의 command registry·keybinding service처럼 키 입력을 중앙에서 받고 command의 일은 기능이 갖는 중간 구조를 요청했다.

결정:
- context key 식, 우선순위 수, 사용자 단축키 설정, extension 소유권은 넣지 않았다. command의 `when` 함수 하나와 "나중 것 먼저" 순서만 둔다. (agent)
- command id는 표의 `Command` 이름 그대로다. id 공간을 새로 만들지 않는다. (agent)
- browser toolbar의 Ctrl/Cmd+D는 그 toolbar의 키로 둔다. 표에 넣으면 terminal의 Ctrl+D(EOF)와 부딪힌다(browser-tab.md). (agent)

## Settings › Keyboard에서 단축키를 보고 바꾼다

```yaml
modules: [packages/shell/renderer, packages/shell/ipc, packages/shell/main, packages/shell/preload, packages/core/config]
checked: [architecture-workspace-layout]
```

- 전: 작업대 단축키는 코드의 표에만 있었다. 사람이 볼 곳은 팔레트의 Terminal 행 hint 하나였고 바꿀 길은 없었다.
- 후:
  - Settings의 General 묶음에 Keyboard 항목이 있다. 작업대 단축키 표의 줄마다 이름과 지금 키를 보인다(26줄: 탭 이동·닫기·다시 열기·옮기기, n번째 탭, 칸, sidebar, explorer, 검색, 터미널, 파일 열기).
  - 키 칸을 누르면 새 키를 받는다. Esc는 취소, Backspace는 키를 뺀다. 받은 키는 바로 저장되고 창과 main에 바로 덮인다(main이 먼저 받는 탭 키도 바뀐 키를 따른다). 바꾼 줄에는 [Reset to default], 아래에 [Reset all shortcuts]가 있다.
  - modifier 없는 키, 팔레트·런처 키, 다른 줄이 쓰는 키는 받지 않고 그 줄에 이유를 보인다("Ctrl+B is already used for Show or hide the sidebar.").
  - 저장은 선언 설정 `shell.keybindings`(OS마다 `mac`·`other`)다. Desktop이 시작할 때 읽어 덮으므로 Settings를 열지 않아도 바뀐 키가 듣는다. 팔레트의 Terminal hint도 바뀐 키를 보인다.

왜: 사람이 단축키를 보거나 바꿀 곳이 없다고 했다.

결정:
- 바꾸는 단위는 표의 줄(binding id)이다. 줄 하나에 키 하나를 받고, 표에 키가 둘인 줄(Ctrl+W·Ctrl+F4)도 바꾸면 하나가 된다. 여러 키를 받는 UI는 두지 않았다. (agent)
- 팔레트·런처·전역 팔레트 키는 바꾸지 않는다. main의 창 shortcut과 OS 전역 등록이 따로 있어 같은 길로 덮을 수 없다. (agent)
- 저장은 OS마다 따로다. macOS의 Cmd 조합을 Linux에 옮기면 뜻이 달라진다. (agent)

후속: 없음.

## Settings › Keyboard: 줄 설명, 검색, 번호 줄 하나, 키로 찾기

```yaml
modules: [packages/shell/renderer, packages/shell/ipc]
checked: [architecture-keybindings]
```

- 전: 앞 항목의 Keyboard는 binding마다 한 줄(26줄)이었고 n번째 탭·칸이 번호마다 따로 섰다. 줄에 설명이 없고 검색이 없었다.
- 후:
  - command마다 한 줄(16줄)이다. "Go to a tab by number"와 "Focus a pane"은 한 줄이고 modifier 하나를 받아 모든 번호에 붙인다(`Alt+0–9`). 번호마다 충돌을 검사하고 같은 줄의 번호끼리는 겹쳐도 된다.
  - 줄 이름 아래에 무엇을 하는지 작은 설명이 있다.
  - 위의 검색 칸이 이름·설명·키 이름으로 줄을 거른다. 오른쪽 토글을 켜면 칸이 누른 키를 받고 그 키를 쓰는 줄만 보인다. 그 칸의 키는 command를 부르지 않는다. Backspace·Esc는 지우고 Tab은 칸을 떠난다.

왜: 사람이 설명과 검색, 키 입력 검색 토글을 요청했고 번호 줄을 나눌 이유가 없다고 했다.

결정:
- 앞 항목의 "줄은 binding id" 결정을 바로잡는다. 저장 단위는 그대로 binding id이고 화면만 command로 묶는다. (사람)

후속: 없음.

## home의 `instructions.read`를 지운다. 지침은 prompt 조립만 싣는다

```yaml
modules: [packages/core/agent-places, packages/core/lophn-agent, packages/core/main, packages/protocol, packages/design]
checked: [architecture-agent-definition]
```

- 전: home session은 project 지침을 prompt로 받지 않고 `instructions.read {project}` tool로 그 project의 `LOPHN.md`를 읽었다. home 지침이 "project 일을 할 때 이 tool로 읽으라"고 시켰다. `GetInstructions`는 home session에만 다른 project를 고르는 `project` 칸을 열었다.
- 후:
  - `instructions.read` tool과 home 지침의 그 줄이 없다. home은 project 지침이 없고, project의 일은 지금처럼 `call`로 그 project의 lophn에 넘긴다. 거기서 조립이 `LOPHN.md`를 싣는다.
  - `GetInstructions`는 언제나 session의 place가 가리키는 project의 `LOPHN.md`를 읽는다.
- 계약:
  - 지운 것: tool `instructions.read`(`agent-places/tools/instructions.ts`), `GetInstructions` 입력 `project`, `mayReadOtherProject`, `InstructionReadDeps.projectExists`·`mayReadOtherProject`, 예약 domain 이름 `instructions`, wording `agents.notice.lophn-no-project`(쓰는 곳이 없었다).

왜: 지침은 harness의 prompt 조립이 싣는 것이다. agent가 tool을 부를지에 지침 적용을 맡기면 안 부르면 지침이 빠진다.

결정:
- 지침 적용을 agent의 tool 사용에 맡기지 않는다. (사람)
- home에 project 지침을 싣지 않는다. home은 project를 고르지 않고 일을 그 project의 session에 넘긴다. 버린 길: home prompt에 모든 project의 `LOPHN.md`를 싣기(project마다 규칙이 섞인다). (agent)

후속: 없음.

## OAuth MCP server를 붙이고 sign-in한다. 앱 secret을 지우고 sign-out한다. 일시 오류로 sign-in이 끊기지 않는다

```yaml
modules: [packages/core/lophn-agent, packages/core/apps, packages/core/secrets, packages/core/main, packages/protocol, packages/shell/main, packages/shell/renderer, packages/design, tools]
checked: []
```

- 전:
  - MCP server form은 인증으로 None, Bearer, API key만 골랐다. 설정 file에 `oauth2`를 손으로 써도 sign-in 단추가 없어 그 server는 늘 Needs sign-in이었다. 끝점은 `${issuer}/authorize|token`으로만 만들었고 `client_credential`은 읽는 곳이 없어 client secret 없이 교환했다.
  - MCP OAuth는 refresh 응답이 400 이상이면 모두 거절로 보고 token을 지웠다. 발급자가 잠깐 503을 내도 사람이 다시 sign-in해야 했다.
  - 앱 Access 탭은 값을 넣기만 했다. 넣은 API key를 지우거나 OAuth sign-in을 끝낼 길이 없었다.
- 후:
  - Settings › Tools and skills와 project 층의 server form이 OAuth 2.1(issuer, client ID, scopes)을 받는다. client secret은 더한 뒤 보호 입력으로 `mcp.<scope>.<server>.client`에 넣고, 넣지 않으면 public client다. OAuth 줄은 로그인 전 [Sign in], 기다리는 동안 [Cancel]이다.
  - MCP sign-in은 발급자의 `/.well-known/oauth-authorization-server`를 먼저 읽어 https 끝점을 쓰고, 없으면 `${issuer}/authorize|token`이다. client secret은 교환과 refresh 본문에만 실린다.
  - 앱 OAuth와 MCP OAuth의 refresh가 같은 규칙이다: 400·401·`invalid_grant`만 거절이고, 그 밖에는 만료 전 token을 그대로 쓴다.
  - 앱 Access 탭의 plain secret 줄은 값이 있으면 [Remove value], OAuth 줄은 `signed_in`·`failed`일 때 [Sign out]이 있다. Sign out은 access·refresh·meta를 지우고 client id·secret은 남긴다.
  - `secrets/put`과 shell의 secret 제출이 byte 배열을 0으로 덮던 코드를 지웠다. 같은 값이 이미 JS 문자열로 있어 효과가 없었다.
- 계약:
  - 생긴 것: memory route `apps.oauth_sign_out`(`{app, name}` → `{signed_out: true}`), `McpOAuth.signOut`, `createMcpAuthControl` deps의 `secrets`, MCP runtime oauth2 auth의 `client_secret`(secret 이름).
  - 지운 것: `McpOAuthServer.refreshRejected`, `refreshToken` 입력의 `rejected`, `createMcpOAuth`의 `keepValidOnUnavailable`.

왜: hosted MCP server 대부분이 OAuth인데 사람이 붙일 길이 없었고, 앱에 넣은 key와 refresh token은 lophn 안에서 지울 수 없었다. 발급자의 잠깐 오류로 sign-in을 잃는 일은 앱 OAuth에서 이미 막았는데 MCP만 남아 있었다.

결정:
- dynamic client registration은 하지 않는다. 사람이 그 서비스에 만든 client를 넣는다(앱 OAuth와 같다). (agent)
- agent 정의 층 server는 OAuth를 고르지 않게 둔다. core에 그 층의 sign-in 길이 없어서다. 남은 일은 `issues/agent-definition.md`다. (agent)
- grant [Revoke]는 앱 secret 값을 지우지 않는다. 이름이 전역이라 다른 앱이 같은 값을 쓴다. (agent)
- 과하다고 본 secret 장치 가운데 앱 log를 읽을 때의 redaction, supervisor의 60초 보관과 redirect 뒤 다시 붙이지 않기는 남긴다. 앞의 것은 core만 아는 값을 지우고, 뒤의 둘은 invocation 끝을 모르는 supervisor와 바깥 서버의 redirect를 막는다. (agent)

후속: `issues/agent-definition.md`의 "agent 정의 층의 OAuth MCP server는 sign-in할 길이 없다".
