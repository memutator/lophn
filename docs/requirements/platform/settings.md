# platform/settings

공개한 lophn 설정을 내장 기본값·사람의 선택으로 합치고 검증하며, 한 번의 적용과 다시 읽기를 일관된 판으로 남기는 일을 맡는다; 각 항목의 값과 의미는 소유 concern이 정하고 provider와 model은 lophn-agent/harness/provider와 lophn-agent/harness/model을 따른다.

## 요구

### 공개 항목과 원본

**[R1]** 일반 설정은 각 concern이 공개한 항목만 받고 설명·값의 종류·기본값 또는 필수 선택 여부·허용값 또는 숫자 범위와 단위·허용 층·적용 시점을 함께 제공하며 개발 도구인 lophn-agent/evaluation의 설정은 제품 일반 설정에서 제외한다.
- 이유: 알 수 없는 기능을 설정으로 추가하지 않고 사람이 선택의 뜻을 이해하게 한다.
- 확인: 공개 목록 밖의 항목은 거절되고 숫자 항목에서 단위·경계값·효력 시점을 조회할 수 있는지 본다.
- 의도: platform#I10

**[R2]** 사람이 명시한 설정 선택은 단일 ledger에만 원본을 두고 내장 기본값과 병합한 적용값은 사람의 선택으로 다시 저장하지 않는다.
- 이유: 기본값 변경이 과거의 사용자 선택으로 굳어지지 않아야 한다.
- 확인: 한 항목만 선택한 뒤 내장 기본값을 바꾸면 선택하지 않은 항목만 새 기본값을 쓰는지 본다.
- 의도: platform#I10, platform#I1

**[R3]** 일반 설정 import·export는 UTF-8 TOML 1.0만 지원하며 JSON5·YAML·환경 변수 치환·다른 문서 include·command 실행·원격 URL을 지원하지 않는다.
- 이유: 설정 문서가 숨은 실행 경로나 두 번째 원본이 되지 않게 한다.
- 확인: 주석이 있는 TOML은 가져오고 나머지 format은 거절하며 치환과 command가 실행되지 않는지 본다.
- 의도: platform#I10, platform#I2

**[R4]** 공개 항목의 기본값과 허용값은 소유 concern의 정의만 쓰며 필수 선택이 비어 있으면 임의의 provider·model·credential로 채우지 않는다.
- 이유: 값이 없다는 사실을 조용한 대체 선택으로 숨기지 않는다.
- 확인: 필수 선택을 삭제하면 해당 기능을 시작하지 못하고 실제 기본값은 platform/api·platform/diagnostics·platform/backup-and-migration·platform/blob-store·platform/ledger·apps/data·apps/automations·documents/formats에서 정한 것과 일치하는지 본다.
- 의도: platform#I10

### 층과 병합

**[R5]** 설정 우선순위는 내장 기본값보다 사용자 공통 선택이 높고 사용자 공통 선택보다 소유 concern이 허용한 역할별 선택이 높으며 다른 지속 설정 층은 두지 않는다.
- 이유: 값의 출처와 이긴 선택이 예측 가능해야 한다.
- 확인: 허용된 항목을 세 층에서 다르게 선택하여 역할별 값이 이기고 assignment별 override는 거절되는지 본다.
- 의도: platform#I10

**[R6]** 작업 디렉터리·앱 문서·세션·환경 변수·CLI 일회 인자·외부 서버 응답은 일반 설정을 덮어쓰는 층으로 해석하지 않는다.
- 이유: 작업의 데이터가 플랫폼 정책을 바꾸면 안 된다.
- 확인: 각 출처에 같은 항목을 넣어도 적용값과 판이 바뀌지 않는지 본다; 설치 위치 선택은 platform/install-and-update를 따른다.
- 의도: platform#I10, platform#I2

**[R7]** provider와 model catalog 보정은 공통 선택에서만 받고 judgment model과 organizing model의 역할별 덮어쓰기는 허용하지 않는다.
- 이유: lophn-agent/harness/model의 두 공통 model slot을 유지한다.
- 확인: 역할별 provider 보정이나 model 선택이 거절되는지 보고 실제 정의와 선택은 lophn-agent/harness/provider와 lophn-agent/harness/model을 따른다.
- 의도: platform#I10

**[R8]** object는 항목별로 병합하고 문자열·숫자·참거짓은 높은 층의 값으로 교체하며 목록은 연결하거나 중복 제거하지 않고 높은 층의 전체 목록으로 교체한다.
- 이유: 병합이 입력하지 않은 값이나 순서를 만들어서는 안 된다.
- 확인: 낮은 층의 두 원소 목록에 높은 층의 한 원소 목록을 적용하여 한 원소만 남고 object의 생략 항목만 낮은 층을 따르는지 본다.
- 의도: platform#I10

**[R9]** 생략은 낮은 층을 따르고 해당 층의 선택 삭제는 낮은 층으로 돌아가며 빈 목록과 false는 명시한 값으로 취급한다.
- 이유: 비우는 선택과 선택하지 않은 상태를 구별한다.
- 확인: 생략·삭제·빈 목록·false를 각각 적용해 낮은 층 복귀와 명시값 유지가 구분되는지 본다.
- 의도: platform#I10

**[R10]** 현재 항목마다 적용값·그 값을 정한 층·위와 아래 층의 명시 선택·적용 판을 조회할 수 있다.
- 이유: 어떤 선택이 적용됐는지 사람이 추측하지 않아야 한다.
- 확인: 같은 항목을 여러 층에서 정하고 조회하여 가려진 선택까지 안전하게 확인할 수 있는지 본다.
- 의도: platform#I10

### 검증과 안전

**[R11]** 검증은 각 층의 문법·알려진 항목·타입·숫자 범위·허용 층을 먼저 검사하고 병합 뒤 필수값·항목 관계·대상 참조를 검사한다.
- 이유: 입력 자체의 오류와 병합 뒤 관계의 오류를 구분한다.
- 확인: 각 단계의 오류를 따로 만들어 올바른 항목과 단계에서 거절되는지 본다.
- 의도: platform#I10

**[R12]** 모르는 항목·틀린 타입·범위 밖 숫자는 오류로 거절하며 숫자 문자열 변환이나 가까운 이름으로의 오타 수정을 하지 않는다.
- 이유: 모르는 선택을 무시하거나 고치면 사람이 요청한 것과 다른 정책이 적용된다.
- 확인: 오타 항목과 숫자 문자열을 보내면 경고 후 무시하지 않고 전체 적용을 거절하는지 본다.
- 의도: platform#I10

**[R13]** 대상의 존재·사용 가능 여부·호환성은 소유 concern의 검증을 따르며 offline 미확인은 그 concern이 허용한 경우에만 미확인 표시와 함께 받는다.
- 이유: 설정 모듈이 다른 concern의 유효성을 임의로 판단하지 않는다.
- 확인: 사용할 수 없는 대상과 offline 대상을 선택해 소유 concern의 허용 여부대로 거절 또는 미확인이 보이는지 본다.
- 의도: platform#I10

**[R14]** 설정 오류는 틀린 항목·선택 층·기대 타입 또는 허용 범위·고칠 방법을 알려 주되 secret 값이나 입력 문서 전체를 포함하지 않는다.
- 이유: 오류를 고칠 정보는 필요하지만 민감한 입력을 다시 노출할 필요는 없다.
- 확인: 잘못된 문서를 import한 결과에서 고칠 항목은 찾을 수 있지만 입력 원문과 secret은 없는지 본다.
- 의도: platform#I10, platform#I2

**[R15]** 일반 설정은 API key·password·OAuth token·인증 header·private key 원문을 거절하고 secret이 필요한 항목에는 소유 concern이 허용한 보호 참조만 받는다.
- 이유: 일반 설정은 secret 보관 경로가 아니다.
- 확인: secret·token·password·API key·private key·credential·인증 값을 원문으로 넣거나 sk-·ghp_·JWT 형태의 값을 넣으면 적용과 기동 검증이 실패하는지 보고 검출은 platform/redaction을 따른다.
- 의도: platform#I8, platform#I2

**[R16]** 어떤 설정 층도 현재 권한과 안전 금지·사람의 credential 결정·사람이 붙이는 외부 MCP 경계·subagent 없음 규칙을 해제하지 못한다.
- 이유: 설정은 안전 경계의 우회 수단이 아니다.
- 확인: 금지를 풀자는 항목을 넣어도 거절되는지 보고 실제 경계는 platform/identity·platform/security·lophn-agent/extensions·lophn-agent/roles/common을 따른다.
- 의도: platform#I2, platform#I10

### 적용과 다시 읽기

**[R17]** 설정 선택은 사람이 명시적으로 apply한 때만 바꾸며 agent 제안·세션의 동의 추측·외부 문서 변경을 적용 요청으로 취급하지 않는다.
- 이유: 제안과 플랫폼 정책 변경은 다르다.
- 확인: 제안이나 TOML 파일 변경만으로 판이 바뀌지 않고 명시적 apply 뒤에만 바뀌는지 본다.
- 의도: platform#I10

**[R18]** 한 번의 apply는 모든 영향 역할의 적용값까지 검증한 뒤 전체 변경을 함께 저장하거나 함께 거절한다.
- 이유: 일부 항목만 새 정책이 되는 중간 상태를 막는다.
- 확인: 여러 항목 중 하나를 잘못 입력하여 어떤 선택도 바뀌지 않는지 본다.
- 의도: platform#I10

**[R19]** apply는 편집을 시작한 판이 현재 판과 같을 때만 받으며 충돌하면 최신 선택과 충돌 항목을 알려 다시 확인하게 한다.
- 이유: 오래된 편집이 다른 변경을 덮어쓰지 않게 한다.
- 확인: 두 편집 중 하나를 먼저 적용하면 나중 apply가 충돌하고 새 선택을 읽을 수 있는지 본다.
- 의도: platform#I10, platform#I1

**[R20]** 성공한 변경은 변경 주체·시각·항목·전후 선택·영향 역할·새 판을 기록하며 선택과 적용값이 모두 같은 다시 읽기는 새 판을 만들지 않는다.
- 이유: 정책 변화의 근거는 남기되 변화 없는 조회는 변경으로 부풀리지 않는다.
- 확인: 변경 뒤 이력을 읽고 같은 선택을 다시 읽을 때 판이 유지되는지 본다.
- 의도: platform#I1, platform#I10

**[R21]** reload는 저장 선택과 현재 내장 기본값을 처음부터 병합·검증해 하나의 적용값으로 교체하며 화면과 CLI는 같은 플랫폼 결과를 쓰고 각각 설정을 해석하지 않는다.
- 이유: 표시 경로마다 정책이 달라지지 않아야 한다.
- 확인: 기본값을 바꿔 명시적으로 reload하고 화면과 CLI가 같은 판과 값을 보여 주는지 본다.
- 의도: platform#I10

**[R22]** apply나 reload가 실패하면 마지막 성공값과 판을 유지하고 실패를 알리며 일부 유효 항목 적용이나 내장 기본값 복귀를 하지 않는다.
- 이유: 실패가 예기치 않은 정책 변경이 되어서는 안 된다.
- 확인: 검증과 저장 실패를 각각 만들고 모든 이전 값과 판이 유지되는지 본다.
- 의도: platform#I10

**[R23]** 첫 시작에 유효한 저장 선택도 마지막 성공값도 없으면 agent 작업은 막되 설정 수정과 무관한 앱 사용·문서 읽기는 허용한다.
- 이유: 잘못된 agent 설정이 플랫폼 전체를 잠그지 않아야 한다.
- 확인: 초기 설정 오류 상태에서 agent는 시작되지 않지만 수정 화면과 기존 앱·문서는 열리는지 본다.
- 의도: platform#I3, platform#I10

**[R24]** model·추론 수준·prompt·tool 목록·문맥 한도·run 한도 변경은 다음 run부터 적용하고 진행 run은 시작 판을 유지하되 현재 권한과 안전 제한은 호출 때 현재값을 검사한다.
- 이유: run의 해석 기준은 고정하되 안전 회수를 늦추지 않는다.
- 확인: 진행 중 공통 설정을 바꾸어 다음 run만 새 판을 쓰고 현재 권한 회수는 진행 run의 다음 호출부터 반영되는지 본다; 항목 의미는 lophn-agent/harness/model·lophn-agent/harness/run-loop·lophn-agent/harness/tool-judgment·lophn-agent/harness/safety를 따른다.
- 의도: platform#I10, platform#I2

**[R25]** 적용 결과는 새 판·즉시 효력이 난 항목·다음 run부터 효력이 나는 항목을 구별하고 바뀌지 않은 provider·extension을 재연결하거나 lophn 전체를 재시작하지 않는다.
- 이유: 설정 변경의 효력을 이해하면서 무관한 작업의 중단을 피한다.
- 확인: 한 항목만 변경해 적용 시점이 보이고 변경하지 않은 연결과 앱이 유지되는지 본다.
- 의도: platform#I10, platform#I3

**[R26]** 첫 판의 설정 교환 문서는 format version 1로 import·export하고 알 수 없는 version은 거절하며 옛 항목 변환은 실제 항목 변경이 있는 lophn update에서 명시적으로 제공한다.
- 이유: 향후 변환을 추측하지 않고 교환 문서의 해석 기준을 고정한다.
- 확인: version 1 문서를 왕복하고 미지원 version을 가져오면 기존 선택과 판을 유지한 채 거절되는지 본다.
- 의도: platform#I10

### 사용 안내와 선택 적용

**[R27]** 공개 설정마다 사람이 읽을 이름·한 줄 설명·현재 선택의 뜻·기본값의 뜻·영향받는 기능·위험·되돌리는 방법·즉시 또는 다음 run의 적용 시점을 함께 제공한다.
- 이유: 값의 종류만 읽어서는 바꾸면 무엇이 달라지는지 알 수 없다.
- 확인: 숫자·목록·model 선택 설정에서 설명과 실제 적용 결과를 대조하고 secret 값 없이 뜻을 읽는다.
- 의도: platform#I10

**[R28]** 설정 설명과 안전한 적용값·선택 층·적용 판은 화면과 lophn 역할이 같은 공개 목록에서 읽고 설명이 없는 항목은 공개 설정으로 등록하지 않는다.
- 이유: agent의 추측이나 화면별 설명 차이가 설정의 뜻을 바꾸지 않게 한다.
- 확인: 같은 항목을 설정 화면과 lophn 역할로 읽어 이름·영향·시점·현재값이 같고 미공개 항목은 선택지로 나오지 않는지 본다.
- 의도: platform#I10

**[R29]** lophn 역할의 설정 변경 제안은 lophn-agent/questions의 정확한 option action으로만 적용하며 사람이 고른 항목·값·층·비교 판을 machine이 검증하고 설명을 묻거나 자유 답만 한 경우에는 설정을 바꾸지 않는다.
- 이유: 사용 안내와 사람의 실제 선택을 구별하고 기존 apply의 원자성과 비교 기준을 유지한다.
