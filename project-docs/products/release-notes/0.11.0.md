# lophn 0.11.0

App screens and artifacts now sit in the same page frame as browser tabs, so floating panels, menus, and notices show above them. The chat screen gets a usage footer, clearer progress and answer actions, and more keyboard shortcuts.

## New
- A usage footer under the message box shows how much of the context window is used, the token count, and the cost. Click it to open `/status`. It turns amber at 80% and red at 90%.
- The row under the message box has buttons for the model, each effort and speed setting the model offers, and the permission mode. Effort and speed buttons hide in narrow panes; their values stay in the model menu.
- Ctrl/Cmd+Shift+M opens the model picker while the message box has focus.
- The working line shows elapsed time from 3 seconds, "Still working" at 30 seconds, and "Taking longer than usual" at 90 seconds. It says when the agent is waiting for your approval or answer.
- Esc in the message box stops the running turn.
- Each agent answer shows its time and a "Fork from here" action. The last finished turn also has "Retry", which sends your message again.
- Queued messages can be edited and moved up or down before they are sent.
- Approval cards: Enter allows once, Ctrl/Cmd+Shift+Enter always allows, Esc opens the deny reason. On a question card, Enter goes to the next question or submits.
- A view menu (Messages, Compact, Everything) controls how steps are shown. Each session remembers its choice.
- Ctrl/Cmd+F finds text in the agent chat, and session search also finds text inside messages.
- Math is rendered, and Mermaid diagrams are drawn in the chat (you can switch to the source). Expanding an edit card shows the change as a diff.

## Changed
- Switching desks no longer reloads app screens, artifacts, or browser pages.
- Detaching an app screen or an artifact tab reloads it, the same as detaching a browser tab. Screen state kept only in the page's URL is not carried over.
- Descriptions of the built-in skills (design-app, new-app, repair-app, check-domains, write-workflow) say only what each skill is for and no longer list its steps.

## Fixed
- The app status tool showed "[object Object]" instead of the app's state. It now shows the state and the reason, such as "unavailable (crash_loop: ...)".
- An agent that asked for a skill's SKILL.md by path got "not available" every time. Reading it by path works now, and a failed read names the files the skill has.
- The `@lophn/ui` guide that agents read when building apps was dropped when it was too large. It now arrives in parts, and every component group is included.
