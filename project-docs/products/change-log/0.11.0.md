# 0.11.0

## 앱 화면과 artifact 화면을 `<webview>` guest로 옮기고, desk를 오가도 page를 지킨다

```yaml
modules: [packages/shell/main, packages/shell/renderer, packages/shell/ipc]
checked: [architecture-workspace-layout, architecture-browser-tab, architecture-annotation, architecture-appearance, architecture-keybindings, architecture-artifact]
```

- 전:
  - 앱 화면(app panel 탭, 앱 place 본문, 앱 card, 앱 전용 창)과 artifact 탭은 native `WebContentsView`였다. native view는 shell DOM 위에 그려져 floated 패널·menu·toast가 page 밑에 깔렸고, 피하려고 view 층(`appViewOrder`), cover로 view 줄이기(`useViewCover`, `createViewCovers`), bounds relay(`placement.ts`, `visibility.ts`, `frame-router.ts`, `renderer/app-frame/bounds.ts`), 앱 place menu가 열린 동안 화면 숨기기라는 장치가 쌓였다.
  - 앱 전용 창은 문서가 없는 빈 `BrowserWindow`에 native view 하나였다. `webviewTag`와 shell preload가 없어 단축키가 닿지 않았다.
  - desk를 떠났다 돌아오면 일반 browser 탭의 `<webview>`를 놓아 page를 url로 다시 load했다(`issues/workspace-layout.md`).
- 후:
  - 앱 화면과 artifact 화면이 browser 탭과 같은 창의 `<webview>` 그릇에 산다(`packages/shell/renderer/app-frame/webview-host.tsx`, kind 중립). project 창은 floats 층, detached 창·앱 전용 창은 본문, 앱 place는 `.content`다. 앱·artifact element는 `src`만 적고 첫 load 전까지 숨긴다. z-index 규칙은 그대로다(pane 화면 1, floated 화면 `--z-sticky + 2L+1`, 패널은 그 위).
  - main registry가 state에 `src`를 싣는다. 앱은 `lophn-app://<label>/<screen>/index.html?view_session=..&mount=<generation>`, artifact는 `lophn-artifact://<host>/<entry>?mount=<n>`이다. `acceptGuest(window, src)`가 그 창의 view이고 아직 안 쓴 src일 때만 1회 받고, `did-attach-webview`에서 guest를 그 view에 묶는다. 붙이기 판정은 `wiring/browser.ts`의 `will-attach-webview` 하나이고 `webview-guest.ts`의 `hardenWebviewAttach`가 kind별로 partition·preload·webPreferences를 강제한다. browser guest는 `lophn-*` src를 거절한다. 신원은 `byContents` 그대로라 app-ipc·annotate·app-call은 바뀌지 않는다. annotation screenshot은 guest `capturePage`다.
  - 앱 전용 창은 shell 문서 `#app-window=<app>/<release>/<screen>`(`packages/shell/renderer/app-frame/app-window.tsx`)이고 `webviewTag`·shell preload를 쓴다. 앱 하나에 창 하나이고 전역 palette·tray는 detached 창처럼 건너뛴다.
  - `<webview>`는 탭 key가 어느 desk의 layout에든 있는 동안 그대로 두고, 모든 desk에서 사라지거나 그 탭이 detached가 될 때만 지운다. desk를 오가도 page를 다시 load하지 않는다.
  - secret 입력 창의 입력 차단이 `hostWebContents`로 guest까지 본다.
- 계약:
  - 바뀐 것: `AppFrameViewState`·`ArtifactViewState`에 `src`가 생겼다. 앱 panel·artifact 탭의 Detach transfer가 `{ value: null, views: [] }`이고 받는 창이 다시 연다. `AppViews.moveViews`는 browser의 크기 준 popup과 DevTools만 옮긴다.
  - 생긴 것: kind 중립으로 옮긴 `<webview>` 그릇(`packages/shell/renderer/app-frame/webview-host.tsx`), `acceptGuest`·`bindGuest`·`dropGuest`, 앱 전용 창 route `#app-window=`, `renderer/app-frame/app-window.tsx`.
  - 지운 것: `app-frame/placement.ts`, `app-frame/visibility.ts`, `browser/frame-router.ts`, `renderer/app-frame/bounds.ts`, `useViewCover`·`createViewCovers`·`ViewCoversProvider`, cover 빼기, 앱 view 층. `app-frame/view-order.ts`는 overlay 층만 남는다. native relay는 `renderer/browser/native-bounds.ts`, `main/browser/native-bounds.ts`, `native-view.ts`, `view-order.ts`에만 있다.

왜: native view가 shell DOM 위에 그려져 menu·popover·floated 패널·toast가 앱 page 밑에 깔렸고, 그 우회 장치가 층·cover·bounds relay로 쌓였다. browser 탭은 같은 이유로 이미 `<webview>`를 쓰고 그 뒤로 겹침 문제가 없다. 앱 화면과 artifact 화면도 같은 그릇으로 모으면 장치가 하나로 줄고, 같은 변경에서 desk를 오갔다 돌아오면 browser 탭 page가 다시 load되던 결함이 닫힌다.

결정:
- 화면 그릇은 `<webview>`다. iframe은 preload의 isolated world, 앱별 partition, `sender.id` 신원을 잃고, remote UI는 앱이 자기 DOM·CSS component를 못 쓰게 한다. Electron은 `<webview>`를 권하지 않지만 browser 탭이 이미 그 위험을 지고 있어 새 위험이 아니다. (사람)
- Detach하면 앱 화면이 다시 load된다. browser 탭과 같다. 앱이 화면 상태를 URL이나 storage에 두면 잃는 것이 줄어든다. (사람)
- artifact 탭도 같이 옮긴다. 같은 겹침 문제를 갖고 있고, 남기면 앱 쪽 장치를 지우지 못한다. (agent)
- 붙이기 ticket은 `src` 하나이고 한 번만 쓴다. renderer가 적은 partition·preload·webPreferences는 버리고 registry가 정한 값만 쓴다. (agent)
- 앱 저장소 partition 이름(`persist:app-<app>:live`, `persist:app-<app>:preview-<bundle hash>`)을 바꾸지 않는다. 사람의 `~/.lophn` cookie·localStorage·IndexedDB가 이어져 migration이 없다. (agent)
- 앱 template `AGENTS.md`(lophn-managed 절)에 "다시 load되어도 잃으면 곤란한 화면 상태는 `localStorage`에 둔다"를 더했다. 새로 만드는 앱에만 들어간다(agent). URL query는 Detach 때 main이 새 `src`를 내므로 남지 않는다.

## 대화 화면에 상시 상태 푸터를 두고, 실행 설정(축·권한)을 composer 안으로 옮긴다

```yaml
modules: [packages/shell/renderer, packages/design, tools]
checked: []
```

- 전:
  - 창 사용률·token·금액은 `/status` panel을 열어야만 보였고, panel을 열 때 한 번만 읽었다.
  - composer 아래 줄에는 model 하나와 option 값이 붙은 model 단추가 있었고, 묻기/skip은 입력칸 밖 switch였다. model 단추 글은 `Sonnet · Medium · Fast`처럼 값이 겹쳐 보였다.
  - 창 사용률 경고 임계값이 없었다.
- 후:
  - composer 아래 24px 푸터가 `12% of 200k`, token, 금액을 늘 보인다. 누르면 `/status`가 열린다. session이 바뀌거나 turn이 끝날 때 다시 읽는다.
  - 푸터와 `/status` 막대는 80%부터 경고색, 90%부터 위험색이다. `status-summary.ts`의 한 식을 같이 쓴다.
  - composer 아래 줄은 `[+] [model] [축…] [권한] [Stop] [↑]`다. 축은 catalog가 주는 Effort·Speed마다 단추 하나이고, 권한은 Ask when needed/Skip permissions menu다. 앱 할당 요약과 자리는 입력칸 밖에 그대로 둔다.
  - composer 폭 560px 아래에서는 축 단추를 감춘다. 값은 model menu 안 축에 그대로 있다. 좁은 pane에서는 오른쪽 단추 묶음이 두 줄로 접힌다.
  - composer 안에 focus가 있으면 Ctrl/Cmd+Shift+M이 model picker를 연다.

왜: 세 앱(ChatGPT·Claude·omp)은 실행 설정을 composer 안에 두고 상태를 상시 보인다. lophn은 `/status`를 열어야 했고 실행 설정이 흩어져 있었다.

결정:
- shortcut은 keybindings 표가 아니라 composer-local로 둔다. tab·pane command가 아니라 지금 session의 picker 상태를 여는 일이라 renderer command 계약에 올릴 이유가 없다. (agent)
- lophn에는 Plan/Goal/Loop 같은 Modes가 없으므로 그 menu를 만들지 않았다. 있는 축(effort·speed)과 권한만 composer에 노출한다. (agent)
- 축 단추는 560px 아래에서 감추고 model menu 안 축으로 모은다(omp의 560px 규칙). model 단추는 이름만 보인다. (agent)

## 대화 화면: 진행·접근성·답 액션, 큐 고치기·순서, 승인 단축키, 단계 보기·찾기, 수식·mermaid·diff

```yaml
modules: [packages/shell/renderer, packages/design, packages/protocol, packages/core/lophn-agent, packages/core/main, tools]
checked: []
```

- 전:
  - 일하는 중 줄은 300ms 뒤 `Working`이고 걸린 시간은 10초가 지나야 붙었다. 사람을 기다리는 때도 `Working`이었다.
  - 대화 log는 `aria-live="off"`이고 새 답 도착을 알리는 영역이 없었다.
  - agent 답 아래에는 `[Copy]` 하나뿐이었다. reasoning 줄은 `Thought for 12s`뿐이었다. 쓰는 중인 글에 caret이 없었다.
  - 큐의 메시지는 지우거나 바로 보내기만 했다. 승인 카드와 질문 카드는 단추만 눌렀다.
  - 단계 묶음은 `compact`로 고정이었다. 대화 안 찾기가 없고 session 검색은 제목만 찾았다.
  - 수식과 mermaid는 원문 글이었다. 편집 카드는 `Edited path +n −m`만 보였다. 본문 로딩은 기울인 글이었다.
- 후:
  - 걸린 시간은 3초부터 붙고, 30초에 `Still working`, 90초에 `Taking longer than usual` 안내가 붙는다. 승인이나 질문을 기다리면 그 사실을 말한다. composer에서 Esc가 도는 turn을 멈춘다.
  - 숨긴 `role="status"` 영역이 답 시작과 끝난 답을 한 번씩 알린다. log 자체는 그대로 off다.
  - agent 답 줄에 시각, `[Fork from here]`, 마지막 끝난 turn에 `[Retry]`가 붙는다. Retry는 그 turn의 사람 글을 새 메시지로 다시 보낸다(`AgentTabSource.repeatTurn`). reasoning 줄은 `Thought for 12s · 54 words`다. 쓰는 중인 글 끝에 caret이 깜빡인다(reduced motion이면 멈춘다).
  - 큐의 사람 메시지는 글을 눌러 고치고 위·아래로 옮긴다. route `session_inputs/edit`·`session_inputs/move`(사람)와 core 안 command `EditQueuedMessage`·`MoveQueuedMessage`(machine)가 표와 입력함을 같이 바꾼다. 가져간 메시지는 `conflict`다.
  - 승인 카드: card 안 focus에서 Enter=Allow once, Ctrl/Cmd+Shift+Enter=Always allow, Esc=Deny 이유 열기·닫기. composer가 비어 있을 때만 카드가 뜨면 focus를 가져간다. 질문 카드는 Enter가 Next·Submit이다.
  - 머리 줄 menu로 단계 보기(Messages·Compact·Everything)를 고르고 session마다 기억한다. 대화 안에서 Ctrl/Cmd+F가 찾기 줄을 연다(CSS Custom Highlight). session 검색이 메시지 글도 찾는다(read `session_messages/search`, 최근 200개 메시지에서 20개까지).
  - 수식(`$…$`, `$$…$$`, `\(…\)`, `\[…\]`)을 KaTeX로 그린다. 모든 Markdown variant가 쓴다. 대화의 ```mermaid는 그림으로 그리고 원문 보기로 바꿀 수 있다. 편집 카드를 펼치면 tool 입력에서 만든 unified diff가 보인다. 본문 로딩은 300ms 뒤 skeleton이다.
- 계약:
  - 생긴 것: read `SearchSessionMessages`, memory route `EditQueued`·`MoveQueued`, command `EditQueuedMessage`·`MoveQueuedMessage`, `AgentTabSource.repeatTurn`·`editQueued`·`moveQueued`·`searchMessages`, design `DiffView`·`VisuallyHidden`.
  - ledger: schema step `lophn-agent.messages.queued-edit`. 아직 가져가지 않은 사람 `next_turn` 메시지만 `body`와 `created_seq`를 고칠 수 있게 trigger를 나눴다. 가져간 메시지는 전과 같이 고정이다.
  - 의존: `katex` 0.19.1(design), `mermaid` 12.2.0(shell renderer). renderer 화면 bundle은 splitting을 켜 mermaid를 `chunks/`로 늦게 읽는다.

왜: ChatGPT·Claude·omp 대화 화면과 대조한 정적 분석(`rea/project/agent-chat-uiux-reversing`)이 lophn의 진행 침묵, 접근성, 답 액션, 큐, 찾기, 읽기 표현이 뒤진다고 보고했다. 사람이 그 목록을 모두 고치라고 했다.

결정:
- 메시지 검색은 FTS index 없이 blob을 읽어 찾는다. 글은 blob에만 있어 index를 만들어도 같은 blob을 다 읽어 채워야 한다. 오래된 기록은 찾지 않는다. (agent)
- 큐 고치기는 행을 지우고 다시 넣지 않고 trigger를 좁혀 그 행을 고친다. id와 순서 번호, 참조가 그대로 남는다. (agent)
- Retry는 rewind가 아니라 같은 글을 다시 보낸다. 첨부와 refs는 다시 싣지 않는다. (agent)
- KaTeX는 정적으로, mermaid는 늦게 읽는다. KaTeX는 문서 화면도 같은 component로 그려서 늦게 읽으면 수식이 나중에 바뀐다. (agent)
- mermaid가 SVG 안에 넣는 `<style>`은 CSP가 막아서 constructable stylesheet로 옮긴다(`editor/adopt-styles.ts`와 같은 길). (agent)
- 찾기 단축키는 keybindings 표에 올리지 않고 Agent 화면 안에서만 받는다. 편집기·browser 탭의 Ctrl+F를 빼앗지 않는다. (agent)

후속: mermaid의 `<style>` 옮기기는 gallery에서만 보았고 Electron 창에서는 보지 않았다.
