## 확인 못함

- 편집기가 파일을 읽고 쓰는 길을 어디에 두는지 문서에 없다. 지금은 shell main이 core의 `files.*` worker route를 부른다. 새 설계의 `file` tool은 agent 쪽이고, 사람 쪽 문서 탭이 core route로 가는지 shell main이 직접 파일을 여는지 정한 곳을 찾지 못했다. 이 목록은 core의 경로 기반 route를 새로 만드는 쪽으로 썼다.
- 외부에서 파일이 바뀌었을 때(다른 편집기, git) 편집기가 무엇을 하는지 요구에 문장이 없다(req-0001은 "다시 열면 보인다"까지). 열린 문서의 변경 감지(watch), 편집 중 충돌 안내를 둘지 정하지 않았다.
- project의 `guide.list/get/outline/read`(설치 사용 안내를 format 추출 규약으로 읽는 route, `core/projects/outline-and-search/guides.ts`, `protocol/projects/guides.ts`)가 남는지 지워지는지 문서에 없다. format 추출 의존이 사라지므로 어느 쪽이든 손봐야 한다.
- project 폴더 겹침 규칙(고칠 것 참조)과 폴더를 찾을 수 없을 때(req-1472)의 현재 구현은 읽지 못했다(`registry/work.ts`, `scan.ts`는 추적 미리보기 쪽이라 판단했으나 실제 호출을 따라가지 않았다).
- archive나 지움 때 돌고 있는 turn을 어떻게 하는지 S8에 없다. 지금 지움은 미종료 run이 있으면 conflict로 거절한다. 사람이 archive를 누르면 turn을 interrupted로 닫는지, 끝나기를 기다리는지 정해야 한다.
- project나 앱을 보관(archive)했을 때 그 place의 Project Manager, App Engineer, Operator와 열린 session을 어떻게 하는지 S8과 요구에 없다. 지금은 보관 event로 assignment를 멈춘다(`assignments/reactions.ts`)이고 assignment를 지우면 이 동작이 같이 사라진다.
- 만드는 중(drafting) context의 진행 표시(`context-drafting.tsx`의 "step n of 4")가 새 설계에 남는지. `contexts.status`의 `drafting` 상태는 요구에 없다.
- 보관한 context가 검색·위반 알림에서 빠지는 규칙(changes-by-topic 7장이 이미 "확인할 것"으로 둠). 지금 코드는 보관된 context를 건너뛴다. 요구에 없고 지운 기록도 없어 그대로 두는 쪽으로 썼다.
- blob-store: 쓰임이 줄었을 뿐 남는 것으로 판단했다(message body, ticket, context content, package guide, app data 복구본, model call body). 문서 판과 format module이 빠져도 이 field들이 있어 본체(`core/storage/blobs`)는 지울 근거가 없다. 다만 `blobs/purposes.ts`의 "document_files" 같은 문서 판 용도 문자열과 `categoryOfPurpose`의 예시 주석을 읽어 실제 등록이 남았는지는 확인 못함.
- `ledger-id` 파일(`core/storage/migration/ledger-id.ts`): restore가 ledger를 바꿀 때 새 값을 쓰고 derived store를 다시 만들게 하려던 장치다. restore가 빠지면 값이 바뀔 일이 없다. derived store(contexts index)가 아직 이 값을 쓰는지 읽지 않았다.
- `sdk/cap-schedule`, grant kind `automation.run`(보류) 같은 앱 쪽 항목은 이 영역이 아니라 05이다.
- 서버 `Host`·`Origin` 검사(`core/server/request.ts`)는 요구에서 폐기(구현 품질·세부 방어)됐으나 req-0211("Origin이 없거나 localhost라는 사실만으로 통과시키지 않는다")는 남는다. 코드는 그대로 둬도 된다고 판단해 목록에 넣지 않았다.
- supervision(`core/supervision`)은 요구 둘(req-0250, 0251)만 남고 나머지가 구현 품질이라 손볼 것을 찾지 못했다. `responsiveness/measure*.ts`가 제품 코드인지 측정 도구인지는 확인 못함.
- install-and-update(보류): `core/install-and-update`의 `data-root.ts`, `lock-check.ts`, `sandbox-check.ts`, `update.ts`, `run-metadata.ts`와 `base/install/*`는 보류라 지우라는 기록이 없어 목록에 넣지 않았다(changes.md 3장에 없다). credential 통로 셋만 coding agent 연결 변경 때문에 "덜어낼 것"에 넣었다. 보류를 코드 제거로 볼지는 정해야 한다.
- `shell/main/desktop/core/connection.ts`·`supervise.ts`의 시작 실패 안내 화면(req-0054 gap)은 요구의 gap 문장만 읽고 코드는 보지 않았다.
- 이미지·pdf를 보는 라이브러리를 이미 번들에 쓰는지(UI 새로 만들 것) 의존성은 보지 않았다.
