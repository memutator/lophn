# 0.14.0

## 앱 panel이 탭과 한 면으로 이어진다, 앱 icon, activity bar에 앱 panel 고정

```yaml
modules: [packages/shell/renderer/workspace, packages/shell/renderer/app-frame, packages/shell/main/workspace, packages/core/apps, packages/protocol/apps/declaration, packages/core/apps/packages/template]
checked: []
```

- 전:
  - project 창의 앱 panel 탭은 탭 줄 아래에 앱 이름·Live·연결 상태 줄(`ViewChrome`)이 늘 있었다. 그 줄과 앱 화면의 바탕이 달라 탭과 본문이 한 면으로 이어지지 않았다. 앱 template의 화면 바탕은 `base.css`·`AppShell`의 `--color-surface-floor`라 탭 본문(`--color-surface-base`)보다 어두웠다.
  - 앱에는 icon이 없었다. 앱 panel 탭은 늘 기본 아이콘, 런처와 place switcher는 첫 글자와 색이었다.
  - 앱 panel은 탭 줄의 + → App panel → 고르기로만 열었다.
- 후:
  - 앱 panel 탭은 화면이 멈추거나 crash했을 때, 앱이 멈췄을 때만 `ViewChrome`을 띄운다. 앱 template에 `src/surface.css`가 생겨 앱 바탕이 `--color-surface-base`다. 앱이 고치거나 지울 수 있다.
  - 앱 선언에 선택 칸 `icon`(bundle 안 경로, svg·png·webp)이 생겼다. release 준비는 그 파일이 commit에 있고 64 KiB 이하인지 본다. core read `apps.icon`이 active release의 icon을 base64로 준다. bundle 밖 경로·symlink, 큰 파일, 선언 없음은 `null`이다. 앱 panel 탭, activity bar의 고정 앱, 런처, place switcher가 그 icon을 쓴다.
  - activity bar 아래쪽(바로 가기와 Settings 사이)에 project마다 앱 panel을 고정한다. 앱 panel 탭의 탭 menu "Pin to activity bar"나 묶음 끝의 +로 더하고, right-click "Unpin from activity bar"로 뺀다. 누르면 같은 앱·화면 탭이 있으면 그 탭으로 가고 없으면 새로 연다.
  - layout 파일이 판 7이고 `rail_apps`가 있다. 판 5·6 파일은 읽을 때 판 7로 올린다.

왜: lophn은 탭과 본문의 바탕을 맞춰 한 면으로 보이게 하는데, 앱 panel만 그 사이에 다른 바탕의 줄과 더 어두운 화면이 끼었다. project마다 자주 쓰는 앱 화면을 매번 + 메뉴에서 고르는 것도 번거로웠다.

결정:
- 크롬 줄은 지우지 않고 문제가 있을 때만 띄운다. 멈춘 화면을 다시 여는 [Open again]이 그 줄에만 있다. (agent)
- 앱 바탕은 `@lophn/ui`가 아니라 template에서 맞춘다. 같은 판의 SDK byte를 바꾸면 기존 앱의 `npm ci`가 깨지고, 판을 올리면 `app-ui`·shell·template 고정이 같이 바뀐다. 사람이 강제하지 말라고 했다. 이미 만든 앱은 그대로다. (사람, agent)
- 고정 앱은 desk가 아니라 project 단위로 layout 파일에 둔다. 등록은 탭 menu와 + 둘 다, 누르면 있는 탭으로 간다. (사람)
- `icon`은 `@lophn/declaration` 판을 올리지 않는다. 선언 검증기 파일이 바뀌어도 판을 올리지 않던 앞선 변경을 따른다. 선언에 icon이 없으면 칸을 두지 않아 옛 선언의 hash가 그대로다. (agent)

## turn의 일한 시간 한도를 지우고 model 호출 수 상한을 기본으로 끄다

```yaml
modules: [packages/protocol, packages/core/lophn-agent]
checked: []
```

- 전: turn 하나는 사람 기다림을 뺀 일한 시간 30분(`lophn-agent.run.active_ms`), model 호출 150번(`lophn-agent.run.model_attempts`), 진행 없이 5분(`lophn-agent.run.stall_ms`) 가운데 먼저 닿는 것에서 멈췄다. 진행 중인 긴 일도 "The agent reached its working time limit and stopped."로 끊겼다.
- 후:
  - 일한 시간 한도가 없다. 설정 `lophn-agent.run.active_ms`를 지웠다. settings 파일에 남은 값은 읽지 않는다. 일한 시간은 "Worked for"에 쓰려고 계속 센다.
  - `lophn-agent.run.model_attempts`는 기본이 `null`(상한 없음)이다. 양의 정수를 고르면 전처럼 그 수에서 멈춘다(eval 판단 case의 15).
  - `stall_ms`(진행 없이 5분)는 그대로다.
  - turn에 고정하는 `limits`가 `{model_attempts: number | null, stall_ms}`다. ledger step `lophn-agent.turns.drop-active-limit`이 시작한 turn의 `limits`에서 `active_ms`를 뺀다.
  - 실패 이유 `active_limit`는 남는다. 그 이유로 끝난 지난 turn의 TurnEnded event가 ledger에 있고 events는 고치지 않는 기록이다. 새 turn은 그 이유를 내지 않는다.

왜: 사람이 앱을 짓는 turn이 30분에 끊겼다. omp, Hermes, opencode는 기본으로 turn 시간이나 step 수 상한이 없다. Hermes는 상한이 "silent mid-task truncation"을 일으켜 기본을 무제한으로 바꿨다. 셋 다 기본으로 켜 둔 것은 stream 단위 무진행 timeout과 retry 수뿐이다.

결정:
- 일한 시간 한도는 지우고 호출 수 상한은 opt-in으로 남긴다. 사람이 한도를 없애라고 했다. 호출 수 상한은 eval이 돈을 막는 데 쓰고, opencode `steps`·Hermes `max_turns`도 opt-in으로 둔다. (사람, agent)
- 무진행 한도는 남긴다. 다른 harness도 무진행 timeout은 기본으로 켜 두고, 진행 없이 멈춘 turn을 끝낼 다른 장치가 없다. (agent)
- 한도에 닿았을 때 tool 없이 model을 한 번 더 불러 한 일·남은 일을 요약하게 하는 안(opencode·Hermes)은 이 변경에 넣지 않았다. (agent)

## `/status` 창 점유가 Compact 뒤, model을 바꾼 뒤, call 사이에도 맞는다

```yaml
modules: [packages/core/lophn-agent, packages/protocol, packages/shell/renderer]
checked: []
```

- 전:
  - `ReadSessionStatus.context`는 마지막으로 끝난 판단 call의 `input + cache_read + cache_write`와 그 call의 `context_limit`이었다. Compact의 요약 call은 `organizing`이라 빠져서, Compact 뒤 다음 call까지 줄기 전 크기가 그대로 보였다. 그 call 뒤의 답, tool 결과, 새로 받은 메시지는 세지 않았다. model을 바꿔도 한도는 옛 model 것이었다.
  - footer와 panel의 입력 token 합에 `cache_write`가 빠졌다. Anthropic처럼 cache 쓰기를 따로 주는 provider에서 입력이 작게 보였다.
- 후:
  - 창 점유 = 그 call의 실제 prompt token + 그 call의 답 blob, 그 call의 tool 결과, 그 call 뒤에 받은 메시지 본문의 byte를 `BYTES_PER_TOKEN`으로 센 값(tool 결과 이미지는 `IMAGE_TOKENS`). session 자신의 답 메시지는 답 blob과 겹치므로 세지 않는다. omp의 `getContextBreakdown`(실제 prompt token + 그 뒤 꼬리 추정)과 같은 셈이다.
  - 그 call 뒤에 Compact가 이어졌거나 그 call의 turn 입력을 덮는 rewind가 적용됐으면 `context`는 다음 call까지 `null`이다.
  - 한도는 지금 session이 쓸 model의 것이다. 그 call과 model이 다르면 resolve와 같은 순서(사람이 적은 정보, catalog, 기본 한계 131072)로 읽는다. 기본 한계와 `withDefaultLimits`는 `models/user-entry.ts`로 옮겨 resolve와 status가 같이 쓴다.
  - footer의 입력과 panel의 입력 칸에 `cache_write`를 더한다. `StatusView`에 `cacheWriteTokens`가 생겼다.

왜: 사람이 lophn의 창 점유가 omp와 다르게 틀린다고 했다. 특히 Compact 직후 창이 여전히 찬 것처럼 보였다.

결정:
- Compact·rewind 뒤에는 추정하지 않고 모름으로 둔다. 요약과 남은 메시지로 다시 세면 system prompt와 tool 정의 크기를 따로 알아야 하는데 status read에는 그 값이 없다. 다음 call이 오면 실제 값이 된다. 버린 길: 요약 call의 token으로 추정하기(요약 call의 prompt는 접은 원문이라 창과 무관하다). (agent)
- system prompt·tool·skill이 그 call 뒤에 바뀐 양은 세지 않는다. omp는 세지만 lophn은 turn마다 prompt를 다시 조립하고 status read가 그 조립을 할 수 없다. (agent)

후속: 없음.

## job은 사람이 등록을 한 번 승인해야 돌고, 앱 tool 호출은 만든 agent의 할당을 보지 않는다

```yaml
modules: [packages/protocol, packages/core/jobs, packages/core/apps, packages/core/runs, packages/shell/renderer]
checked: []
```

- 전:
  - agent가 `job.create`로 만든 job은 바로 돌았다. 사람은 Settings에서 보고 끄거나 지울 수만 있었다.
  - job의 tool_run은 만든 agent의 지금 할당과 domain으로 판정했다. 앱 place에서 앱을 만든 lophn처럼 그 앱이 할당되지 않은 agent가 만든 job은 만들 때는 통과하고, 차례마다 `gate_blocked`(run은 `tool_denied`)로 말없이 실패했다.
  - `job.update`로 할 일(`action`)을 바꿀 수 있었다.
- 후:
  - job record에 `approved_at`이 있다. agent가 만든 job은 승인 대기(`approved_at`, `next_due_at`이 null)이고 돌지 않는다. 대기 목록의 Scheduled jobs 묶음에 승인 card가 뜨고 [Approve]는 그 순간부터 차례를 센다. [Reject]는 job을 지운다. 종류(agent_run, tool_run, workflow_start)와 상관없다.
  - route `job.pending`(승인 대기 목록), `job.approve`(`approve` | `reject`)가 생겼다. 둘 다 user만 받는다.
  - `job.update`에서 `action`이 빠졌다. 다른 일은 새 job으로 만든다.
  - job의 앱 tool 호출(program caller)은 앱 호출 경로가 막지 않는다. `CallAuth.program`과 run의 job 출처에서 만든 agent·place가 빠졌다.
  - Scheduled jobs 화면과 project panel은 승인 대기 job에 "Waiting for your approval"을 보인다.
  - ledger step `jobs.approval`이 `jobs.approved_at`을 더하고 기존 job을 모두 승인 대기로 옮긴다(`next_due_at`을 지운다). 기존 job은 대기 목록에서 한 번 승인해야 다시 돈다.

왜: Mahas 앱의 15분 수집 job이 만든 agent(lophn)에게 Mahas가 할당되지 않아 매번 막혔다. job을 만든 agent가 그 tool을 직접 쓸 이유는 없다. 할당으로 허락하면 job 하나를 위해 그 agent에게 앱 전체를 열어 줘야 한다.

결정:
- job의 허락은 만든 agent의 할당이 아니라 사람의 등록 승인이다. 버린 길: 앱 place에서 만든 job이 자기 앱 tool을 부를 때만 할당 검사를 건너뛰기(그 경우만 풀고 근본이 남는다), 만들 때 할당을 검사해 거절하기(필요 없는 할당을 강요한다). (사람)
- 승인은 job마다 한 번이고 다시 묻지 않는다. 할 일은 바꾸지 못하게 해 승인한 일과 도는 일이 어긋나지 않게 한다. (사람, agent)
- [Reject]는 job을 지운다. 거절한 job을 남겨 둘 쓸모가 없다. (agent)
- agent_run과 workflow_start도 승인을 받는다. 사람 없이 되풀이되는 것은 셋 다 같다. 받은 agent는 지금처럼 자기 할당으로 일한다. (agent)

후속: 기존 job(예: Mahas 사용량 증분 수집)은 업데이트 뒤 대기 목록에서 [Approve]해야 돈다.

## 하나의 shell: Home place, desk, 자유 split group, drag and drop, launcher·activity bar 제거

```yaml
modules: [packages/shell/renderer, packages/shell/main, packages/shell/preload, packages/shell/ipc, packages/design]
checked: []
```

- 전:
  - 창이 Launcher, project 작업대(activity bar, 6칸 pane grid, desk selector, place switcher), 앱 공간(위쪽 바와 오른쪽 side panel), Settings 공간으로 나뉘었다. 새 창은 launcher로 열렸다.
  - project layout은 `<data>/shell/layouts/<project>.json`(판 7)이고 칸 tree에 칸마다 tab 줄이 있었다. 고정 앱 panel(`rail_apps`)이 activity bar에 있었고 앱 공간의 배치는 localStorage `lophn.app-layout.<app>`에 있었다.
  - Jobs는 Settings의 Scheduled jobs 항목이었고 대기 목록(Inbox)은 overlay뿐이었다.
  - 모든 길에서 radius가 작았고 shell 바탕은 `surface.floor/subtle`을 썼다.
- 후:
  - Home, project, 앱, Settings가 한 shell 틀을 쓴다: title bar에 tab 줄, 왼쪽 sidebar(New session, Inbox·Jobs, place마다 session과 Recent, 빠른 실행 Terminal·Browser·App·Search, Settings), 둥근 card 하나, 오른쪽 sidebar(project Files·Domain·Artifacts·Workflows·Jobs, Home Places·Jobs, 앱 App·Domain·Logs). launcher 화면은 없고 새 창은 Home으로 열린다(Home은 folder와 터미널이 없다). Places 줄(왼쪽 sidebar, Home의 Places panel)과 팔레트가 place를 옮긴다. project 등록·New app·보관은 Home의 Places panel이 한다.
  - desk: Main(`_default`) 하나, 사람이 만든 desk(New desk, 이름 바꾸기, 닫기), workflow마다 하나인 workflow desk. 사람이 만든 desk의 x는 그 일을 끝내는 것이다. 확인 dialog 뒤에 그 desk의 tab·float·detached 창을 보통 닫기 길로 닫고(터미널은 멈추고, 저장 안 된 파일은 묻는다. 하나라도 거절하면 거기서 멈추고 desk는 남는다) desk를 지운다. 탭을 Main으로 옮기지 않는다.
  - split: tab 2~4개를 한 칸(group)으로 묶고 배치는 나눔 tree(row·column, 몫 0.15~0.85, 나누는 선을 끌어 바꾼다)다. tab 줄은 하나이고 칸마다 card 머리 줄이 있다. 만들기는 tab menu의 Split right·down·Remove from split·Unsplit(all), `pane.split`, tab을 card 가장자리에 끌어 놓기다. 끌기는 pointer drag이고 알약, 자리 비우기, drop zone(가장자리는 split, 가운데는 swap, tab 줄은 순서 바꾸기·group에서 꺼내기)이 있다. 끄는 동안 `<webview>`는 pointer를 받지 않는다.
  - 한 tab당 card 머리 줄 하나다. browser(nav·address·actions), 파일(저장 상태·Info), agent(session switcher·Rename·Fork·Archive), artifact가 자기 머리 줄을 따로 그리지 않고 card 머리 줄에 올린다. card 밖(float, detached 창)에서는 본문이 자기 줄을 그린다.
  - Jobs는 Settings에서 빠졌다. 왼쪽 sidebar의 Jobs overlay와 Inbox overlay(둘 다 [Open in tab]), 모든 place의 Jobs 탭과 Inbox 탭, 오른쪽 Jobs panel로 본다.
  - keybinding: command `tab.to-prev-pane`·`tab.to-next-pane`·`pane.split-down`을 지웠다(Split down은 tab menu에 있다). `pane.focus:1~4`는 고른 group의 N번째 칸, 새 `pane.focus-left/right/up/down`(Ctrl+Alt+화살표, mac Cmd+Alt+화살표)는 맞닿은 칸, `pane.split`은 다음 plain tab과 오른쪽으로 묶기다. 창 안 chord `launcher`(Ctrl+Shift+L)는 `home`이 되어 Home place로 간다. 사람이 `shell.keybindings`에 둔 지운 id의 줄은 읽을 때 버려진다.
  - layout 파일이 place마다 하나인 `<data>/shell/places/<place>.json`(판 8, place는 `home`, project id, 앱 id)이다. IPC는 `shell:place-layout-read/save`다. desk는 `{ tabs, selected_tab, groups, floats, detached }`다. 옛 `<data>/shell/layouts/*.json`(판 5~7)은 더는 읽지 않는다(사람이 결정). 파일이 없으면 모든 place가 기본 layout(빈 Main desk)으로 시작한다.
  - `rail_apps`(고정 앱 panel)와 activity bar는 없다(옛 layout을 읽지 않으므로 없다). 앱 panel은 + menu나 빠른 실행의 App ▾로 연다. 앱 localStorage `lophn.app-layout.<app>`은 읽지 않는다. 앞 항목의 "activity bar에 앱 panel 고정"과 layout 판 7의 `rail_apps`는 이 항목으로 대체된다. 앱 place는 앱 화면 탭 하나로 열리고 새 앱은 앱 화면과 lophn session을 붙인 group으로 열린다.
  - 앱·artifact·browser `<webview>`의 아래 두 모서리가 card 모양으로 둥글다(native popup·DevTools·overlay는 각진 채).
  - design: radius 척도가 xs 6, sm 8, md 10, lg 14, xl 20이고 shell 바탕 token `color.surface.shell`이 생겼다(light는 subtle, dark는 floor. 배경 preset 셋에도 있다). card 둘레 여백 16px.
  - gallery: Drafts의 shell 초안을 지우고 Screens › Shell이 실제 shell을 그린다.

왜: 공간이 넷으로 나뉘고 칸 grid와 activity bar가 있어 같은 일(session 열기, 파일 보기, 둘 나란히 보기)이 공간마다 달랐고 화면이 무거웠다. place마다 같은 shell 하나를 쓰면 탭, desk, panel, 단축키가 어디서나 같다.

결정:
- 이름은 desk를 유지하고 기본 desk 문구는 Main이다. desk가 tab 줄, group, float, detached를 통째로 가진다.
- split은 처음 "tab 둘을 붙인 split tab 하나"로 정했다가 자유 배치(위 둘 아래 하나, 2×2)를 위해 group(2~4칸, 나눔 tree)으로 넓혔다. 칸마다 tab 줄이 있는 옛 방식으로는 돌아가지 않는다. 버린 길: 칸 tree와 칸마다의 tab 줄 유지(탭이 어느 칸에 있는지가 복잡하다).
- desk를 닫는 것은 그 일을 끝내는 것이다. 버린 길: tab을 Main으로 옮기고 desk만 지우기.
- Jobs는 Settings가 아니라 overlay·탭·panel이다.
- 창 하나가 place 하나를 보이고 place 이동은 창 안에서 한다. detach는 project만 한다. (agent)
- drag and drop은 HTML5 drag가 아니라 pointer drag다. `<webview>` 위를 지날 때 guest로 이벤트가 새지 않게 하려고 끄는 동안 webview의 pointer를 끈다. (agent)
- 옛 `shell/layouts/*.json`(판 5~7)은 올리지 않고 읽지도 않는다. 사람이 자기 data에서 지웠고 layout은 새로 시작해도 되는 화면 상태라 읽기·올리기 코드를 두지 않는다. 앱 localStorage 배치도 읽지 않는다. (사람)

후속: 사람이 `npm run dev:mock`/실제 Electron에서 layout 복원, detached 창, webview 모서리와 drag, desk 닫기를 확인한다(`project-docs/plan/ui-overhaul/README.md` "남은 것"). 개발 data(`.dev-data/`)는 지우지 않아도 된다.
