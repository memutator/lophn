# workspace layout

workspace 창(Home, project, 앱)이 가진 탭이 어디에 있는가를 정하는 메커니즘이다. 모든 workspace와 Settings가 shell 틀(`renderer/shell/`) 하나를 쓰고, layout은 workspace(Home, project, 앱) 하나에 desk 여럿이다. 옛 launcher, 앱 공간의 위쪽 바와 side panel, activity bar, 6칸 pane tree는 없다. desk는 기본 desk(`_default`, 화면 이름 "Main") 하나, 사람이 만든 desk(New desk, 이름 바꾸기, 닫기), 그 project의 workflow마다 하나인 workflow desk다. project의 title bar 왼쪽 desk 단추로 바꾼다(Home과 앱은 Main 하나라 단추가 없다). desk 하나가 tab 줄(tabs와, 그중 tab 2~4개를 한 칸으로 묶은 group), workspace 위에 뜬 패널(floats, 접힌 것은 title bar 오른쪽 칸의 아이콘), OS 창(detached)을 통째로 가진다. 모든 탭 kind가 같은 길을 쓴다. renderer의 순수 함수 desk model, main이 workspace마다 검증해 저장하는 layout 파일, 패널을 그리는 float 층, workspace를 넘는 전역 float 층, `WorkspaceWindow`마다 만드는 `<webview>` 그릇과 그 z-index, 창 맨 아래 작업 표시줄, 탭을 창 사이로 옮기는 main 중계(`transfer`/`receive`)에 걸친다. browser 탭 page, 앱 화면, artifact 화면은 native view가 아니라 그 `<webview>` 그릇에 산다(`browser-tab.md`, `renderer/app-frame/webview-host.tsx`). native view는 browser의 크기 준 popup·DevTools와 overlay뿐이다.

## Home workspace

Home은 같은 `WorkspaceWindow`에 `workspace: { kind: "home" }`를 주어 그린다(`desktop/main.tsx`의 `home` 공간. 새 기본 창의 첫 화면이고 옛 launcher 화면은 없다). project 창과 코드가 같고 project가 필요한 것만 빠진다.

- **project가 없다(`TabHost.projectId === null`).** 터미널(통로를 주지 않는다), Explorer·Artifacts·Workflows panel, 검색 탭, project settings, desk 단추(Main 하나), detached 창(`detached`를 주지 않는다)이 없다. 그 kind가 Home layout에 있어도(손상) `render`가 null을 돌려 크래시하지 않는다. html 파일은 artifact 탭이 project 파일로만 열리므로 Home에서는 문서 탭으로 연다.
- **오른쪽 sidebar는 Workspaces와 Jobs다**(`workspace/sidebar/sidebar-panels.tsx`의 `kinds`에 `home`이 든 panel). Workspaces는 `shell/workspaces-panel.tsx`(project·앱 목록, 등록, New app, 보관)이고 줄을 누르면 그 workspace로 간다. Jobs는 project panel과 같은 `JobPanel`에 `project: null`을 주어 모든 job을 보인다.
- **layout은 workspace key `home`(`<data>/shell/workspaces/home.json`)이고 agent 탭은 `workspace: { kind: "home" }`로 저장한다**(project는 `{ kind: "project", id }`). 탭 `fields.workspace`는 `workspaceKey(workspace)`(project id 또는 `"home"`)이고 render는 이 창의 workspace와 다르면 그리지 않는다. Home session(`workspace === null`)은 그 session의 agent로 연 agent 탭이다(`agentRow`가 workspace가 null인 session을 찾는다). 다른 workspace의 session은 그 workspace 창으로 간다(toast 행동의 기본 처리기).
- **core가 준비되지 않았거나 시작에 실패하면 Home 창 대신 `HomeGate`(`desktop/workspaces/home-gate.tsx`)가 선다**: 같은 `ShellFrame`에 빈 왼쪽 sidebar와 tab 줄을 두고, card 가운데에 연결 화면(`ConnectionGate`. 준비 중은 `Shimmer` 한 줄, 실패는 [Retry])이나 `StartFailureScreen`을 보인다. 준비되면 같은 틀의 Home 창으로 바뀐다. 연결이 끊긴 채(stale) 마지막 화면이 있으면 Home 창이 `ConnectionNotice`를 card 위 한 줄(`notice` prop)로 얹는다.

## 앱 workspace

앱은 같은 `WorkspaceWindow`에 `workspace: { kind: "app", id }`를 주어 그린다(`desktop/main.tsx`의 `app` 공간. 옛 `AppSpace`의 위쪽 바와 오른쪽 `SidePanel`은 없다). project가 없는 점은 Home과 같고, 앱 화면 탭과 앱 panel이 더해진다.

- **layout은 workspace key = 앱 id(`<data>/shell/workspaces/<app_id>.json`)이고 저장된 것이 없으면 Main desk에 앱 화면 탭 하나가 고른 채 선다**(`freshLayout`). localStorage `lophn.app-layout.<app>`은 읽지 않는다. agent 탭은 `workspace: { kind: "app", id }`로, 앱 화면 탭은 `{ kind: "app_screen", key: "app-screen:<app>", app }`로 저장한다(`main/workspace/kinds/app-screen.ts`, 위험 test는 `workspace-layout_test.ts`).
- **앱 화면 탭(`workspace/kinds/app-screen.tsx`, `app-screen-tab.tsx`)은 그 앱의 현재 release의 선언에서 `tab` 자리를 가진 첫 screen을 `place="tab"`으로 연다**(`entryScreen`. 앱 전용 창의 `createEntryScreen`과 같은 규칙이고 `tab` 화면이 없으면 열지 못한다). 앱 workspace마다 하나이고 닫으면 + menu의 App screen으로 다시 연다. 화면은 지금 workspace를 `usePlace().workspace`로 받는다(`AppWorkspaceProvider`가 창의 workspace를 `EmbeddedView`의 `workspace`로 내린다). 앱 panel 탭(`app_panel`)과 달리 보관소 key(`keepKey`)가 탭 key라 Float·desk 바꾸기에도 view가 이어진다. 화면이 멈추거나 앱이 멈췄을 때만 `ViewChrome` 줄이 선다. Detach하지 않는다(`noDetach`; 앱 workspace 창은 `detached`를 받지 않는다).
- **앱 화면은 lophn이 감싸는 모든 프레임의 머리 줄에 올린다**(앱 머리 줄). 앱 page는 `@lophn/app-ui`의 `useTabHead`로 글과 id만인 `TabHead`(경로 조각, 탭, 상태 글, ⋯ 앞 단추, ⋯ menu 묶음, ← → 덮어쓰기)를 보내고, 앱 화면을 여는 `EmbeddedView`(`tabHead`)가 `app-frame/app-tab-head.tsx`에서 `CardHeadSpec`으로 바꾼다. 그리는 곳은 프레임마다 다르다: 탭(앱 화면 탭, dock한 앱 panel 탭)은 `ContentCard`의 머리 줄이 `CardHeadContext`로 받아 ← →와 ⋯ 메뉴 사이에 그린다. card 칸이 없는 프레임(tray popup 머리, 앱 sidebar panel 머리의 단추 자리, 앱 panel float(desk float과 전역 float)의 bar, 세션 앱 카드의 `ViewChrome` 줄 끝)은 `useHeadSlot()`이 만든 setter를 `HeadSlotScope`로 화면 둘레에 달고 `HeadControls`로 같은 spec의 가운데·단추·⋯ 메뉴를 그린다(nav는 탭만. tray popup은 `actionsOnly`라 앱 단추만 icon 단추로 그린다). 단추의 `icon`은 `TAB_HEAD_ICONS`(`protocol/shell/app-bridge-types.ts`: refresh, add, open, edit, delete, copy, run, stop, download)의 이름이고 `renderer/icons/action.ts`의 `actionIcons`로 그린다. `readTabHead`가 모르는 이름을 버려 글 단추가 된다. 다른 프레임은 icon을 label 글 앞에 붙인다. 그 프레임의 제목과 단추(pin, minimize, dock, close)는 그대로 둔다. `HeadSlotScope`는 프레임이 이미 제목을 보이므로 경로 첫 칸(앱 이름)도 뺀다. 앱 전용 창만 머리 줄이 없다. 누르면 id가 page로 돌아간다. 통로는 main을 거치지 않는다: preload가 `ipcRenderer.sendToHost`로 올리고 webview 그릇이 그 element의 `ipc-message`로 받고 element의 `send`로 내린다(`ipc/app-tab-head.ts`). 머리 줄은 그 탭 안의 표시라 신원이 필요 없고 보낸 element가 곧 그 탭이다. 받은 값은 `readTabHead`가 글·bool만 남기고 자른다(앱 코드가 객체를 보내 React child가 되면 창이 깨진다). page는 preload가 붙자마자 hello로 shown(지금 shell이 그리는지)을 물어 보통 첫 render 전에 답을 쥔다. 답을 못 보냈으면(guest가 아직 안 붙음) 그릇이 dom-ready에 다시 보낸다. detached 창의 앱 panel과 앱 전용 창은 머리 줄이 없어 shown이 false이고 앱이 같은 조작을 스스로 그린다. 같은 길로 살려 두기의 boolean 신호도 올라간다(`ipc/app-keep-alive.ts`, 채널 `app:keep-alive`, preload `lophnApp.setKeepAlive(active, key?)`). 신호는 key별이고(`useKeepAlive`와 `@lophn/agent`의 turn 동안 자동 신호가 각자 key로 켠다) preload가 켠 key 집합을 쥐어 호스트에는 "켠 key가 있나" 하나만 올린다. 그릇은 element의 `ipc-message`로 받아 그 화면의 신호로 쥐고(key를 모른다), page가 새로 load되면(`did-navigate`) 지운다. preload도 새로 만들어져 key 집합이 비므로 둘이 어긋나지 않는다.
- **Annotate는 앱 화면 탭 머리 줄 ⋯ 메뉴의 맨 위 항목이다.** 앱 화면 탭이 자기 view로 `useAnnotate`를 열고, 항목을 `EmbeddedView`의 `shellHead.menu`로 넘겨 `useAppTabHead`가 앱이 올린 메뉴 항목 앞에 둔다(앱이 머리 줄을 올리지 않아도 선다). artifact 탭도 ⋯ 메뉴 항목이고, ⋯ 메뉴가 없는 card 밖(floated)에서만 자기 toolbar의 단추다. 켜진 동안은 머리 줄 전체가 Annotate 줄(`app-frame/annotate/annotate-head.tsx`: 가운데 Annotate · 앱 이름, 오른쪽 끝 모두 지우기·Done·보내기와 모은 수)로 바뀌고 앱이 올린 머리 줄은 그리지 않는다. 모은 목록은 화면 옆이나 위에 따로 없다. 메모는 화면 안 표지 옆 칸(preload)에서 고치고 그 칸의 ×로 하나를 지운다. card 밖(floated 패널)에서는 머리 줄이 없어 단추도 없다. 보냄·실패 알림은 같은 탭이 view 위쪽 toast로 띄운다. 받는 쪽은 이 앱 workspace의 열린 lophn session이고 없으면 새 session이다(보낸 뒤 그 session 탭을 연다).
- **새 앱(`openNewApp`)은 앱 화면과 lophn session을 붙인 group(좌우)으로 열린다**(`startLophn`). session 요청(`route.session`)은 일반 desk 규칙으로 탭을 연다.
- **앱 상세는 App details 탭이다**(`workspace/kinds/app-detail.tsx`). 왼쪽 sidebar 지금 앱 줄의 톱니로 열고, 본문은 Domains를 뺀 `AppDetail`(Icon, Folders, Version·Access·Activity)이다.
- **오른쪽 sidebar의 내장 panel은 Logs 하나다**(`workspace/sidebar/sidebar-panels.tsx`의 `kinds`에 `app`이 든 panel. 앱 sidebar panel은 따로 선다). Logs는 `useAppRuns`가 읽은 이 앱의 run 기록이다(`RunList`; session 줄을 누르면 그 session의 Agent 탭). desk 단추는 없다(Main 하나). Files는 두지 않는다: 옛 패널도 앱 source 파일 탐색기는 없었고 연결 폴더 목록(Folders)은 App details 탭에 있다. sidebar에 preview 열기·승격 UI는 없다. preview는 앱 화면 탭 toolbar의 [Preview]로 연다("agent가 연 탭").
- **agent 탭의 `fields.workspace`는 앱 id**이고 source workspace는 `app`이다(`agent/tab-fields.ts`의 `sourceWorkspaceOf`). `agentRow`·`openedWorkspaceLophnSession`은 session의 workspace가 이 앱일 때만 이 창의 것으로 본다.

## 빠른 실행

작업 표시줄이 켜져 있으면 그 왼쪽 끝, 꺼져 있으면 왼쪽 sidebar 맨 아래 줄이다(`shell/quick-launch.tsx`의 `QuickLaunchRow`, 값은 `workspace/workspace-window.tsx`가 만든다. 왼쪽 sidebar는 `quick`과 `onSettings`를 받을 때만 그 줄과 톱니를 그린다).

- **값은 전역 하나와 project마다의 덮어쓰기다.** 전역 값은 core 선언 설정 셋이다(`packages/core/config/shell-settings.ts`, `<data>/settings.json`): `shell.quick_launch`(단추 순서, 고정 앱 panel, 끈 단추. layout `quick`과 같은 모양), `shell.app_launch`(`<app>:<surface>` → `{ open: dock|float, rect? }`), `shell.coding_agents`(`{ favorites, commands }`). renderer는 창마다 하나인 store(`desktop/settings/quick-launch/store.tsx`, entry가 `QuickPrefsProvider`로 내린다)로 읽고 쓴다. 쓰기는 먼저 화면에 반영하고 거절되면 다시 읽는다. 다른 창이 바꾼 값은 창 focus 때 다시 읽는다. project의 layout에 `quick`이 있으면 그 project는 그 값을 통째로 쓰고(합치지 않는다), 없으면 전역 값이다. Home과 앱 workspace는 늘 전역 값이다.
- **Terminal hover 목록은 coding agent 묶음 다음에 project의 명령 묶음(Commands)을 둔다.** 명령은 layout의 `commands`이고 Project settings의 Terminal commands 구역(`QuickCommandList`)이 고친다. 누르면 coding agent와 같은 길(`onNewCoding` → `openTerminalTab`)로 새 터미널이 그 명령 줄을 돌린다. 즐겨찾기가 없어도 명령이 있으면 목록이 뜬다.
- **단추는 순서를 바꾸고 끌 수 있다.** 목록 줄마다 위·아래와 Switch다(`project-settings/quick-launch-editor.tsx`). 끈 단추는 `hidden`에 들고 순서에는 남아, 다시 켜면 그 자리로 돌아온다. 고정을 풀면 그 id의 꺼짐도 버린다. 그릴 때는 `shownQuickOrder`가 끈 것을 뺀다.
- **Terminal · Browser · App은 누르기와 hover가 다르다.** 누르면 그 탭을 연다(새 터미널, 새 browser 탭, 앱을 고르는 앱 panel 탭). pointer를 올리면 목록이 뜨고 줄을 누르면 바로 연다: Terminal은 즐겨찾기 coding agent(그 명령어로 docked 새 터미널. workspace +의 hover 목록의 coding agent 묶음도 같은 즐겨찾기다), Browser는 bookmark(새 browser 탭), App은 앱 workspace의 앱 화면과 설치된 앱의 panel 화면 전부다. hover 면은 design `Popover`의 `hover`다(`Anchor`라 누르기가 면을 토글하지 않는다).
- **앱 panel 화면은 여는 자리를 기억한다.** App hover 목록과 고정 단추는 `openPinnedAppPanel`로 연다: 같은 앱·화면 탭이 어디든 있으면 그 자리에서 보이고, 없으면 `shell.app_launch`의 `open`대로 tab이나 float이다. float은 마지막 rect(float 층 기준)를 지금 float 층 안으로 당겨 쓰고, 없으면 float 층 가운데 60%다. 사람이 앱 panel float을 옮기거나 크기를 바꾸면(놓을 때 한 번) 그 화면의 rect를 쓴다. tab menu의 Float도 기억한 rect를 쓴다. `open`은 Settings › Quick launch의 App panels 줄(Tab · Float)에서만 바꾼다. 그 화면이 이미 전역 float이면 새로 열지 않고 그것을 펴서 맨 위로 올린다(`launchAppPanel`).
- **coding agent 즐겨찾기와 명령어는 Settings › Coding agents 표의 Command·Favorite 열이다.** 명령어를 비우면 adapter의 첫 명령어다. 기본 즐겨찾기는 Claude Code, Codex, OpenCode다.

## Settings

Settings는 workspace가 아니라 같은 shell 틀을 쓰는 창 안의 한 자리다(`desktop/settings/settings-space.tsx`, route `settings`). 왼쪽 sidebar가 Settings 항목 목록과 [Back](Settings를 열기 전 workspace로 돌아간다)이고, tab 줄(`TabStrip`)에는 Settings tab 하나뿐이며(닫으면 [Back]과 같다), 오른쪽 sidebar는 없다(`ShellFrame`의 `right={false}`). desk, group, float, layout 파일이 없고 Inbox overlay와 palette는 workspace 창과 같이 쓴다. Jobs는 Settings 항목이 아니라 Jobs overlay와 Jobs 탭이다.

## 지키는 것

- **탭 하나는 한 곳에만 있다.** tabs, floats, detached 중 하나다. 같은 탭을 두 자리에 그리면 editor는 session이 둘이 되어 conflict가 나고, terminal은 입력을 받을 수 있는 webContents가 하나뿐이다. desk model 함수가 이를 지키고 `desk-model_test.ts`의 위험 test가 열기, split·swap·ungroup, float, dock, minimize, restore, detach, reattach, close를 이어서 해도 탭이 사라지거나 둘이 되지 않는지 본다. `openTab`은 floated·detached 탭을 새로 붙이지 않는다. floated 패널이면 펴서 맨 위로 올리고, detached 탭이면 `WorkspaceWindow`가 그 창을 앞으로 가져온다.
- **"탭 하나는 한 곳에만 있다"는 desk를 건너서도 지킨다.** 같은 key의 탭은 두 desk에 없다. `host.openTab`(workspace-window.tsx)은 `findTab(layout, key)`로 그 탭이 있는 desk를 먼저 찾아 그 desk로 바꿔 보인다(floated면 펴서 맨 위로, detached면 창을 앞으로). 새 탭이라도 `after`가 다른 desk의 탭이면 그 desk로 바꿔 그 탭 뒤에 연다(숨은 desk의 terminal이 연 URL, `architecture/browser-tab.md`). 탭을 빼앗아 오지 않는 까닭은 detached 창과 살아 있는 terminal이 딸려 있어서다. 사라진 workflow의 desk는 Main으로 합친다(`mergeDeskIntoMain`): tabs는 Main 끝, floats·detached는 상한(20)이 남아 있을 때만 그대로 가고 아니면 tab으로 간다. Main에 이미 같은 key가 있으면 옮기지 않는다. 합치기는 workflow 목록 읽기에 성공했을 때만 한다(실패나 읽는 중에 합치면 desk의 탭이 모두 Main으로 옮겨진다). `desk-model_test.ts`의 위험 test가 desk를 지우고 건너 열어도 탭이 사라지거나 둘이 되지 않는지 본다.
- **화면이 그리고 고치는 것은 보이는 desk뿐이고, `<webview>`는 탭이 사는 동안 모든 desk에서 산다.** 고르지 않은 탭과 떠난 desk의 탭은 React에서 unmount한다(card는 고른 탭, group이면 그 group의 leaf만 mount한다). terminal은 창의 `TerminalDisplays`가 xterm·DOM·출력 구독을 유지해 돌아오면 다시 붙이며 과거 raw 출력을 다시 재생하지 않는다. browser 탭·앱 panel·artifact 탭의 `<webview>`는 탭 key가 어느 desk에서든 layout에 있으면 그릇이 숨긴 채 들고 있어 탭이나 desk를 오가도 page를 다시 load하지 않는다(`workspace-window.tsx`가 이전 key와 지금 `allTabs(layout)`의 차로 `webviews.release`를 부른다). 놓는 것은 탭 key가 모든 desk에서 사라졌거나 그 탭이 detached가 됐을 때다(detached 탭의 page는 그 창이 갖는다). `ViewKeeps`는 앱 panel·artifact 탭의 view_session과 마지막 state를 unmount·Float·Dock 사이에 잇는다. 떠난 desk의 detached 창은 닫지 않고 숨긴다(`showOnly`, main의 `DetachedEntry.hidden`). PTY와 그 창의 guest page가 그대로 산다. 숨은 창이 예기치 않게 사라지면 그 탭이 있는 desk가 `docked`를 받는다. 복원 때는 보이는 desk의 detached 창만 열고, 다른 desk의 것은 그 desk로 갈 때 `showOnly`의 `missing`으로 연다. `showOnly`는 보낸 project 창의 detached 창만 건드리고 detached 창이 부르면 `forbidden`이다(`ipc_test.ts`). key를 만들거나 열린 탭을 찾는 곳(agent 탭 번호, 같은 session 재사용, 파일 이름 바꾸기, 닫은 탭 다시 열기, 대기 목록의 terminal)은 `host.windowTabs()`·`allTabs(layout)`로 모든 desk를 본다.
- **workspace를 떠나도 살려 두는 page.** 기본은 떠나는 workspace의 `<webview>`를 모두 놓는 것이다(돌아오면 다시 load). page가 "살려 둬" 신호를 켠 동안은 그릇(layer)이 창에 있어 그 page가 숨은 채 남는다. 구성은 둘이다. (1) 창마다 하나인 `WorkspaceViewsProvider`(`app-frame/workspace-views.tsx`)가 `<webview>` 그릇을 `WorkspaceWindow` 밖에 한 번 놓고, workspace마다 `{webviews, keeps}` pool을 둔다(`useTabHostSlices`의 `pool`). `WorkspaceWindow`는 본문을 provider의 `.context`(position: fixed, 예전 `.workspace`와 같은 stacking context)에 portal로 그려, 그릇과 패널·menu의 z-index 관계가 그대로다(`.workspace[data-pooled]`는 `position: absolute`). provider가 없는 곳(테스트·gallery)은 예전처럼 창 안에 그릇을 둔다. (2) `WorkspaceWindow`를 떠날 때 `pool.leave`가 한 틱 뒤(자식의 cleanup이 view를 `keeps`에 넣은 뒤) `WebviewHost.park(tabKeys)`를 부른다. layout에 아직 있는 탭(detached 제외)이면서 살려 둘 이유가 있는 화면만 두고 나머지 화면과 view(`keeps`)는 닫는다. 이유는 (a) 앱 page의 `useKeepAlive`(`@lophn/app-ui`) 신호, (b) browser 탭의 사람이 켠 Keep alive(탭 `fields.keepAlive`, 저장 `keep_alive: true`), (c) browser 탭이 download를 받는 중(main이 `will-download`~`done`를 `download` BrowserEvent로 알림), (d) browser 탭이 소리를 내는 중(`isCurrentlyAudible`, 떠날 때 한 번 본다)이다. artifact 탭은 page에 bridge가 없어 신호가 없고 늘 놓는다. 돌아오면 `acquire`가 같은 pool을 주고 `WorkspaceWindow`가 배치를 읽은 뒤 가져온 key를 지금 탭과 맞춰, 그 사이 layout에서 사라진 탭의 화면은 놓는다. 탭을 닫으면 이미 있는 차이 규칙(`webviews.release`)이 놓는다. 숨은 page의 `EmbeddedView`는 unmount되어 있으므로 알림 쪽 `useReportViewVisible`은 not visible로 끝나 있다. 살려 둔 page는 창마다 6개(`MAX_KEPT_PAGES`)까지이고 넘치면 가장 오래 안 본 것(그릇이 가려진 때, 창의 단조 tick)부터 놓는다. 전역 float은 이 규칙과 상관없이 늘 남는다. 놓는 시점은 떠날 때뿐이라 떠난 뒤 소리가 멈추거나 신호를 끈 page도 상한이나 돌아옴까지 남는다.
- **workflow 탭은 자기 workflow의 desk에 산다.** `TabKindDef.homeDesk`가 있는 탭을 여는 길(sidebar의 workflow 줄, `openWorkflow`)은 어디에도 열려 있지 않으면 그 desk로 가서 연다(desk가 없으면 `addDesk`로 workflow 이름을 key·label·`workflow`로 만든다). 그 desk가 보이면 sidebar Workflows의 그 줄이 강조된다.
- **탭을 찾고 바꾸는 곳은 tabs, floats, detached를 모두 본다.** `findTab`(layout, 어느 desk의 무엇인지), `allTabs`, `mapLayoutTabs`를 쓴다. `host.openTab`, `patchTab`, `removeTab`, 닫은 탭 다시 열기, 파일 이름 바꾸기, 대기 목록의 terminal 고르기가 floated 탭에도 같다. 닫은 floated 탭은 tab으로 돌아온다. detached 탭을 여는 길은 모두 그 창을 앞으로 가져오고, 닫는 길(`removeTab`)은 그 창을 닫고 항목을 버린다. palette 탭 행에는 보이는 desk의 tabs만 나온다.
- **탭 안에서 연 것의 자리는 `workspace/open-policy.ts`의 `openAt` 하나가 정한다.** source가 이 desk의 tab 줄에 있는 터미널(shell, coding agent)이고 새 탭이면 터미널을 가리지 않도록 그 옆 칸에 연다(`openTab`의 `beside`, `desk-model.ts`의 `openBeside`): 터미널이 group에 없으면 [터미널 | 새 탭] row group(0.5)을 만들고, 이미 group에 있으면 터미널 다음 leaf(끝이면 처음)의 칸 stack 끝에 새 탭이 쌓여 보인다(전에 보이던 탭은 그 칸에 숨어 남고 칸 머리의 ‹ › 로 돌려 본다. group은 자라지 않는다. 아래 "칸의 stack"). lophn agent 대화의 파일 link, 검색 결과처럼 그 밖의 탭(source) 안에서 연 새 탭은 source 바로 뒤다(group의 leaf 뒤면 group 뒤로 비킨다). source가 floated·detached이거나 없으면 desk 끝, 보이지 않는 desk면 source 바로 뒤(`openTab`이 그 desk로 건너간다)다. 대화 코드 블록의 실행(`run`)은 floated 새 터미널이다. 이미 열린 탭은 이 규칙을 거치지 않고 있는 자리에서 보인다. 여는 쪽은 `openFile(host, path, { from })`처럼 source key만 넘기고 `after`를 스스로 계산하지 않는다.
- **project 창 renderer가 detached 항목까지 layout 전체를 갖고 저장한다.** detached 창은 자기 탭 하나를 main을 거쳐 받고(`take`), 바뀐 값(`changed`), 탭 열기(`open-tab`, project 창에 docked로), 닫기(`closed`)를 main을 거쳐 project 창에 알린다. layout 파일은 workspace마다 하나(`<data>/shell/workspaces/<workspace>.json`)이고 마지막에 쓴 것이 이기므로 저장하는 곳은 하나다. 창은 workspace마다 `WorkspaceWindow`를 새로 mount한다(`desktop/main.tsx`의 `key`: project id, `home`, app id). 그 안의 `<webview>`는 DOM에서 빠지면 guest가 사라지므로, 떠나는 workspace의 page는 기본은 놓고 돌아오면 다시 load한다. 살려 둘 이유가 있는 page만 예외다(다음 항목, 아래 "workspace를 떠나도 살려 두는 page"). 그렇지 않으면 저장된 layout이 없는 workspace로 갈 때 앞 workspace의 탭이 남아 그 workspace의 layout으로 저장된다. Detach는 project만 한다(Home과 앱 창은 `detached`를 받지 않는다). main은 탭 값을 열어 보지 않고(key와 kind만) 같은 project 창에만 중계하며, 보낸 창으로 역할을 가려 `forbidden`으로 막는다(`main/desktop/detached/ipc.ts`). detached 창 bounds는 main이 저장할 때 살아 있는 창 값으로 채우고, 창을 옮기거나 크기를 바꾸면 `moved`로 project 창에 다시 저장하게 한다.
- **desktop 창의 자리는 layout이 아니라 앱에 하나다(`window.json`).** 한 창이 Home·project·settings를 오가므로 창 자리는 project에 속하지 않는다. desktop 창을 옮기거나 크기를 바꾸면 500ms 뒤에, 최대화·되돌림·닫기 때는 바로 마지막 자리를 쓴다. 최대화한 창은 되돌렸을 때의 자리(`getNormalBounds`)와 `maximized`를 둔다. 최소화와 전체 화면은 쓰지 않는다. 새 desktop 창(시작, tray, 단일 instance 요청)은 그 자리를 지금 화면 작업 영역 안으로 당겨(`desktop/work-area.ts`) 열고, 다른 desktop 창이 떠 있으면 32px 비켜 연다. detached 창은 이 값을 쓰지도 고치지도 않는다.
- **webview는 card의 아래 두 모서리를 직접 둥글게 그린다.** `<webview>`는 slot 부모로 잘리지 않고 그릇의 형제라 조상의 `overflow: hidden`이 닿지 않는다. 그릇의 page 요소(`webview-host.module.css`의 `.page`)가 `border-radius: 0 0 var(--radius-lg) var(--radius-lg)`와 `overflow: hidden`을 갖는다. 화면은 card·float 패널의 머리 줄 아래에 있어 위 두 모서리는 머리 줄에 닿는다. group이면 안쪽 아래 모서리도 둥글다(알려진 모양). 앱 전용 창은 창 전체를 쓰므로 `app-window.module.css`가 각지게 덮는다. native view(browser popup, DevTools, overlay)는 각진 채다.
- **Detach와 Dock은 transfer → main이 창을 열거나 닫고(native view가 있으면 옮김) → 성공했을 때만 layout 바꾸기 순서다.** 어느 단계가 실패해도 layout은 그대로라 탭이 사라지지 않는다. `TabKindDef.transfer`가 null을 내면 옮기지 않는다(editor는 `EditorSessions.flush`가 실패하면 null이라 저장 안 된 글을 잃지 않는다. `editor/transfer_test.ts`). 값은 `TabTransfer { value(JSON), views(옮길 native view의 view_session) }`이고 받는 창의 `receive`가 그리기 전에 받는다. terminal은 `terminal_ref`·`generation`(받는 창이 snapshot을 0부터 받는다), agent는 그 session의 composer draft(새 session 탭은 `new:` draft 전부, 받는 창의 글은 덮지 않는다), browser popup만 view_session과 state를 넘긴다(native view를 옮긴다). 앱 panel·artifact 탭은 transfer를 선언하지 않고(기본 `{ value: null, views: [] }`), 보통 browser 탭도 같은 값을 낸다. 받는 창이 다시 열며 page를 다시 load한다. 나머지 kind는 `toStored` 값으로 다시 연다. `noDetach` kind(browser DevTools 패널)는 Detach 항목과 단추가 없다. tab은 보내기 전에 `slimDetachedTab`으로 4096자를 넘는 `fields` 값(favicon data URL)을 뺀다(IPC 한 번이 64KiB까지다).
- **native view는 닫지 않고 창을 옮긴다. 그 항구를 쓰는 것은 browser의 크기 준 popup과 DevTools뿐이다.** `AppViews.moveViews(from, to, sessions)`가 모든 view가 `from` 창의 것인지 먼저 보고(아니면 아무것도 옮기지 않고 `invalid_input`), 기다리던 bounds를 버린 뒤 browser registry(`main/browser/registry.ts`의 popup·DevTools 항목)의 `move`로 보낸다(`main/browser/native-bounds.ts`). 옮긴 view는 떼어 숨긴 상태이고 새 창 renderer가 bounds를 보내면 붙는다. 옛 창 renderer가 늦게 보내는 요청은 소유 검사로 거절되어 무해하다. renderer에서는 `ViewKeeps.lookup`/`track`이 mount된 view의 session과 최신 state도 찾게 한다. `<webview>` guest는 이 항구로 오지 않는다: 앱·artifact·보통 browser 탭은 보내는 창이 element를 지우고 받는 창이 새로 만든다(보통 browser 탭은 url로 다시 load되고 cookie는 partition에 남는다. 그 탭의 DevTools는 닫힌다). popup 탭의 DevTools는 같이 옮긴다(floated 패널이던 것은 탭 안으로 바꿔서).
- **detached 창의 ×는 dock이다.** main이 창 닫기를 가로채 renderer에 `dock-request`를 보내고 renderer가 [Dock]과 같은 흐름을 돈다. 실패하면 창이 그대로 남는다. 앱을 끄는 중에는 가로채지 않고 자동으로 dock하지도 않는다(다음 실행에 `detached`로 돌아온다). 창이 예기치 않게 사라지면(renderer crash 등) main이 저장된 값으로 `docked`(transfer 없음)를 보내 탭이 layout에 남는다. project 창을 닫거나 같은 창에서 다른 공간으로 가면 그 창의 detached 창이 조용히 닫히고 상태는 `detached`로 남는다. 다시 열면 `WorkspaceWindow`가 저장된 값과 bounds(지금 화면 작업 영역 안으로 당긴 것)로 창을 연다. 같은 실행 안이면 terminal은 PTY에 다시 붙는다: detached 창이 kind의 `resume`(terminal은 `terminal_ref`·`generation`)을 `changed`로 알려 main이 들고(`DetachedRegistry`의 kept, 메모리에만), 조용히 닫힐 때(`close({ key: null })`, project 창 닫힘) (project, key)로 남겨 두었다가 같은 key의 `open({ transfer: null })`에 한 번 쓰고 지운다. 다시 열 때 쓰든 말든 지워 같은 PTY가 두 창에 붙지 않고, 개별 close·dock·remove와 앱 종료에서도 지운다. 앱을 다시 띄우면 transfer가 없어 재시작과 같다(PTY에 못 붙는다). 같은 (project, key)의 창이 이미 있으면 새로 띄우지 않고 앞으로 가져온다(`conflict`).
- **detached 창은 탭 하나만 그린다.** `Desktop`의 `detached` route이고 탭 줄도 sidebar도 floats 층도 없다(`<webview>` 그릇 하나가 자기 탭의 화면을 담는다). 그 안의 `openTab`은 project 창에 docked로 열고(agent 새 탭의 key가 project 창의 다른 session 탭과 겹치면 project 창이 새 번호로 바꿔 연다), 크기 준 browser popup은 또 하나의 detached 창으로 연다(popup view를 그 창으로 옮겨 `window.opener`를 지킨다). floats 층이 없어 browser 탭의 DevTools 자리 menu에서 floated를 뺀다. toast와 전역 palette intent는 이 route에서 끄고, tray와 전역 palette 키는 detached 창을 "가장 최근 창"으로 고르지 않는다.
- **`dockFloat`·`reattachTab`은 tabs 끝에 넣고 고른다.** preview와 transient 표시를 지운다. 떠나기 전 자리는 저장하지 않는다.
- **minimized는 floated에서만 간다.** 접혀도 `rect`는 접기 전 값을 지킨다. 접힌 float은 mount하지 않고(keep kind도) title bar 오른쪽 칸의 아이콘으로 있으며, 아이콘을 누르면 펴서 맨 위로 온다(`restoreFloat`). 펴진 float의 아이콘은 눌린 모양이다.
- **float은 고정(pinned, always on top)과 고정 안 함이 있다(사람).** 새 float은 고정 안 함이다. 패널 bar의 핀 단추로 켜고 끈다(`pinFloat`). 고정한 패널은 늘 고정 안 한 패널 위다: model이 floats 배열에서 고정한 것을 뒤로 모으고(`stacked`), 고정 안 한 패널은 raise해도 고정한 패널 바로 아래까지다. 고정 안 한 펴진 패널은 그 패널 밖을 누르면 접힌다(`minimizeLooseFloats`, `FloatLayer`가 document의 pointerdown을 capture로 본다). `<webview>` 안의 click은 embedder로 오지 않아 webview 그릇이 slot에 쏘는 focusin(`isTrusted`가 false)으로 본다. 패널에서 연 menu·dialog(portal)와 접힌 패널 아이콘 칸은 밖이 아니다. 코드가 옮긴 focus로는 접지 않는다. 저장은 `pinned: true`일 때만 적는다(판 9의 선택 필드).
- **float 패널 bar를 두 번 누르면 dock이다.** [Dock] 단추와 같다(`FloatPanel`의 `onBarDoubleClick`). 행동 단추 위는 제외한다.
- **전역 float은 `panel` 자리 앱 화면만 된다.** 다른 탭 kind(파일, 터미널, session)는 workspace에 묶여 있다. 목록은 `<data>/shell/global-floats.json` 하나이고 workspace layout 파일은 건드리지 않는다. 접힘, rect, pin이 workspace와 재시작을 넘는다. 저장은 `shell:global-floats-read|save`(`ipc/global-floats.ts`, main의 `core/global-floats-ipc.ts`, preload `lophnGlobalFloats`)이고 main이 schema(`global-floats.ts`)로 검증해 원자 교체로 쓴다(검증에 실패하면 `invalid_input`이고 파일은 그대로, 읽을 때 틀린 파일은 빈 목록). 접기·펴기·고정·쌓임·rect 규칙은 desk float과 같은 model 함수(`desk-model.ts`의 floats 함수)를 빈 desk 위에서 쓴다(`global-floats/store.ts`). 같은 화면은 전역 float 하나이고 다시 더하면 맨 위로 온다. 전역 float 밖을 누르면 고정 안 한 펼친 것이 접힌다.
- **앱을 영구히 지우면(`app.delete`) 그 앱 workspace의 layout 파일(`<data>/shell/workspaces/<app>.json`)과 전역 float 목록의 그 앱 float이 지워진다**(core가 commit 뒤 내는 남지 않는 event `AppRemoved`를 main이 받는다. 열린 창의 전역 float 층도 그 float을 닫는다). 다른 workspace layout의 앱 panel 탭과 `quick.apps` 고정은 지우지 않는다: 없는 앱은 앱 panel이 "앱이 없다" 안내로 그리고 고정 단추는 건너뛴다. 설정 쪽(`shell.quick_launch`, `shell.app_launch`, `shell.sidebar_panels_off`, `shell.tray_off`, `shell.tray_order`)은 core가 같은 때 지운다(`architecture/app-call.md`).
- **float bar의 단추 하나가 desk float과 전역 float 사이를 옮긴다.** desk의 앱 panel float은 "Show in all workspaces", 전역 float은 "Move to this desk" 단추다(`FloatPanel`의 `global`·`onGlobal`). rect, 접힘, pin을 가져가고 옮기는 쪽의 자리는 닫는다. 받는 쪽이 못 받으면(전역 20개, 이 desk에 더 둘 수 없음) 옮기지 않아 float이 사라지지 않는다. "이 desk로"는 `WorkspaceWindow`가 `registerDesk`로 받는 길을 등록해 있을 때만 된다. 그릇이 달라 옮길 때 page를 다시 load한다. 전역 float 층의 앱 화면은 workspace 없이 연다(`AppWorkspaceProvider` 밖이라 `usePlace().workspace`가 null). 어느 workspace의 것도 아니기 때문이다.
- **전역 float 층은 `Desktop`에 창마다 하나고 `WorkspaceWindow` 밖이다.** `{space}` 옆(project·Home·앱·Settings 공간)에 놓아 workspace를 바꿔 `WorkspaceWindow`가 다시 mount돼도 층의 `<webview>` 그릇과 `ViewKeeps`가 남는다. 층의 영역은 title bar 아래 창 몸통 전체라 rect 기준이 desk float과 같다(작업 표시줄이 있으면 그 위에서 끝나고 CSS `:has([data-taskbar])`가 맞춘다). z-index가 desk float 층보다 늘 위다. 빠른 실행의 앱 panel 단추와 hover 목록도 전역 float이면 그것을 펼친다.
- **작업 표시줄은 `.shell`의 맨 아래 줄이고 몸통 밖이다.** `ShellFrame`의 `taskbar` slot이 있으면 `<footer data-taskbar>`를 몸통 다음에 그리고 `.stage`의 아래 여백이 0이 된다. 몸통(`.body`, desk float 층의 자리) 밖이라 float이 덮지 않는다. 높이는 title bar와 같은 `--space-10`이고 `shell-frame.module.css`와 전역 float 층의 CSS가 같은 값을 쓴다. 왼쪽 끝은 빠른 실행(`taskbarStart`, 폭은 열린 왼쪽 sidebar 폭 이상이라 chip이 tab 영역 아래에서 시작한다), 맨 오른쪽은 tray 뒤의 설정 톱니다. 설정 `shell.taskbar`(기본 true, `packages/core/config/shell-settings.ts`)가 켜져 있으면 workspace 창이 `Taskbar`를 채우고, QuickPrefs로 읽는다. 바꾸는 곳은 Settings › Appearance의 Switch다. 꺼지면 chip은 tab 줄 끝에 아이콘만 서고, 빠른 실행과 톱니는 왼쪽 sidebar 맨 아래로 가며, `taskbar` slot은 비어 줄이 없다. 왼쪽 chip은 전역 float이 먼저이고 그 뒤가 지금 desk의 float이며(`FloatChips`) 4개를 넘으면 +N menu에 든다. chip을 누르면 그 float을 펴고 접는다. Settings와 detached 창, 앱 전용 창에는 작업 표시줄이 없다.
- **오른쪽 sidebar의 panel은 한 목록이고 앱 sidebar panel은 선언하면 나오고 사람이 끈다.** 내장과 앱 panel이 같은 `SidebarPanel` 모양이라 title bar의 icon 줄(`PanelTabs`)과 본문이 같은 목록 하나만 본다. `kinds`가 종류 거르기, `available`이 조건(Jobs 통로)이다. 고른 panel이 목록에 없으면(앱이 지워졌거나 다른 종류의 workspace로 옮김) 목록의 첫 panel이다. 앱 panel은 화면 선언에 `sidebar` 자리가 있고 설정 `shell.sidebar_panels_off`(`{app, screen}[]`, Settings › Quick launch의 Sidebar panels 줄이 끄고 켠다)에 들지 않았을 때 서며, workspace 종류를 가리지 않고 모든 sidebar에 나온다(화면이 `usePlace().workspace`를 보고 맞춘다). view는 `sidebar:<app>:<screen>` key의 `ViewKeeps`에 남아 panel을 바꿔도 page가 이어진다. 앱의 `useTabHead` 머리는 panel 머리 줄의 단추 자리(`PanelActions`)에 그린다. 오른쪽 sidebar의 열림은 workspace마다, 왼쪽의 열림과 두 쪽의 폭은 쪽마다 하나다. 앱 sidebar panel·tray·빠른 실행의 앱 목록은 창이 `useScreensRead`로 읽은 화면 목록(`apps/list`와 `apps/tools`)에서 나오고, 읽을 때 앱의 활성 판(`release`)도 싣는다. main은 live view를 판 없이 열지 않으므로(`checkOpen`, 아니면 `invalid_input`) sidebar·tray의 `EmbeddedView`는 이 판으로 연다. 목록은 core 연결이 ready가 될 때와 `AppViewChanged`(reason `activation`)가 올 때 다시 읽는다. 처음 한 번만 읽으면 core가 준비되기 전의 실패와 새 판이 창을 다시 열 때까지 남는다.
- **`transient` 탭은 저장하지 않는다.** popup처럼 잠깐 뜬 패널이다. `layoutToStored`가 `tabToStored`에서 transient를 거른다. Dock하면 사람이 고른 것이라 저장한다.
- **rect는 float 층(title bar 아래 창 몸통, 양쪽 sidebar 포함) 왼쪽 위 기준 정수 CSS px다(사람).** 패널이 card 칸에 갇히지 않고 sidebar 위로도 간다. 가장 작은 크기는 320×200이다. 그릴 때는 지금 float 층 안으로 당겨(`clampFloatRect`) 그리고 저장된 rect는 사람이 옮기거나 크기를 바꿀 때만 바뀐다. 창이 줄었다 커지면 원래 자리로 돌아온다. float 층을 아직 못 쟀거나 0이면 패널을 그리지 않고 rect를 저장하지 않는다. 기준을 stage에서 몸통으로 옮길 때 저장된 rect는 옮기지 않았다: 옛 rect는 왼쪽 sidebar 폭만큼 왼쪽에 그려진다(그 폭은 창마다 달라 옮길 값이 없다).
- **패널 DOM 순서는 탭 key 순으로 고정하고 위아래는 z-index로만 정한다.** raise할 때 요소를 재배열하면 안에 있던 focus와 scroll(terminal, editor)이 날아간다. 누르거나 focus가 들어오면 맨 위로 온다.
- **`<webview>`는 그릇 하나에 탭 key(앱 card는 그 화면의 view_session)당 한 번 만들고 옮기지 않는다.** 그릇은 `WorkspaceWindow`가 mount될 때 만들어지므로(`useTabHostSlices`) workspace를 옮기면 새 그릇이 되어 page를 다시 load한다. workspace를 넘어 page가 살아야 하는 것은 전역 float뿐이고 그 층이 자기 그릇을 따로 든다. 다른 부모로 옮기면 guest가 다시 만들어져 page가 다시 load된다. floats 층은 stacking context를 만들지 않고 패널 z-index가 --z-sticky + 층 번호 × 2라서, card 화면은 z-index 1, floated 화면은 자기 패널 위·다음 패널 아래(--z-sticky + 2L+1)에 놓인다. browser 탭의 층 번호는 펴진 float 중 몇 번째인지다(`host.desk.floats`에서 접힌 것을 빼고 센다). browser element는 `partition`·`allowpopups`를 직접 적고, 앱·artifact element는 `src`만 적는다(partition·preload는 main이 붙일 때 강제한다). main이 새 `src`를 내면 같은 자리에서 element를 새로 만든다. 자리는 사각형만 알린다(`renderer/app-frame/webview-host.tsx`).
- **focus는 group의 leaf 하나(`group.focus`)이고 `desk.selected`와 같다.** card의 칸을 누르거나 tab 줄의 반쪽을 누르면 옮긴다. kind의 `render`가 받는 `active`는 group이 아니거나 focus leaf일 때 true이고 floats 안의 탭은 늘 true다. terminal의 사람 입력은 DOM focus가 있는 곳에만 간다. resize는 보이는 terminal의 칸 크기를 따르고, 숨은 xterm의 질의 응답은 별도로 처리한다. 탭 단축키(Ctrl+W 등)는 focus leaf(= `selected`)에 듣는다.
- **native view는 overlay뿐이고, 그 위아래는 `viewOrder`가 정한다.** browser의 크기 준 popup·DevTools는 `main/browser/view-order.ts`가 card 화면 < floated 화면 순으로 쌓고, overlay native view는 `app-frame/view-order.ts`의 `viewOrder`가 늘 그 위에 둔다. native view는 shell DOM 위에 그려지지만 앱·artifact 화면은 DOM(`<webview>`)이라 그 문제가 없다.
- **DOM 패널은 `<webview>` 위에 z-index로 그린다.** floated 패널은 `<webview>` 그릇의 층보다 높고(--z-sticky + 2L), 오른쪽 sidebar는 card 옆 열이라 화면을 덮지 않는다. 화면을 줄이던 cover 장치는 없다.
- **앱 panel·앱 화면·artifact 탭의 `<webview>`는 탭이 사는 동안 산다.** Float, Dock, 접기, desk 바꾸기로 `EmbeddedView`가 다시 mount되어도 그릇이 element를 들고 있어 page를 다시 load하지 않는다. `ViewKeeps`(창마다 하나, renderer)는 view_session과 마지막 state를 이어 탭이 다시 mount될 때 같은 view를 쓴다. 탭 key가 모든 desk에서 사라지거나 detached가 되면 그릇이 element를 지운다(`WorkspaceWindow`). 앱 card는 그 화면이 unmount될 때 닫는다. 열기 입력이 바뀌면 옛 view를 닫고 새로 연다.
- **앱 panel 탭에는 평소 shell 크롬 줄이 없다(사람).** 탭 이름이 이미 앱 이름이고, 탭 줄과 앱 화면 사이에 다른 바탕의 줄이 끼면 탭과 본문이 한 면으로 이어지지 않는다. 화면이 멈추거나 crash했을 때, 앱이 멈췄을 때(`stopped`·`unavailable`)만 `ViewChrome`이 상태와 [Open again]을 띄운다(`app-panel-tab.tsx`). 앱 template의 `src/surface.css`는 앱 바탕을 탭 본문과 같은 `--color-surface-base`로 둔다. 강제하지 않는다.
- **앱 icon은 사람이 올린 것이 선언한 것보다 앞서고 layout에 싣지 않는다.** 선언의 `icon`(bundle 안 `/…/x.svg|png|webp` 경로, 64 KiB 이하)은 release 준비가 source commit에 그 파일이 있는지 보고, core의 `apps.icon` read(`{app}` → `{icon: {content_type, data(base64)} | null, uploaded}`)가 먼저 사람이 올린 icon(`app_icons` 표, 아래)을 보고 없으면 active release의 bundle 사본에서 읽는다. bundle 밖을 가리키는 경로·symlink, 큰 파일, 선언 없음은 모두 `null`이고 오류가 아니다. 사람은 App details의 Icon 절에서 올리고 지운다(`app.set_icon {app, icon: {content_type, data} | null}`, 지우면 선언한 icon, 그것도 없으면 첫 글자 `WorkspaceMark`로 돌아간다). renderer는 `app-frame/app-icon.tsx`의 `useAppIcon(app)`로 data URL을 받아 앱 패널 탭 아이콘(`iconOf`), Workspaces panel 앱 줄과 왼쪽 sidebar의 `WorkspaceMark`에 쓴다. 탭의 `toStored`에는 들어가지 않고 그릴 때마다 읽는다(10초 cache, 올리거나 지우면 cache를 버리고 떠 있는 표식이 다시 읽는다. `parts/icon-upload/icon-reader.ts`).
- **project icon은 사람이 올린 이미지만 있다.** project에는 선언이 없다. core `projects.icon`(`{project}` → `apps.icon`과 같은 출력)과 `projects.set_icon`(`{project, icon | null}`)이고, renderer는 `parts/project-icon/project-icon.tsx`의 `useProjectIcon(project)`·`ProjectWorkspaceMark`로 Workspaces panel project 줄과 왼쪽 sidebar에 쓰고, 올리는 칸은 `ProjectIconField({project, name})` 하나다. 올리는 줄(`parts/icon-upload`)은 앱과 project가 같이 쓴다.
- **올린 icon의 저장과 검사.** 올린 icon은 ledger 표(`app_icons`·`project_icons`, schema step `apps.registration.icons`·`projects.registry.icons`)에 base64 글 그대로 앱·project당 한 줄로 둔다(64 KiB 이하라 blob 저장소의 준비·중계를 거치지 않고, revision도 event도 올리지 않는다). 검사는 `protocol/base/icon.ts`의 `checkIconUpload` 하나다: svg·png·webp만, 64 KiB 이하, 선언한 type과 바이트 앞부분이 맞아야 하고 아니면 `invalid_input`, 없는 앱·project는 `not_found`다.
- **앱 전용 창은 shell 문서 하나다.** main이 선언의 `places`에 `tab`이 든 첫 screen을 골라(`createEntryScreen`) `openDesktopWindow`로 `#app-window=<app>/<release>/<screen>`(각 부분 `encodeURIComponent`) hash의 desktop 창을 연다. 앱 하나에 창 하나이고 다시 요청하면 그 창을 앞으로 가져온다. renderer의 `app-window` route(`renderer/app-frame/app-window.tsx`)가 앱 이름과 창 단추가 있는 위쪽 bar와 그 화면 하나를 창 본문 전체의 `<webview>`로 그린다(`mode: live`, `place="tab"`, workspace는 그 앱 workspace `{kind: "app", id, folders: []}`). `webviewTag`·shell preload는 다른 shell 창과 같고, 전역 palette·tray의 "가장 최근 창"에서 detached 창과 같이 빠진다(`ctx.appWindows`).
- **여는 길은 tab 메뉴(tab 줄 오른쪽 클릭과 card 머리 줄 ⋯가 `shell/tab-menu.tsx`의 같은 항목: Rename·Close·Close others·Close others in pane(칸이 여러 tab을 돌려 보면, 그 칸의 다른 tab만)·Close group(group 구성원이면, 칸에 숨은 tab까지 group 전부)·Close to the right·Close saved·Close all·Split right·Split down·Move out of pane(칸이 여러 tab을 돌려 보면)·Remove from split(group이 셋 이상)·Unsplit(leaf 둘이면)/Unsplit all·Float·Move to new window·Copy path·Copy relative path·Reveal in Explorer·Keep open), 패널 bar의 Minimize·Dock·Close, title bar 오른쪽 칸의 아이콘(누르면 펴고 접는다), tab 줄 끝의 새 탭 + menu, tab 줄 끌어 순서 바꾸기·group 만들기(pointer drag, 아래 "group과 이동 기록"), 단축키 `pane.split`(다음 plain tab과 오른쪽으로 split)·`pane.focus`(1~4, 고른 group의 leaf 순서)·`pane.focus-left/right/up/down`(Ctrl+Alt+화살표, mac Cmd+Alt+화살표, 고른 group 안에서 `group-geometry.ts`의 `neighborLeaf`가 고르는 맞닿은 칸으로. 가장자리에서는 멈춘다)·`tab.*`, 명령 palette(Float tab, Dock panel, Minimize panel), detached 창 bar의 [Dock]이다.** Detach는 palette 명령이 없다. palette의 Dock·Minimize 대상은 맨 위의 접히지 않은 패널이다. 접힌 패널은 먼저 펴야 Detach할 수 있다.

## desk

- **tab 메뉴의 여러 개 닫기(Close others·Close others in pane·Close group·Close to the right·Close saved·Close all)는 한 번만 묻는다.** `workspace-window.tsx`의 `closeMany`가 `closeTargets`로 닫을 tab을 고르고, 파일의 마지막 고침을 먼저 보낸 뒤(`EditorSessions.flush`) 살아 있는 터미널(`terminal/deps.ts`의 `terminalLive`)과 그래도 저장이 남은 파일이 있으면 `shell/tabs-close-dialog.tsx`의 `TabsCloseDialog` 하나에 줄로 보인다. 물을 것이 없으면 dialog 없이 닫는다. 확인하면 보인 파일의 남은 고침을 버리고(`EditorSessions.discard`) tab마다 `beforeClose`를 `confirmed`로 거쳐 터미널은 되묻지 않는다. 그 사이 새로 저장이 남은 파일만 그 tab에서 묻고, 거절하면 거기서 멈춘다.
- **desk의 x(사람이 만든 desk)는 그 일을 끝내는 것이다.** `DeskCloseDialog`가 몇 tab·터미널·float·창이 닫히는지와 저장이 남은 파일(이름과 경로)을 보이고, 확인하면 `workspace-window.tsx`의 `finishDesk`가 그 desk의 tab·float·detached를 보통 닫기 길(kind의 `beforeClose`)로 하나씩 닫은 뒤 `removeDesk`로 desk만 지운다(보던 desk면 Main으로 간다). 사람이 이미 확인했으므로 터미널은 되묻지 않고(`beforeClose`의 `confirmed`), 저장이 안 되는 파일처럼 잃을 것이 남는 질문은 묻는다. 하나라도 거절하면 거기서 멈추고 desk는 남는다. 탭을 Main으로 옮기지 않는다. workflow desk가 workflow가 끝나 사라질 때만 `mergeDeskIntoMain`이 tab(group은 그대로, Main과 key가 겹치는 leaf는 빠지고 1개가 되면 풀린다)·float·detached를 Main에 합친다.
- **사람이 만든 desk는 이름을 바꿀 수 있고(desk 단추 줄의 연필), 지울 수 있다(x).** Main은 이름도 지우기도 없다. 이름은 `renameDesk`로 label만 바꾸고 key는 그대로다. 새 desk(`addDesk`)는 빈 desk이고 label은 "Desk N"이다.

## group과 이동 기록

- **group은 tabs의 tab 2~4개를 한 칸으로 묶은 값이고 배치는 나눔 tree다.** `Group { layout, focus }`, `GroupNode = { tab, stack? } | { dir: "row" | "column", ratio, a, b }`(row는 a가 왼쪽, column은 a가 위, `ratio`는 a의 몫 0.15~0.85). leaf(칸)의 `tab`이 보이는 tab이고 leaf 수는 보이는 칸 수다. 불변 조건(함수와 저장 schema와 test가 같이 지킨다): leaf key는 모두 `desk.tabs`에 있고, tab은 group 하나에만 들며, group의 tab은 tabs에서 leaf 순서(왼쪽·위에서부터)로 붙어 있다(tab 줄은 group을 한 칸으로 보이고 칸의 key는 첫 leaf다). leaf가 1개가 되면 group은 풀리고 최대 4개다. `selected`가 구성원이면 그 group의 `focus`가 selected다. float(접힌 것 포함)과 detached는 group이 아니라 desk가 갖는다: group 구성원을 floats·detached로 보내거나 닫으면 먼저 group에서 빠지고, dock·reattach는 plain tab으로 tabs 끝에 붙는다. 모든 변경은 끝에 `settle`을 거쳐 위 조건을 맞춘다(없는 leaf 걷어내기, 1개 group 풀기, 붙여 두기).
- **함수.** `splitTab(desk, target, new, side)`는 new를 target 옆(left·right·top·bottom)에 놓는다(target이 group이면 그 leaf로 끼고 아니면 둘로 group을 만든다. new는 있던 group에서 빠진다. group이 이미 4개면 그대로다). `swapTabs`는 leaf끼리 또는 leaf와 plain tab의 자리를 맞바꾸고, `ungroupTab(desk, key, toIndex?)`는 leaf를 plain tab으로 꺼내 고르고, `ungroup`은 group을 푼다(tab은 그 자리에 남는다). `setRatio(desk, key, path, ratio)`의 path는 나눔 node까지 가는 `"a" | "b"` 열이다. `moveTab`·`reorderTab`은 group의 tab을 함께 옮기고 다른 group 한가운데로는 못 든다. `splitPartner`는 menu·`pane.split`이 key 옆에 붙일 tab(칸 뒤의 첫 plain tab, 없으면 앞의 마지막)이다. drag·drop은 이 함수들을 부르는 일이다.
- **card는 group을 평평한 absolute 칸들로 그린다**(`shell/content-card.tsx`, `group-geometry.ts`). 칸(머리 줄 + 본문)은 tab key로 key를 주고 DOM 순서도 key 순으로 고정해, leaf가 자리를 바꾸거나 구조가 달라져도 요소가 옮겨지거나 본문이 다시 mount되지 않는다. 자리는 tree에서 CSS `calc` 식으로 계산하고(나누는 선은 실제 폭 `--space-3`을 가진다) 선마다 끌어 몫을 바꾼다(놓을 때 한 번 저장, 더블클릭이면 0.5). 칸을 누르면 그 칸이 focus가 된다.
- **칸의 stack은 칸 하나가 돌려 보는 tab들이다.** `stack`은 온 순서이고 `tab`을 포함하며 둘 이상일 때만 있다. 나머지(숨은 tab)는 `desk.tabs`에 있어 저장·닫기 확인·창 사이 이동을 그대로 거치지만 tab 줄 칸(`deskEntries`)과 card에는 없다. group의 tab은 tabs에서 `membersOf` 순서(보이는 leaf를 leaf 순서로, 그 뒤 숨은 tab)로 붙어 있고 `groupOf`는 숨은 tab도 그 group으로 본다. 숨은 tab을 고르면(`selectTab`, 이미 열린 탭 다시 열기) 그 칸이 그 tab을 보인다. tab 줄의 group 칸은 그 반쪽 자리에 칸의 tab을 모두 차례로 그리고(숨은 tab은 옅고, 누르면 그 tab이 보인다) 고른 group이면 이름까지, 고르지 않은 group이면 숨은 tab은 아이콘만 그린다(줄이 넘칠 때 접히는 규칙은 아래 반쪽과 같다). 칸 머리의 ‹ n/m ›는 `cyclePane`으로 돌려 본다(끝에서 처음으로). 보이는 tab이 칸을 떠나면(닫기, float, detach, 끌어 옮기기, Remove from split, ⋯의 Move out of pane = `ungroupTab`) stack의 이웃(뒤, 없으면 앞)이 보이고 칸은 남는다. Unsplit(`ungroup`)은 숨은 tab까지 모두 tab 줄에 내놓는다. 지금 stack을 만드는 길은 터미널 옆에 열기(`openBeside`)뿐이다.
- **tab 줄의 group 칸은 반쪽 N개와 이웃 반쪽 사이의 방향 표시다.** tab은 이름 폭만큼이고(고르지 않은 tab의 긴 이름은 잘린다) 고른 tab은 이름이 다 보인다. 줄이 넘치지 않으면 group의 반쪽도 모두 이름이 보인다. 넘치면 먼저 고르지 않은 group 칸이 아이콘만 남고(이름은 tooltip), 그래도 넘치면 고른 group 칸의 focus 아닌 반쪽도 아이콘만 남고, 그래도 넘치면 고르지 않은 tab이 좁아지다 최소 폭에서 가로 scroll이 된다. `tab-strip.tsx`가 그릴 때와 줄 폭이 바뀔 때 tab이 좁아지기 전 폭으로 재서 고른다. 반쪽의 닫기·menu는 그 반쪽 tab에 한다. 닫기 자리는 tab(group이면 반쪽)마다 이름 뒤에 하나다: 저장 안 된 ●나 상태 점이 있으면 평소 그것을 보이고 그 tab에 hover하거나 단추에 focus가 오면 ×가 된다. 둘 다 없으면 고른 tab(group이면 focus 반쪽)과 hover한 tab에만 ×가 보인다. 고르지 않은 group에는 ×가 없다(숨은 닫기 자리가 이름 사이에 빈 칸을 만들어서다). 그 group의 반쪽은 ●나 상태 점만 보이고 누르면 그 tab을 고른다. 닫기는 가운데 클릭, tab 메뉴, group을 고른 뒤의 ×다. 칸에 숨은 tab도 ×가 없고 누르면 그 tab이 보이며 그때 ×가 생긴다. 같은 칸의 tab 사이에는 세로 선이 있다.
- **drag and drop은 pointer drag이고(HTML5 drag 아님) `shell/tab-drag.tsx`의 `TabDragProvider`가 맡는다.** tab 줄의 칸(group 칸이면 누른 tab 하나(leaf나 칸에 숨은 tab, origin `leaf`)이고 칸의 빈 곳(방향 표시, 가장자리)을 누르면 통째로, `whole`)과 group 칸의 머리 줄(leaf 하나)이 `useTabDrag().start`로 시작하고, 4px 넘게 움직여야 drag다(그 전은 click, 놓은 뒤의 click은 삼킨다). 놓을 자리는 요소 위의 event가 아니라 사각형으로 찾는다: title bar의 tab 구역이면 `strip`(어느 칸 앞인지)이되 group 칸의 안쪽(양 끝 12px 밖)이면 `stack`(가장 가까운 tab의 앞이나 뒤, 그 tab이 든 칸 stack의 자리. group 통째로 끌 때는 없다), 칸(`[data-pane]`)이면 `pane`(가장자리 안쪽 28%는 left·right·top·bottom, 나머지는 center). 떠 있는 패널 위는 놓을 곳이 아니다. 무엇이 되는지는 provider 밖의 순수 함수가 정한다: `tabDropState(desk, item, hit)`는 ok·full(group이 가득 찬 곳의 가장자리, 같은 group 안의 옮김은 빼고)·none(자기 자신, group 칸 통째로 칸에 놓기, 옮기면 group이 풀리는 가운데 놓기)이고 `applyTabDrop`은 줄이면 `reorderTab`(group의 tab 하나는 `ungroupTab(desk, key, toIndex)`로 group에서 나온다), group 칸 안이면 `stackTab(desk, target, key, index)`(그 칸 stack의 그 자리에 들어가 보인다), 가장자리면 `splitTab`, group 칸의 가운데면 `stackTab`(그 칸 stack 끝에 쌓여 보인다), group이 아닌 칸의 가운데면 `swapTabs`(그 tab이 보인다)다. 모양은 portal(webview 그릇보다 위)의 알약(`--floating-surface`, 커서를 따라간다)과 칸 위 미리보기(`--color-focus` 반투명, full이면 점선), 그리고 줄이 `drag` 값으로 그리는 자리 비우기(끈 칸은 놓일 자리로 가서 옅은 자리 표시, 사이 칸은 비켜 선다)다. 끄는 동안 `<html data-tab-dragging>`이 켜져 `<webview>`가 pointer를 받지 않는다(받으면 guest로 새서 놓을 자리가 안 보인다). Esc·pointercancel은 취소다. Explorer 파일을 card에 놓는 것은 HTML5 drag(`onDropPath`)라 그대로다. 접힌 칸 아이콘과 float 층은 drag 대상이 아니다.
- **이동 기록은 창 하나의 메모리에만 있다.** `{ desk, key(고른 칸), focus(그 칸의 focus tab) }` 최대 50개이고(`workspace-window.tsx`의 `trail`) 저장하지 않는다. desk·고른 칸·group 안의 focus가 바뀔 때 쌓고, 뒤로 간 뒤 새로 쌓으면 앞은 잘린다. 닫은 tab·지운 desk의 자리는 건너뛴다. ← →로 걸을 때는 걷는 자리가 이미 기록의 현재 자리라 더 쌓지 않는다. layout을 다 읽은 뒤부터 쌓는다.

## agent가 연 탭

- **agent와 사람 token은 `lophn tab open`으로 탭을 열고 `lophn tab close`로 자기가 연 탭만 닫는다.** 대상은 같은 workspace의 열린 agent session(대화 탭), http·https url(browser 탭), runtime이 harness인 session의 TUI(터미널 탭, `--tui`, `coding-agent.md` "harness agent"), 앱의 지금 preview(preview 탭, `--preview <app>`)다. 명령은 `packages/cli/commands/{tab,browser}.ts`, route는 memory route `tabs/open`·`tabs/close`(actor agent·user)와 `browser/read`(actor agent)(`packages/protocol/lophn-agent/host-queue.ts`)이고 caller session은 자격에서 읽는다. 탭의 주인은 연 session이고, 사람 token(터미널의 coding agent와 사람)은 모두 같은 주인 `"person"`이다. 사람 token은 `--url`과 `--preview`만 연다(`--session`·`--tui`는 `invalid_input`). 사람 token의 `--url` 탭은 입력 `workspace`(`--workspace '{"project":…}'`)의 workspace에, 없으면 env `LOPHN_WORKSPACE`(shell이 project 터미널의 PTY에 넣는다)의 workspace에, 그것도 없으면 home에 열린다. 열기는 요청을 넣고 바로 `accepted`를 답한다. agent는 기다리지 않는다. 남이 연 탭을 닫으면 `forbidden`, 없는 탭은 `not_found`다.
- **preview 탭은 그 앱 workspace의 session과 사람 token만 연다.** 다른 workspace의 session이면 `not_found`(남의 앱을 알리지 않는다), 그 앱에 돌고 있는 preview가 없으면 `conflict`다. 요청의 workspace는 그 앱이다. 앱마다 preview 탭은 하나라 표에 이미 있으면 새로 넣지 않고 그 탭 id를 돌려주며 주인을 나중 caller로 바꾼다. `lophn preview start`는 preview가 ready가 되면 같은 자격으로 `tabs/open {preview}`를 불러 탭을 연다(새 통로 없음. 열기가 실패해도 preview는 떠 있고 결과의 note에 적는다). 탭 kind `app_preview`는 layout에 저장하지 않는다. 앱 view를 `mode: "preview"`로 열고 안내 줄(preview, fixture data, 바깥 연결은 대역, 기기 고르기)과 [Stop](`previews.stop`)을 두며, target의 `device`가 있으면 그 기기로 연다(`browser-tab.md` "기기 emulation"), preview가 멈추면 "돌고 있는 preview 없음"을 보이고 다시 start되면 같은 탭이 새 preview를 연다. 앱 화면 탭 toolbar의 [Preview](돌고 있는 preview가 있을 때만)는 사람이 key `app-preview:<app>`의 탭을 연다. 이 탭은 host 표에 없다. 같은 앱의 host preview 탭이 오면 renderer가 그 탭을 닫고 그 자리에 `host:<tab>` 탭을 연다.
- **core는 layout을 모르므로 요청을 core 메모리의 host queue에 둔다.** `packages/core/host-queue/`가 queue와 agent가 연 탭의 표(`tab → 주인(session 또는 "person"), workspace, 종류(agent·browser·preview), preview의 앱, browser 상태`)를 갖고, `packages/core/main/daemon/wiring/host-queue.ts`가 route를 붙이고 port `hostQueue`(`enqueue`, `openTab`, `attached`)를 내놓는다. 꺼지면 queue와 표가 사라진다. shell main(`packages/shell/main/desktop/wiring/surface.ts`)이 core에 붙어 있는 동안 사람 token으로 `host/take {workspaces, tui}`를 쉬지 않고 이어 부른다(long-poll). take는 닿는 요청이 있으면 바로, 없으면 요청이 들어오기를 `HOST_TAKE_WAIT_MS`(5초)까지 기다리다 null을 답한다. 5초인 것은 매 take가 TUI hold의 heartbeat이고 hold 갱신이 10초라서다. 기다리는 동안 보이는 workspace가 바뀌면 그 workspace의 요청은 그 take가 끝난 뒤(5초 안) 간다. take가 실패하거나 창이 탭 요청을 받지 못하면 1초 쉰다. core가 멈출 때 기다리는 take는 null로 끝난다. `workspaces`는 창마다 renderer가 layout을 다 읽은 뒤 `shell:surface-workspace`로 알려 온 것이다(detached 창은 빠진다). 그 workspace를 보이는 창 가운데 가장 최근에 focus를 받은 하나에만 `shell:surface-request`를 보내고, 1.5초 안에 ack(`shell:surface-ack`)가 오면 `host/done {done}`, 아니면 `retry`로 queue 끝에 되돌린다. 빌려 간 요청에 10초 동안 done이 없으면 다시 대기한다. shell이 없거나 그 workspace를 보이는 창이 없으면 요청은 기다린다(200개를 넘으면 오래된 것부터 버린다). `attached`는 기다리는 take가 있거나 마지막 take가 끝난 지 3초 안이면 참이다.
- **browser 호출(`browser_call`)은 extension tool 호출(`tool_call`)과 같은 결과 길을 쓴다.** `lophn browser snapshot|act|navigate|screenshot|evaluate|logs|wait`(memory route `browser/*`, actor agent·user)가 주인을 확인한 뒤(남의 탭, 사람이 손으로 연 탭, session·TUI 탭은 `not_found`) `HostQueue.callBrowser({tab, view: browser|preview, action})`로 요청을 넣는다. 요청에는 workspace가 없어 아무 shell main이 가져가고, shell main이 `browser/agent/driver.ts`로 실행해 `host/done {output}`(`hostToolOutputSchema`)에 결과를 싣는다. 기한은 `BROWSER_CALL_MS`(30초)이고 core가 1초마다 보아 넘으면 `unavailable`로 끝내고 요청을 거둔다(늦은 done은 버린다). 기다리는 동안 shell이 떨어져도 `unavailable`이다. 행동의 꼴과 오류 code는 `browser-tab.md` "agent가 다루는 browser 탭"이다.
- **열린 탭의 key는 `host:<tab id>`이고 자리는 hint와 source가 정한다.** renderer `workspace/use-surface-requests.ts`가 요청을 받는다. source는 그 창에서 연 agent의 session을 보이는 agent 탭이다. hint는 `openAt(desk, source, "show", place)`(`workspace/open-policy.ts`)가 푼다: `beside`는 source와 나눔(source가 group이면 다음 칸의 stack에 숨겨 놓는다), `group`은 source의 group에 칸을 더하고 4칸이 차면 group 뒤 탭, `float`는 float, 없으면 source 뒤 탭이다. source가 없으면 desk 끝이고, source가 보이지 않는 desk에 있으면 desk를 바꾸지 않고 그 desk에 둔다. 모두 `select: false`이고 창을 앞으로 가져오거나 focus하지 않는다(toast의 `reveal()`과 다르다). 그 session의 탭이 이미 창에 있으면 새로 열지 않고 ack한다.
- **사람이 host 탭을 닫거나 layout에서 사라지면 renderer가 `shell:surface-report`로 `closed`를 알리고, main이 `host/report`로 core 표에서 뺀다.** agent가 연 browser 탭의 상태는 `browser-tab.md`의 "agent가 연 browser 탭"이다.

## workspace layout (판 10)

workspace 창이 읽고 쓰는 저장과 model이다. 옛 project layout 파일(`layouts/<prj_id>.json`, 판 5~7)은 읽지도 올리지도 않는다.

- **파일은 workspace마다 하나다.** `<data>/shell/workspaces/<workspace>.json`이고 workspace는 `home`, project id, app id다(`main/workspace/workspace-layout*.ts`). 파일 이름이 되는 key는 `[A-Za-z0-9_-]{1,64}`만 받아 폴더 밖으로 나갈 수 없다(`invalid_input`). 원자 교체와 mode는 `atomic-file.ts`가 정한다.
- **모양은 `{ schema_version: 10, active_desk, desks: { <key> → { label, workflow?, tabs, selected_tab, groups: [{ layout, focus }], floats: [{tab, rect, minimized}], detached: [{tab, bounds}] } }, quick?: { order, apps: [{ app, surface }], hidden? }, commands?: [{ id, label, command }] }`다.** `quick`은 project만의 빠른 실행 순서(단추 id), 고정한 앱 panel 화면, 끈 단추 id이고, 없으면 전역 값(`shell.quick_launch`)을 쓴다. `commands`(최대 20개)는 project만의 터미널 명령이라 전역 값과 `quick`의 전역 값 따르기와 상관없이 남고, 전역 값은 없다. 없어진 앱과 모르는 id는 그릴 때 건너뛴다. 터미널 탭은 coding agent가 돈 적이 있으면 `harness`를 지녀, 다른 workspace의 창이 저장된 layout만 보고 coding agent 터미널을 알아본다. 그런 탭은 agent가 정한 지금 이름(사람 이름이 없고 자동 이름과 다를 때)을 `agent_title`로 남겨, store가 아직 이름을 모를 때 다른 workspace의 sidebar가 쓴다. 복원은 `agent_title`을 쓰지 않는다. `layout`은 `{ tab: <key>, stack?: [<key>…] }`(leaf, stack은 판 8에서 더한 선택 필드라 옛 파일도 그대로 읽힌다)나 `{ dir, ratio, a, b }`이고 `focus`는 leaf의 key다. desk는 1~200개이고 `_default`(Main)가 늘 있다. 한 desk 안에서 tab key는 tabs·floats·detached를 통틀어 한 번만 나오고, `selected_tab`과 group의 leaf는 tabs 안에 있다. group은 leaf가 2~4개이고, tab은 group 하나에만 들며, leaf는 tabs에서 leaf 순서로 붙어 있고 숨은 tab이 그 바로 뒤에 붙으며, `selected_tab`은 숨은 tab이 아니고, `ratio`는 0.15~0.85, `focus`는 leaf다. schema가 이를 거절한다. renderer의 순수 model은 `renderer/shell/desk-model.ts`가 같은 불변 조건을 지키고, 저장된 값과의 변환은 `renderer/shell/layout-source.ts`가 kind registry로 한다(저장할 수 없는 tab이 빠지면 그 leaf를 걷어내고 1개가 된 group은 푼다).
- **읽는 순서.** workspace 파일이 있으면 판 10만 읽는다(다른 판은 `unsupported_schema`이고 파일은 그대로다). 판 10은 place를 workspace로 부르며 agent 탭의 `work_place`를 `workspace`로 바꾼 판이다. 옛 자리 `<data>/shell/places/`의 판 9 파일은 core의 data step `shell.workspace-layouts`가 `shell/workspaces/`로 옮겨 판 10으로 쓴다(옮길 자리에 파일이 있으면 덮지 않는다). 그 앞의 판 8 파일은 data step `artifacts.container`가 `shell/places/`에서 먼저 판 9로 올린다(domain을 모르는 artifact 탭은 그 탭만 뺀다). 없으면 `absent`이고 renderer가 Main 하나인 기본 layout을 쓴다. 옛 `layouts/<prj_id>.json`은 보지 않으므로 처음 여는 workspace는 모두 기본 layout이다.
- **IPC.** `shell:workspace-layout-read`(`{ workspace }`)와 `shell:workspace-layout-save`(`{ workspace, layout: { active_desk, desks } }`)다. desktop 창 본문만 부르고, 저장할 때 main이 살아 있는 detached 창의 bounds로 덮는 것은 옛 저장과 같다. preload는 `lophnLayout.readWorkspace/saveWorkspace`다.
- **renderer의 길.** workspace를 바꾸면 `WorkspaceWindow`가 새로 mount되고 저장된 배치만 읽은 뒤 desk를 그린다(project·파일 목록은 기다리지 않는다). 읽기 전에는 card가 빈 desk 안내 대신 빈 card다(`ContentCard`의 `pending`). 왼쪽 sidebar가 읽는 목록(workspace, agent, session 제목, 다른 workspace의 탭, 저장한 터미널 session, 사람 차례 workflow)은 창마다 하나인 `SidebarMemory`(`shell/sidebar-memory.tsx`, Desktop이 context로 내린다)의 마지막 값에서 시작해, 다시 mount돼도 빈 목록부터 그리지 않는다. `WorkspaceWindow`는 `source.layout`(`WorkspaceSource.layout: LayoutSource`, `createLayoutSource()`가 preload의 `lophnLayout`을 감싼다)으로 자기 workspace(`workspaceKey`)의 layout을 읽고(null이면 `defaultWorkspaceLayout()`, 앱은 앱 화면 탭 하나가 선 `freshLayout`) 바뀔 때마다 저장한다. 읽던 위치·입력처럼 잦은 바뀜은 200ms 모아 쓴다. 옛 `layout:read`·`layout:save` IPC와 `lophnLayout.read/save`는 없다.

## 왜 이 모양인가

- **agent가 연 탭은 core 메모리의 host queue를 shell main이 가져가는 꼴이다(계획 agent-surface, 2026-11-08).** core → shell 요청 통로가 없었다. harness queue는 session마다 turn 입력을 담는 run-loop queue라 요청 종류를 실을 자리가 없어 같은 꼴(core 메모리, shell main이 가져감)로 새로 두었다. 창 IPC 직통이나 새 socket push 같은 통로를 더 만들지 않는다. shell main의 poll loop는 extension `harness`의 tick과 합치지 않았다. 그 tick은 extension 안에서 설정 `extensions.harness.enabled`가 꺼지면 돌지 않고, extension은 shell main 내부를 import하지 못한다(check-deps rule `extension`). focus를 뺏지 않는 것은 agent의 일이 사람이 하던 일을 끊지 않게 하려는 것이다.

- **layout 파일은 workspace마다 하나다.** 하나를 앱 전체가 쓰면 다른 project를 열어 저장할 때 앞 project의 layout을 덮어써 workflow desk를 모두 잃는다. 이름은 `project.update`로 바뀌므로 id다.
- **desk key는 workflow desk면 그 project 안의 workflow 이름이고 기본 desk는 `_default`다.** 사람이 만든 desk는 `desk-<시각>-<번호>`이고 label은 "Desk N"이다. project 이름을 넣지 않아 project 이름을 바꿔도 desk가 남는다. `_`로 시작하는 값은 slug가 아니라 workflow 이름과 겹치지 않는다. renderer `shell/desk-model.ts`와 main `workspace-layout.ts`가 같은 값을 따로 적는다. workflow 폴더 이름을 바꾸면 옛 desk는 Main으로 합쳐진다(바뀌지 않는 workflow id가 없다).
- **desk를 건너 탭 key가 겹치는지는 schema가 거절하지 않는다.** 거절하면 읽기가 손상이 되어 layout 전체를 잃는다. 겹침은 model과 그 위험 test가 막는다.
- **desk를 바꿀 때 detached 창은 "보일 key 목록" 한 번으로 맞춘다.** 창마다 부르면 중간에 일부만 바뀐 채 남을 수 있다. 창이 없는 key를 main이 열지 않는 까닭은 열기에 필요한 탭 값과 bounds를 renderer가 갖고 있고, 이미 있는 창에 `open`을 부르면 앞으로 가져와 focus를 뺏어서다. 보이기는 focus 없이(`showInactive`) 한다.
- **workspace 이동은 왼쪽 sidebar의 Workspaces 줄이 맡는다.** 별도 workspace switcher나 launcher 화면이 없다. 창 하나가 한 번에 workspace 하나를 보이고 옮기면 `WorkspaceWindow`를 새로 mount한다. 앱 줄을 누르면 그 앱의 앱 화면 탭으로 간다: 지금 앱이면 앱 화면 탭을 열거나 고르고(`openAppScreen`), 다른 앱이면 route의 `startAppScreen`으로 그 앱 workspace로 가서 연다. 앱 화면 탭을 닫아도 앱 줄로 다시 연다. Home 줄, Settings 단추, 빠른 실행도 왼쪽 sidebar에 있고 파일 경로는 card 머리 줄의 crumb이다. 파일 탭의 crumb 조각은 단추이고, 누르면 Popover에 Explorer와 같은 tree(`workspace/sidebar/crumb-browse.tsx`)가 뜬다(VS Code breadcrumb처럼 폴더 조각은 그 위 폴더의 목록에서 그 폴더를 펼치고, 연결 폴더 조각은 그 폴더, 파일 조각은 파일이 든 폴더). 거기서 파일을 연다. 팔레트(Ctrl+K)와 home chord(Ctrl+Shift+L)도 workspace를 옮긴다.
- **floats 개수(20)는 schema만 막는다.** 사람이 20개를 띄울 일이 없다.
- **새 패널은 float 층 가운데 60% 크기로 겹쳐 뜬다.** 비껴 놓기(cascade)는 하지 않는다.
- **겹치는 패널은 `<webview>` 위에 그린다.** native view 때는 화면이 DOM 위에 그려져 겹치는 동안 view를 cover로 줄여야 했다. 앱·artifact 화면은 DOM(`<webview>`)이라 패널이 그 위에 바로 겹친다. 버린 안: 겹치는 동안 마지막 `capturePage` 그림을 보이기(page가 멈춘다), DOM 패널도 native view로 띄우기(패널마다 shell renderer 하나라 가장 크다). 잃는 것은 없다. 밑의 page가 패널에 가려진 채 계속 돈다.
- **view 보관소는 renderer에 둔다.** `<webview>` element는 창의 그릇이 들고 view_session·state는 `ViewKeeps`가 든다. main registry가 이미 view와 붙은 guest를 구분하므로 새 IPC가 필요 없다. 탭을 닫는 길이 여럿이라 길마다 닫지 않고 layout에 없으면 닫는다.
- **전역 float 층은 `WorkspaceWindow` 밖 `Desktop`에 둔다.** `<webview>` 그릇이 `WorkspaceWindow`마다 새로 생겨서(workspace를 바꾸면 창 본문이 다시 mount된다) 그 안에 두면 workspace를 옮길 때 page가 다시 load된다. 층을 `{space}` 옆에 두고 그릇과 view 보관소를 층이 들면 workspace를 넘어 page가 산다. 저장을 workspace layout 파일 밖에 둔 까닭은 한 float이 어느 workspace에도 속하지 않아서다(layout 파일은 workspace마다 하나라 거기 두면 workspace 수만큼 복사본이 생긴다).
- **전역 float은 앱 panel 화면만 된다.** 파일, 터미널, session 탭은 project나 workspace의 것이라 다른 workspace에서 열면 뜻이 없다. 앱 화면은 workspace를 인자로 받으므로(`usePlace().workspace`) 어느 workspace에서도 그릴 수 있고, 전역 float은 workspace를 주지 않아 "어느 workspace에도 묶이지 않는 화면"으로 연다.
- **작업 표시줄은 몸통 밖 줄이다.** 몸통 안에 두면 floats 층(title bar 아래 몸통 전체)이 덮고 stage 아래 여백과 겹친다. `.shell`의 마지막 줄로 두면 float이 닿지 않고 chip을 늘 누를 수 있다. 접힌 float과 전역 float을 한 곳에서 보이려는 줄이라 이름이 보이고, 줄이 필요 없는 사람은 끌 수 있다(끄면 chip은 옛 자리인 tab 줄 끝이다).
- **오른쪽 sidebar의 열림을 workspace마다 기억한다(사람).** 오른쪽은 workspace마다 쓰임이 달라(project Files, Home Workspaces, 앱 Logs) 한 workspace에서 접은 것이 다른 workspace의 모양을 정하면 어색하다. 왼쪽은 어느 workspace에서나 같은 목록이라 하나로 둔다. 폭은 사람이 끌어 맞춘 값이라 쪽마다 하나다.
- **옛 layout 파일(판 1~7)은 읽지 않는다.** 새로 시작한다(AGENTS.md "호환성", 사람이 결정).
- **detached 창은 탭 하나만 갖는다.** 탭 줄이 있는 detached 창은 workspace를 하나 더 만드는 일이다. 탭 여럿을 보려면 창을 여럿 띄운다. dock은 그 desk의 tabs 끝에 붙이고 떼기 전 자리는 저장하지 않는다(floated였어도 docked로 온다).
- **값은 창이 뜬 뒤 `take()`로 당겨 받는다.** hash `#detached=<key>`는 route 선택용이다. 탭 key가 4096자까지이고 transfer가 커질 수 있다.
- **두 방향(project 창, detached 창)을 IPC 하나(`ipc/detached.ts`, `window.lophnDetached`)로 묶는다.** 같은 renderer bundle과 preload를 쓰는 창이고 main이 보낸 창으로 역할을 가른다. 통로를 둘로 가르면 preload·노출·type이 두 벌이 된다.
- **browser 탭·앱 화면·artifact 화면은 Detach하면 다시 load된다(사람).** `<webview>`는 그것을 띄운 shell 문서에 묶여 다른 부모로 옮기면 guest가 다시 만들어진다. 쓰던 form, scroll, 그 page가 연 popup의 `window.opener`를 잃는다. 다시 load 없이 옮길 수 있는 곳은 native view뿐이고 그것이 `window.opener`가 걸린 browser popup과 DevTools다.
- **detached 창 안의 popup은 또 하나의 detached 창이다.** 가장 단순하게 `window.opener`를 지킨다. 대안인 project 창 floats 층으로 옮기기는 opener 소유 이동이 더 필요하다. `open`의 bounds에 opener 창 가운데 features의 크기를 넣고, 화면 작업 영역 안으로 당긴다. detached 창만 최소 크기가 320×240이다(다른 창과 bounds가 없는 detached 창은 960×600).
- **group은 칸 tree가 아니라 tabs 위의 값 하나다(사람).** 옛 칸 tree는 칸마다 탭 줄·focus·drop zone을 따로 갖게 해 탭이 어느 칸에 있는지가 복잡했다. 탭 줄은 하나로 두고 같이 보고 싶은 tab 2~4개만 한 칸(group)으로 묶으면 탭 줄·선택·저장이 모두 한 줄로 끝난다. 처음에는 붙은 두 tab뿐이었으나 자유 배치(위 둘 아래 하나, 2×2 등)를 위해 나눔 tree를 가진 group으로 넓혔고(최대 4칸), 칸마다 탭 줄이 있는 옛 방식으로는 돌아가지 않는다.
- **칸은 구조와 상관없이 평평한 absolute 상자다.** tree를 중첩 flex로 그리면 나눔이 늘거나 줄 때 leaf의 부모가 바뀌어 본문이 다시 mount된다(terminal·editor 상태, webview slot). 자리를 tree에서 계산해 평평하게 놓으면 구조가 바뀌어도 leaf의 React 부모가 같다.
- **activity bar는 없고, 앱 panel 고정은 빠른 실행 단추다.** 앱 panel은 + menu, 빠른 실행의 App(누르면 고르는 탭, hover 목록은 바로 열기), 고정한 빠른 실행 단추(Settings › Quick launch나 Project settings의 App panels), 앱 workspace의 열기로 연다. 옛 `rail_apps`는 읽지 않는다. 앱 workspace의 localStorage `lophn.app-layout.<app>`도 읽지 않는다(배치 기본값으로 돌아갈 뿐 data가 아니다).
- **옛 project layout(`~/.lophn/shell/layouts/`, 판 5~7)은 읽지 않는다.** 사람이 결정했다: 지웠고 layout은 새로 시작해도 되는 화면 상태다. 첫 열기는 기본 layout이다.
- **앱 화면도 `<webview>`로 옮겼다(사람, 2026-10-31).** native view는 shell HTML 위에 그려져 menu·popover·floated 패널·toast가 앱 page 밑에 깔렸고, 피하려고 층·cover·bounds relay가 쌓였다. browser 탭이 같은 이유로 이미 `<webview>`를 쓰고 그 뒤로 겹침 문제가 없다. iframe은 preload의 isolated world, 앱별 partition, sender 신원을 잃고, remote UI는 앱이 자기 DOM·CSS component를 못 쓰게 해서 버렸다. Electron은 `<webview>`를 권하지 않지만 browser 탭이 이미 그 위험을 지고 있어 새 위험이 아니다.
- **artifact 탭도 같이 옮겼다(agent).** 같은 겹침 문제를 갖고 있었다. 남겨 두면 앱 쪽 장치를 지우지 못한다.
- **붙이기 ticket은 `src` 하나이고 한 번만 쓴다(agent).** registry의 `acceptGuest(window, src)`가 그 창의 view이고 그 src를 아직 안 쓴 때만 받는다. renderer가 적은 partition·preload·webPreferences는 버리고 main이 정한 값만 쓴다. renderer가 붙이기 값을 위조해도 다른 session이나 preload로 갈 수 없다.
- **앱 저장소 partition 이름은 그대로다(agent).** `persist:app-<app>:live`·`persist:app-<app>:preview-<bundle hash>`를 바꾸지 않아 사람의 `~/.lophn` cookie·localStorage·IndexedDB가 이어지고 migration이 없다.
- **`<webview>`는 layout에 있는 동안 숨기기만 한다.** desk를 떠났다 돌아오면 쓰던 form·scroll을 잃던 결함(`issues/workspace-layout.md`)이 있었다. 탭 key가 어느 desk에든 있는 동안 element를 들고 있으면 desk 전환에 드는 것이 없고, detached 탭만 그 창에 넘긴다(page가 두 창에 살지 않게).
