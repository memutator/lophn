## 10. core 재시작: 진행 중인 일이 어떻게 닫히나

문서(architecture/place-session.md:41, event.md:52, approval.md:43-46, agent-call.md:46-47, app-call.md:43, activation.md 지키는 것)와 코드:
- 돌던 turn → interrupted: core 시작 때 machine command `RecoverCalls`(`calls/recover`, router/commands.ts:21-32, 133-146)가 `failLostOnStart`(받았지만 turn이 안 가져간 열린 call을 `failed(lophn_restarted)`로 닫고 보낸 session에 알림)와 `interruptRunningTurns`(main/daemon/wiring/router-registration.ts:184, `lophn-agent/run-loop/interrupt.ts`: `state='running'` turn 전부를 `{kind:"interrupted", reason:"restarted"}`로 `finishRow`, `publishTurnEnded`)를 같은 tx에서 한다. wiring 호출은 `main/daemon/wiring/router.ts:57,323`.
- turn 안 permission request: 메모리(`approvals/turn-requests.ts`)라 재시작에 사라진다(주석 "꺼졌다 켜지면 비어 있고 다시 열지 않는다"). `TurnDecision`의 `cancelled.cause`는 `turn_ended | session_closed | restart`. "이 session 동안" 허락(`SessionAllowances`)도 메모리. `ask` 질문도 메모리(`QuestionResolved`).
- 보류 request(표 `approval_requests`)는 남고 허락됐는데 적용 결과가 없는 것은 시작 때 다시 적용(`approvals/applier.ts:66,73`, `approvals/unapplied`, `main/daemon/wiring/approvals.ts:325 afterReady`).
- 앱 호출: 안 끝난 invocation은 `closeUnfinishedInvocations`(core/apps/invocations/restart.ts:80)가 `status:"unknown", reason:"core_restarted"`로 닫는다(`restartOwners: [observeInvocations, observeReleaseActivations]`, wiring/apps.ts:103, core.ts:160 `checkRestart`). 앱 rewind의 applying은 `cancelled`/`reason_code='core_restarted'`(apps/rewind/store.ts:158).
- activation: 끊긴 시도는 ledger 기록대로 잇는다(`observeReleaseActivations`; 채택됐으면 그 release를 다시 띄우고 진행 중이면 알려진 복구본으로만 복원). 앱 process는 core가 새로 띄운다.
- coding: `coding_lines`(앱별 줄)는 `recoverCoding`이 비운다. 상태는 hook 신호를 받기 전까지 unknown(event.md:52). coding session token은 registry 메모리에만 있어 재시작에 사라진다(coding-token.ts 주석).
- session 자체는 열린 채로 남는다. 입력함은 메모리. 한 turn이 interrupted된 뒤 새 `messages/send`는 새 turn이 된다.
- agent runtime child와 app supervisor는 core가 새로 띄운다(`policy:"always"`, 512MiB).

## 11. secret

- 자리: `<data root>/secrets.json`(`SECRET_FILE_NAME`, protocol/secrets/secret-file.ts:11). 평평한 JSON 객체 `이름 → 문자열`. 권한 0600: 쓸 때 같은 폴더의 `secrets.json.tmp`에 0600으로 만들어 fsync하고 rename(실패하면 이전 파일 그대로), 시작 때 mode가 0600보다 넓으면 0600으로 고치고(못 고치면 파일을 읽지 않고 unavailable) (`core/secrets/file-store.ts`). 파일이 없으면 빈 저장소. 읽거나 쓸 수 없으면 secret 기능만 고정 문장 이유와 함께 unavailable이고 환경 변수·다른 파일 fallback은 없다. `<root>`는 0700.
- route(`secretStatus` memory, `secretPut` upload, `secretDelete` memory): user만 값을 만진다. `secrets/status`는 user가 아닌 actor가 이름을 지정하면 `forbidden`, 안 주면 빈 목록. 값은 UTF-8이어야 하고 최대 `SECRET_INPUT_MAX_BYTES` 64KiB, 선언 길이와 body가 다르면 `invalid_input`(secret-routes `secretPutHandler`, core/secrets/routes.ts). 처리 뒤 byte를 0으로 덮는다.
- 알려진 값 registry와 redaction: `openSecretStore`(core/secrets/secret-store.ts)가 시작 때와 put/delete 뒤에 파일의 모든 값을 core 보호 메모리(`createKnownSecretRegistry`)와 reader pool의 알려진 값 통로(`ctx.runtime.readers.known.register|revoke|setReady`, wiring/secrets.ts)에 올리고 회수한다. put은 파일에 쓰기 전에 새 값을 먼저 등록한다. 값을 아직 다 모르면 `known.ready`가 false라 redactor가 null로 답한다(fail-closed, 2s~30s backoff 재시도).
- redaction 채널 두 개: (a) core 안 텍스트 handler용 `createProductRedactor(known)`(`packages/base/redaction/product-redactor.ts`, 51줄): `matchCredential` pattern 규칙과 알려진 값이 겹치면 앞에서 시작하는 쪽, 같으면 긴 쪽을 `REDACTION_REPLACEMENT`로 바꾼다. (b) agent runtime child용: 감독 pipe `redact_request{windows[]}` → core `answerRedactRequest`(`run-loop/runtime-redaction.ts`)가 같은 규칙으로 지울 자리(span)만 답한다(`REDACT_SPANS_MAX 4096`, 못 끝내면 `ok:false`이고 child는 그 글을 보내지 않는다). child는 model로 갈 요청, tool 결과, 지침, 저장할 blob을 모두 전송·저장 전에 이 길로 지운다(`run-loop/blobs.ts`).
- ledger·event·log에 값이 안 남는 장치: provider credential은 `provider_credentials.secret_name`(이름)과 `secret_ref:{name}`만(값·sealed_ref 열 없음). 값은 `createFileSecretAttach`가 transmit callback에 한 번 건네고 결과·오류·log에는 `sent` 여부만. attach 대조 실패는 값 없는 `forbidden/unavailable`(message 200자). `known` registry 준비 전에는 값을 child로 주지 않는다(runtime-secret.ts 머리 주석). 오류 문장은 고정 문장(예외 message 복사 금지). `ModelCall` 기록에는 header·credential이 없다(auth-transport.ts 주석). 옛 keychain 길(`core/secrets/store.ts`, MCP OAuth/앱 secret 참조)은 참조가 하나도 없으면 keychain을 열지 않는다. 제품 E2E에서 MCP를 안 쓰면 OS keychain은 호출되지 않는다(코드 주석으로 확인. 열어 보진 않음).
- 지금 test: `core/secrets/file-store_test.ts`(175줄), `shell/main/secret-input/submit_test.ts`, `base/redaction/product-redactor_test.ts`(33줄), `core/lophn-agent/providers/secret-refs_test.ts`(112줄), `providers/commands_test.ts`(53줄, 이번 계획에서 추가).
