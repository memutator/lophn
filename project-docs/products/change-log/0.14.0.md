# 0.14.0

## 앱 panel이 탭과 한 면으로 이어진다, 앱 icon, activity bar에 앱 panel 고정

```yaml
modules: [packages/shell/renderer/workspace, packages/shell/renderer/app-frame, packages/shell/main/workspace, packages/core/apps, packages/protocol/apps/declaration, packages/core/apps/packages/template]
checked: []
```

- 전:
  - project 창의 앱 panel 탭은 탭 줄 아래에 앱 이름·Live·연결 상태 줄(`ViewChrome`)이 늘 있었다. 그 줄과 앱 화면의 바탕이 달라 탭과 본문이 한 면으로 이어지지 않았다. 앱 template의 화면 바탕은 `base.css`·`AppShell`의 `--color-surface-floor`라 탭 본문(`--color-surface-base`)보다 어두웠다.
  - 앱에는 icon이 없었다. 앱 panel 탭은 늘 기본 아이콘, 런처와 place switcher는 첫 글자와 색이었다.
  - 앱 panel은 탭 줄의 + → App panel → 고르기로만 열었다.
- 후:
  - 앱 panel 탭은 화면이 멈추거나 crash했을 때, 앱이 멈췄을 때만 `ViewChrome`을 띄운다. 앱 template에 `src/surface.css`가 생겨 앱 바탕이 `--color-surface-base`다. 앱이 고치거나 지울 수 있다.
  - 앱 선언에 선택 칸 `icon`(bundle 안 경로, svg·png·webp)이 생겼다. release 준비는 그 파일이 commit에 있고 64 KiB 이하인지 본다. core read `apps.icon`이 active release의 icon을 base64로 준다. bundle 밖 경로·symlink, 큰 파일, 선언 없음은 `null`이다. 앱 panel 탭, activity bar의 고정 앱, 런처, place switcher가 그 icon을 쓴다.
  - activity bar 아래쪽(바로 가기와 Settings 사이)에 project마다 앱 panel을 고정한다. 앱 panel 탭의 탭 menu "Pin to activity bar"나 묶음 끝의 +로 더하고, right-click "Unpin from activity bar"로 뺀다. 누르면 같은 앱·화면 탭이 있으면 그 탭으로 가고 없으면 새로 연다.
  - layout 파일이 판 7이고 `rail_apps`가 있다. 판 5·6 파일은 읽을 때 판 7로 올린다.

왜: lophn은 탭과 본문의 바탕을 맞춰 한 면으로 보이게 하는데, 앱 panel만 그 사이에 다른 바탕의 줄과 더 어두운 화면이 끼었다. project마다 자주 쓰는 앱 화면을 매번 + 메뉴에서 고르는 것도 번거로웠다.

결정:
- 크롬 줄은 지우지 않고 문제가 있을 때만 띄운다. 멈춘 화면을 다시 여는 [Open again]이 그 줄에만 있다. (agent)
- 앱 바탕은 `@lophn/ui`가 아니라 template에서 맞춘다. 같은 판의 SDK byte를 바꾸면 기존 앱의 `npm ci`가 깨지고, 판을 올리면 `app-ui`·shell·template 고정이 같이 바뀐다. 사람이 강제하지 말라고 했다. 이미 만든 앱은 그대로다. (사람, agent)
- 고정 앱은 desk가 아니라 project 단위로 layout 파일에 둔다. 등록은 탭 menu와 + 둘 다, 누르면 있는 탭으로 간다. (사람)
- `icon`은 `@lophn/declaration` 판을 올리지 않는다. 선언 검증기 파일이 바뀌어도 판을 올리지 않던 앞선 변경을 따른다. 선언에 icon이 없으면 칸을 두지 않아 옛 선언의 hash가 그대로다. (agent)

## turn의 일한 시간 한도를 지우고 model 호출 수 상한을 기본으로 끄다

```yaml
modules: [packages/protocol, packages/core/lophn-agent]
checked: []
```

- 전: turn 하나는 사람 기다림을 뺀 일한 시간 30분(`lophn-agent.run.active_ms`), model 호출 150번(`lophn-agent.run.model_attempts`), 진행 없이 5분(`lophn-agent.run.stall_ms`) 가운데 먼저 닿는 것에서 멈췄다. 진행 중인 긴 일도 "The agent reached its working time limit and stopped."로 끊겼다.
- 후:
  - 일한 시간 한도가 없다. 설정 `lophn-agent.run.active_ms`를 지웠다. settings 파일에 남은 값은 읽지 않는다. 일한 시간은 "Worked for"에 쓰려고 계속 센다.
  - `lophn-agent.run.model_attempts`는 기본이 `null`(상한 없음)이다. 양의 정수를 고르면 전처럼 그 수에서 멈춘다(eval 판단 case의 15).
  - `stall_ms`(진행 없이 5분)는 그대로다.
  - turn에 고정하는 `limits`가 `{model_attempts: number | null, stall_ms}`다. ledger step `lophn-agent.turns.drop-active-limit`이 시작한 turn의 `limits`에서 `active_ms`를 뺀다.
  - 실패 이유 `active_limit`는 남는다. 그 이유로 끝난 지난 turn의 TurnEnded event가 ledger에 있고 events는 고치지 않는 기록이다. 새 turn은 그 이유를 내지 않는다.

왜: 사람이 앱을 짓는 turn이 30분에 끊겼다. omp, Hermes, opencode는 기본으로 turn 시간이나 step 수 상한이 없다. Hermes는 상한이 "silent mid-task truncation"을 일으켜 기본을 무제한으로 바꿨다. 셋 다 기본으로 켜 둔 것은 stream 단위 무진행 timeout과 retry 수뿐이다.

결정:
- 일한 시간 한도는 지우고 호출 수 상한은 opt-in으로 남긴다. 사람이 한도를 없애라고 했다. 호출 수 상한은 eval이 돈을 막는 데 쓰고, opencode `steps`·Hermes `max_turns`도 opt-in으로 둔다. (사람, agent)
- 무진행 한도는 남긴다. 다른 harness도 무진행 timeout은 기본으로 켜 두고, 진행 없이 멈춘 turn을 끝낼 다른 장치가 없다. (agent)
- 한도에 닿았을 때 tool 없이 model을 한 번 더 불러 한 일·남은 일을 요약하게 하는 안(opencode·Hermes)은 이 변경에 넣지 않았다. (agent)
