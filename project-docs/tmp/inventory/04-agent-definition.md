## 문서끼리 어긋난 것

- S4 3장 file 줄이 근거로 req-1475를 쓰는데 req-1475는 `rejected`다("VS Code처럼 project 밖 파일도 열 수 있다. 거절할 이유가 없다", `requirements/core-projects.yaml:28`). 사람이 파일을 여는 길과 agent file tool 경계는 다르지만 근거 줄이 폐기 요구를 가리킨다. agent의 file 범위를 정한 요구가 따로 없다.
- visuals: `changes-by-topic.md` 5장은 `lophn-agent/visuals`를 "새 요구 없음, 그대로"로, 4장 shell/workspace는 "시각 블록(MVP 밖)"으로 쓴다. S4 4장 표에는 `visual.*`가 없다. 같은 문서 안에서 어긋나고 코드(`visual.show` 등)의 운명이 정해지지 않았다.
- `changes.md` 4장 lophn-agent 줄과 req 문구의 "다음 run부터"는 S4 1장에서 turn으로 바뀌었다. docs-review 120~147줄(skill hot-reload 절)은 run 기준 옛 서술이다.
- `notes/removed.md` 4장 "바뀐 모델"이 "Context Engineer는 전체에 하나"라고 쓴다. S4 2장·11장 13은 Project Manager가 project마다 하나다. `removed.md`는 기록 문서라 그대로 둔다고 docs-review가 정했으므로 낡은 줄이다.
- `changes-by-topic.md` 5장 lophn-agent/roles/context-engineer 줄은 이름이 바뀐 것을 적었지만 3장 지울 코드와 `changes.md` 2장에는 Project Manager 전환 작업이 코드 항목으로 없다(S4 11장 13이 "코드의 이름은 refactor session 몫"이라고만 적음).
- S4 2장 설정 층은 "전역, project, agent(Operator)"인데 5장 지침 층은 built-in agent에도 "agent 지침"을 둔다. req-0038은 "Operator 층"이라고만 쓴다. built-in agent(App Engineer, Project Manager)가 agent 지침을 갖는지 문서가 한 곳에서 답하지 않는다.

## 확인 못함

- 전역 층 model의 모양(role별인지, 하나인지)과 composer에서 session 단위로 model을 고르는 `session` 층(`ResolveInput.session_model`)을 유지하는지.
- skill 등록 폴더(`lophn-agent.extensions.skill_folders`)와 개인 보관소(`<data root>/skills`)를 새 설계에서 유지하는지. 요구에 없다.
- 앱 place의 skill 폴더(`<data root>/apps/<앱>/skills`), 앱 place의 MCP 서버(`ChangePlaceExtensionSettings`가 project와 app 둘 다 받음)를 새 층(전역/project/agent)에서 어떻게 하는지.
- file·shell·web tool을 agent runtime child에서 실행할지 core가 대신 실행할지. 지금 child는 Deno 권한이 좁고(`register.ts`) shell이 child 안에서 돌면 `allow_run`·`allow_read`·`allow_write`·`allow_net`·`allow_env`가 모두 달라진다.
- `glob`, `grep`, `shell`, `web.search`, `web.fetch`의 정확한 tool 철자. S4 4장 꼴(`<자원>.<동사>`)과 3장의 이름("glob, grep, shell, web search·fetch")이 같지 않다.
- pdf를 읽는 라이브러리(`pdf.read`)와 이미지를 model에 싣는 provider 경로(`image` part). 지금 adapters에 이미지 part가 없는 것만 grep으로 확인했다.
- `project.list`, `project.read`, `app.health`, `app.invocations`, `app.commands`, `app.blueprint`(읽기), `context.overview`, `context.read_entity`, `context.glossary` 삭제, `visual.*`가 S4 표에 없다. 지울지, 다른 tool에 합칠지 정해야 한다. 이 목록의 "덜어낼 것"에는 위에서 근거가 있는 것만 넣었다.
- 자동 compact를 언제 돌리는지(S4 6장은 compact 방식만 말함)와 `fork`·`recap`을 도는 turn 중에 부르면 어떻게 되는지(7장은 다음 turn).
- 질문 카드 Skip(`DeferQuestionGroup`)을 새 설계에서 어떻게 하는지.
- deferred로 두는 token 문턱을 어떻게 세는지(S4는 "session을 시작할 때 고정"만 말함).
- `roles/*`의 순수 함수들은 roles 밖에서 import하는 곳이 없다는 것까지만 grep으로 확인했다. 동적 import나 문자열 참조는 보지 않았다.
- 렌더러 테스트(`*_test.tsx`)와 e2e는 읽지 않았다. 지운 tool과 옛 모델에 묶인 테스트는 AGENTS.md 규칙대로 옮기지 않고 지우고 다시 쓴다.
