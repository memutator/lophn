# lophn-agent/revert

사람이 lophn agent run 하나의 확정 변경 전체를 확인하고 복원 가능한 변경을 새 변경으로 되돌리는 revert, 충돌 차단과 복원 불가 영향의 설명을 맡는다.

## 요구

### 책임과 범위

**[R1]** revert는 완료·실패·멈춤으로 끝난 agent run 하나의 확정 변경 전체를 대상으로 하며 종료 때 별도 묶음 확정을 기다리지 않는다.
- 이유: 실패한 run의 이미 저장된 변경도 사람에게 남겨 두고 별도 커밋 정본을 만들지 않는다.
- 확인: failed·stopped run의 문서 변경도 목록에 나오고 기다리는 run은 먼저 멈춰야 요청할 수 있는지 본다.
- 의도: lophn-agent#I7

**[R2]** revert는 사람만 요청할 수 있으며 agent가 대신 적용하거나 원래 run을 다시 시작하는 기능으로 쓰지 않는다.
- 이유: 사람의 복원 결정과 agent의 새로운 변경을 구분한다.
- 확인: agent의 revert 요청은 거절되고 사람 적용 후 새 agent run이 자동 생성되지 않는지 본다.
- 의도: lophn-agent#I7

**[R3]** 적용 전에 전체 변경과 대상별 복원 가능·불가·남길 사실·충돌 및 이유를 보여 주고 적용 뒤 실제 복원·남은 영향·부분 결과를 구별한다.
- 이유: 모든 변화가 돌아간다는 오해를 막는다.
- 확인: 복원 불가 효과가 있는 run에서 그 영향이 숨겨지지 않고 실제 결과를 구별할 수 있으며 확인 화면은 shell/confirmation-window를 따르는지 본다.
- 의도: lophn-agent#I7

**[R4]** 복원 시작 전 대상에 후속 변경이 있거나 복원 뒤 관계를 안전하게 유지할 수 없으면 어떤 변경도 시작하지 않으며 시작 뒤 앱의 새 충돌·실패·효과 불명을 부분 동의로 강제 덮어쓰지 않는다.
- 이유: 사람이 나중에 한 변경과 참조 관계를 보호한다.
- 확인: 사전 검사에서 두 대상 중 하나만 충돌해도 둘 다 그대로이고 시작 뒤 앱 실패는 실제 결과로 남는지 본다.
- 의도: lophn-agent#I7

**[R5]** 복원은 과거 사실을 지우거나 현재 version을 과거로 옮기지 않고 소유 concern의 새 변경으로 남기며 문서 내용은 documents/versions의 이전 내용 새 version 계약을 따른다.
- 이유: 원래 판단과 복원 판단을 모두 보존한다.
- 확인: 문서 version 수가 늘고 원래 내용·변경 기록이 그대로 읽히는지 본다.
- 의도: lophn-agent#I7

**[R6]** 실제 외부 영향·activation·secret 사용·되돌리기 contract 없는 앱 업무 변경·소스 git·디스크 원본은 이 revert가 복구했다고 표시하지 않으며 복원 가능한 변경만 적용해도 전체 복원으로 표시하지 않는다.
- 이유: ledger 변경과 외부 세계 복구는 다르다.
- 확인: 이미 보낸 외부 결과나 활성 앱 상태가 남는데 복구 완료라고 쓰지 않는지 본다.
- 의도: lophn-agent#I7

**[R7]** 복원 불가 업무 변경이 섞이면 기본적으로 적용을 막고 사람이 남을 영향을 명시적으로 확인한 경우에만 안전하고 독립적인 복원 가능 변경 전체를 적용한다.
- 이유: 부분 revert를 암묵적 성공이나 충돌 무시로 만들지 않는다.
- 확인: 남는 영향 확인 전에는 아무것도 바뀌지 않고 확인 뒤에도 관계 검사에 실패하면 전체가 막히는지 본다.
- 의도: lophn-agent#I7

**[R8]** 같은 revert 요청을 반복해도 복원은 한 번만 적용하며 원래 질문 답·승인 결정·호출 결과·관측 사실과 사용량은 실제 사실로 남긴다.
- 이유: 복원으로 과거 결과를 거짓으로 지우거나 중복 복원하지 않는다.
- 확인: 같은 요청 재전송 뒤 새 문서 version이 추가되지 않고 원래 답·test result·invocation이 유지되는지 본다.
- 의도: lophn-agent#I7

**[R9]** 대상별 복원 가능성과 충돌은 그 대상 concern의 현재 판·관계·권한 검사를 따르며 분류되지 않은 영향을 목록에서 누락하거나 안전하다고 가정하지 않는다.
- 이유: revert가 다른 영역의 안전 규칙을 대신 정하지 않는다.
- 확인: 문서는 documents/versions와 documents/addressing, 티켓은 coding-agent/tickets의 실제 판정을 사용하는지 본다.
- 의도: lophn-agent#I7

**[R10]** run에서 되돌리기 지원 앱 write가 성공했으면 저장한 invocation·receipt·현재 revision을 검증하여 앱의 선언된 revert command를 원래 호출 역순으로 직접 부르고 실제 복원 결과를 run revert에 포함한다.
- 이유: 앱이 제공한 되돌리기를 전체 run 복원에서도 사용한다.
- 확인: 앱 write 두 번의 run을 되돌리면 receipt 두 개가 역순으로 한 번씩 호출되고 문서 복원과 구별되는지 본다.
- 의도: lophn-agent#I7

**[R11]** 앱 revert와 ledger 복원은 하나의 transaction으로 보장하지 않으며 호출 중 실패·충돌·응답 유실이 생기면 실제 복원·미시작·불명확을 보존하고 전체 복원 완료나 전체 미실행으로 표시하지 않는다.
- 이유: direct call의 실제 효과를 ledger 상태로 덮을 수 없다.
- 확인: 첫 앱 복원 성공 뒤 두 번째 실패·응답 유실을 넣고 첫 복원과 남은 변경·미적용 문서를 각각 확인한다.
- 의도: lophn-agent#I7

## 버린 것
- run 하나에 원본 커밋 하나를 두고 종료 때 확정하는 구조는 P4·lophn-agent/harness/run-loop의 짧은 변경 기록과 run 전체 조회로 바꿨다.
- context와 용어집(옛 항목 set/remove event와 용어 후보 owner)의 run 단위 복원: 항목과 후보가 없어지고 context는 계약 판으로 바뀌어 이 revert의 owner에서 뺐다. context 판의 이전 판 적용은 documents/contexts가 맡고, 이 revert는 context 변경을 복원했다고 표시하지 않으며 retained로 둔다. 이 문서의 나머지는 session 안 rewind 작업이 다시 쓴다.
