# apps

## 왜
coding agent에게 만든 앱을 받은 뒤에는 코드를 읽지 않고도 쓰고, 멈추고, 바꿀 수 있어야 한다.
새 코드나 의존성 때문에 쓰던 동작과 데이터가 몰래 달라지지 않아야 오래 쓸 수 있다.

## 무엇을 약속하나

- **[I1]** 코드 없이 목적만으로 앱을 등록하고, blueprint로 앱이 무엇을 하고 무엇이 필요한지 안다.
- **[I2]** 새 앱은 공용 SDK와 템플릿에서 시작하고, 쓰던 앱은 내가 바꾸기 전에는 그대로다.
- **[I3]** 바꿀 앱은 preview와 테스트로 확인한 뒤 내가 release를 고르고, 데이터는 backup한 뒤에만 바꾼다.
- **[I4]** 앱은 내가 허락한 권한과 다른 앱만 쓴다.
- **[I5]** 허락한 앱은 보는 사람이 없어도 정해진 일을 하고, 무엇을 했는지 되짚을 수 있다.
- **[I6]** 잘못 고른 release는 이전 release로 되돌릴 수 있다.
- **[I7]** secret은 내가 허락한 앱만 쓰고, 값은 앱 코드에 주지 않고 lophn이 보낼 때 붙인다.
- **[I8]** 한 앱의 고장이 다른 앱을 막지 않는다.
- **[I9]** 앱과 데이터를 밖으로 가져갈 수 있다.
- **[I10]** 탭이나 대화에 넣으려고 만든 앱은 패널과 카드 크기로도 보인다.
- **[I11]** 앱의 command는 다른 앱과 agent가 MCP 없이 그대로 쓸 수 있다.
- **[I12]** 앱은 agent에게 보여 줄 화면 상태를 정하고, 민감한 칸은 내보내지 않는다.

## 하지 않는 것
- 코드를 짜는 도구나 앱 마켓을 만들지 않는다.
- preview·시작·호출 성공을 업무 정확성이나 수리 완료로 대신하지 않는다.
- 옛 release 선택이나 권한 회수를 이미 쌓인 데이터·외부 효과의 취소로 표시하지 않는다.

## 잘되고 있다는 신호
- 두 번째 앱은 공용 재료 덕분에 더 적은 일로 만들어진다.
- 쓰던 앱은 update 뒤에도 같은 동작을 하고, 바꿀 때는 내가 무엇이 달라지는지 안다.
- 앱을 멈추고 접근을 거둔 결과를 확인할 수 있으며, 한 앱이 깨져도 다른 앱을 쓴다.
