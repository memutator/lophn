# lophn 0.8.0

This release adds flows, workflows written as code that call apps and agents in an order of their own, and lets apps sign in to OAuth services such as Google Drive. It also fixes several problems in the launcher, the project window and the installed app.

## New
- Flow workflows: a workflow can now be a flow, a program that calls apps and agents. Start it from the workflow tab (there is no first step to pick), from the CLI, or from a job. A flow can read only its own workflow folder and the SDK, and cannot write files or use the network. Its memory is limited to 512 MiB. Its report is marked "Program", and when it ends the log shows the exit code and the last lines of its error output.
- The Project Manager can check a flow's code for type errors before the flow runs.
- Apps can sign in to OAuth services. In an app's Access tab, enter the client ID, set the client secret, and choose Sign in. Cancel stops a sign-in that is waiting. A signed-in token refreshes itself before it expires.
- A person can set an app's secret value in the Access tab through a protected input.
- Apps can send request bodies (up to 10 MiB) and headers with their network requests.
- Apps can use date pickers, a date range picker, a calendar, and a segmented control from the UI kit.
- The launcher has a New app button. It creates an app and opens a new App Engineer session for it.
- The launcher has an Ask lophn button in its bottom right corner. It opens lophn in a floating panel without opening a project.
- A handoff message from lophn has an Open conversation button that opens the session that received the work.

## Changed
- An app's definition is called its declaration everywhere. The word "blueprint" is gone from the CLI, agent tools and release records.
- Agents using Claude models load app tools and outside tools only when they need them, so each request starts smaller.
- A lophn tab always talks to lophn, whichever project or app window it is opened from.
- In an app window, the agent select opens that agent's most recent session. A new session starts from the session list in the header.
- Flow calls show as "Workflow" in app activity and in the session rewind list.

## Fixed
- The installed app shows the lophn icon in the taskbar and on its windows.
- A project folder outside the install's read area no longer fails to register with the message "wasn't registered, so nothing was saved".
- A lophn tab opened from a project or app window no longer talks to Project Manager or App Engineer instead of lophn. The lophn row in the sidebar and the Agent button in the activity bar now open lophn.
- Agent tabs keep their names after Settings is opened or the connection drops and comes back.
- Large request bodies sent by an app could be cut off.
- A provider sign-in token could reach an app whose secret permission matched the token's name. Such tokens are no longer sent to apps.
- Headers an app sets on a network request are sent only to the first host, not to hosts the request is redirected to.

## Action needed
- Apps released before 0.8.0 must be released again to use the new UI kit, OAuth sign-in and the declaration name.
- lophn may report a conflict error when it starts after this update, for data created before this version.
