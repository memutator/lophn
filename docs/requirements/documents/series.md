# documents/series

같은 틀로 이어지는 독립 문서를 series로 묶고 가족 규칙·key·정렬·다음 문서 이름 계산을 맡는다; 각 문서와 version은 documents/versions를 따른다.

## 요구

### 가족과 멤버

**[R1]** 사람·허용된 앱·coding agent는 프로젝트나 앱 자리 안에 series의 이름·제목·문서 format·정렬 기준·다음 이름 규칙을 등록하며 series는 문서 간 관계 간선 대신 멤버십으로 가족을 표현한다.
- 이유: 주간 보고나 changelog를 독립 문서로 보존하면서 같은 가족으로 찾아야 한다.
- 확인: 자리의 가족을 등록하고 두 문서를 넣으면 가족 목록으로 이어지되 문서 영향 관계가 생성되지 않으며 lophn agent의 가족 등록은 거절된다.
- 의도: documents#I5

**[R2]** series 멤버로 저장할 때는 가족과 그 안의 비어 있지 않은 key를 함께 정하고 key는 그 가족 안에서 유일하며 멤버를 빼도 다른 문서에 재사용할 수 없고 문서 address 이름과 별개이다.
- 이유: 가족의 정렬 자리와 문서 주소를 같은 이름으로 강제하지 않는다.
- 확인: 0.3 key와 0-3 문서 이름을 함께 쓸 수 있고 key 없이 가족만 지정하거나 같은 가족 key를 중복 저장하면 거절된다.
- 의도: documents#I5

**[R3]** 같은 가족의 멤버는 같은 자리와 정한 format을 따르며 멤버를 고쳐도 같은 문서의 새 version이 생길 뿐 새 가족 멤버가 생기지 않는다.
- 이유: 멤버 순서와 판 이력을 구분한다.
- 확인: 형식·자리가 다른 문서 추가는 거절되고 기존 멤버 수정 뒤 멤버 수는 같고 version만 늘어난다.
- 의도: documents#I5, documents#I2

### 목록과 정렬

**[R4]** 자리별 가족 목록에는 가족 규칙과 멤버 수를 주고 가족 상세와 가족 목차는 같은 순서의 key·문서 제목·고정 최신 판·보관 상태 목록을 돌려준다.
- 이유: 같은 가족을 두 통로에서 달리 보게 하지 않는다.
- 확인: 가족 상세와 목차를 읽어 같은 멤버·판·순서를 얻으며 page는 documents/outline-and-search 방식으로 이어 본다.
- 의도: documents#I5, documents#I3

**[R5]** 가족은 format이 선언한 정렬 값이 있으면 그 값으로, 없으면 key로 멤버 순서를 정하고 key의 숫자 부분은 수로 비교하여 0.9 다음에 0.10을 두며 해석 불가·동점은 locale에 독립적인 key 순으로 결정한다.
- 이유: 문자열 순서나 OS locale 때문에 보고 순서가 바뀌지 않아야 한다.
- 확인: 0.2·0.9·0.10과 자유 이름을 정렬한 뒤 locale을 바꿔도 같은 결과를 받는다.
- 의도: documents#I5

### 다음 이름

**[R6]** 다음 key 계산은 기존 마지막 key와 저장한 규칙으로만 제안하며 저장하지 않고 계산 근거 key와 이미 사용된 이름 여부를 함께 보여 준다.
- 이유: 다음 이름을 읽었다는 것과 새 문서를 만들었다는 것은 다르다.
- 확인: 다음 제안을 두 번 읽어도 문서가 늘지 않고 마지막 key·충돌 여부가 같으며 사람이 제목을 바꿔도 규칙은 유지된다.
- 의도: documents#I5

**[R7]** 처음 멤버의 key는 사람이 직접 정하고 마지막 key를 규칙으로 읽을 수 없는 가족의 다음 이름은 빈 제안으로 돌려 사람이 정하게 한다.
- 이유: 처음 값이나 날짜 이름을 임의로 만들어서는 안 된다.
- 확인: 빈 가족과 날짜 key 가족에서 자동 숫자를 꾸미지 않고 사람이 첫 key를 입력해 저장한다.
- 의도: documents#I5

**[R8]** 처음 지원하는 다음 규칙은 정수 증가·감소와 major·minor·patch 변경 및 최대 4자리 0 채움이며 P001→P002·0.2→0.3·0.2→1.0·0.2.1→0.2.2를 동일하게 계산한다.
- 이유: 이전 제품에서 실제 지원한 규칙의 의미를 보존한다.
- 확인: 같은 규칙을 화면과 API에서 계산하여 예시가 같고 해석할 수 없는 규칙이나 5자리 채움 요청은 등록 때 거절된다.
- 의도: documents#I5

### 권한과 정리

**[R9]** lophn agent의 series 통로는 가족 목록·상세·다음 제안 읽기만 제공하고 가족 등록·구성 변경·멤버 추가는 하지 못하며 보관·해제·draft 변경·멤버 제거는 사람만 한다.
- 이유: 가족 구성 규칙을 알아야 저장하되 lophn agent에게 새 관리 범위를 주지 않는다.
- 확인: lophn agent는 가족을 읽기만 하고 허용된 앱·coding agent의 등록·멤버 저장은 받으며 실제 멤버 저장 범위는 documents/versions를 따른다.
- 의도: documents#I5

### 가족과 멤버

**[R10]** 사람은 가족을 보관·해제할 수 있고 그 상태와 이름은 문서의 상태와 독립적이다.
- 이유: 가족 정리가 멤버 문서의 보관이 되어서는 안 된다.
- 확인: 가족을 보관해도 멤버의 판·주소가 그대로이며 기본 가족 목록에서는 숨겨진다.
- 의도: documents#I5

### 작성 준비

**[R11]** 가족은 새 인스턴스 작성을 위한 key·예정 문서와 template 기반 draft 값을 한 개 보존하고 확정 멤버 목록에서는 제외한다.
- 이유: 작성 중 내용과 확정 문서의 가족 이력을 구분한다.
- 확인: draft를 다시 열어 작성 값을 복원하고 첫 version 확정 전에는 문서나 context 대상으로 읽을 수 없으며 template은 documents/formats를 따른다.
- 의도: documents#I5

### 가족과 멤버

**[R12]** series는 ID 또는 자리와 가족 이름으로 조회하고 별도 문서 address나 version을 갖지 않는다.
- 이유: 가족 목록과 문서 본문을 같은 대상으로 읽게 해서는 안 된다.
- 확인: 가족 이름으로 상세를 읽되 문서 본문 읽기에는 멤버의 고정 판을 사용한다.
- 의도: documents#I5

**[R13]** 가족 영구 삭제는 제공하지 않고 멤버 문서 처리와 구별하여 보관만 제공한다.
- 이유: 가족 삭제가 멤버의 자료와 예약 key를 없애는 약속은 아직 없다.
- 확인: 가족 삭제 요청은 제공되지 않고 보관 뒤에도 멤버 구성과 key를 읽는다.
- 의도: documents#I5

### 완료와 기록

**[R14]** 가족 규칙·draft·멤버 구성은 ledger에 보존하고 생성·변경·멤버 추가의 확인된 주체를 남기되 목록 읽기와 재조회는 변경 기록을 만들지 않는다.
- 이유: 검색 index를 지웠다고 가족이 없어지거나 읽었다고 새 판이 생기면 안 된다.
- 확인: derived search를 지워도 같은 가족 구성을 조회하며 읽기 전후 version과 변경 기록 수는 같고 변경 주체는 platform/ledger를 따른다.
- 의도: documents#I5

## 버린 것

- Home 연결은 버렸다; 가족은 프로젝트나 앱 자리에 속한다.
- 작성 중 draft를 첫 version 없는 Document로 저장하던 방식은 버렸다; draft는 가족 안의 작성 준비 값으로 남긴다.
- 날짜·주차 다음 이름 규칙은 이번에서 뺐다; 숫자 규칙을 쓰고 날짜 key는 사람이 직접 정한다.
- Operator가 가족의 다음 독립 문서를 만드는 확장은 이번에서 뺐다; 새 판은 기존 문서에만 두고 가족 생성은 사람·허용 앱·coding agent가 한다.
