# browser-tab

workspace 창의 탭으로 인터넷 page를 여는 탭 kind `browser`의 설계다. 사람은 탭에 주소를 적어 page를 보고, popup·DevTools·bookmark를 쓰고, terminal이 연 URL과 Ctrl/Cmd-click한 link도 이 탭으로 받는다. agent는 자기가 연 browser 탭, 사람이 넘겨준 browser 탭, 앱 preview 탭을 CLI(`lophn browser`)로 읽고 조작한다. cookie와 저장 login은 browser profile마다 따로이고 agent 정의가 그 agent의 profile을 고른다(아래 "browser profile"). 같은 명령이 사람의 폰에 뜬 앱 preview 화면(`phone` 탭)도 다룬다(아래 "phone 탭"). display가 없는 Linux에서는 core가 창 없는 page host를 띄워 agent가 같은 명령으로 browser를 쓰고, 사람은 다른 기기(폰, 다른 기계의 desktop)에서 그 기계의 browser 탭을 보고 다룬다(아래 "화면 없는 기계의 page", "멀리서 보기"). lophn이 다루는 것 가운데 가장 믿지 못할 입력이 인터넷 page이므로, page가 닿는 길(navigation, popup, permission, download, IPC)은 shell main의 순수한 규칙이 정하고, Electron 연결은 그 규칙을 부르기만 한다.

page를 그리는 그릇은 둘이다. 보통 탭은 shell renderer 안의 `<webview>`(앱 화면·artifact 화면과 같은 창의 같은 그릇)이고, `window.opener`를 지켜야 하는 크기 준 popup과 DevTools만 native `WebContentsView`다.

## 문제

- 사람은 terminal에서 dev server를 띄우거나 `gh auth login`을 하면 lophn 창과 OS browser를 오가야 했다.
- page는 인터넷이다. 앱 화면과 달리 lophn이 만든 코드가 아니므로, 이동·새 창·권한·download·IPC로 shell이나 사람의 data를 건드리지 못하게 막아야 한다.
- 보이는 page가 shell의 menu·popover·floated 패널 밑에 깔리면 쓸 수 없다.
- terminal이 여는 로그인 URL(OAuth 등)을 잃으면 사람이 다시 할 길이 없다.
- agent가 사람의 dev site를 직접 보고 조작하려면 로그인한 session을 써야 하지만, page 글이 agent를 속이면 그 로그인으로 site를 건드릴 수 있다.
- 사람과 모든 agent가 cookie와 로그인을 하나로 같이 쓰면 업무 계정과 개인 계정을 가를 수 없고, page 글에 속은 agent가 사람의 모든 로그인에 닿는다.
- 화면이 없는 기계(server, VM)의 core에서는 agent가 browser를 쓸 수 없었고, 그 기계의 site 로그인을 사람이 할 길도 없었다. 사람은 다른 기기에서 agent의 page를 보거나 끼어들 수 없었다.
- profile과 저장 login이 컴퓨터마다 따로라 사람은 컴퓨터마다 profile을 만들고 login을 다시 넣어야 했다. 그렇다고 password와 TOTP seed가 cloud에 올라가는 같이 보는 폴더를 지나면 안 된다.

## 목표와 비목표

- 목표: 탭 안에서 일반 page, 크기 준 popup(로그인), DevTools, bookmark, favicon을 쓴다. terminal의 `$BROWSER`와 Ctrl/Cmd-click link가 같은 창에서 탭으로 열린다. agent가 자기가 연 탭과 사람이 넘긴 탭을 읽고 조작한다. browser profile로 cookie와 저장 login을 나누고 agent마다 단다. profile 정의와 저장 login(값 포함)이 사람의 짝지은 컴퓨터들에서 같다. 화면 없는 Linux에서도 agent가 같은 명령으로 browser를 쓰고, 사람이 다른 기기에서 그 기계의 page를 보고 다룬다.
- 비목표: tab 수 cap, site 목록, capability 승인, storage mode, 사용자가 쓰지 않는 설정(rea가 모은 것 가운데 dev server와 로그인에 필요한 것만 남겼다). cookie·site 저장소를 기계 사이에 맞추기, agent에 단 profile을 기계 사이에 맞추기(agent 정의는 기계마다다). 진짜 폰의 web 화면(emulation은 크기·touch·user agent까지다. 진짜 폰에서 도는 앱 preview는 `phone` 탭이 다룬다). localhost·사설 IP 차단. page 쪽 preload나 IPC. 앱 live 화면을 agent가 다루는 일.

## 모델

- **탭.** layout의 browser 탭은 `{key, url, favicon}`과 선택 필드 둘만 저장한다. title, history, DevTools 자리는 저장하지 않고 다시 열면 그 url을 load한다. `keep_alive: true`는 켠 탭만 적는다(없는 옛 파일은 꺼진 탭이다). `profile`(browser profile id)은 기본이 아닌 profile의 탭만 적고 정해지면 바뀌지 않는다(없으면 기본 profile). 탭의 주인과 사람이 넘긴 탭의 표시는 모든 kind의 공통 칸(`owner`, `handed_tab`)이다(`workspace-layout.md` "탭의 주인").
- **page 그릇 둘.**
  - guest: 보통 탭의 `<webview>`. 창마다 하나인 webview host에 탭 key당 하나 만들고, 탭 자리는 사각형만 알린다. view session 이름은 `wv-<guest contents id>`이고 main과 renderer가 IPC 없이 같은 이름을 안다. 앱·artifact 화면도 같은 host와 그릇을 쓴다.
  - native view: 크기 준 popup과 DevTools. browser 자기 registry의 항목이고 앱 view registry에 넣지 않는다. 위치는 renderer 사각형을 창 좌표로 바꿔 정하고, 층은 창마다 하나다. popup은 opener의 contents를 그대로 감싼 것이고, DevTools는 page마다 새 native view 하나에 붙는다(`devtools-<page id>`).
- **session.** browser 탭은 자기 browser profile의 persistent partition 하나를 쓴다. 기본 profile은 처음부터 쓰던 `persist:lophn-browser`이고 사람이 만든 profile은 `persist:lophn-browser-<profile id>`다. 앱 저장소 partition과 나뉘어 page가 앱 화면의 cookie·storage를 보지 못한다. partition마다 그 첫 view, 첫 `<webview>` attach, 첫 데이터 지우기 때 한 번 설치한다. 거기서 permission, download, user agent 규칙이 걸린다.
- **browser profile.** profile 하나는 cookie·저장소 partition 하나와 그 profile의 저장 login이다. 이름(1~40자, 이 컴퓨터에서 만들거나 이름을 바꿀 때 대소문자를 가리지 않고 겹치지 않는다)과 색(agent 얼굴과 같은 색 목록)이 있고 id는 `bpf_<ULID>`다. 목록은 core의 vault(`<data>/browser-vault.json`, 사람만 바꾼다, 이 컴퓨터에서 만드는 것은 16개까지)이고 기본 profile은 목록에 없으며 id가 없다(null). profile 정의와 저장 login은 사람의 다른 컴퓨터와 같게 둔다(아래 "기계 사이"). bookmark는 전역 하나다.
  - 탭의 profile은 여는 쪽이 정한다. 사람은 탭 줄 + menu에서 Browser를 바로 눌러 기본 profile로 열고, 다른 profile이나 bookmark가 있을 때 hover로 열리는 하위 menu에서 profile과 bookmark를 고른다(빠른 실행, 단축키, 터미널 link는 기본 profile이다). agent가 `tab open --url`로 여는 탭은 그 session의 agent 정의 `browser_profile`이다(`agent-definition.md`). page 안에서 연 탭, 크기 준 popup과 그것을 dock한 탭, Open in new tab은 연 탭의 profile을 따르고, 사람이 넘긴 탭은 자기 profile을 그대로 든다.
  - 탭 머리(탭 줄과 칸 머리)는 기본이 아닌 profile의 색 점을 보이고 tooltip이 이름이다. 목록에 없는 profile(사람이 지운 것)의 탭은 표시 없이 기본 partition으로 열린다. 목록을 아직 읽지 못했으면 profile이 있는 탭은 page를 만들지 않고 기다린다.
  - Settings › Browser › Profiles: 맨 위의 Default 줄(지우지 못한다)과 사람이 만든 profile 줄. 줄마다 색 점, 이름, 그 profile을 쓰는 agent, Rename·Color·Clear data·Delete가 있고 [Add profile]이 끝에 더한다. Logins는 profile마다(기본 먼저) 묶어 보인다. 옛 Clear browsing data는 기본 profile을 지운다.
- **사용자 입력(activation).** contents마다 마지막 mouseDown·keyDown 시각이다. 5000ms 안이면 fresh다. popup, download가 이것을 본다. lophn(agent, 멀리서 보기)이 넣은 input도 여기에는 센다(agent가 로그인 popup을 연다). OS 넘기기(mailto·tel 같은 바깥 link)는 이 컴퓨터 사람의 입력만 따로 센다: lophn이 input을 넣는 동안(37) 그 page의 입력은 세지 않는다.
- **여는 길 셋.**
  - 주소 칸: 사람이 적은 글을 main이 정규화하고(주소가 아닌 검색어는 설정한 검색 엔진 URL로 바꾼다. 명시한 scheme은 검색어로 바꾸지 않는다) navigation 규칙을 지나게 한 뒤 load한다.
  - page 안: link 이동은 navigation 규칙, `window.open`은 popup 규칙을 지난다.
  - terminal: shell 탭이 부른 `$BROWSER <url>`(shim → socket bridge)과 Ctrl/Cmd-click한 link가 같은 판정과 같은 push로 탭을 연다.
- **popup.** `window.open`(입력 5000ms 안):
  - 크기 준 것은 native view로 등록하고(아직 adopt 안 됨) `popup` event를 보낸다. renderer가 transient floated 탭을 열어 adopt한다. dock하면 그 탭은 같은 주소의 `<webview>` 탭으로 다시 열린다.
  - 크기 없는 것(`target=_blank`)은 거절하고 `open-tab` event로 연 탭 바로 뒤에 `<webview>` 탭을 연다.
  - page의 `window.close()`는 `close` event로 renderer가 탭을 지운다. 사람이 session에 넘긴 탭은 지우지 않는다: 넘긴 탭은 사람의 탭이라 page script도 agent의 `evaluate`도 닫지 못한다. Electron이 `close` 뒤 그 guest를 없애므로 창이 같은 탭 자리에서 마지막 주소로 page를 새로 연다(탭 key, 주인, core 탭 id, take control 상태는 그대로이고 그 page의 이동 기록은 새로 시작한다). mount되지 않은 workspace에 숨은 넘긴 탭의 page도 같다. 넘긴 탭을 session이 자기 밑에 주어도(`tabs/give`) 넘긴 탭이라 같다. agent가 연 탭도 연 session이 아닌 session이 드는 동안은 같다: core의 `tab_owner`가 싣는 표시를 그 workspace를 보이는 창의 page 그릇이 메모리에 들고, 표시가 있는 동안 page를 새로 연다(저장하지 않는다). 한계: 그 표시는 `tab_owner`를 받은 창의 그 workspace page 그릇에만 있어, 전역 float으로 옮긴 준 agent 탭, 다른 창이 page를 든 탭, 창을 다시 연 뒤의 탭은 `window.close()`에 닫힌다(잃는 것은 준 session의 탭이고 그 session이 다시 연다). 또 그 탭의 workspace를 어느 창도 보이지 않는 동안 한 주기는 그 workspace가 보일 때까지 창에 닿지 않아(`tab_owner`는 보이는 창을 기다린다), 그 사이 page의 `window.close()`는 page를 부순다: 탭은 남고 page는 죽은 채다(agent가 스스로 연 숨은 탭이 지금 끝나는 상태와 같다).
- **DevTools.** 자리 셋: 탭 안 오른쪽·아래(경계 막대로 크기), floated 패널(transient kind `browser_devtools`, detached 창의 자리 menu에는 없다), 따로 뜬 OS 창. 자리를 바꿀 때 다시 열지 않고 view를 옮긴다.
- **bookmark.** `<dataRoot>/shell/bookmarks.json` 하나. main만 쓴다.
- **terminal bridge(lophn 터미널만).** core가 켜질 때마다 per-run 폴더에 shim과 bridge socket(Windows는 named pipe)을 준비한다. core가 터미널을 열 때 터미널마다 key(64 hex)를 발급하고 env `BROWSER`(shim 경로)와 `LPN_BROWSER_BRIDGE`(`{"socket","key"}`)를 PTY host의 open 요청에 실어, host가 terminal env 뒤에 덮는다(restart도 같은 env). 요청 한 줄 `{v:1,key,url}`을 받은 core는 key 표와 설정으로 판정해 그 터미널의 project에 browser 탭을 host queue(`tab_open`)로 열어 달라고 하고, 붙은 shell이 탭을 열었다고 답하면 `{"result":"pane"}`, shell이 붙어 있지 않거나 2000ms 안에 답이 없으면 `{"result":"declined"}`를 shim에 돌려준다. shim은 pane이면 끝나고, 그 밖(declined, 접속 실패, 3000ms)은 bridge env를 지운 채 OS opener(`xdg-open`·`open`·Windows `cmd.exe start`)로 연다. Ctrl/Cmd-click은 `shell:terminal-link`로 shell main에 오고 같은 설정으로 정해 browser 탭이면 창이 그 터미널 옆에 열고, 아니면 shell main이 OS browser로 연다.
- **agent가 다루는 탭.** 주인(연 session, 넘겨받은 session, 다른 session에게서 받은 session, 사람 token이면 "person")이 host queue의 `browser_call`로 host(desktop 앱의 shell main이나 page host)에 요청하고, host가 CDP로 그 탭의 page를 조작한다. 상태(Agent가 다루는 중인가, 사람이 가져갔나)는 host 메모리에 탭마다 있고, core는 누가 멀리서 보는 동안만 host가 알려 준 것을 든다. 대상은 `tab open`으로 연 browser 탭(host 탭, key가 `host:`로 시작), 사람이 session에 넘긴 browser 탭(탭 값의 `handed_tab`이 core 탭 id), preview 탭, artifact 탭뿐이다. host browser 탭과 넘긴 탭의 page는 그 탭을 든 창이 사는 동안 어느 workspace를 보이든 산다(결정 5, 41).
- **Keep alive.** workspace를 떠날 때 guest를 지울지 숨겨 둘지: 소리가 나는 중, download를 받는 중, 사람이 탭 menu에서 Keep alive를 켠 탭은 창의 그릇에 숨겨 둔다. 창마다 6개이고 넘치면 오래 안 본 것부터 놓는다. agent가 `tab open --url`로 연 탭의 page는 이 규칙 밖이다(창마다 12개, 따로 센다. page host에서는 기계 전체에 12개).
- **page host.** display가 없는 Linux에서 core가 띄우는 같은 Electron binary다(launch intent `--page-host`, 창 없는 flag `--ozone-platform=headless --disable-gpu`). shell main entry의 launch mode 하나이고 창, tray, renderer, extension, 전역 단축키를 조립하지 않는다. 탭마다 offscreen 창 하나(page 하나)를 든다. desktop 앱처럼 `/host-link`로 붙어 같은 host 요청을 받고 같은 CDP driver와 stream을 쓴다. 다른 것은 탭의 page를 찾는 법 하나다(창이 알려 주던 것을 스스로 만든다). desktop 앱과 같은 browser profile과 single-instance lock을 써서 한 기계에서 같이 돌지 않는다.
- **멀리서 보기.** 사람의 다른 기기(폰, desktop 창의 다른 기계 탭)가 core가 아는 browser 탭(agent가 `tab open --url`로 연 탭, 사람이 멀리서 연 탭)을 `page_view/*` route로 본다. 보는 쪽이 lease를 잡은 동안 host가 그 page의 CDP screencast frame(JPEG)을 core에 밀고, core는 탭마다 최신 frame 하나만 들고 내용 없는 event로 알린다. 보는 쪽이 읽어 가면 core가 host에 알려 다음 frame이 온다. 입력, take control, 탭 열기는 터미널 입력을 허락받은 기기만 하고 core가 host에 연결 요청으로 넘긴다. 터미널 보기(`terminal-agent.md`)와 같은 꼴이다.

## 지키는 것

### navigation과 guest

1. **navigation 결정은 순수 함수 하나가 한다.** main frame은 http/https(어느 host든, localhost와 사설 IP 포함)와 정확히 `about:blank`만 받는다. 최상위 `data:`·`blob:`은 막는다. subframe은 http/https와 `data:`·`blob:`·`about:`도 받는다. 그 밖의 scheme(`file:`, `lophn-*:`, `chrome:`, `devtools:`, `javascript:`, custom protocol)은 두 frame 모두 막는다. main frame의 userinfo(`user:pass@`) URL은 막는다. main frame 이동은 이동 직전 hook과 redirect hook 모두에서 검사한다.
2. **`<webview>`는 shell 창에서만, 우리 설정으로만 붙는다.** 이 그릇을 켜는 창은 shell 창(project 창, detached 창, 앱 전용 창)뿐이고 secret 입력 창은 끈다. 붙이기 판정은 모든 kind가 한 곳을 지난다. shell 문서(`lophn-shell://desktop`)가 아닌 곳에서 온 붙이기는 거절한다. browser는 알려진 browser profile의 partition(기본 profile과 core vault의 profile들. shell main이 든 `browser_profiles/list`의 사본을 붙일 때마다 본다. 아직 읽지 못했으면 기본 profile뿐이다) 가운데 하나이고 `lophn-*` src가 아닐 때만 받아 그 partition을 강제하고 첫 src를 navigation 규칙에 지나게 한다(못 지나면 `about:blank`). 앱·artifact는 registry가 받아 준 그 src와 partition일 때만 받고 renderer가 적은 값을 쓰지 않는다. 어느 쪽이든 renderer가 넣은 preload·webpreferences·`disablewebsecurity`·`nodeintegration`·`useragent`·`allowpopups`를 지우고 hardened `webPreferences`로 덮은 뒤 partition·preload를 다시 넣는다(지우면 guest가 다른 session에 붙는다). 붙인 뒤에는 받아 둔 붙이기를 순서대로(FIFO) guest 항목에 묶는다.
3. **page에는 preload도 IPC도 없다.** 뒤로·앞으로·새로 고침·주소 이동·DevTools는 shell의 머리 줄(주소 칸과 단추)이 main IPC로 시킨다. navigate·command·adopt·DevTools 요청은 caller 창이 그 항목의 소유 창일 때만 받는다.
4. **`<webview>`는 다른 부모로 옮기지 않는다.** 옮기면 guest가 다시 만들어져 page가 다시 load되고 opener가 끊긴다. 탭이 모든 desk의 layout에서 사라지거나 Detach될 때만 지운다. desk를 바꾸는 것만으로는 지우지 않아 돌아와도 다시 load하지 않는다. 쌓는 순서는 pane 탭의 `<webview>`가 pane의 경계 잡는 띠 아래·패널 모두 아래이고, floated 탭의 것은 자기 패널 위·다음 패널 아래다(`workspace-layout.md`).
5. **workspace를 떠날 때는 기본적으로 guest를 지운다(돌아오면 다시 load).** 소리가 나는 중, download를 받는 중, Keep alive를 켠 탭은 지우지 않고 숨겨 둔다(창마다 6개, 오래 안 본 것부터 놓는다. `workspace-layout.md`). 살려 둘지는 떠날 때 한 번 정한다. Keep alive의 켜고 끄기는 탭 menu에서 한다. 소리 여부는 떠날 때 한 번 본다. 예외가 하나 있다: agent가 `tab open --url`로 연 탭(key `host:`)과 사람이 session에 넘긴 탭의 page는 workspace를 떠나도 지우지 않고 그 탭을 든 창이 사는 동안 둔다. 6개 상한과 따로 창마다 12개까지이고 오래 쓰지 않은 것부터 놓는다(agent의 browser 호출과 bind가 쓴 것이다. 넘긴 때도 쓴 때로 센다. `workspace-layout.md`). 상한이 넘긴 탭의 page를 놓으면 탭은 layout에 남고 사람에게 돌아간다.
6. **다른 OS 창으로 탭을 옮기면 `<webview>` 탭(browser·앱·artifact)은 다시 load되고 그 탭의 DevTools는 닫힌다.** 다시 load 없이 옮길 수 있는 것은 native 항목(popup, DevTools)뿐이다. 소유 창은 항목마다 있고 Detach·Dock이 바꾸므로, popup의 adopt·요청 검사는 옮긴 뒤의 창을 기준으로 한다(`workspace-layout.md`). 앱·artifact 탭은 보내는 창이 element를 지우고 받는 창이 새 view를 연다.
7. **session 설치는 partition마다 한 번이고, browser 탭은 자기 profile의 partition 하나를 쓴다.** 앱 저장소 partition과 나뉜다. 탭의 profile은 정해지면 바뀌지 않아 같은 탭 key의 `<webview>`는 처음 partition 그대로다. crash 뒤 다시 여는 popup도 쓰던 partition으로 연다.

### popup

8. **크기 준 popup만 native view로 받아 `window.opener`를 남긴다.** Electron이 새 창 요청에 준 contents를 그대로 감싸야 opener가 남는다. 표준 Electron에는 그 contents를 `<webview>`에 넣는 길이 없다. popup contents는 opener의 session과 webPreferences를 물려받고 features로 바꾸지 못한다. 입력 없는 popup은 거절하고 `popup-blocked`를 알린다.
9. **크기 없는 popup은 거절하고 새 `<webview>` 탭으로 연다.** opener가 끊긴다. Chrome도 `target=_blank`는 기본이 noopener다. 크기 없이 `window.open`을 쓰는 로그인은 깨질 수 있다.
10. **popup view는 renderer가 탭을 만들어 adopt하기 전까지 state를 밀지 않는다.** adopt는 소유 창(opener의 창)에서 한 번만 된다. 다른 창은 `invalid_input`, 두 번째는 `forbidden`이다. adopt되지 않은 view는 그 창이 닫힐 때 같이 지운다. popup은 opener 탭을 닫아도 남는다.

### OS로 넘기기, permission, download

11. **`mailto:`·`tel:`만 OS로 넘기고, main frame에서 사용자 입력 직후일 때만 넘긴다.** subframe은 조용히 막는다. 주소 칸에 적은 `mailto:`는 page 입력이 아니라서 거절한다. main frame의 이 이동은 `will-frame-navigate`가 먼저 오고 거기서 막으면 `will-navigate`가 오지 않으므로, 넘기는 일은 `will-frame-navigate`와 redirect에서 한다.
12. **permission은 clipboard write(`clipboard-sanitized-write`)를 main frame의 http/https가 요청할 때만 허락한다.** 그 밖(clipboard read, media, 위치, 알림, device)은 모두 거절한다.
13. **download는 저장 경로를 정하지 않아 Electron 저장 dialog가 뜬다.** 시작한 contents를 모르거나 입력 직후(fresh)가 아니면 거절한다.
14. **user agent와 요청 header에서 `Electron/x`만 빼고 앱 이름 token(`lophn/x`)은 남긴다.** Chrome인 척하지 않는다. client hints(`sec-ch-ua`)와 page JS의 `navigator.userAgentData`는 Chromium 값 그대로다.
15. **사용자 입력의 시각은 인자로 받는다.** 전역 시계를 읽지 않는다.

### favicon, bookmark, 데이터 지우기

16. **favicon은 main이 그 page의 session으로 받아 data URL로 바꿔 싣는다.** shell CSP가 `img-src 'self' data: blob:`이고 shell 화면이 인터넷에 직접 요청하지 않는다. `page-favicon-updated`는 `did-finish-load`까지 기다려 늦게 오므로, `dom-ready` 시점에 main frame DOM의 `<link rel="...icon...">`(없으면 `<origin>/favicon.ico`)을 먼저 읽어 후보를 순서대로 시도하고, 뒤이어 오는 `page-favicon-updated`로 SPA 동적 변경까지 반영한다. 요청 `Referer`는 Chromium의 `strict-origin-when-cross-origin` 정책에 맞게 `<origin>/`만 싣고 `https:`→`http:` 다운그레이드에서는 뺀다. main은 `origin`·아이콘 URL 단위 메모리 cache(시작 시 bookmark favicon으로 seed, browsing data 삭제 시 비움)를 두어 재방문 시 `did-navigate`에서 바로 보이고 중복 fetch를 막는다. 작은 이미지(48KB 이하, content-type이 `image/`)는 그대로 싣고, 그보다 큰 이미지나 content-type이 빠진 이미지는 nativeImage로 32px PNG로 줄여 싣는다(받는 byte 2MiB, 결과 PNG 48KB, data URL 65536자까지). `text/html`·json·xml 같은 문서 응답은 디코딩하지 않고 버린다(WAF 챌린지 페이지가 favicon 자리에 오는 경우). `.ico`는 nativeImage가 디코딩하지 못해 축소 경로가 null이고, 48KB 이하일 때만 그대로 통과한다.
17. **탭의 favicon은 탭 필드에 두고 layout에도 저장한다.** 탭이 다시 mount될 때(접힘 해제, Float·Dock, desk 전환) 이 값을 이어 받는다(`<webview>`는 favicon을 모른다). main은 favicon을 바뀔 때만 밀므로, mount 여부와 상관없이 창이 state push를 받아 탭의 favicon을 갱신한다. 접힌 float과 다른 desk의 탭은 mount하지 않아 이 값이 접힌 아이콘의 출처이고, workspace를 옮겼다 오거나 다시 시작할 때 page가 아직 없는 탭의 아이콘도 이 값이다. layout의 favicon은 `data:image/`로 시작하는 65536자까지만 받고, 맞지 않으면 renderer가 빼고 저장한다(탭을 잃지 않게). bookmark favicon은 더할 때 저장하고, 이후 어떤 탭에서든 같은 주소나 같은 origin page의 favicon을 받으면 비어 있거나 바뀐 bookmark에 자동으로 반영해 모든 창에 알린다.
18. **데이터 지우기는 profile 하나의 저장소 전체를 지우고 cache를 지운 뒤 그 profile의 열린 page만 다시 load한다.** Settings의 Clear browsing data는 기본 profile이고 profile 줄의 Clear data는 그 profile이다. 목록에 없는 profile id도 받는다(지운 profile의 data를 지우는 길이다). 지울 종류를 이름으로 고르지 않는다(Electron 44의 이름이 rea·Chrome 문서와 달라 이름을 적으면 덜 지워진다).
19. **bookmark는 `<dataRoot>/shell/bookmarks.json` 하나에 main만 쓴다.** temp 뒤 rename으로 쓰고(폴더 0700·파일 0600) layout과 같은 방식이며, 쓰기를 한 줄로 세워 창 둘의 요청이 서로 덮지 않는다. 바뀌면 열린 모든 shell 창에 `shell:bookmarks-changed`로 알린다.
20. **깨진 `bookmarks.json`(JSON 아님, schema·version 불일치, 모르는 칸)은 어떤 쓰기도 덮어쓰지 않는다.** 목록은 `corrupt` 상태로 보이고 화면은 고치는 길을 열지 않는다. byte 단위로 그대로 남는다.
21. **bookmark url은 http/https이고 userinfo가 없는 것만, `href` 완전 일치로 하나만 둔다.** 1000개, title 200자, url 8192자까지다.

### DevTools

22. **DevTools는 page마다 새 native view 하나에 붙인다.** `<webview>`는 DevTools를 담지 못한다(frontend가 page에 붙지 않는다). 붙은 view는 탭 안, floated 패널, 다른 OS 창으로 옮겨도 끊기지 않는다. 닫을 때는 view를 부순다. 닫은 뒤 같은 view로 다시 열면 붙지 않는다. 열린 상태는 main이 든다(Electron의 열림 질의가 이 방식에서는 늘 false다).
23. **DevTools 경계 막대는 DOM drag다.** 끄는 동안 투명한 막을 page 위에 덮고 DevTools native view를 숨긴다.

### terminal bridge

24. **bridge의 권한 판정은 순수 함수가 한다.** 요청 줄은 JSON 한 줄, `v === 1`, key 64자 hex, 8192 byte 이하만 받는다. browser 탭으로 넘기는 URL은 절대 http/https, userinfo 없음, 8192자 이하다. local은 `localhost`·`*.localhost`·`*.local`·loopback·사설·link-local IPv4와 `::1`·`fc00::/7`·`fe80::/10`이다.
25. **`pane`은 "창이 실제로 탭을 열었다"는 뜻이다.** core는 host queue에 browser 탭을 올리고 shell이 page를 만들었다고 답할 때만 `pane`이다. 2000ms(shim의 3000ms보다 짧다) 안에 답이 없거나 shell이 붙어 있지 않으면 거두고 `declined`다. 조용히 사라지는 URL은 없다. Ctrl/Cmd-click도 탭이 안 열리면 shell main이 OS browser로 연다. bridge가 준비 실패로 꺼져 있어도 link는 OS browser로 간다.
26. **key는 터미널마다 core가 발급한다.** bridge가 자기 listen에 성공한 뒤에만 key와 env를 만들고, host open이 성공해야 key를 그 터미널에 묶는다. 묶이지 않은 key의 요청은 `declined`다. 터미널이 끝날 때 폐기한다. 인증은 key가 표에 있는지만 본다(SID·DACL 검사는 더하지 않는다). 그 터미널의 process는 env로 key를 이미 알고, POSIX socket은 `0700` 폴더 안의 `0600` file이고 Windows는 named pipe다.
27. **env는 `BROWSER`와 `LPN_BROWSER_BRIDGE` 둘이다.** `LOPHN_`로 시작하는 env는 terminal이 지우므로 이름을 `LPN_`으로 했다. host는 strip 뒤에 덮는다. 사용자가 앱 env에 `BROWSER`를 두었으면 넣지 않는다. 그 shell은 key도 없어 Ctrl/Cmd-click link도 OS browser로 간다. 단 `LPN_BROWSER_BRIDGE`가 같이 있으면 바깥 lophn의 shim이라 덮는다.
28. **shim은 core가 켜질 때 만든다.** 박아 넣는 Electron 실행 경로가 packaged와 dev에서 달라 설치 묶음에 싣지 않는다. POSIX는 per-run 폴더의 sh, Windows는 data root `run\browser-<hash>\browser.exe`이고 둘 다 공통 JS를 Electron Node로 띄워 사용자 PATH의 `node`를 기대하지 않는다. Windows exe는 OS의 .NET Framework 4 `csc.exe`로 build하고 같은 내용이면 다시 쓴다. csc가 없으면 bridge만 끈다. `.cmd`를 쓰지 않는 이유는 cmd.exe가 인자의 `& | % ^`를 명령으로 해석하고(URL이 잘리고 `&` 뒤가 실행됐다) file을 console 코드페이지로 읽어 한글 경로가 깨졌기 때문이다. exe는 자기 child에만 `ELECTRON_RUN_AS_NODE=1`을 두고 인자를 CommandLineToArgvW 규칙으로 다시 묶어 넘긴다. Windows OS fallback은 `cmd.exe start`의 빈 title과 URL을 분리하고 cmd metacharacter를 escape한다. shim은 URL·key를 출력하지 않고, OS opener에 넘길 때 `BROWSER`·`LPN_BROWSER_BRIDGE`·`ELECTRON_RUN_AS_NODE`를 지운다(안 지우면 `xdg-open`이 shim을 다시 부른다).
29. **공통 JS는 CJS·ESM 어느 package 아래서도 돈다.** Windows 개발 실행은 file 폴더가 저장소 data root 아래라 `"type": "module"`을 물려받는다. 그래서 `require` 전역에 기대지 않고 async 안의 dynamic import로 Node 모듈을 읽는다.
30. **per-run 폴더 자리는 core socket 폴더 규칙을 따른다.** POSIX는 공통 directory 아래 `core-<pid>/`(0700), Windows file은 `<data root>/run/core-<pid>/`이고 endpoint는 별도 named pipe다. pipe는 file처럼 mkdir·chmod·remove하지 않는다. 두 endpoint의 UTF-8 byte가 플랫폼 한도(Linux 107·macOS 103·Windows 256)를 넘으면 폴더 정리 전에 hook·bridge를 끄고 로그 한 줄만 남긴다. pointer file·TCP fallback은 없다. 터미널은 그대로 뜬다(OS browser). 시작할 때 같은 data root의 자기 pid 또는 죽은 pid의 `core-<숫자>` 폴더와 옛 판 shell이 남긴 죽은 pid의 `shell-<숫자>` 폴더만 지우고, 살아 있는 sibling·다른 이름·core socket·다른 data root는 건드리지 않는다.
31. **hook 준비는 shim·bridge listen과 분리한다.** 폴더가 준비되면 hook은 자기 endpoint를 독립적으로 연다. shim 쓰기나 bridge listen이 실패해도 hook이 쓰는 폴더는 지우지 않는다.
32. **link를 열 곳은 core 선언 설정 `shell.browser.web_links`·`shell.browser.local_links`(`browser_tab` | `system_browser`, 기본 `browser_tab`)다.** core의 bridge와 shell main(Ctrl/Cmd-click, `memory:settings/list`)이 요청마다 읽고, 못 읽으면 기본값이다. Settings › Browser › Links가 고친다. key 글자는 core의 선언·bridge와 shell의 판정에 있다(shell은 core를 import하지 못해 사본을 둔다).
33. **탭을 여는 자리는 renderer의 open 규칙이 정한다.** 규칙은 `workspace-layout.md`의 "탭 안에서 연 것의 자리"다. terminal이 보이지 않는 desk에 있으면 그 desk로 넘어가 terminal 탭 바로 뒤에 연다(로그인 URL은 사람이 그 page를 봐야 해서). 그 desk의 view를 hook이 모르므로 반대쪽 pane 규칙은 보이는 desk에만 쓴다. 그냥 click은 text 선택이고 Ctrl/Cmd-click만 link다. OSC 8 자동 링크는 지금도 삼킨다.

### agent가 다루는 탭

34. **`lophn browser snapshot|act|navigate|screenshot|evaluate|logs|wait`는 `tab open`으로 연 browser 탭, 사람이 넘긴 browser 탭, preview 탭, artifact 탭, phone 탭만 다룬다.** 주인(연 session, 넘겨받은 session, 받은 session, 사람 token이면 "person")만 부른다. session이 든 탭을 자기 밑 session에 주면(`tabs/give`, `workspace-layout.md` "agent가 연 탭"의 주기) 준 session은 되찾기 전까지 그 탭을 부르지 못하고 받은 session만 부른다. 탭 id, page, profile은 그대로다. 사람이 손으로 연 탭(사람이 연 artifact 탭 포함)은 사람이 session에 넘기기 전에는, 앱 live 화면은 늘 다룰 수 없다(앱 live 화면은 sender view 신원으로 operation 막기를 건너므로 어떤 bind로도 고르지 않는다). 길은 host queue의 `browser_call`이다(`workspace-layout.md` "agent가 연 탭").
35. **상태는 core 표에 있는 탭만 core에 알린다.** agent가 연 탭(key `host:`)과 사람이 넘긴 탭의 url·title·loading을 renderer가 `shell:surface-report`로 보내고 main이 `/host-link`의 `report` frame으로 core 표에 둔다. state와 bind는 창 단위로 알려 그 workspace가 mount되지 않은 동안에도 간다. agent와 사람 token은 `lophn browser read <tab>`으로 자기 탭의 마지막 상태를 읽는다. 없는 탭, 닫히거나 page가 없어져 core 표에서 빠진 탭, 남의 탭, 사람이 되찾은 탭은 같은 `not_found` 문장 하나다(탭이 있는지 새지 않게). 사람이 손으로 연 탭(넘기지 않은)과 상태가 아직 없는 탭도 `not_found`다. 넘긴 탭은 넘길 때 그 url로 상태가 선다.
36. **page에서 온 글은 `<lophn-untrusted source="browser.<명령>">`로 감싼다.** page는 인터넷이다. lophn agent는 tool 이름 규칙으로, binary는 찍는 글에 같은 tag를 둔다. 본문의 `<lophn-`는 escape되어 tag를 닫지 못한다. tag를 만들고 escape하는 곳은 core 밖 공유 protocol 코드 하나다(binary가 core를 import하지 못해서). 반대로 `browser`·`tab` 호출의 `unavailable`·`conflict` 문장과 `browser` 호출의 `not_found` 문장은 감싸지 않고 model에 그대로 간다. 그래서 그 문장은 lophn이 쓴 고정 문장(원인, 다음 할 일, 되풀이해도 되는지)이고 page나 Chromium의 글을 넣지 않는다(net error 이름만 예외). `not_found`는 없는 탭과 남의 탭이 같은 문장이라 존재가 새지 않고, 탭이 닫혔으면 다시 열라고 알려야 해서 싣는다. 이유를 못 받은 agent가 바깥 browser를 띄운 일이 있어서다.
37. **host가 CDP로 실행한다.** page host에서는 탭마다 든 offscreen page가 그 탭의 page다(63). desktop 앱에서는 renderer가 host 탭의 view session을 `shell:surface-report {bind}`로 알리면(host browser 탭은 창 단위로 알려 workspace가 mount되지 않아도 된다) main이 browser 탭은 `wv-<id>`의 guest(알려진 browser profile의 partition인 것만. page의 profile을 그 partition에서 읽는다), preview 탭은 앱 view registry에서 `mode: "preview"`인 view만, artifact 탭은 artifact view registry에 붙은 guest만 고른다. 그 탭의 첫 호출에서 debugger를 붙여 탭이 닫힐 때까지 둔다. 마우스는 CDP `Input.*`이고 키와 글은 그 page의 `webContents.sendInputEvent`다. CDP의 key event는 page가 아니라 창에서 keyboard focus가 있는 곳(shell 입력칸, 사람이 보던 다른 page)으로 가서 agent가 누른 Control+w가 사람의 탭을 닫았다. `sendInputEvent`는 탭이 숨었든 접혔든 사람의 focus가 어디 있든 그 page에만 가고, page가 받지 않으면(그릴 view가 없음) 남은 key를 보내지 않고 `unavailable`이다. input을 넣는 동안(page를 한 번 다녀오고 150ms 뒤까지) 그 page를 표시한다. 표시는 그 창에 먼저 알리고 창이 받은 뒤에 넣는다(`shell:driver-input`·`shell:driver-focus`). 표시 중에는 (가) lophn의 키가 창 단축키·menu 단축키가 되지 않고, (나) page를 누르거나 page 끝에서 Tab을 쳐 Chromium이 옮긴 창 focus를 창이 곧바로 사람이 있던 요소로 되돌리며(입력칸의 선택까지, 그 focus event는 삼킨다), (다) focus가 잠깐 그 page에 간 사이 사람이 친 키는 버린다(사람이 원래 그 page에서 치고 있었거나 표시 중에 그 page를 눌렀으면 그대로 둔다). 표시를 받기 전에 온 같은 page의 다음 input은 먼저 온 input 뒤에 들어간다. 되돌리는 것은 focus가 그 page로 들어간 것, 창 문서가 focus를 잃은 것, 그 page에 Tab을 넣은 뒤의 이동뿐이고, 그사이 다른 이동(timer가 연 dialog, 사람이 누른 다른 page)은 그대로 둔다. 그래서 agent의 input은 사람이 치던 곳을 거의 바꾸지 않지만 빈틈이 남는다("열린 것"). DevTools가 열려 있으면 붙지 못해 `conflict`다. page가 사라진 틈(그 page를 든 창이 닫힘, page가 죽음)에는 browser 탭에는 "page가 없다, `tab open --url`로 다시 열어라"를 `unavailable`로 답한다.
38. **snapshot과 ref.** accessibility tree를 `- <role> "<name>" [ref=eN]` 줄로 쓴다(입력 칸은 `value=`). ref 번호는 탭마다 하나의 counter에서 이어지고(다음 snapshot은 앞 번호 다음부터) 탭은 마지막 snapshot의 ref만 든다. main frame이 이동하면 비운다. 그래서 옛 ref는 새 node를 가리키지 않고 `conflict`다.
39. **dialog는 자동으로 닫는다.** alert·beforeunload는 accept, confirm·prompt는 dismiss이고 그 호출(다루지 않는 사이에 뜬 것은 다음 act·navigate·wait)의 결과에 `dialog`로 적는다.
40. **take control.** agent가 다루기 시작한 탭은 탭 머리(preview는 안내 줄)에 "<주인 agent 이름> is controlling this tab"(이름을 모르면 "An agent is controlling this tab")과 [Take control]을 둔다. 사람이 넘긴 탭이면 그 줄에 [Take back]이 더 선다(`workspace-layout.md` "agent가 연 탭"). 사람이 가져오면 agent의 act·navigate·evaluate는 `conflict`이고 snapshot·screenshot·logs·wait·read는 된다. [Hand back]으로 푼다. 사람은 다른 기기에서도 가져오고 돌려준다(70). "agent가 다루는 중"은 그 탭에 browser 호출이 한 번이라도 온 것이다(사람 token의 `lophn browser` 호출도 같다). 상태는 host 메모리에 탭마다 있고, core는 보는 쪽이 있는 page의 상태만 host가 알려 준 대로 든다(70). 넘기기와 take control 규칙은 agent가 다루는 터미널 탭(`terminal-agent.md`)과 같은 모델을 쓴다.
41. **뒤에 연 탭도 바로 다룬다.** `tab open`은 늘 뒤에 열리므로 host 탭의 browser·preview·artifact 본문은 고르지 않아도 숨은 그릇에 mount된다. agent가 다루는 동안 숨은 guest는 그리기를 이어 가야 screenshot과 입력이 되므로, 다른 내용 뒤가 아니라 창 오른쪽 아래 1px만 걸쳐 둔다(뒤에 두면 Chromium이 그리기를 멈춘다). host browser 탭(`--url`)은 여기에 더해 workspace가 mount되지 않아도 page가 있다. 창이 page를 그 workspace의 pool에 숨은 항목으로 만들어 두고 자리는 다음 mount로 미루며(다시 load하지 않는다), `tabs/open`은 page가 붙은 뒤에 답한다(shell이 있으면 10초, 앱을 띄웠으면 30초, 실패는 `unavailable`이고 탭이 남지 않는다). page는 탭을 닫거나 창이 닫히거나 상한(창마다 12개, 가장 오래 쓰지 않은 것)이 놓을 때까지 있다. 없어지면 탭도 core 표에서 빠지고 뒤의 `browser.*`는 `not_found`다(마지막 url을 되살리지 않는다. agent가 다시 연다). 창이 하나도 없으면 lophn이 창을 focus 없이 열고 앱이 꺼져 있으면 앱을 띄운다(`workspace-layout.md`, `platform.md`). display가 없는 Linux에서는 앱 대신 page host를 띄우고 page는 탭을 닫거나 page host가 끝나거나 기계 전체 상한(12개, 66)이 놓을 때까지 있다(64). 열린 창이 최소화되어 있으면 그리지 않아 screenshot이 실패한다. page host의 offscreen page는 늘 그린다.
42. **screenshot.** lophn agent는 image content로 받는다. binary는 PNG를 `--out <path>`나 `<os tmpdir>/lophn-screenshots/<tab>-<unix ms>.png`에 쓰고 그 path를 찍는다(harness는 자기 Read tool로 본다). emulation된 page의 screenshot은 CSS px 크기다.
43. **기기 emulation은 preview 탭에만 있고, 고른 기기는 탭 상태에만 있다.** emulation은 driver와 같은 debugger를 owner를 나눠 같이 쓴다(webContents 하나에 debugger 하나). DevTools가 열려 있으면 걸지 못해 Desktop으로 돌아가고 안내를 보인다. 건 뒤에 사람이 DevTools를 열면 debugger가 떨어져 기기가 풀리고, main이 건 상태를 비운 뒤 `shell:surface-emulation`으로 그 view session을 알려 preview 탭이 Desktop으로 돌아가 같은 안내(DevTools를 닫으라)를 보인다. 탭이 풀린 기기의 phone frame과 이름을 그대로 두지 않는다.

### site login

44. **login은 browser profile 하나에 속하고 값과 metadata를 나눠 둔다.** metadata `{id: "lgn_…", label, origin, username, note, profile?}`는 profile 정의와 함께 vault `<data>/browser-vault.json`(0600, atomic write, 없으면 빈 vault)에, 값은 `secrets.json`의 `login.<id>.password`와 `login.<id>.totp`(TOTP seed)다(`architecture/agent-definition.md` secret 저장소). vault는 칸마다 마지막으로 바꾼 stamp와 지운 것의 흔적을 함께 둔다(아래 "기계 사이"). `profile`이 없으면 기본 profile의 login이다: 읽을 때 null로 내고 기본 profile의 login은 칸 없이 쓴다. profile 말고 소유자(workspace, agent)는 없다. 어느 login을 누가 보고 치는지는 그 탭의 profile이 정한다(79~81). 저장된 값은 모두 known-value redaction에 오른다.
45. **사람만 넣는다.** Settings › Browser › Logins에서 줄을 더하고 고치고 지운다(`logins/save|delete`, 지우면 두 secret 이름도 지운다). 목록은 profile마다 묶이고 [Add login]은 그 묶음의 profile로 저장한다. 고쳐도 login의 profile은 그대로다(다른 profile로 옮기는 동작은 없다). password와 TOTP seed는 보호 입력 창(purpose `login`)이 받고, 창은 그 login의 origin을 크게 보인다.
46. **model은 handle만 본다.** `lophn login list [--origin] [--tab]`은 한 profile의 login(79)만 id, label, origin, username, note, profile, TOTP 유무로 낸다. agent는 `lophn browser act <tab> fill-login --ref eN --login <id> --field username|password|totp`로 친다. host queue의 `browser_call`과 ledger에는 login id만 있다. username은 비밀이 아니라 core가 metadata의 글로 `fill`을 만든다.
47. **origin은 그 ref 요소가 든 frame의 것이고 정확히 일치해야 값이 나온다.** shell main이 CDP로 ref node가 든 frame을 찾아 `Page.getFrameTree`의 `securityOrigin`을 잰다(최상위 URL도, page가 위조할 수 있는 `location.origin`도 아니다). core의 `logins/release`가 저장된 origin과 글자 그대로(scheme·host·port) 비교한다. 와일드카드·상위 도메인은 없다. 다르면 `forbidden`이다. page의 browser profile도 login의 profile과 같아야 한다(80). TOTP는 core가 지금 6자리 code(RFC 6238, SHA1, 30초)를 만들어 내준다.
48. **값은 shell main만 받는다.** `logins/release`는 입력에 shell capability(`connect {client: shell}`이 준 값)를 실어야 하고, 그 값은 shell main 메모리에만 있다. renderer allowlist에 release는 없다. HTTP user token, agent·worker credential, CLI는 부르지 못한다. 받은 값은 driver의 지역 변수에만 있고, 오류 글은 고정 문구이며, 결과는 `filled: true`뿐이다. 이 컴퓨터 밖으로는 명단의 다른 컴퓨터의 core에게 가는 vault 맞추기(85)만 있다.
49. **치는 동안 frame이 이동하거나 focus가 그 칸의 문서를 떠나면 멈춘다.** 값은 한 글자씩 치고 글자마다 그 frame이나 최상위가 이동했는지, frame이 떨어졌는지, keyboard focus가 아직 그 칸의 문서(origin)의 입력칸에 있는지 본다. 그렇지 않으면 더 치지 않고 `conflict`다. 지키는 경계는 칸이 아니라 origin이다: 비밀번호 보기 단추나 mask가 칸을 새 요소로 바꾸거나 한 자리씩인 OTP 칸이 다음 칸으로 넘어가도 친다. 다 친 뒤 그 칸이 그대로 focus면 글 길이(code point)가 값과 같아야 한다. 확인은 글자 사이에만 하므로 같은 process의 다른 origin frame이 focus를 가져가면 멈추기 전에 한 글자가 그 frame에 갈 수 있다(64자를 20번 쳐서 한 번 한 글자, 열린 것). 사람이 탭을 가져간 동안은 다른 act처럼 `conflict`다.
50. **browser 결과는 caller에 가기 전에 known-value redaction을 거친다.** snapshot, act, navigate, evaluate, logs, wait의 text와 read의 url·title이다. 알려진 값을 아직 다 모르면 `unavailable`이다. snapshot은 `type=password` 칸의 value를 찍지 않는다(값이 있으면 `••••`). Chromium AX가 가리는지에 기대지 않는다. `evaluate`와 screenshot은 막지 않는다(탭 주인 제한, untrusted 감싸기, take control이 그대로 있다).
51. **agent는 사람에게 login 입력을 요청할 수 있지만 보호 입력 창을 열지는 못한다.** `lophn login request <tab> --ref eN --mode save|once [--label]`(`input_request/ask`의 kind `login`)은 `ask`와 같은 session 대기열에 선다. 같은 요청 모델의 다른 종류가 secret 자리 요청과 sign_in(로그인) 요청이다(`architecture/agent-definition.md` secret 저장소). session당 사람에게 보이는 요청은 하나이고, 사람이 없는 turn이면 바로 `unattended`다. 요청은 대화에 card(agent 이름, 탭 제목, origin)로 뜨고, 사람이 card의 [Enter]를 눌러야 shell main이 창을 연다. [Cancel], turn 끝, 사람의 메시지는 `cancelled`다.
52. **card와 창의 origin은 shell main이 잰다.** 요청을 받으면 core가 host queue로 그 ref가 든 frame의 origin을 재게 한다(47과 같은 길). agent가 적은 글이 아니다. 피싱 site에 넣게 속은 요청을 사람이 origin으로 거른다.
53. **save는 새 login을 만들고 once는 값을 저장하지 않는다.** save 창은 label, username, password, 선택 TOTP를 받아 잰 origin과 그 탭의 profile(81)로 `logins/save`와 `secrets/put`을 부르고, agent는 `{login: id}`를 받아 이어서 `fill-login`을 부른다. once 창은 값 하나를 받는다. shell main이 그 값을 core 메모리에 known value로 붙들고(`input_request/hold`, 그 session이 끝날 때 푼다) 같은 frame의 origin을 다시 잰 뒤 같으면 친다. 다르면 치지 않고 `conflict`다. 값은 `secrets.json`, ledger, host queue, 결과 어디에도 없고 agent는 `{filled: true}`만 받는다. `hold`는 renderer allowlist에 없다. `done`은 대화 card가 sign_in 요청의 로그인 결과를 알리는 데만 쓰고(`architecture/agent-definition.md` secret 저장소) login·secret의 결과는 shell main만 낸다.

### phone 탭

사람의 폰(lophn 폰 앱)에 뜬 사용자 앱 preview 화면을 컴퓨터의 agent가 같은 `lophn tab`·`lophn browser`로 보고 다룬다. 폰 화면은 폰 앱 안의 guest runtime에서 도는 React Native라(`phone-screen.md`) CDP가 없다. core가 폰 link로 묻고(`remote.md`의 "core가 폰에 묻는 길", kind `drive.*`) 폰 앱의 native module이 guest의 Android view tree를 읽고 입력을 넣는다.

54. **여는 것은 그 앱 workspace의 session과 사람뿐이다.** `lophn tab open --phone <app> [--screen <key>]`(`tabs/open`의 target `{phone: {app, screen}}`)는 `--preview`와 같은 주인 검사를 한다. 다른 앱 workspace의 session은 `not_found`, 그 앱의 preview가 돌지 않으면 `conflict`(먼저 `preview start`), 폰이 그 preview를 보이지 않으면(`--screen`이면 그 화면을) `unavailable`이고 문장이 사람에게 부탁하라고 말한다. 탭은 core의 같은 탭 표에 kind `phone`으로만 있고 shell에는 생기지 않는다. 앱마다 하나(`phone:<app>`)라 다시 열면 같은 탭이 주인과 `--screen`만 바꿔 돌아온다. `tab show`는 `invalid_input`(탭이 폰에 있다), `tab close`는 core 표에서만 지운다.
55. **기기와 view는 부를 때마다 고른다.** 탭은 view를 쥐지 않는다. 호출마다 core의 view 표에서 그 앱의 preview view 가운데 기기 owner(`device:<id>`)의 것, `--screen`이면 그 화면의 것만 보고 가장 최근 쓴(열기, operation 호출) view 하나를 고른다. 탭은 마지막으로 고른 기기를 core 메모리에 기억해 그 기기에 preview view가 있는 동안은 그 기기에 머문다(두 기기가 같은 앱의 preview를 열어 두면 다른 기기가 화면을 쓰기만 해도 가장 최근 쓴 view가 바뀌어서다). 그 기기의 view가 사라지면 다시 고른다. live view와 desktop(사람·shell)의 view는 결코 고르지 않는다. 사람이 preview를 닫았다 다시 열어 view id가 바뀌어도, preview가 새로 지어져 폰이 새 view로 다시 열어도 같은 탭이 쓰인다. 고를 view가 없으면 폰에 묻지 않고 `unavailable`이다.
56. **폰은 자기가 연 preview view에만 답한다.** 폰 앱은 preview 화면이 열릴 때 그 view를 그 컴퓨터의 것으로 등록하고 닫힐 때 지운다. 요청의 view가 등록부에 없으면(live 화면, 닫힌 화면, 모르는 id, 다른 컴퓨터가 연 화면) native module을 부르지 않고 `unavailable`이다. 폰 앱이 앞에 있고 화면이 켜져 있을 때만 답하고, 무언가(sheet, dialog, notification shade)가 preview를 덮으면 `unavailable`(이유 `covered`)이다. 폰을 깨우거나 lophn 앱을 앞으로 부르지 않는다.
57. **되는 것은 일부다.** snapshot, screenshot, read, `wait --text`, act `click`·`type`(끝에 붙이기)·`fill`(바꾸기)·`press Enter`·`scroll`(`--ref`면 그 요소를 화면 안으로, 아니면 `--dy` dp만큼 세로로)이다. `navigate`, `evaluate`, `logs`, `hover`, `select`, `fill_login`, Enter 밖의 `press`(Back 포함), `wait --url`은 정한 문장과 `invalid_input`이다. 좌표 누르기는 없다. screenshot은 guest 영역만 JPEG(q80, 긴 변 1080 px)로 찍고(`browser/screenshot`의 `media_type`이 `image/jpeg`, CLI는 `.jpg`로 쓴다) 1 MiB를 넘지 않는다. read는 폰에 묻지 않고 `phone://<app>/<screen>`과 화면 key를 낸다.
58. **snapshot과 ref.** 폰은 snapshot마다 자기 node 번호(1부터)와 snapshot id를 내고, core가 탭의 counter로 `eN`을 매겨 `eN → (view, snapshot, node)`를 든다. 첫 줄은 `screen <key> <w>x<h>dp`이고 줄마다 desktop과 같은 `- <role> "<name>" [value=…] [flag…] [ref=eN]`에 flag(`disabled`, `checked`, `selected`, `scrollable`, `offscreen`)를 더한다. scroll container 안의 화면 밖 줄은 `[offscreen]`으로 싣는다. 입력 칸의 이름은 그 칸을 감싼 kit `Field`의 label이고 없으면 placeholder다. 마지막 snapshot이 아닌 ref, 다른 view나 기기의 ref는 폰에 묻지 않고 core가 `conflict`로 거른다. 폰도 node가 사라졌거나 role·name이 바뀌었으면 `conflict`(`stale_ref`), 화면 안으로 들이지 못한 node는 누르지 않고 `conflict`(`off_screen`)다(clamp한 점을 누르지 않는다).
59. **redaction과 untrusted.** snapshot 글, act·wait·read의 page(url, title)는 caller에 가기 전에 known-value redaction을 거치고 page 글은 다른 탭처럼 `<lophn-untrusted source="browser.<명령>">`로 감싼다. 폰은 secure 입력의 값을 읽지 않고 `••••`(비었으면 빈 값)를 낸다. 오류 문장은 lophn이 정한 고정 문장(`PHONE_TAB_TEXT`)이다: 보이지 않음, 앞에 없음·화면 꺼짐, 덮임, 폰 앱이 옛 판, 시간 초과, take control, 낡은 ref, 들이지 못함, 되지 않는 명령.
60. **take control은 폰에 있다.** 요청이 오는 동안 폰의 preview 화면 위 줄 아래에 "<agent> is driving this screen"과 [Take control]이 선다(사람 token이면 "Someone on your computer"). 사람이 가져가면 act는 `conflict`(`taken_over`)이고 snapshot·screenshot·wait는 된다. [Hand back]으로 돌려준다. 사람의 손 입력은 늘 된다. 상태는 폰 앱 메모리에 있고 그 preview 화면을 떠나면 끝난다. core는 모른다.
61. **입력은 guest에만 간다.** 누르기는 guest 표면(sandbox view의 직계 자식)에 touch를 넣고 글은 그 칸의 InputConnection으로 친다. lophn 폰 앱 자신의 화면, 다른 앱, system UI에는 닿지 않는다. 글을 친 뒤 soft keyboard를 내린다(guest는 keyboard에 줄지 않아 사람의 화면을 덮는다).

### 화면 없는 기계의 page

display가 없는 Linux(server, VM)에서도 agent가 같은 `lophn tab`·`lophn browser`로 browser를 쓴다. 사람은 그 page를 다른 기기에서 보고 로그인한다(아래 "멀리서 보기").

62. **page를 주는 쪽은 같은 link의 host다.** core는 지금처럼 link 건너편 host에 탭 열기와 `browser_call`을 시킨다. 화면 있는 기계에서 host는 desktop 앱이고, display가 없는 기계에서는 core가 띄운 page host다. page host는 같은 Electron binary를 창 없이(`--ozone-platform=headless --disable-gpu`) 띄운 것이고 탭마다 offscreen 창 하나를 든다(창 없는 Chromium은 offscreen 창이어야 page를 그린다. 숨긴 창과 창에 붙지 않은 view는 screenshot과 screencast가 끝나지 않는다). core 쪽에 browser provider를 따로 만들지 않는다: driver와 link가 이미 host를 가리지 않는다. page host는 workspace를 보이지 않으므로(`visible`이 빈 목록) workspace에 묶인 탭 요청(preview·artifact·session 탭)은 오지 않는다. browser가 아닌 탭 열기가 오면 `unavailable`이다.
63. **driver는 하나다.** page host는 desktop 앱이 쓰는 CDP driver(snapshot과 ref, act, screenshot, dialog, take control, site login의 `fill-login`)와 멀리서 보기의 stream을 그대로 쓴다. 다른 것은 탭의 page를 찾는 법 하나다: desktop 앱은 창이 view session을 알려 주고(37), page host는 탭을 열 때 만든 offscreen page를 스스로 든다. page host에는 보호 입력 창이 없다(51~53의 save·once 창을 띄울 화면이 없다). 그래서 page host는 `lophn login request`가 부르는 origin 재기를 정한 문장과 `unavailable`로 끊는다: 받아 두면 아무도 답하지 못하는 card에 agent가 끝없이 기다린다. 화면 없는 기계의 로그인은 이미 저장한 login의 `fill-login`이거나, agent가 `tab show`로 펴서(74) 사람이 멀리서 보며 직접 친다(68).
64. **어느 쪽인지는 lophn이 고른다.** core가 앱을 띄울 env(service core면 user manager에서 화면 값을 가져온 뒤, `platform.md`)에 `DISPLAY`도 `WAYLAND_DISPLAY`도 없는 Linux에서만 page host를 띄운다. 그 밖(display가 있거나 Linux가 아님)은 지금 그대로다(창이 없으면 창을, 앱이 없으면 앱을 띄운다. 41). agent에게는 같은 tool이다. 한 기계에서 둘이 같이 돌지 않는다: desktop 앱과 같은 single-instance lock을 잡아 나중에 뜬 쪽이 물러난다.
    - 이미 떠 있는 desktop 앱이 core의 `--page-host` 시작을 받으면 `--agent-window`로 읽는다(그 앱이 host다).
    - page host가 떠 있는데 사람이 desktop 앱을 켜면(화면 있는 기계에서 SSH로 core를 먼저 띄운 경우), 그 시작이 display가 있는 env를 실어 오면 page host가 desktop 앱을 다시 띄우고 1초 뒤 끝난다(바로 끝나면 누른 시작이 lock을 잡아 창이 둘 섰다). 다시 띄우는 인자와 env는 page host가 자기 쪽에서 만든다: data root는 page host 자신의 것(`--home`과 `LOPHN_HOME`)이고 누른 시작에서는 display 값만 가져온다. 누른 시작의 argv는 Electron이 순서를 바꿔 다시 읽지 않는다. 한 번 눌러 desktop 앱이 선다. 그 env에도 display가 없으면 page host가 남는다. `--quit`이면 끝나고, core만 띄우는 시작(`--core`)과 core가 다시 보낸 `--page-host`는 그대로 둔다.
    - page host의 수명은 core에 묶인다. page host는 desktop 앱과 같은 core 연결을 써서 core가 죽으면 다시 띄운다(선 지 60초 안에 죽는 일이 5번 이어지면 그만 띄운다). `lophn core stop`이면 다시 띄우지 않고, `/host-link`가 60초 넘게 닫혀 있으면 끝난다. 마지막 page를 닫아도 끝나지 않는다. desktop 앱에 물려줄 때 page host가 든 page는 닫힌다. 열린 연결은 idle-exit의 client라 page host가 붙은 core는 stop 전에는 idle-exit하지 않는다(`platform.md`).
65. **browser profile은 desktop 앱과 같다.** page host는 desktop 앱과 같은 profile 자리(userData)와 같은 profile partition(`tab_open`의 browser target이 싣는 profile, 없으면 기본 `persist:lophn-browser`)을 쓰고 partition마다 처음 쓸 때 같은 permission·user agent 규칙을 건다. 화면 없는 기계에서 사람이 멀리서 한 로그인이 남고, 나중에 그 기계에 화면이 생겨도 이어진다. 저장된 site login(44~50, 79~81)도 그대로 쓴다. popup은 둘 자리가 없어 거절하고, download는 저장 dialog를 띄울 화면이 없어 모두 거절한다.
66. **page를 여는 차례와 상한.** offscreen 창은 headless에서 1x1이라 크기를 정해 준다. 먼저 `about:blank`를 열고, debugger를 emulation owner로 붙여 1280x800 크기를 건 뒤(아무것도 load하지 않은 page에 크기 emulation을 보내면 process가 죽는다), 첫 주소를 load한다. 주소가 바뀔 때마다(main frame navigation) 크기를 다시 건다: 걸지 않으면 screenshot은 맞아도 screencast가 실제 1x1 창을 찍고 첫 frame 뒤에 멈췄다. owner는 page가 사는 동안 떼지 않는다(떼면 크기가 풀린다). 첫 주소도 page 안의 이동과 같은 navigation 규칙을 지나고 못 지나면 빈 page다. 그리는 빈도는 10 fps로 둔다(보는 쪽 없이 움직이는 page의 비용과 stream의 상한). page는 기계 전체에 12개이고(창 하나의 상한과 같은 수, 41) 넘치면 가장 오래 쓰지 않은 page(열기와 browser 호출이 쓴 때)를 닫는다. page가 닫히거나 renderer가 죽으면 탭도 core 표에서 빠진다.

### 멀리서 보기

사람의 다른 기기(폰, 다른 기계의 desktop 창이 연 탭)가 이 기계의 browser 탭을 보고 다룬다. 화면 없는 기계의 page도, 화면 있는 기계의 page도 같다.

67. **터미널 보기와 같은 모양이다.** 보는 쪽이 `page_view/watch`로 lease(30초, 10초마다 갱신)를 잡은 동안 core가 host에 `page_stream`을 켜고, host가 그 page의 CDP screencast frame(`page_frame`, JPEG q60, 1280x800까지, 한 장 2 MiB까지)을 민다. 켜면 host가 지금 frame 하나와 상태(`page_state`)를 바로 보낸다. core는 탭마다 최신 frame 하나만 메모리에 들고(ledger 없음) 내용 없는 `PageViewChanged`를 내며, 보는 쪽이 `page_view/snapshot`으로 읽어 간다. 마지막 lease가 끝나면 끄고 그 탭의 frame과 상태를 지운다(다음에 보면 seq가 0부터 다시 오른다). 보는 쪽이 없으면 host는 frame을 만들지 않는다. host에 닿지 않아도 lease는 남아 연결이 다시 열리면 core가 다시 켠다. 켜고 끄는 요청은 탭마다 한 줄로 서서 순서가 뒤집히지 않는다.
    - 읽어 간 만큼만 다음 frame이 간다. core는 snapshot으로 내준 frame의 host seq가 마지막으로 host에 알린 seq와 다르면 `page_read`를 보낸다(크기가 아니라 다름을 본다: 다시 뜬 host는 seq를 처음부터 센다). host는 그것이 오기 전에는 그 탭의 다음 frame을 보내지 않고 마지막 하나만 들며 CDP screencast의 ack도 미룬다. 그래서 느린 보는 쪽에는 Chromium이 다음 frame을 만들지 않고, frame이 건너뛰어질 뿐 core와 link에 쌓이지 않는다. 보내기 사이는 100 ms 이상이다(10 fps).
    - 켠 탭이 다른 view에 다시 bind되면(다른 창이 page를 새로 만듦) host가 옛 page에서 끄고 새 page에서 다시 켜 frame과 입력이 탭을 따라간다. 연결이 다시 열리면 host는 모두 끄고 core가 살아 있는 lease마다 다시 켠다.
68. **대상은 core가 아는 browser 탭이다.** agent가 `tab open --url`로 연 탭과 사람이 `page_view/open`으로 그 기계에 연 탭(http·https, 주인 person, home workspace. 사람 token의 `tab open --url`과 같은 길이라 host가 없으면 띄운다)이다. 사람이 손으로 연 탭, preview·artifact·phone 탭, 앱 화면은 보지 않는다. 화면 없는 기계의 로그인은 사람이 탭을 열고 멀리서 보며 직접 한다. 사람이 연 탭을 멀리서 닫는 길은 두지 않는다. 목록과 snapshot의 url·title은 caller에 가기 전에 known-value redaction을 거친다(알려진 값을 아직 다 모르면 `unavailable`). 그림은 가리지 않는다(screenshot과 같다).
69. **보는 것은 내 기기 모두, 다루는 것은 터미널 입력을 허락받은 기기다.** `page_view/list|snapshot|watch`는 사람 자격이면 되고, `input`·`control`·`open`은 그 기기(`device:<id>`)의 터미널 입력 허락이 있어야 한다(없으면 `forbidden`. 기기가 아닌 사람 token도 `forbidden`이다). desktop 창의 다른 기계 탭은 이 컴퓨터 core의 `machines/call`로 그 기계에 이 컴퓨터의 기기로 닿으므로 받는 컴퓨터가 자기 허락 표(`remote.md`의 터미널 입력 허락)에서 이 컴퓨터를 본다. 사람의 CLI token으로 부른 `terminal` 요청은 허락이 있어도 이 route를 쓰지 못한다. list와 snapshot의 `control`이 부른 쪽이 다룰 수 있는지를 알려 화면이 열기 칸과 입력을 미리 그리거나 감춘다. 로그인된 browser를 다루는 것은 터미널에 치는 것만큼 센 권한이다. agent 자격은 이 길을 아예 쓰지 못한다(자기 탭도. agent에게는 `browser screenshot`이 있다).
70. **끼어들면 agent가 멈춘다.** `page_view/control`은 그 기계의 take control(40)과 같은 상태를 잡고 놓는다. 잡기는 그 탭을 보고 있어야(lease) 하고(없으면 `conflict`), 놓기는 다룰 수 있는 기기 누구나 한다. 멀리서 잡아도 agent의 쓰기 동작이 `conflict`로 막히고 놓으면 풀린다. 멀리서 잡은 것은 잡은 기기의 lease에 묶인다: 그 기기가 보기를 멈추거나(폰에서 뒤로 가거나 앱을 내림, desktop 탭을 닫거나 창이 보이지 않음) lease 기한이 지나거나(연결이 끊김) 그 기기가 다룰 수 없게 되면(명단에서 빠짐, 허락을 거둠) core가 host에 놓으라고 보낸다(5초마다 본다). 그렇지 않으면 보는 쪽이 떠난 뒤 agent가 멈춘 채로 남는다. core는 누가 멀리서 잡았는지 메모리에 들고 `page_view/list`의 `held_by`(부른 기기 자신, 다른 폰이나 컴퓨터)로 보인다. 그 기계의 화면에서 잡은 것은 core를 지나지 않아 여기 없다. 그 기계의 화면에도 잡혀 있음이 보인다. 아무도 browser 호출을 한 적 없는 탭(사람이 연 탭 등)에는 잡을 것이 없어 그대로다. 상태(agent가 다루는 중인가, 잡혀 있나)는 host가 `page_state`로 알리고 core가 snapshot에 싣는다.
71. **멀리서 하는 것은 pointer, 글자와 key, scroll, 주소로 가기, 뒤로, 다시 읽기다.** 입력은 그 탭을 보고 있어야(lease) 받는다(좌표가 본 frame에 대한 것이라서. 없으면 `conflict`). pointer는 왼쪽 단추 하나의 down·move·up이다(폰의 손가락과 desktop의 click·끌기를 같은 꼴로 받는다. hover는 없다). 좌표는 보는 쪽이 본 frame의 page CSS px다. key 이름은 agent의 `press`와 같고 key를 넣는 code도 같다. 입력은 agent의 입력과 같은 길(마우스는 CDP, 키는 `sendInputEvent`, 37)로 들어가고 사람의 입력이라 take control을 보지 않는다. key·text·pointer down은 37의 표시를 쓰고, pointer move·up과 scroll은 표시하지 않고 앞 input의 표시를 창이 받기만 기다린다(보는 쪽은 답을 기다리지 않고 보내므로 그래야 up이 down 앞에 들어가지 않는다). 주소는 navigation 규칙을 지나야 가고, 다시 읽기는 page 안의 `location.reload()`다. 같은 `key`는 한 번만 넣고, host가 없거나 끊기면 넣지 않고 다음 연결로 다시 보내지 않는다(늦은 입력이 page에 들어가면 안 된다).
    - 폰: 한 번 누르기는 down·up, 끌기는 누른 동안 move(초당 30번까지), 두 손가락은 scroll이다. 글은 글 칸에서 `text`로 보내고 key 줄이 Enter, Backspace, Tab, 화살표를 보낸다.
    - desktop: 그림 위의 숨은 입력칸이 쳐진 글을 받아 `text`로 보낸다(IME 조합이 끝난 글도 한 길로 온다). Ctrl·Cmd·Alt를 낀 조합과 이름 있는 key만 `key`다. Ctrl·Cmd+V는 이 컴퓨터의 clipboard 글을 `text`로 보낸다. 창의 단축키가 먼저 가져간 key는 보내지 않는다.
72. **그리지 않는 page는 그렇다고 보인다.** 화면 있는 기계의 창이 최소화되거나 숨겨져 있으면 page가 그리지 않아 frame이 없다. host가 `page_state`의 `painting: false`로 알리고 보는 쪽은 그 이유를 보인다(같은 이유로 screenshot도 실패한다. 41). host는 그 page를 든 창의 최소화·숨김, debugger가 떨어짐, 켜거나 깨운 뒤 2초 동안 frame이 없음을 그리지 않는 것으로 본다. 창이 되살아나면(restore, show) screencast를 다시 켜 첫 frame을 받고, frame이 오면 다시 그리는 것이다.
73. **보는 화면은 둘이다.** 폰 앱의 Pages(sidebar의 줄. 목록과 열기 칸, page 하나의 화면)와, desktop 창의 탭이다. 새 탭 menu가 연결된 다른 기계마다 "Pages on <기계>"를 두고, 그 항목이 그 기계의 Pages 탭(목록 탭)을 연다. 탭이 기계를 든다(`TabItem.machine`): 목록 탭은 기계마다 하나이고 page마다 탭이 따로 서며 탭 줄에 그 기계의 꼬리표가 붙는다. 탭 본문은 그 기계의 범위(`TabScope`)에서 그 기계의 core로 `page_view/*`를 부르고, 그 기계가 꺼져 있으면 본문 대신 그 기계의 상태 한 줄이다. 한 대만 쓰는 사람의 menu에는 이 항목이 없고, 이 컴퓨터의 agent page는 browser 탭이다. page id가 그 기계 core의 것이고 agent가 닫으면 사라지므로 page 탭은 저장하지 않는다. 둘 다 다룰 수 없으면 머리의 주소·뒤로·다시 읽기·잡기와 입력을 감추고 볼 수만 있다는 것과 허락을 켜는 곳을 한 줄로 보인다. page가 닫히면(`not_found`) 닫혔다는 한 줄만 남고 lease를 놓는다. 폰은 뒤로 가면, desktop은 탭이 닫히거나 창이 보이지 않으면 보기를 멈춘다.
74. **agent가 편 page는 그 session을 보는 다른 컴퓨터의 창에도 뜬다.** `tab show`(`tabs/show`)는 그 기계의 창에 tab_show를 보내고, browser 탭이면 core가 `TabShowRequested {tab}`(subject는 session)도 낸다. 그 session의 대화 탭을 다른 컴퓨터의 창에서 그리고 있으면 그 창이 그 page의 원격 보기 탭을 열고 고른다. 이 컴퓨터의 session은 듣지 않는다(shell main이 float을 편다). 그래서 사람 손이 필요한 page(로그인, captcha)가 화면 없는 기계에서도 사람이 보는 화면에 닿는다. 그 기계에 화면이 있고 다른 컴퓨터에서도 보고 있으면 둘 다에 뜬다. 보는 화면이 없으면 아무 데도 뜨지 않는다(화면 있는 기계의 창이 최소화된 것과 같다).

### browser profile

profile마다 cookie·저장소와 저장 login을 나눈다(모델의 "browser profile"). 번호는 앞 묶음을 다시 매기지 않으려고 이어 붙였다.

75. **기본 profile은 처음부터 쓰던 partition이고 id가 없다.** `persist:lophn-browser`를 그대로 써서 profile을 두기 전의 로그인과 cookie가 기본 profile에 남는다. 사람이 만든 profile의 partition은 `persist:lophn-browser-<profile id>`이고 디스크 자리는 Electron이 userData 아래에 정한다. "칸이 없으면 기본 profile"이 탭 값의 `profile`, agent 정의의 `browser_profile`, 저장 login의 `profile`에 같아서 옛 data를 옮기는 step이 없다.
76. **main은 알려진 profile의 partition만 붙이고 driver도 그 guest만 browser 탭으로 본다.** 붙이기는 renderer가 적은 partition이 기본이나 지금 core의 profile 목록(main이 `browser_profiles/list`를 읽고 `StateChanged{browser_profiles}`에 다시 읽는 사본)의 profile partition일 때만 받는다(2). 목록을 아직 읽지 못했으면 기본 profile만 알려진 것이다. driver는 그 partition의 guest만 고르고 page의 profile을 그 partition에서 읽는다(37).
77. **탭의 profile은 정해지면 바뀌지 않고 탭에서 연 것은 연 탭을 따른다.** page 안에서 연 탭, 크기 준 popup(opener의 contents라 같은 session이다), 그 popup을 dock한 탭, Open in new tab은 연 탭의 profile이다. profile이 있는 탭은 목록을 읽기 전에 page를 만들지 않는다: 그 사이 기본 partition으로 만들면 다른 cookie로 site에 가고 그 탭의 partition은 다시 바뀌지 않는다.
78. **agent는 profile을 고르지 못한다.** `tabs/open`의 browser target 입력에는 profile이 없다. core가 연 session의 agent 정의 `browser_profile`을 풀어 host 요청의 browser target에 싣는다. 정의에 칸이 없거나 그 profile이 지금 목록에 없으면(사람이 지웠다) 기본이다. ledger나 정의를 읽지 못하면 기본으로 떨어지지 않고 `unavailable`이며 탭을 열지 않는다. 사람 token이 연 탭은 기본 profile이다.
79. **agent는 한 profile의 login만 본다.** `logins/list`는 agent가 `tab`을 주면 그 탭(자기 탭이어야 하고 남의 탭·없는 탭은 `not_found`)의 profile, 주지 않으면 자기 agent 정의의 profile에 든 login만 낸다. 사람은 `tab`을 주면 그 탭(사람 token의 탭)의 profile, 주지 않으면 전부다. browser 탭이 아닌 탭(preview, artifact, phone)의 page는 browser profile partition이 아니라서 그 탭의 login은 기본 profile의 것이고, 자기 profile이 기본인 쪽(사람, profile을 달지 않은 agent)만 그 탭에서 보고 친다. profile을 단 agent에게는 그 탭의 목록이 비고 `fill-login`은 없는 login과 같은 `not_found`이며 login 저장 요청(save)은 `forbidden`이다(once는 저장하지 않아 된다). 자기 profile을 알아야 하는데 정의를 읽지 못하면 `unavailable`이다.
80. **값은 page의 profile이 login의 profile과 같을 때만 나간다.** core는 `fill-login`의 login이 그 탭에서 다룰 profile(79)의 것이 아니면 "no login with that id"(`not_found`)로 답한다: 다른 profile의 login은 그 탭에 없는 login이다. shell main은 `logins/release`에 page의 profile(driver가 page의 partition에서 읽은 값)을 싣고 core는 login의 profile과 다르면 origin이 다를 때와 같이 `forbidden`이다. 다른 profile의 탭에는 다른 cookie로 들어간 site가 있다.
81. **login 저장 요청은 그 탭의 profile에 둔다.** `login request`의 card와 save 창이 그 탭의 profile을 싣고 save가 그 profile로 `logins/save`를 부른다. `logins/save`의 `profile`은 새 login에만 쓰고 있는 login을 고칠 때는 그 login의 profile을 그대로 둔다.
82. **profile을 지우면 그 profile의 partition data를 지우고, 그다음 core가 그 profile의 login 값, login, profile을 지운다.** 앞이 실패하면 멈추고 알리며 profile이 남아 다시 할 수 있다. 확인 dialog가 지울 login 수와, 그 profile을 쓰던 agent가 기본 profile로 연다는 것을 말한다. agent 정의의 칸은 지우지 않는다(풀 때 기본이 되고 편집기가 표시한다).

### 기계 사이

profile 정의(이름, 색)와 저장 login(metadata와 password·TOTP seed)을 사람의 짝지은 컴퓨터(명단의 컴퓨터)들에서 같게 둔다. cookie와 site 저장소, 어느 agent가 어느 profile을 쓰는지는 컴퓨터마다다.

83. **길은 컴퓨터 사이 link 하나다.** 각 컴퓨터가 link가 붙은 명단의 컴퓨터마다 그 vault를 받아(`browser_vault/exchange`) 자기 vault에 합친다. 받기만 있고 보내기는 없다. link는 두 core의 host key 사이 Noise IK(X25519, ChaCha20-Poly1305)라 relay를 거쳐도 relay는 암호문만 본다. `computers` 폴더, 사람이 고른 같이 보는 폴더, 폰, relay가 읽는 곳에는 profile 이름도 origin도 username도 값도 쓰지 않는다. 그래서 두 컴퓨터가 같은 때 켜져 있어야(직접이든 relay든) 맞춰진다. 늘 켜 둔 컴퓨터가 있으면 저절로 가운데가 된다.
84. **받는 것은 명단의 컴퓨터의 core 자신뿐이다.** 기기 입구는 이 route를 그 컴퓨터의 core가 요청한 쪽 없이 보낸 call로만 받는다(`remote.md`의 REMOTE_COMPUTER_CORE_ROUTES). 폰, 그 컴퓨터의 화면·터미널(그 컴퓨터의 coding agent도 같은 token이다)·agent·앱 요청은 `forbidden`이다. handler는 부른 기기가 지금 명단의 컴퓨터인지 한 번 더 본다: 이 컴퓨터의 사람 token, agent, CLI는 막힌다. 명단에서 빠진 컴퓨터는 자격과 연결이 곧바로 거둬져 그 뒤로는 받지 못한다. 이미 받아 그 컴퓨터의 `secrets.json`에 있는 값은 거둘 수 없다.
85. **값은 shell main 말고는 core 밖으로 나가지 않는다는 규칙에 이 하나를 더한다.** 다른 컴퓨터의 core로 가는 exchange 응답이다. 받은 값은 secret store의 put으로 쓰여 쓰기 전에 알려진 값(redaction)에 오른다. 값은 ledger, log, event, mail, 오류, model 입력에 없다. agent가 보는 것은 그대로 handle(46)이다.
86. **칸마다 합친다.** vault는 profile과 login의 칸마다(login은 label, origin, username, note, password, totp) 마지막으로 바꾼 stamp를 든다. stamp는 바꾸는 컴퓨터의 max(지금 ms, vault에서 본 가장 큰 stamp + 1)이다. 합칠 때 칸마다 stamp가 큰 쪽이 이긴다. stamp가 같으면 값이 있는 쪽이 이긴다: 값은 더 새 stamp로만 지워진다. 둘 다 값이면 글자 순서가 큰 쪽이라 어느 컴퓨터에서 합쳐도 같다. 그래서 떨어져 있는 동안 두 컴퓨터가 한 login의 다른 칸을 고치면 둘 다 남고, 같은 칸을 고치면 나중에 친 값이 남는다(앞 값은 남지 않는다). 값을 넣거나 지우면(보호 입력 창) 그 칸의 stamp가 오른다.
87. **지운 것은 흔적으로 남고, 지울 때 몰랐던 고침이 있으면 되살아난다.** 흔적은 지울 때 본 칸 stamp를 든다. 다른 컴퓨터의 사본에 그보다 새 칸이 있으면 그 항목은 되살아나고 흔적이 빠진다. 아니면 지운 것이 이기고 그 컴퓨터에서도 지워진다. 지운 profile에 지울 때 몰랐던 login이 살아 있으면 profile도 되살아난다(그 login이 다른 cookie의 profile로 떨어지지 않게). 흔적은 지우지 않는다.
88. **처음 맞출 때는 합집합이다.** id가 `bpf_`·`lgn_` ULID라 컴퓨터마다 다르고 흔적이 없어 아무것도 지워지지 않는다. 같은 이름으로 따로 만든 profile은 둘로 남는다(이름 겹침 검사는 이 컴퓨터에서 만들거나 이름을 바꿀 때만 한다. 같은 이름의 둘 가운데 하나의 색만 바꾸는 것은 받는다). 같은 site를 두 컴퓨터에서 따로 저장했으면 login 둘이다. 기본 profile은 id가 없어 컴퓨터마다의 기본 profile끼리 맞는다: 기본 profile의 login은 다른 컴퓨터의 기본 profile에 간다.
89. **다른 컴퓨터에서 지워진 profile의 partition data는 이 컴퓨터의 합치기가 그 profile을 흔적으로 지웠을 때만 지운다.** 합친 vault를 쓴 뒤 그 id를 `clear`에 두고, shell main이 지운 뒤 `cleared`로 뺀다. 목록에 없는 것만으로는 지우지 않고, 되살아난 profile은 `clear`에서 빠져 지우지 않으며, 기본 profile은 들지 않는다.
90. **이 컴퓨터의 값을 못 읽으면 내주지도 합치지도 않는다.** `secrets.json`을 못 읽는 동안 exchange는 `unavailable`이고(상대는 실패한 받기로 보고 물러난다) 받기도 아무것도 쓰지 않는다. 못 읽은 값을 "없음"으로 내면 첫 맞추기 뒤 stamp가 같은 모든 컴퓨터가 password와 TOTP seed를 지우고 그것이 퍼진다.
91. **값은 흔적이 있는 login의 것만 지운다.** 합친 뒤 지우는 값은 합친 vault의 흔적(`removed`)에 든 login의 값뿐이다. vault에 없다는 것만으로는 지우지 않는다: `browser-vault.json`이 지워지거나 비면 빈 vault로 읽히고, 그때 vault 밖 값을 지우면 모든 저장 login 값이 사라진다. vault가 비어 있으면 받기가 다른 컴퓨터의 vault로 다시 채우고 남은 값은 같은 id로 다시 이어진다.
92. **login 값 쓰기와 합치기는 한 줄로 돈다.** 사람이 값을 넣거나 지우고 그 칸 stamp를 올리는 것, login·profile 지우기, 다른 컴퓨터 vault 합치기는 core 안에서 한 번에 하나씩이다. 합치는 사이 사람이 같은 칸을 저장해 사람의 새 stamp에 다른 컴퓨터의 값이 붙어 퍼지는 일을 막는다. 값을 쓴 뒤 stamp를 올리지 못하면 앞 값으로 되돌리고 오류를 낸다(새 값에 옛 stamp가 붙지 않게).
93. **나누기는 컴퓨터마다 하나의 설정(`shell.browser.share_with_computers`, 기본 켬, 사람만 바꾼다)이다.** 끈 컴퓨터는 받지도 내주지도 않는다(exchange가 `forbidden`이고 상대는 실패로 보지 않고 다음 계기를 기다린다). 이미 받은 것은 남는다.
94. **계기.** link가 붙음, 상대의 `StateChanged{browser_profiles|logins}`(2초 debounce), 5분 timer, 이 컴퓨터의 나누기를 켬. 컴퓨터마다 한 번에 하나이고 실패는 1분부터 두 배씩 1시간까지 물러난다. 물러나는 동안 온 계기는 버리지 않고 물러나기가 끝나면 한 번 받는다(줄을 세우지 않는다). 그 컴퓨터와 link가 다시 붙으면 물러나기를 풀고 바로 받는다. 받은 답이 오면 그 컴퓨터가 아직 명단에 있는지 다시 본다. 받은 값을 먼저 쓰고, 합치는 사이 vault가 바뀌지 않았을 때만 합친 vault를 쓰고, 그 뒤 흔적이 있는 login의 값을 지운다. 끊겨도 다시 합치면 같다.

## 경계와 계약

**shell IPC(renderer ↔ main).** preload `window.lophnBrowser`는 shell 창(project 창과 detached 창)에만 있다.
- 요청: `shell:browser-navigate`, `shell:browser-command`(뒤로·앞으로·새로 고침), `shell:browser-adopt`, `shell:browser-clear-data {profile}`(null은 기본 profile), `shell:browser-devtools-open|close|window`, `shell:bookmarks-list|add|update|remove`. native 항목의 자리는 `shell:view-bounds`·`shell:views-hidden`.
- push: `shell:browser-state`(url·title·loading·favicon·crash), `shell:browser-event`(kind `popup`, `popup-blocked`, `open-tab`, `close`, `bookmark-key`, `download`, `devtools-closed`), `shell:bookmarks-changed`.
- terminal: `shell:terminal-link`(Ctrl/Cmd-click). `$BROWSER`로 연 탭은 shell IPC가 아니라 host link의 `tab_open`으로 온다.
- agent 쪽: `shell:surface-report {bind}`, `shell:surface-request`·`surface-ack`, `shell:surface-control`·`surface-take`(take control), `shell:surface-emulate`, `shell:surface-emulation`(main → 창: 건 기기가 DevTools로 풀렸다), `shell:surface-workspace`.
- 오류는 공통 일곱 code다. 예: popup adopt의 다른 창은 `invalid_input`, 두 번째는 `forbidden`.

**layout.** browser 탭 `{key, url, favicon}`과 선택 `keep_alive`, `profile`(`bpf_…`, 없으면 기본 profile). 탭 공통 칸 `owner`·`handed_tab`은 `workspace-layout.md`다. 탭은 desk당 1200개 상한(layout 일반 규칙)이 있어 browser 전용 cap은 두지 않는다.

**저장 file.** `<dataRoot>/shell/bookmarks.json`(0600, 폴더 0700, atomic write, version과 알려진 칸만). run 폴더(`core-<pid>/`)는 core가 도는 동안만 있는 shim·socket 자리다.

**설정 key.** `shell.browser.web_links`·`shell.browser.local_links`(`browser_tab` | `system_browser`, 기본 `browser_tab`). `shell.browser.search_engine`(`google` | `duckduckgo` | `bing` | `naver` | `brave` | `perplexity` | `custom`, 기본 `google`)·`shell.browser.search_engine_custom`(`%s`를 포함한 http(s) URL template, 기본 `""`). `shell.browser.share_with_computers`(boolean, 기본 켬, locked라 사람만 바꾼다. 이 컴퓨터가 vault를 다른 컴퓨터와 맞추는가). `shell.devices`(preview 기기: 이름, 크기, DPR, OS `ios|android`, 32개까지, 기본 `[]`). 사람이 넣은 항목과 pairing한 폰의 항목이 같이 있다. 폰의 항목은 `device`(기기 id)를 달고 remote가 그 id로만 바꾸고 지운다. 이름이 겹치면 pairing이 숫자를 붙인다. `device`가 없는 항목은 remote가 건드리지 않는다.

**terminal bridge protocol.** 요청 `{v:1,key,url}` 한 줄 → 답 `{"result":"pane"|"declined"}` 한 줄. env `BROWSER`, `LPN_BROWSER_BRIDGE={"socket","key"}`. ack 대기 1500ms, shim 접속 한도 3000ms.

**host queue의 browser 호출.** memory route `tabs/open`, `tabs/close`, `tabs/show`, `tabs/list`, `tabs/hand`(사람만), `tabs/give`(agent만, 자기 밑 session에), `browser/read|snapshot|act|navigate|screenshot|evaluate|logs|wait`(boundary-catalog의 host queue 계약). host 요청 `tab_open`의 browser target은 `{url, profile?}`이고(`tabs/open` 입력의 browser target은 `{url}`뿐이다) payload에 주인 `owner?`(session, 없으면 사람)가 있다. 탭 목록과 넘기기는 `workspace-layout.md` "agent가 연 탭"이다. 호출 기한 30초. act는 `click|type|fill|fill_login|press|hover|select|scroll` 하나이고 대상은 snapshot의 ref(`e12`). wait는 `--text`나 `--url` 하나와 `timeout_ms`(기본 10초, 최대 25초). `lophn tab open --preview <app> --device <name>`은 emulation 기기를 고르고(없는 이름은 `not_found`) `--screen <key>`는 연 화면을 고른다(아래 "폰 화면 preview"). `tabs/open --url`은 page가 붙은 뒤에 답하고 실패는 `unavailable`이다. `tabs/open`의 target `{phone: {app, screen}}`은 phone 탭을 연다(위 "phone 탭"). `browser/screenshot`의 `media_type`은 `image/png`이고 phone 탭만 `image/jpeg`다. `tabs/open`의 `relation`(`--as peer|stage|aside|work|glance`)은 연 탭이 연 session에게 무엇인지이고 자리는 core가 고르지 않는다. 작업용 browser 탭(`work`)은 접힌 float이라, 사람 손이 필요하면(로그인, captcha) agent가 `lophn tab show <tab>`(`tabs/show`, 연 쪽만)으로 펴고 `ask`로 알린다. agent가 편 browser 탭이면 core가 transient event `TabShowRequested {tab}`(subject는 session, 기기 event 목록에 있다)을 낸다(74).

**오류 code(agent 호출).** 남의 탭·없는 탭은 `not_found`(page가 없어져 core 표에서 빠진 host browser 탭, shell이 없을 때의 host browser 탭, 사람이 되찾은 탭도 같다), 넘겨받은 탭과 받은 탭 닫기는 `forbidden`, 낡은 ref·DevTools 열림·사람이 가져간 탭의 쓰기는 `conflict`, shell 없음(preview·artifact 탭)·탭이 창에 없음(preview·artifact 탭)·기한·wait 시간 끝·agent 정의를 읽지 못해 profile을 모름은 `unavailable`, 틀린 url·preview·artifact 탭의 navigate는 `invalid_input`이다.

**기기 emulation.** 사람이 Settings > Browser에 기기를 등록하고 preview 탭 안내 줄의 기기 고르기(Desktop과 등록한 기기)나 `--device`로 고르면 main이 그 guest에 크기·DPR(`mobile`), touch, OS별 고정 user agent를 걸고 page를 다시 load한다.

**폰 화면 preview.** `lophn tab open --preview <app> --screen <key> [--device <name>]`은 preview release 선언의 그 화면을 연다(`tabs/open`의 preview target `{app, device, screen}`). 선언에 없는 key는 `not_found`이고 message에 있는 화면을 적는다. `--screen`은 `--preview`와만 쓴다. 폰 화면(`places`가 `["phone"]`)은 `phone` 자리로 열고, `--device`가 없으면 core가 기준 폰(`devices`의 primary)에 대응하는 `shell.devices` 항목(`device`가 그 기기 id)의 이름을 채운다. 기준 폰도 `--device`도 없으면 `conflict`다: 넓은 desktop 틀에 폰 화면을 그려 agent가 잘못 믿게 하지 않는다. 기기 id는 agent에게 가지 않고 이름만 간다. 그려지는 것은 build의 react-native-web 진입(`index.html`, `preview.js`)이고 `lophnApp`은 desktop 앱 view와 같은 preload가 준다. web emulation이라 입력·키보드·scroll·글꼴이 폰과 다르고, 마지막 확인은 사람이 폰에서 한다. 이미 열린 preview 탭에 `--screen`이나 `--device`를 주면 같은 탭이 그 화면과 기기로 바뀐다. 사람이 앱 화면 탭의 [Preview]로 여는 탭은 안내 줄에 화면 고르기(Screen)와 기기 고르기가 서고, 고르지 않으면 앱의 첫 `tab` 화면을 연다. 폰 화면만 있는 앱은 첫 폰 화면을 기준 폰으로 연다(넓은 desktop 틀에 폰 화면을 그리지 않는다). agent가 `--screen`을 다시 주면 그것을 따른다. preview 번들은 kit의 글꼴(Pretendard, JetBrains Mono woff2)을 화면 폴더에 싣고 `index.html`이 `@font-face`로 건다(폰 화면마다 release에 약 1.9 MB가 든다). 폰 화면의 설계는 `architecture/phone-screen.md`다.

**site login.** memory route `logins/list {origin?, tab?}`(user·agent, 값 없음, 행마다 `profile`. null은 기본), `logins/save`(user, 새 login의 `profile?`)·`logins/delete`(user), `logins/release`(shell capability, `{id, field, origin, profile, shell_capability}` → `{value}`). 저장 file `<dataRoot>/browser-vault.json`(`{format: 1, profiles, logins, removed, clear}`. profile은 `{id, name, color, revs}`, login은 `{id, label, origin, username, note, profile?, revs}`이고 `revs`는 칸마다 stamp(password·totp 포함), `removed`는 `{id, at, seen}` 흔적, `clear`는 partition data를 지울 profile). browser profile route `browser_profiles/list`(user, `{profiles, clear}`)·`save`(user, `{id?, name, color}` → `{id}`, 만들거나 바꾼 이름이 겹치거나 새 profile이 16개를 넘으면 `conflict`)·`delete`(user)·`cleared`(shell capability, `{ids, shell_capability}`, renderer allowlist 밖). 기계 사이 route `browser_vault/exchange`(명단의 컴퓨터의 core만, `{}` → `{profiles, logins(값 포함), removed}`, 나누기를 끈 컴퓨터는 `forbidden`). data step `browser.vault`(옛 설정 `shell.browser_profiles`와 `logins.json`을 같은 id와 칸으로 vault에 옮긴다). CLI `lophn login list [--origin] [--tab]`. login 요청 card의 login view에 그 탭의 `profile`이 있다. 요청은 `login_request/ask`(agent), `read`·`cancel`(card), `hold`·`done`(shell main)이다.

**shell 설정 UI.** Settings > Browser pane: Bookmarks, Search engine(기본 검색 엔진 고르기와 Custom URL template), Links(두 설정), Profiles(Default 줄과 profile 줄: Rename, Color, Clear data, Delete, 쓰는 agent, [Add profile]), Logins(profile마다 묶음), Your other computers(나누기 설명 한 줄과 Switch. 나누는 동안 명단에 다른 컴퓨터가 있으면 profile·login 지우기 확인은 다른 컴퓨터에서도 지워진다고 말한다), 기기 등록, 데이터 지우기(기본 profile). agent 편집기 Sees의 Browser profile은 `agent-definition.md`다.

**멀리서 보기(`page_view/*`).** 모두 사람 자격이다. `page_view/list`(read) `{}` → `{pages: [{tab, url, title, loading, by, held_by}], control}`(by는 연 agent의 이름, 사람이 연 탭은 null. core가 주인 session마다 한 번 읽어 둔다. held_by는 멀리서 잡은 기기로 부른 쪽 자신이면 `you`, 아니면 `phone`·`computer`, 없으면 null(70). control은 부른 쪽이 다룰 수 있는가), `page_view/snapshot`(read) `{tab}` → `{tab, seq, frame, painting, agent, held, url, title, loading, by, control}`(frame은 `{media_type: "image/jpeg", data_base64, width, height}`이고 아직 없으면 null, 크기는 viewport CSS px. seq는 core가 그 탭의 frame이나 상태가 바뀔 때마다 올리고 마지막 lease가 끝나면 0으로 돌아간다), `page_view/watch` `{tab, on}`(lease 30초, 10초마다 갱신), `page_view/input` `{tab, key, input}`(input은 `pointer {phase: down|move|up, x, y}`, `scroll {x, y, dx, dy}`, `text {text}`, `key {key}`, `navigate {url}`, `back`, `reload`), `page_view/control` `{tab, held}`(잡기는 lease가 있어야 한다), `page_view/open` `{url, key}` → `{tab}`. 오류는 터미널 보기와 같은 여섯(`invalid_input`, `unauthorized`, `forbidden`, `not_found`, `conflict`, `unavailable`)이다. event `PageViewChanged {tab, seq}`(transient, subject `page:<tab>`, 내용 없음)와 StateChanged 이름 `browser_pages`(목록이나 url·title이 바뀜).

**host link의 page 요청과 frame.** 연결 요청 `page_stream {tab, on}`, `page_read {tab, seq}`, `page_input {tab, input}`, `page_control {tab, held}`는 연결이 있을 때만 넣는다. 연결이 없거나, 답하기 전에 끊기거나, 기한(`page_input` 10초, 나머지 5초)이 지나면 `unavailable`이고 다음 연결로 다시 가지 않는다. host는 `page_frame {tab, seq, frame}`(seq는 host가 탭마다 process가 사는 동안 올리고 다시 켜도 0으로 돌아가지 않는다. host가 다시 뜨면 처음부터 센다)과 `page_state {tab, painting, agent, held}`를 민다. frame은 JSON 글이다(link는 binary frame을 닫는다). JPEG 2 MiB의 base64는 host→core frame 상한(16 MiB) 안에 든다. host는 상한을 넘거나 크기가 0인 screencast frame을 보내지 않고 ack만 한다. 그래도 계약에 맞지 않는 `page_frame`이 오면 core는 그 frame만 버리고 연결을 둔다(연결을 닫으면 진행 중인 agent의 browser 호출이 모두 끝난다). host 쪽 오류 가운데 `invalid_input`·`not_found`·`conflict`·`unavailable`은 route에 그대로, 그 밖은 `unavailable`로 간다. page host의 launch intent는 `--page-host`이고 core는 `--ozone-platform=headless --disable-gpu`를 같이 붙인다.

**phone 탭의 폰 요청.** kind `drive.snapshot`·`drive.act`·`drive.screenshot`·`drive.wait`(protocol의 drive 계약, `PHONE_KINDS`). 모든 입력에 `view`(core가 고른 preview view)와 `by`(부르는 agent의 이름)가 있다. 거절 이유는 `unavailable`의 `no_preview`·`phone_in_background`·`screen_off`·`covered`·`unsupported`·`phone_unreachable`·`timeout`, `conflict`의 `taken_over`·`stale_ref`·`off_screen`이고 core가 `PHONE_TAB_TEXT`의 문장으로 바꾼다. `drive.wait`의 deadline은 `timeout_ms + 5_000`, 못 찾으면 desktop wait와 같은 `unavailable` 문장이다.

## 결정

- **보통 탭을 `<webview>`로 두고 크기 준 popup과 DevTools만 native `WebContentsView`로 둔다(사람, 2026-10-19).** 처음에는 앱 화면과 같이 native view였다. native view는 shell HTML 위에 그려져 toolbar menu, 별 popover, floated 패널이 page 밑에 깔렸고 피하려고 page를 숨기거나 줄였다. `<webview>`는 DOM 안에 그려져 그 위에 DOM이 겹친다. ChatGPT desktop도 `<webview>` 탭이지만 popup을 `<webview>`에 adopt하는 것은 고친 Electron으로 한다. 표준 Electron에는 그 길이 없어 크기 준 popup만 native로 남겼다.
- **dock한 popup은 같은 주소의 `<webview>` 탭으로 다시 연다(사람).**
- **앱 화면과 artifact 화면도 이 그릇을 쓴다(사람, 2026-10-31).** 같은 겹침 문제가 있어 한 그릇으로 모았다. 그래서 native view의 층 순서는 browser의 popup·DevTools만의 것이다. iframe은 preload의 isolated world, 앱별 partition, `sender.id` 신원을 잃고 remote UI는 앱이 자기 DOM·CSS component를 못 쓰게 해서 버렸다(사람). Electron이 `<webview>`를 권하지 않지만 browser 탭이 이미 그 위험을 지고 있어 새 위험이 아니다.
- **DevTools는 Chrome처럼 탭 안에 붙이고 floating·분리를 고른다(사람).** `<webview>`는 DevTools를 담지 못해 native view에 붙이고, 자리를 바꿀 때 다시 열지 않고 view를 옮긴다(실험).
- **favicon을 보인다(사람).** 처음 roadmap의 "favicon 하지 않는다"를 뒤집었다. main이 page session으로 받아 data URL로 싣는다(agent).
- **머리 줄의 bookmark menu와 card 밖 줄의 ⋮ menu는 overlay view로 띄운다(사람).** card의 ⋯ menu는 DOM이라 열려 있는 동안 탭이 native view(DevTools 자리, popup)를 숨긴다. native popup 탭과 DevTools 위에서도 보여야 해서 한 길로 둔다. menu·popover의 overlay view는 창 본문 전체를 덮고 부르는 쪽은 trigger 사각형을 보낸다. 별 popover는 `<webview>` 탭에서는 DOM popover(이름 칸과 [Remove])이고 native popup 탭에서는 overlay(이름과 [Remove])다. 바로 지우는 [Remove]는 secondary(휴지통 아이콘)다. 줄마다 채운 빨강이 서면 과해서다(agent).
- **규칙을 rea `desktop-embeded-browser`에서 TS로 옮겨 짰고 library를 dependency로 넣지 않았다(agent).** CommonJS 그대로는 Result·Clock 같은 lophn 규칙과 맞지 않는다. 같은 때 tab cap, site list, capability 승인, storage mode는 두지 않기로 했다.
- **localhost와 사설 IP를 막지 않는다(agent).** 가장 많이 쓸 곳이 사람의 dev server다. core API는 token으로 막혀 있다.
- **Chrome인 척하지 않고 자기 이름을 단 Chromium 브라우저로 보인다(agent, 실험 2026-11-03).** 사람이 browser 탭에서 Google 로그인이 안 된다고 했다. 이전에는 UA에서 `Electron/x`와 앱 이름 token을 모두 빼고 `sec-ch-ua`에 Chrome brand를 지어 넣었다. 실험에서 accounts.google.com의 이메일 단계는 UA가 순수 Chrome(`... Chrome/x Safari/x`)이면 header·page JS brand를 맞춰도(CDP `Emulation.setUserAgentOverride`), Firefox UA로 바꿔도 "This browser or app may not be secure"로 막았고, `Electron/x`나 `lophn/x` token이 하나라도 남으면 통과했다. Edge·Brave처럼 자기 이름을 단 Chromium으로 보이게 한다. ChatGPT desktop도 UA에 `CodexBrowser` token을 붙인다. `Electron/x`는 계속 뺀다. Electron을 보고 막는 사이트가 있다. 버린 안: Chrome UA 위장, Firefox UA.
- **subresource 요청 guard는 두지 않는다.** 이 partition에는 `lophn-shell`·`lophn-app` protocol handler가 없어 그 요청은 어차피 실패한다.
- **tab 수 cap을 두지 않는다.** layout 파일의 tabs 상한이 이미 있다.
- **DevTools 경계 막대는 DOM drag다(agent).** native view는 pointer를 삼킨다. overlay drag 표면으로 한 시도는 press가 shell에서 시작해 움직임을 받지 못했다. 버린 안: overlay drag 표면.
- **page에 focus가 있을 때 Ctrl/Cmd+D는 main이 `bookmark-key` event로 보낸다(agent).** 작업대 단축키 표에 넣지 않는다. terminal의 Ctrl+D(EOF)와 부딪힌다.
- **다른 OS 창으로 옮기면 `<webview>` 탭은 다시 load한다(사람, `<webview>` 결정의 결과).** 다시 load 없이 옮기는 것은 native 항목뿐이다(agent). detached 창 안 popup은 features 크기를 따르지 않고 기본 창 크기이고, 그 창에서는 DevTools를 floated 패널로 둘 수 없다(agent).
- **bridge는 renderer ack가 있어야 `pane`이다(agent).** push만 하고 `pane`으로 답하면 그 terminal 탭을 가진 창이 없는 때(Settings route, 닫힌 창) URL이 조용히 사라진다. OAuth 로그인 URL을 잃으면 사람이 다시 할 길이 없다.
- **bridge의 범위는 shell 탭이다(agent).** coding 탭은 app space 패널에 붙어 browser 탭을 열 pane이 없다.
- **bridge key는 terminal 탭마다 main이 발급하고 key 표 조회로만 인증한다(agent).** socket이 0700 폴더 안 0600 file이고 key는 그 터미널 process만 안다.
- **per-run 폴더는 data root 아래가 아니라 core socket 폴더 규칙을 따른다(agent).** unix socket 경로 한도(104 byte) 때문이다. Windows file은 data root 아래, endpoint는 named pipe다.
- **link 설정은 renderer가 밀어 넣지 않고 main이 요청마다 읽는다(agent).** 낡은 값을 들 일이 없고 terminal link도 main을 거치므로 판정이 한 곳이다. web과 local을 나눈 것은 ChatGPT를 따랐다. 이미 로그인된 OS browser로 보낼 web link와 탭에 띄울 dev server가 갈린다.
- **bridge는 앱 시작 코드가 아니라 terminal IPC를 만드는 곳에서 만든다(agent).**
- **agent가 연 browser 탭도 사람의 browser 탭과 같은 partition을 쓴다(사람, 2026-11-09).** 2026-11-21부터는 agent 정의에 browser profile을 달지 않은 agent에만 그렇다(아래 browser profile 결정). 사람이 로그인한 dev site와 서비스를 agent가 다시 로그인 없이 쓴다. 대가로 page 글이 agent를 속이면 사람의 로그인으로 그 site를 건드릴 수 있다. 막는 것은 다룰 탭을 주인으로 좁힌 것, untrusted 감싸기, take control이다. `evaluate`도 browser 탭에 준다(agent). 2026-11-10부터 사람이 없는 때(창이 없거나 앱을 끈 채 job이 돌 때)도 쓸 수 있다. job을 등록할 때의 승인이 그 job의 browser 사용을 포함한다고 본다(`PRODUCT.md`의 결정 피로를 줄인다). 그래서 따로 묻거나 설정이나 표시를 두지 않는다. 이 접근은 다음으로 좁힌다: 탭은 연 session만 다루고, 연 창이 사는 동안과 창마다 12개까지만 page가 있고, 앱을 띄우는 것은 browser 탭 열기뿐이며, 창이 화면에 뜬다. 남는 대가는 browser로 바깥 site에 한 일을 rewind로 되돌릴 수 없다는 것이다(사람, 2026-11-10).
- **agent의 browser 조작은 CLI + skill이고 extension tool로 만들지 않는다(사람).** lophn agent, harness agent, 터미널의 coding agent가 같은 구현을 쓴다. host queue는 shell main이 붙은 `/host-link` 연결로 요청을 밀고 browser 호출은 `tool_call`의 결과(`response` frame)를 같이 쓴다. 새 통로는 없다(사람. 전에는 `host/take` long-poll이었고 연결로 바꿨다, `platform.md`). browser 호출 기한은 30초, wait는 기본 10초·최대 25초다(agent).
- **앱은 preview만 다룬다(agent).** live 화면은 sender view 신원으로 operation 막기를 건너므로 다루지 않는다.
- **기기 emulation은 preview 탭에만 있고 기기 목록은 사람이 등록한 것뿐이다(사람, 2026-11-08).** 일반 기기 표는 두지 않는다. emulation은 shell 본체의 preview 탭에 둔다.
- **Keep alive: 기본은 놓고 신호를 켠 page만 살린다(사람이 추천을 받음, 2026-11-07).** 모두 살리면 자원을 쓰고 program은 page 안의 뜻을 모른다. browser 탭은 builder가 없어 program이 알 수 있는 신호(소리, download)와 사람의 탭별 toggle로 정한다. 상한은 창마다 6개이고 오래 안 본 것부터 놓는다(사람이 추천을 받음). 살려 둘지는 떠날 때 한 번 정한다(agent).
- **agent가 연 browser 탭의 page는 그 탭을 든 창이 사는 동안 산다(사람, 2026-11-10: `<webview>` 유지).** 사람이 보는 workspace에 묶이면 job과 workflow가 사람 없이 browser를 못 쓴다. native view를 숨은 창에 두는 안은 shell DOM 위에 그려져 menu·패널이 page 밑에 깔리고 browser 탭의 그릇이 둘이 되어 버렸다. 대신 창이 하나도 없을 때는 lophn이 창을 연다. 마지막 url 다시 load와 idle 기한은 두지 않는다. 사라진 page는 사라진 탭이고 agent가 다시 연다(agent). 열리는 창은 자동으로 닫지 않는다(agent).
- **site login은 model에 값을 주지 않고 handle로 채운다(agent, 2026-11-09, 계획 browser-vault).** 평문을 `type`으로 치면 tool 인자로 transcript와 ledger에 남는다. Hermes·Skyvern처럼 handle만 주고 origin을 확인한 뒤 shell main이 친다. origin 비교는 ref가 든 frame의 실제 origin이다. 최상위 URL로 비교하면 다른 origin의 iframe 칸에 값이 들어간다.
- **`secrets.json`은 암호화하지 않는다(agent, 2026-11-09).** 같은 사용자의 process에는 파일 키도 막지 못한다(Hermes·Skyvern 기본값과 같다).
- **login은 전역 하나다(agent, 2026-11-09).** cookie partition이 이미 전역이라 workspace·agent로 나눠도 막는 것이 없다. 2026-11-21 browser profile을 두며 login은 profile에 속하게 바꿨다(아래).
- **browser profile을 나누고 agent 정의에 단다(사람, 2026-11-21).** 위의 "agent 탭은 사람 탭과 같은 partition"을 고친다. profile을 적지 않은 agent는 기본 profile(사람의 것)을 써서 2026-11-09·10의 결정이 그대로 서고 지금 도는 job이 그대로 돈다(agent). 탭마다 agent가 profile을 고르는 길은 요구가 생기면 한다(agent).
- **기본 profile은 `persist:lophn-browser`를 그대로 쓴다(agent).** 사람의 로그인이 이어진다. 버린 안: 모든 profile을 새 이름 규칙으로 옮기기(사람이 다시 로그인해야 한다).
- **profile 정의는 저장 login과 같은 vault file에 둔다(agent, 2026-11-22, browser-profile-sync).** 처음에는 locked 설정 `shell.browser_profiles`였다(새 route가 필요 없어서). 기계 사이에 칸마다 합치려면 칸 stamp와 지운 것의 흔적이 있어야 하는데 설정은 기계마다의 값이고 화면이 목록을 통째로 쓴다. 버린 안: 설정을 그대로 두고 합치는 쪽이 목록 차이로 고침을 추리기(진실이 두 곳이 된다).
- **저장 login은 profile에 속한다(agent).** 전역 하나였던 근거가 "partition이 전역"이었다. `profile` 칸이 없으면 기본 profile이다. 옛 `logins.json`은 vault로 옮길 때(data step `browser.vault`) 같은 id와 칸 그대로 간다.
- **profile 정의와 저장 login을 기계 사이에 맞추고, 그 길은 link 하나다(사람: 맞추기 2026-11-21, 길은 lead·agent 2026-11-22, browser-profile-sync).** 값은 cloud에 올라가는 같이 보는 폴더를 평문으로 지나면 안 되고, 이미 있는 것 가운데 두 core 사이가 끝에서 끝까지 암호화된 것은 link(Noise IK)뿐이다. metadata(origin, username, profile 이름)도 폴더에 두지 않는다: 어느 site의 어느 계정을 쓰는지가 cloud에 드러난다. 대가: 두 컴퓨터가 같은 때 켜져 있지 않으면(dual boot, relay 없이 따로 켜는 컴퓨터) 맞춰지지 않는다. 버린 안: 받는 컴퓨터의 host key로 암호화한 file을 폴더로 보내기(새 암호 code가 필요하고, 뒤에 host key가 새면 cloud에 남은 옛 사본이 다 열리며, 명단이 바뀔 때마다 다시 암호화해야 한다).
- **나누기는 짝지은 컴퓨터마다 자동이고 끄는 스위치가 컴퓨터마다 하나다(lead·agent).** 항목마다 고르는 화면은 없다. 기본은 켬이라 판을 올리면 사람의 저장 login이 짝지은 모든 컴퓨터로 간다(change-log checklist가 알린다).
- **합치기는 칸마다 새 쪽이 이기고, 지울 때 몰랐던 고침은 지운 것을 되살린다(lead·agent).** 한 login의 password를 A에서, note를 B에서 고친 것이 둘 다 남는다. 지우기와 고치기가 엇갈리면 login이 돌아온다: 말없이 사라지지 않는다. 버린 안: 항목 하나를 통째로 새 쪽이 이기기(note를 고친 옛 사본이 새 password를 덮는다), 같은 칸이 엇갈리면 login을 둘로 나누기(목록이 지저분해지고 어느 쪽이 맞는지 사람이 가려야 한다), 나중 것이 이기는 지우기(고친 login이 말없이 지워질 수 있다).
- **같은 이름의 profile은 둘로 남는다(lead·agent).** 자동으로 이름을 바꾸면 사람의 profile 이름을 program이 고친다.
- **기본 profile의 login도 맞춘다(lead·agent).** "저장 login이 사람을 따라간다"가 profile마다 다르지 않게 한다. 대가: 다른 컴퓨터에서 profile을 달지 않은 agent도 그 login을 친다(값은 handle로만, origin이 같을 때만).

- **browser 탭이 아닌 탭의 login은 기본 profile의 것이고 자기 profile이 기본인 쪽만 다룬다(lead, 2026-11-21).** 그 page의 partition은 browser profile이 아니라서 다른 profile의 login을 내줄 근거가 없다. 버린 안: 부른 agent의 profile로 풀기(profile을 단 agent가 자기 artifact 탭으로 사람의 login 목록을 읽는다. 독립 review가 찾았다).
- **profile을 읽지 못하면 기본으로 떨어지지 않는다(lead, 2026-11-21).** 기본이 되는 것은 정의에 칸이 없을 때와 적힌 profile이 지워졌을 때뿐이다. 버린 안: 읽기 실패를 기본으로 보기(profile을 단 agent가 사람의 로그인으로 page를 연다).
- **profile을 지우면 그 profile의 login도 지운다(agent).** profile 하나가 partition과 그 login이라 남기면 어느 화면에도 보이지 않는 login과 secret 값이 남는다. 쓰던 agent는 기본 profile로 떨어지고 편집기가 표시한다(agent).
- **사람이 새 탭의 profile을 고르는 자리는 + menu의 Browser 하나다(agent).** 빠른 실행, 단축키, 터미널 link는 기본 profile이다. 버린 안: 여는 길마다 고르기(고르는 길만 늘어난다).

- **폰의 앱도 preview만 다룬다(planner, 2026-11-15).** live 화면은 사람의 실제 data에 operation을 부른다. desktop의 "앱은 preview만"과 같은 규칙이다.
- **사람이 폰에서 preview를 여는 것이 동의다(planner).** 앱 화면 menu의 "Preview from lophn"(live 폰 화면이 아직 없는 앱은 앱 줄이 바로 preview를 연다)을 여는 것이 "이 화면을 다뤄도 된다"는 뜻이고 동작마다 묻지 않는다. 대신 요청이 오는 동안 폰이 누가 다루는지 보이고 사람이 언제든 가져간다. 컴퓨터에서 폰을 깨우거나 lophn 앱을 앞으로 부르지 않는다. 사람이 폰을 들고 있을 때만 하는 확인이라서다.
- **보기와 입력은 lophn 폰 앱 안의 native module이 한다. Accessibility service와 adb는 쓰지 않는다(planner, spike 판정).** Accessibility service는 Play 정책상 이 용도로 쓰기 어렵고 사람이 설정에서 켜야 하며, 켜면 다른 앱과 system UI까지 닿는다. adb는 cable이나 개발자 옵션이 필요하다. native module은 lophn 앱 안의 guest view tree만 걸으므로 범위가 preview 화면으로 좁고 사람의 설정이 필요 없다. guest 쪽 JS tree를 쓰는 길은 버렸다(AI가 쓴 화면 code가 답을 꾸밀 수 있다).
- **phone 탭은 앱마다 하나이고 기기·view를 부를 때마다 고른다(agent).** 조사의 `<app>:<device>` 탭보다 단순하고 사람이 preview를 닫았다 다시 열어도 탭이 그대로 쓰인다.
- **ref 번호는 core가 매긴다(agent).** 폰은 snapshot id와 자기 node 번호만 낸다. 조사의 "core가 counter 시작값을 보낸다"보다 두 쪽 상태가 어긋날 곳이 적다. 마지막 snapshot이 아닌 ref는 core가 폰에 묻지 않고 거른다.
- **screenshot 기본은 JPEG q80, 긴 변 1080 px다(agent, spike 측정).** PNG는 1 MiB 상한을 자주 넘는다.
- **화면 없는 기계의 browser는 core가 띄운 page host가 같은 link의 host로 든다(사람: "core에서 headless로 브라우저를 열 수 있게하는 길 하나만").** core 쪽 provider를 새로 두면 driver와 take control, site login을 두 벌 갖는다. page host는 같은 binary와 driver를 쓰고 page를 찾는 법만 다르다(agent, spike로 offscreen page의 screenshot·AX·입력·cookie를 확인).
- **멀리서 보기는 터미널 보기와 같은 꼴이다(사람: "기반은 다 있을 거 아니야").** frame과 상태를 snapshot route 하나로 읽고 내용 없는 event 하나로 알린다. host가 frame을 밀되 core가 읽어 간 만큼만 다음 frame을 받아 느린 연결에서 쌓이지 않는다(agent).
- **보는 쪽의 pointer는 왼쪽 단추 하나의 down·move·up이다(agent).** 폰의 손가락과 desktop의 click·끌기를 같은 꼴로 받는 가장 작은 모양이다. hover와 오른쪽 단추는 없다.
- **`tab show`를 받는 곳은 "탭을 연 곳"이 아니라 "그 session을 보는 화면"이다(사람, fix headless-login-show).** page는 늘 agent가 도는 기계에 있고, 다른 것은 사람이 그 session을 어느 화면에서 보느냐다. 화면 없는 기계의 page host는 tab_show를 펼 창이 없어 agent는 폈다고 믿지만 아무 데도 뜨지 않았고, `login request`는 그 기계 앞에서만 끝나는 card로 끝없이 기다렸다. core가 보는 화면을 골라 보내지 않고 event를 내어 그 session을 그리는 창이 스스로 원격 보기 탭을 연다: 고른 탭만 그려지므로 그 창이 곧 지금 보는 화면이고, core에 presence 판단을 더하지 않는다. 버린 안: page host가 tab_show를 정한 문장으로 거절하기(agent는 알지만 사람에게는 여전히 닿지 않는다).
- **사람이 연 탭을 멀리서 닫는 route는 두지 않는다(agent).** 멀리서 하는 것(71)에 없다.
- **page host는 따로 build한 entry가 아니라 shell main entry의 launch mode다(agent, 계획 core-browser).** core 연결, host link, browser session, driver, stream, 경로를 desktop과 같은 bundle에서 쓰고 renderer가 필요 없다. `--core`가 같은 꼴이다. flag는 `--ozone-platform=headless --disable-gpu`다: spike에서 `XDG_SESSION_TYPE`까지 없는 기계에서도 뜨고, `--headless`보다 page 하나에 약 200 MB 적고 GPU 오류가 없었다.
- **사람이 desktop 앱을 켜면 page host가 그 시작을 다시 띄우고 물러난다(agent).** 같은 lock이라 나중에 뜬 desktop 앱은 그냥 끝나고, page host의 env에는 display가 없어 page host가 창을 열 수도 없다. 물러나기만 하면 사람이 앱을 두 번 눌러야 한다. 그래서 두 번째 시작이 lock 요청에 자기 env를 실어 보내고 page host가 자기 data root와 그 env의 display 값으로 다시 띄운다. 버린 안: 물러나기만 하기, 누른 시작의 인자와 env를 그대로 쓰기(인자의 `--home` 값을 잃어 누른 shell의 `LOPHN_HOME`, 곧 사람의 data root로 갔다).
- **그리지 않는 것은 frame이 오지 않는 것으로 잰다(agent, spike).** 창의 최소화·숨김 event만 보면 Wayland에서 최소화했다 되돌린 창처럼 보인다고 답하면서 그리지 않는 경우를 놓친다. 켜거나 깨운 뒤 2초 동안 frame이 없으면 `painting: false`다.
- **멀리서 잡기는 그 기계의 take control을 그대로 쓴다(agent).** 상태를 둘 두면 그 기계의 화면과 다른 기기가 어긋난다. 그래서 browser 호출이 온 적 없는 탭에는 잡을 것이 없다. 잡기와 입력은 lease가 있어야 한다(입력은 좌표가 본 frame에 대한 것이라서, 잡기는 보는 쪽이 떠나면 풀려야 해서). 멀리서 잡은 것은 잡은 기기의 lease가 끝나면 core가 푼다(agent, fix-browser): 보는 쪽이 앱을 내리거나 연결을 잃으면 돌려줄 사람이 없고, 화면 없는 기계에서는 그 기계의 화면도 없어 agent가 끝없이 멈췄다. 버린 안: 보는 쪽이 닫을 때 돌려주기만 하기(앱이 죽거나 연결이 끊기면 가지 않는다).
- **다시 읽기는 page 안의 `location.reload()`다(agent, 실험).** CDP `Page.reload`를 `<webview>` guest에 보내면 guest가 아니라 그것을 품은 shell 창이 다시 load됐다.
- **desktop의 글은 숨은 입력칸이 받은 대로 보낸다(agent).** keydown으로는 IME 조합 글(한글)을 받지 못한다(조합 중 key는 `Process`다). 칸의 input·compositionend가 쳐진 글을 `text`로 보내고 keydown은 조합과 이름 있는 key만 보낸다. 붙여 넣기는 이 컴퓨터의 clipboard 글이다(그 기계의 clipboard에 닿는 길은 없다).
- **덮인 화면은 따로 이유(`covered`)를 낸다(agent).** 앱은 앞에 있는데 sheet·dialog·notification shade가 덮은 때는 "앞에 없다"가 아니라 사람에게 닫아 달라고 하고 그 부분은 손으로 보라고 해야 한다. 폰 앱이 앞에 있을 때만 요청이 native에 닿으므로 그때의 창 focus 없음을 덮임으로 본다.

## 열린 것

- **사람이 막 만든 profile을 main이 목록 바뀜으로 받기 전에 붙이면 거절된다(빈 page).** 드문 틈이라 막지 않는다.
- **기계 사이 맞추기는 한 기계의 개발 core 둘로만 보았다(change-log `browser-profile-sync`).** 서로 다른 기계와 OS, relay 길, 다른 컴퓨터에서 받은 login의 `fill-login`(shell이 있는 기계)은 돌려 보지 않았다. 같은 칸을 두 컴퓨터가 고치면 앞 값은 남지 않는다. 시계가 크게 앞선 컴퓨터의 고침은 stamp로 이긴다.
- **명단에서 뺀 컴퓨터가 이미 받은 login은 그 컴퓨터에 남는다.** 도둑맞은 컴퓨터면 사람이 site의 password를 바꿔야 한다. Settings › Remote에서 컴퓨터를 빼는 확인 창이 그 말을 한다.
- **vault는 통째로 오간다.** 한 응답이 link frame 상한(16 MiB) 안이라 login 만 개 남짓까지 된다. 흔적은 지우지 않아 쌓인다.
- **persist partition 여럿의 디스크·메모리와 page host의 partition 여럿은 재지 않았다.**
- **DevTools로 풀린 기기를 Desktop으로 돌리는 길은 Electron에서 돌려 보지 않았다.**
- **크기 없이 `window.open`을 쓰는 로그인은 깨질 수 있다.** opener가 끊기는 대가다.
- **coding 탭의 `BROWSER`.** coding 탭은 app space 패널에 붙어 browser 탭을 열 pane이 없어 지금은 OS browser로 간다(roadmap `browser-tab.md`의 "남은 bridge 일").
- **다시 열어 복원한 detached terminal과 host가 죽은 뒤 사람이 다시 시작한 shell은 bridge가 없다.** OS browser로 간다(`workspace-layout.md` 이슈의 terminal 재연결과 함께 풀린다).
- **detached 창에서 DevTools를 floated 패널로 둘 수 없다.**
- **fill-login의 한 글자(49).** 같은 process의 다른 origin frame이 치는 사이 focus를 가져가면 멈추기 전 한 글자가 그 frame에 갈 수 있다. 글자를 넣는 것과 확인 사이를 page 안에서 묶는 길이 없다.
- **agent input과 사람의 focus(37)에 남은 빈틈.** 창이 focus를 되돌리기 전 몇 ms 사이 사람의 키는 main이 버리지만(사람이 그 page에 있지 않았을 때) 이것은 headless에서 재지 못했다(흉내 낸 키는 그 길을 지나지 않는다. 흉내로는 65키/초에 agent가 다섯 번 누르면 0~2자가 agent page에 갔다). 사람이 표시된 그 page 자체를 누르면 그 뒤 키는 사람의 것으로 두지만 창이 그 focus 이동을 먼저 보면 되돌릴 수 있다. 사람이 이미 그 page에서 치고 있었다는 창의 답이 오기 전(1~2ms) 친 키는 버려진다. page 끝의 Tab은 창 focus는 돌아오지만 다음 순서의 page 안 focus를 바꿀 수 있다. page가 받지 않은 키가 창 menu 단축키(Close Window)로 가지 않는 것은 headless가 menu 단축키를 돌리지 않아 보이는 창에서만 확인할 수 있다.
- **실제로 보이는 창에서의 agent 입력·1px·기기 frame은 사람이 아직 보지 않았다(headless Electron으로만 확인).** Windows bridge의 실기 확인도 별도다.
- **agent page는 보이는 창에서만 그린다.** `<webview>` guest는 화면에 보이는 창(숨기거나 최소화하지 않은)에서만 그린다. 숨기거나 최소화한 창은 그리지 않아 screenshot이 끝나지 않는다(x11에서 쟀다). 다른 창에 덮인 것은 그린다. 창 안에서는 화면에 있거나 1px 띠가 가려지지 않은 것만 믿을 수 있고 완전히 덮거나 viewport 밖에 두면 그리지 않는다. 숨은 page의 1px 띠는 창 오른쪽 아래에 점으로 보일 수 있다(설치한 앱에서 눈으로 확인한다). macOS와 Windows는 돌려 보지 않았다. Wayland에서는 focus 없이 연 창이 focus를 가져갈 수 있다. 화면이 없는 Linux는 page host가 page를 든다(62~66).
- **화면 없는 기계는 흉내만 보았다.** spike와 page host 모두 display를 뺀 개발 기계(`env -u DISPLAY -u WAYLAND_DISPLAY`)에서만 돌렸다. 실제 화면 없는 VM, 최소 server image에 Electron이 뜨는 데 필요한 library(X11 library 등)가 있는지, 설치본이 `--no-sandbox` 없이 뜨는지(setuid `chrome-sandbox`)는 보지 못했다. macOS·Windows의 화면 없는 길은 없다(그 기계에서는 늘 desktop 앱을 띄운다).
- **page host에서는 `lophn login request`를 받지 않는다(63).** 다른 컴퓨터의 창에서 값을 받아 그 기계에 저장하는 길은 아직 없다. 사람은 원격 보기로 page에 직접 친다(74). 이미 저장한 login의 `fill-login`은 된다.
- **창의 frame은 사람이 아직 보지 않았다.** 개발 앱과 폰 둘로 목록, 입력(누르기, 글, Enter, 주소, 뒤로, 다시 읽기), 멀리서 잡기와 놓기, 허락 없는 기기의 `forbidden`, lease 끝남은 보았으나 화면이 잠겨 있어 보이는 창의 frame, scroll, 최소화와 되살리기(`painting`)는 보지 못했다. Wayland에서 최소화했다 되돌린 창은 spike에서 다시 그리지 않았다(숨겼다 보이면 돌아왔다). 지금 제품에서는 2초 규칙이 `painting: false`로 보이겠지만 다시 그리게 하는 길은 없다. desktop의 IME 입력과 붙여 넣기도 실제 다른 기계의 창에서 보지 않았다.
- **core가 다시 뜨거나 host 연결이 끊기면 host의 page가 고아로 남는다.** core의 탭 표는 메모리라 다시 뜬 core는 그 page를 모르고, 같은 core도 `/host-link`가 닫히면 browser 탭을 표에서 뺀다(host가 죽으면 닫혔다고 알릴 길이 없어 목록에 없는 page가 남지 않게). page host는 죽은 core를 스스로 다시 띄우고 새 core에 붙어 끝나지 않는다. 그 page는 상한에 밀려 닫힐 때까지(desktop 앱은 그 탭을 닫을 때까지) 남는다.
- **page 상한 12개는 agent의 탭과 사람이 멀리서 연 탭이 같이 쓴다.** 화면 없는 기계에서 agent가 page를 많이 열면 사람이 로그인하려고 연 탭이 밀려 닫힐 수 있다.
- **`tabs/open --url`은 page의 dom-ready까지 기다린다.** 첫 응답이 기한(10초, 앱을 띄웠으면 30초)보다 늦는 site는 실패한다.
- **emulation은 진짜 폰이 아니다.** iOS는 WebKit이다. 실제 폰의 preview 화면은 phone 탭이 다룬다.
- **phone 탭은 emulator와 개발 core에서만 보았다.** 실제 폰, 실제 model의 agent turn, iOS는 보지 못했다(change-log `mobile-browser-use`). guest의 kit `Sheet`·`Menu`는 화면 안의 층이라 읽고 누를 수 있지만(기기에서 보지 않았다) kit `Sidebar`·`Drawer`와 화면 source가 직접 연 `Modal`은 새 창이라 닿지 않는다. 가상화된 목록의 그려지지 않은 줄과 가로 scroll은 snapshot에 들지 않는다(지침 `phone-check.md`가 `scroll --dy` 뒤 다시 snapshot하라고 말한다). scroll 뒤 누르기는 정한 시간(150 ms, 300 ms)만큼 기다린다(실제 폰에서 빗나가면 이슈 `phone-drive-settle-timing`을 되살린다). type·fill은 손가락과 달리 칸의 onPress를 부르지 않는다(지침이 먼저 `click`하라고 말한다).
