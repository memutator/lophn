# 0.22.0

## 보관한 앱을 영구히 지운다(app.delete)

```yaml
modules: [packages/protocol, packages/core/apps, packages/core/main, packages/core/jobs, packages/core/approvals, packages/core/lophn-agent, packages/core/config, packages/core/storage, packages/shell/main, packages/shell/renderer, tools]
checked: []
```

- 전: 앱은 보관(`app.archive`)만 되고 지우는 길이 없었다. 보관한 앱의 source, data, 대화, release, 기록이 영원히 남았다.
- 후:
  - 사람 전용 command `app.delete {app}`(compare `{base_revision}`, 오류 `conflict`·`forbidden`·`not_found`·`unavailable`). 보관한 앱만 지운다(active 앱은 `conflict`). agent·앱·job은 부르지 못한다(`forbidden`).
  - 한 Tx에서 ledger를 지운다: 앱, release, 활성화 요청·동의, grant, 앱 data 기록, invocation 기록과 changeset, rewind 기록, 앱 알림, annotation, 폴더·icon, 그 앱 workspace의 session 전부(session delete와 같은 규칙), 그 앱에 범위가 있는 agent 정의, 다른 agent의 할당, 그 앱을 부르는 job, 열린 공유 요청. commit 뒤 `<data>/apps/<app>/` 폴더, 지운 session의 tool-results, 설정에서 이 앱을 가리키는 값(고정, app launch, sidebar panel·tray 끔, coding agent 공유 slug)을 지운다.
  - shell은 `AppRemoved` event로 앱 view의 browser 저장소(partition), 그 앱 workspace의 layout 파일, 전역 float을 지운다.
  - Home의 Workspaces panel Archived 구역의 보관한 앱 줄에 Delete(휴지통) 단추가 생기고, 누르면 지워지는 것(소스 코드와 앱 data, 대화, release와 기록)을 보이는 확인 dialog(빨간 Delete)가 뜬다. 이름을 따로 치게 하지 않는다.
  - 지우지 않는 것: `events`·`command_results`(immutable, `AppDeleted`가 남는다), program 알림, 다른 앱·다른 workspace가 가진 기록(이 앱을 부른 다른 앱의 invocation, session의 되돌리기 결과), job run·run·workflow 줄, 공개 SDK package, secret 값. 자세한 목록과 이유는 `architecture/app-call.md`.
- 저장 모양: ledger step `apps.delete.erase-windows`가 `apps`·`releases`·`grants`·`invocations`·`app_rewinds`의 DELETE trigger를 erase window 조건부로 바꾼다. 창은 `app.delete` Tx 안에서만 열려 평소 DELETE는 그대로 막힌다.

옮기기: ledger step이 자동으로 돈다. data root 파일은 바뀌지 않는다.

왜: 쓰지 않는 앱을 보관만 할 수 있어 source와 data가 남았고, 사람이 완전히 지울 길을 원했다(사람).

결정:
- 보관 → 지움 두 걸음이다. active 앱을 바로 지우지 않는다. (사람)
- 앱 하나가 혼자 가진 것(source 폴더, 데이터, 대화, release, 앱 기록, browser 저장소)은 모두 지우고, secret 값(이름은 전역)과 다른 앱·다른 workspace에 속한 기록, 설계상 append-only인 기록(`events`, program 알림)은 남긴다. (사람)
- 지우기 확인 dialog는 danger Delete이고 이름을 따로 치게 하지 않는다. (사람)
- 이 앱의 invocation 기록은 지운다(append-only trigger는 erase window로 풀었다). 앱의 data 변경분(changeset)을 담고 있어 앱이 사라진 뒤 남길 이유가 없다. (agent)
- ledger를 먼저 지우고 파일을 나중에 지운다. 끊기면 앱은 이미 없고 이름 없는 폴더만 남는다. 파일을 먼저 지우면 끊긴 뒤 source 없는 설치된 앱이 남는다. (agent)
- 앱 process가 아직 멈추는 중(`AppStarted` 뒤 `AppStopped` 전)이면 `unavailable`로 거절한다. 강제로 죽이고 지우지 않는다. 보관한 직후 바로 지우려 하면 잠시 뒤 다시 한다. (agent)
- 그 앱 workspace가 만든 job과 그 앱에 범위가 있는 agent 정의도 지운다. 같은 slug의 새 앱이 할당과 공유 설정을 물려받지 않게 다른 agent의 할당과 coding agent 공유 slug에서도 뺀다. (agent)
- 다른 workspace layout의 앱 panel 탭과 고정은 지우지 않는다. "앱이 없다" 안내와 건너뜀으로 이미 안전하게 그려진다. (agent)

후속: 없음.

## app.delete의 "process가 아직 있나" 판정을 살아 있는 supervisor로 바로잡는다

```yaml
modules: [packages/core/apps, packages/core/main]
checked: []
```

- 전: 바로 위 항목은 ledger의 마지막 process 사실이 `AppStarted`이면 `unavailable`로 거절했다. core가 꺼질 때는 `AppStopped`를 남기지 않아, 켜져 있다 꺼진 뒤 보관한 앱은 영영 못 지웠다.
- 후: ledger 사실을 보지 않는다. 보관한 앱이면 쓰기 앞 처리기가 supervisor에 지금 process(멈추는 중 포함)가 있는지 묻고, 있을 때만 `unavailable`이다.

결정:
- 판정은 ledger 사실이 아니라 살아 있는 supervisor 관측이다. 버린 길: 옛 `AppStarted`를 지우는 보정 기록(append-only를 건드린다). (agent)

후속: 없음.


## 앞 turn의 tool 이력을 다음 turn에 그대로 잇는다

```yaml
modules: [packages/protocol, packages/core/lophn-agent]
checked: []
```

- 전: 새 turn의 prompt는 앞 turn들의 사람 메시지와 agent 글 답만으로 다시 만들었다. 앞 turn의 tool 호출과 결과는 버렸다. turn이 바뀔 때마다 대화 prefix cache가 system 뒤에서 깨졌고(실측: 91k를 쌓은 turn 다음 turn의 첫 call이 cache 8.5k만 읽었다), model은 앞 turn에서 tool로 본 것을 잊어 다시 불렀다. `/status`의 창 점유도 그만큼 작게 나왔다.
- 후:
  - turn은 tool 묶음이 끝날 때마다, 그리고 끝내기 직전에 CheckpointTurn(`history`, `history_size` 새 칸)으로 turn 안 이력을 blob(`turn`/`history`)으로 남긴다. 참조는 마지막 하나만 남는다.
  - 다음 turn은 앞 turn의 요청 뒤에 그 이력을 그대로 잇는다. 이력이 맡은 그 turn의 답·steering 메시지는 따로 넣지 않는다. ReadTurnBody에 `turn_history`가 생겼다(machine만).
  - 다음 turn 전 Compact 기준: turn 첫 call이 예산의 50% → 70%를 넘을 때.
  - 이미지 상한은 앞 turn 이력까지 합쳐 센다.
  - `/status`의 창 점유 anchor가 `started_seq`가 같은 call들 사이에서 시작 시각으로 마지막 call을 고른다(전에는 아무 call이나 골라 앞 turn의 큰 값이나 작은 값이 나올 수 있었다).
- 저장 모양: 새 blob field `turn`/`history`. 표와 data root 파일은 바뀌지 않는다.

옮기기: 없다. 이 판 이전 turn은 이력이 없어 전처럼 메시지로만 읽는다.

왜: 다른 harness(omp, pi, codex, opencode, Claude Code)는 모두 transcript 전체를 이어 보내고 창이 찰 때만 Compact한다. lophn만 turn마다 tool 이력을 버려 cache와 맥락을 함께 잃었다(사람).

결정:
- 앞 turn의 tool 이력을 버리지 않고 다음 turn에 그대로 잇는다. (사람)
- 다시 조립하지 않고 turn이 보낸 이력을 blob으로 남겨 그대로 잇는다. tool 호출 기록과 응답 blob으로 다시 만들면 redaction·줄인 결과·steering 자리가 달라져 바이트가 어긋난다. (agent)
- 이력은 별도 표 열 없이 blob 참조로 둔다(`turn`/`resolved`와 같은 길). ledger step이 필요 없다. (agent)
- 멈춘 turn은 FinishTurn을 거치지 않으므로 tool 묶음마다 checkpoint에 싣는다. 마지막 묶음 뒤 멈추면 그 뒤에 남긴 답 글 하나는 빠질 수 있다. (agent)
- 다음 turn 전 Compact를 70%로 미룬다. 이력이 이어져 이전 대화가 빨리 크고, Compact도 cache를 깨므로 너무 일찍 하지 않는다. 넘치면 turn 안 Compact(85%)가 받는다. (agent)

후속: 없음.

## harness GUI: 다시 붙을 때 snapshot, 사용량 복원, 탭 이름, 빈 session, 받은 메시지, bookmark

```yaml
modules: [packages/shell/main, packages/shell/ipc, packages/shell/preload, packages/shell/renderer]
checked: []
```

- 전:
  - handle이 publish된 갱신(글 조각까지)을 모두 쌓아 GUI view가 붙을 때마다 하나씩 다시 보냈다. 긴 session은 workspace를 오갈 때 멈췄고, TUI→GUI와 resume 때 대화가 한 줄씩 다시 그려졌다.
  - Claude GUI를 다시 열면 token 합계와 비용이 0부터 다시 셌다.
  - GUI 동안 탭 이름이 shell prompt의 OSC 제목(`user@host: 경로`)으로 덮였다.
  - 메시지를 보내기 전의 TUI에서 GUI로 넘기면 저장되지 않은 session을 resume하려다 실패했다(Claude, Codex, omp. OpenCode는 실패 줄을 남겼다).
  - task 알림, lophn call·reply, 다른 session이 넣은 메시지가 다시 열면 사람 메시지로 그려졌다.
  - thread index card의 bookmark 단추를 누르면 bookmark되지 않고 다른 메시지로 scroll됐다(lophn agent 화면도 같다).
- 후:
  - handle은 `reduceAcp`로 접은 `AcpState` 하나만 쥔다. IPC `harness-gui:tab-update`는 붙을 때 snapshot 하나, 그 뒤 20ms마다 모은 갱신 배열이다(`HarnessGuiTabBatch`). renderer는 묶음을 한 번에 접어 한 번 그린다.
  - Claude는 transcript의 `cost-state`(없으면 assistant usage를 `message.id:requestId`로 중복을 빼고 합함)로 합계와 비용을 되살린다.
  - GUI 제목은 탭 field `guiTitle`이고 `tabName`이 GUI view일 때 사람 이름 다음으로 쓴다.
  - 저장되지 않은 session은 실패 없이 새 session으로 연다(Claude는 같은 id).
  - adapter가 transcript의 `origin.kind`와 `<lophn-call>`·`<lophn-reply>` tag로 받은 메시지를 `actor: "received"`(sender, `call`, `reply_to`)로 그린다. rewind 시점과 bookmark가 되지 않는다.
  - thread index rail이 portal의 hover card에서 올라온 event를 무시한다.

옮기기: 없음. 탭 field `guiTitle`은 GUI view일 때만 읽고, 저장본에 남은 값은 무시한다.

왜: 사람이 harness GUI를 써 보고 찾은 bug다(사람). emdash·t3code·happy가 같은 문제를 접은 상태와 snapshot, 묶은 갱신으로 푼 것을 참고했다.

결정:
- 저장되지 않은 session을 resume하려 하면 실패를 보이지 않고 새 session을 연다. (사람)
- 받은 메시지는 있는 ACP 칸(`received`, sender agent | program)으로만 가른다. ACP sender 확장과 A2A 화면은 사람이 모양을 정한 뒤에 한다. (agent)
- Claude의 usage 원본 줄은 SDK `importSessionToStore`(@alpha)로 읽는다. `getSessionMessages`에는 `cost-state`·`origin`이 없다. (agent)

## 앱이 tray popup 크기를 정한다

```yaml
modules: [packages/protocol, packages/core/apps, packages/core/agent-workspaces, packages/sdk, packages/shell/renderer, tools, tests]
checked: []
```

- 전: tray popup은 늘 360×480px이었다. 내용이 적어도 480px 높이였고 앱이 크기를 바꿀 길이 없었다.
- 후:
  - 화면 선언에 `tray: {width?, height?}`(px) 칸이 생겼다. 너비 240~720, 높이 160~720의 정수이고 하나는 있어야 하며, `places`에 `tray`가 없는 화면에 두면 선언 오류다. 없는 쪽은 기본값(360, 480)이다.
  - shell은 그 크기로 popup을 열고 창이 더 작으면 창 안으로 줄인다. `apps.tools`의 `screens[].tray`로 읽는다.
  - SDK: `@lophn/declaration` 4.1.0(`tray` 칸, type `TraySize`), `@lophn/app-ui` 2.8.0(declaration pin만). migrate-sdk 메모와 Instruction diff(declaration guide, design-app skill, 앱 template `AGENTS.md`)가 있다.
- 저장 모양: 없는 칸은 정본 json에 두지 않아 옛 선언과 hash가 그대로다. ledger와 data root 파일은 바뀌지 않는다.

옮기기: 없다.

왜: 내용에 맞지 않는 고정 크기라 popup이 비거나 늘 스크롤됐다. 앱이 몇 가지 중에 고르지 않고 숫자로 직접 정하기를 원했다(사람).

결정:
- 크기는 앱이 화면 선언에 px로 직접 적는다. 미리 정한 크기 몇 가지에서 고르지 않는다. (사람)
- 선언에만 둔다. 실행 중 바꾸기(`setTray`)는 열린 popup이 출렁여서 두지 않는다. (agent)
- 범위 밖 값은 줄여 받지 않고 선언 오류로 거절한다. 앱 agent가 release 전에 알 수 있다. (agent)

후속: 없음.

옮기기: 없다.

- 4.1.0을 고치지 않고 4.2.0으로 올린다. 4.1.0은 이미 설치된 package로 나가 앱 agent가 메모를 읽었을 수 있다. (agent)
- 너비는 넘칠 때만 넓힌다. 폭을 채우는 화면의 "자연 너비"는 늘 최대라 줄어드는 너비를 잴 수 없다. (agent)

## 공통 socket 자리와 Windows hook·browser bridge·PowerShell 시작 층

```yaml
modules: [packages/base, packages/protocol, packages/core/apps, packages/coding-agent, packages/shell/main, packages/shell/terminal-host]
checked: [boundary-catalog, context-component-registry, architecture-testing, architecture-coding-agent, architecture-keybindings, architecture-app-call, architecture-workspace-layout, tool-dev, tool-package, tests-support, tool-e2e]
```

- 전: core와 shell이 socket 자리 규칙을 따로 적었고 shell은 104 byte 한도를 썼다. Windows에서는 bridge 전체 gate가 hook·시작 층까지 껐다. POSIX에서도 browser shim이나 listen 실패가 hook을 같이 껐다.
- 후:
  - base의 순수 `socketDirectoryPath` 한 곳이 자리 규칙을 정한다. Node SHA-256은 호출자가 주입한다. POSIX data-root key는 기존 SHA-256 앞 12자이며 앱 socket 경로·slot 수·0700 준비는 그대로다. hook·bridge는 `ipcPath`와 OS별 한도(Linux 107·macOS 103·Windows 256 byte)를 쓴다.
  - file 폴더 준비와 hook·bridge listen을 나눴다. browser 준비 실패에도 hook은 별도 endpoint를 연다. Windows file은 data root의 `run/shell-<pid>/`, endpoint는 별도 named pipe다. POSIX private mode와 현재 data root의 자기 pid/죽은 pid만 지우는 cleanup 경계를 유지한다.
  - POSIX sh와 Windows `.cmd` shim이 공통 `browser.js`를 Electron Node로 실행한다. CJS·ESM package 아래 모두 읽히도록 dynamic import를 쓴다. 실패·declined·timeout 때 OS opener로 넘기며 bridge env와 `ELECTRON_RUN_AS_NODE`를 제거한다. Windows fallback은 `cmd.exe start`다.
  - PowerShell 7·5.1은 profile 뒤 per-run `functions.ps1`을 읽는다(UTF-8 BOM). GUI 넷과 private-server wrapper를 기존 규칙대로 제공하고, 사용자 profile·alias·function·execution policy는 바꾸지 않는다. win32 bridge 전체 gate를 없앴다.

옮기기: 저장 data 모양 변경 없음. 앱 socket 경로가 유지돼 migration은 없다.

결정:
- base는 Node를 import하지 않으므로 hash를 주입하고 POSIX key는 바꾸지 않는다. (agent)
- Windows 인증은 기존 64 hex key만 쓴다. SID·DACL 검사는 더하지 않는다. 경로 초과는 기능을 끄고 로그 한 줄만 남기며 pointer file·TCP로 우회하지 않는다. (agent)
- hook 준비는 browser shim·listen 성공과 분리한다. PowerShell은 사람의 실행 정책을 우회하지 않는다. (agent)
- Windows foreground·signal·TUI toggle·GUI adapter 전체 대응은 이번 범위가 아니다. (agent)
- 사람이 Windows 실기 미확인을 기록한 채 land와 계획 닫기를 승인했다. 원래의 Windows 확인 선행 조건을 변경하되 full check·기존 E2E·core 기동은 유지한다. Windows 통과로 기록하지 않고 루트 `WINDOWS-CHECKLIST.md`에서 수동 확인을 이어간다.

검증: 각 task merge의 full check·core 두 번 기동·renderer build, merge 뒤 `npm run check` 통과. Linux에서 실제 shim·socket·hook CLI, declined·접속 실패의 opener 인자/env, 실제 Electron의 shim 쓰기·bridge listen 실패 뒤 hook 유지, CJS·ESM 아래 generated JS 실행을 확인했다. Bash wrapper의 인자·native 종료 상태·GUI JSON·사용자 함수 우선권도 실행했다. Windows는 launch API·BOM byte만 확인했으며 **PowerShell 7·5.1·named pipe·`.cmd`·실제 browser·알림은 미확인**이다. macOS는 platform 인자의 기존 경로와 byte 한도 unit만 확인했고 실기 실행하지 않았다.

Land: 구현을 `90a4cd00e`로 main에 반영했다. land의 full check·기존 E2E·core 두 번 기동이 모두 통과했다. 사람 승인에 따라 roadmap을 끝남으로 바꾸고 계획 폴더를 닫는다. Windows 수동 확인은 루트 checklist에 미확인으로 남는다.

- 앱 key는 홑 타이고 modifier나 F1~F12가 있어야 한다. (agent)
- 입력 history는 그 GUI session에서 보낸 사람 메시지다. CLI history file은 읽지 않는다. (agent)

검증: task마다 full check·core 두 번 기동·renderer build. gallery `harness-gui-perf`의 key→paint(보통 속도)는 전 p50 12ms·p95 18ms, `key-agent` 뒤 12·18ms, `key-parity` 뒤 15~16·18ms였다(p50은 frame 하나 안의 흔들림). 실제 앱에서 CLI마다 눌러 보는 것은 사람이 한다.

후속: 북마크 머리 줄·desktop palette의 Home hint, main이 먼저 받는 chord의 앱 key, harness keymap의 겹침 검사, Electron 기본 menu의 Ctrl+R Reload는 `project-docs/issues/keybindings.md`.

## core가 shell 밖에서 스스로 선다

```yaml
modules: [packages/protocol, packages/core/server, packages/core/main, packages/core/jobs, packages/core/runs, packages/core/workflows, packages/core/install-and-update, packages/shell/main, packages/cli, packages/design, tools, tests]
checked: []
```

- 전: core는 shell main(Electron)의 child였고 parent pipe의 stdin EOF로 끝났다. 앱을 끄면 job도 멈췄다. CLI는 `run/user-token`·`run/location.json`을 읽어 붙었고 core를 띄우지 못했다(꺼져 있으면 exit 5). autostart는 `--tray`로 Electron 전체를 띄웠다.
- 후:
  - core는 data root마다 control socket(공통 socket 자리의 `core`, POSIX 0700 unix socket, win32 named pipe)을 연다. `identify`·`connect {client: cli|shell}`·`stop`·`diagnostic`과 shell capability로만 받는 사람 결정 handle 등록이다. shell과 CLI는 같은 `ensureCore`로 붙거나 core를 detached로 띄운다. 띄운 core는 stdout 첫 줄로 `ready`나 `start_failed`만 알린다(token 없음).
  - 앱의 Quit(Cmd+Q, tray `Quit lophn`)는 shell만 끈다. core는 남고, 켜진 job·열린 job run·running run·running workflow instance·Gateway 구독·진행 중 요청이 모두 없이 10분이 지나면 스스로 끝난다(idle-exit). 모두 끄는 tray `Stop lophn`과 `lophn core stop`이 생겼다. `core stop`은 core를 띄우지 않는다.
  - CLI는 사람 명령이면 core를 띄워서라도 붙는다. 주소는 `LOPHN_DAEMON_URL` 또는 identify다. agent 자격(`LOPHN_AGENT_CREDENTIAL`)이 있으면 그것만 쓰고 user 자격으로 바꾸지 않는다.
  - 로그인 autostart는 `--core`(macOS는 `wasOpenedAtLogin`)로 core만 띄우고 Electron은 바로 끝난다. 켜 둔 옛 `--tray` 등록은 다음 일반 실행에서 한 번 `--core`로 다시 쓴다.
  - parent pipe의 hello·stop·diagnostic·confirmation 메시지, `run/user-token`, `run/location.json`이 없어졌다. core↔child 감독 protocol은 그대로다.
  - 같은 core에 shell과 CLI가 각자 connect하므로 core마다 user credential 하나라는 제한을 지웠다.
- 저장 모양: ledger·설정·agent 파일은 그대로다. `run/user-token`·`run/location.json`은 runtime file이라 lock을 잡은 core가 남은 것을 지운다.

옮기기: 없음(runtime file과 OS 로그인 등록만 바뀐다).

왜: job이 Electron 수명에 묶여 앱을 끄면 멈췄고, 화면 없는 머신에서 CLI만으로 core를 켤 길이 없었다(사람, 2026-11-08, `products/roadmap/standalone-core.md`).

결정:
- 앱의 Quit는 shell만 끄고 core는 idle-exit로 끝난다. 모두 끄는 `Stop lophn`을 따로 둔다. (사람이 추천을 받음)
- CLI도 ensure로 core를 띄운다. 끄는 것은 idle-exit와 `lophn core stop`이다. (사람이 추천을 받음)
- idle-exit는 일도 client도 없이 10분이다. 앱 process와 control 요청은 세지 않고, 승인 대기 중인 켜진 job도 일로 친다. 30초마다 다시 보고 읽기 실패는 일로 친다. (agent)
- OS service(systemd, launchd agent, Windows service·scheduled task)로 등록하지 않는다. 로그인 autostart가 core만 띄우는 것으로 충분하다. (agent)
- 사람 결정 handle은 control `connect {client: shell}`의 shell capability로만 등록한다. HTTP token, agent·worker credential, route, CLI에는 길이 없다. OS peer 신원 검증은 하지 않는다. (planner)
- 동시 시작은 `run/instance.lock`이 가르고 liveness는 identify다. pid file과 HTTP health probe를 쓰지 않는다. 판이 다르면 stop → 종료 확인 → 새로 띄우기를 한 번 한다. (agent)
- 명시 stop 뒤 shell은 core를 저절로 다시 띄우지 않는다. (agent)

후속: `project-docs/issues/platform.md`(Quit 중 ensure, 다른 client의 stop 뒤 다시 붙기, 업데이트 뒤 첫 로그인 창). Linux에서 core SIGKILL 뒤 child가 스스로 끝나는 것을 `tests/e2e/boot_test.ts`가 본다. macOS·Windows는 확인하지 않았다.

## 팀 자식의 질문과 승인이 부모에게 먼저 간다

```yaml
modules: [packages/protocol, packages/core/approvals, packages/core/router, packages/core/lophn-agent, packages/core/main, packages/core/storage, packages/core/apps, packages/cli, packages/coding-agent, packages/shell/main, packages/shell/renderer]
checked: [architecture-agent-chat, architecture-run, architecture-workflow, architecture-agent-definition, architecture-app-call, architecture-terminal-agent, module-catalog, tool-eval]
```

- 전: spawn된 session의 `ask`(질문)와 shell 규칙 `ask`(승인)는 팀 밖 session처럼 사람의 대기 목록에 카드로 떴다. unattended turn에서는 질문이 `unattended`, shell ask가 그냥 실행이었다. 팀 상한 기본은 `max_depth: 3`, `max_members: 16`이었다.
- 후:
  - spawn된 session(`spawned_by` 있음)의 질문과 shell 승인은 부모에게 가는 result call이다(`agent_calls.ask`: `question` | `approval`). 자식 turn은 지금처럼 기다리고 부모의 답이 푼다. 부모가 판단할 수 없으면 자기 `ask`를 써서 위로 올리고 root에서 사람에게 닿는다.
  - attended·unattended 상관없이 같은 길이다. skip session의 shell ask는 지금처럼 그냥 돌고, 질문은 skip이어도 부모에게 간다. 팀 밖 session은 그대로다.
  - 부모는 `lophn call reply <call> --allow | --reject [--body <이유>]`로 답한다(`ReplyCall.decision`). 허락은 이번 한 번뿐이고 `always`(규칙 더하기)는 없다. `deny`는 부모에게 가지 않는다. 질문의 답은 자식에게 `{outcome: "parent_reply", message}`로 간다. harness·bare 부모의 자동 답이 승인 call에 닿으면 거절이다.
  - 자식 쪽이 먼저 끝나면 ask call이 취소되고, 부모가 끝나면 승인은 거절·질문은 `cancelled`로 풀린다. 재시작하면 부모가 가져간 ask call도 `lophn_restarted`로 닫힌다.
  - 자식 탭과 알림에는 이 물음의 카드가 뜨지 않는다(`TurnRequest.to_parent`, `QuestionAsked.to_parent`로 거른다). session 상태는 `waiting`이다.
  - `team read`의 팀원마다 답하지 않은 call(`open_calls`)이 보인다. `team spawn`의 첫 call 앞에 팀 지시문 고정 글이 붙고 help와 skill `lophn-agent`도 같은 말을 한다.
  - 팀 상한 기본값이 `max_depth: 2`(root 0), `max_members: 8`이다. 거절 글이 "do the work yourself or ask your parent"로 끝난다.
- 저장 모양: ledger step `router.agent-calls.ask`(`agent_calls.ask` 칸, 옛 행은 null).

옮기기: 없음(옛 call은 null이라 그대로다. 사람이 설정한 팀 상한은 설정 file에 있어 그대로다).

왜: 팀으로 일할 때 자식의 물음이 모두 사람에게 오면 coordinator가 할 일을 사람이 한다. "coordinator든 leader든 걔가 먼저 답하고 걔 판단으로 안 되겠음 걔가 사용자한테 올리고"(사람, 2026-11-08, `project-docs/products/roadmap/agent-surface.md` 정한 것 11~15).

결정:
- 올리는 장치를 따로 두지 않는다. 부모가 자기 `ask`를 쓰면 같은 규칙이 사슬을 만든다. (agent)
- 부모의 승인 답은 글이 아니라 `call reply`의 구조 칸이다. 새 명령을 두지 않았다. 부모는 이미 `call reply`를 안다. (agent)
- call과 request의 짝은 request처럼 main thread 메모리에 두고, 행에는 `ask` 표시만 둔다. (agent)
- 팀 자식의 event는 그대로 내고 표시로 거른다. `TurnResumed`, snapshot의 `waiting`, acp가 그 event에 기댄다. (planner)
- skip은 지킨다: skip session의 shell ask는 부모에게 가지 않는다. (planner)
- 팀 지시문은 system prompt에 넣지 않는다(prompt cache). (agent)

후속: 없음.

## agent가 팀을 늘리고 탭을 연다, shell extension이 agent의 tool을 낸다

```yaml
modules: [packages/protocol, packages/core/host-queue, packages/core/router, packages/core/approvals, packages/core/lophn-agent, packages/core/agent-workspaces, packages/core/config, packages/core/main, packages/core/storage, packages/cli, packages/coding-agent, packages/shell/main, packages/shell/renderer, packages/design, tools]

```

- 전: agent는 `call.send`로 새 session을 열 수 있었지만 누가 누구를 위해 열었는지 기록이 없어 팀이 없었다. agent는 탭을 열 길이 없었고, harness agent session을 TUI로 여는 화면도 없었다. shell extension은 agent에게 아무것도 주지 못했다.
- 후:
  - host queue: core 메모리의 요청 queue(`packages/core/host-queue/`)를 shell main이 1초마다 `host/take`로 가져가 그 workspace를 보이는 창에 push한다. shell이 없거나 창이 없으면 기다린다.
  - `lophn tab open (--session <ses> [--tui] | --url <url>) [--place beside|group|float]`, `lophn tab close <tab>`, `lophn browser read <tab>`. agent가 연 탭(key `host:<tab>`)은 선택과 focus를 뺏지 않고, agent는 자기가 연 탭만 닫고 자기가 연 browser 탭의 url·title·loading만 읽는다.
  - 팀: `lophn team spawn|read|end`. `team spawn`으로 연 session에 `spawned_by`가 남는다. 팀원의 call은 부모·형제·자기 자손으로만 가고(call 정책은 그 위에 겹친다), `team end`는 자기 자손만 닫는다. 상한은 설정 `lophn-agent.team`이다. 팀이 바뀌면 다음 turn에 notice `team_changed`가 붙는다. 같은 workspace의 자식은 부모 옆 group에 열린다. `call.send`의 새 session은 그대로 팀 밖이다.
  - harness agent의 TUI 탭: 터미널 탭에 그 CLI의 resume 줄을 친다(project workspace의 session만). 탭이 있는 동안 그 session의 headless turn은 시작하지 않고 입력은 queue에 남는다.
  - extension tool: manifest `contributes.tools`, `ctx.tools.handle`. 사람만 쓰는 정의 칸 `extensions`로 할당한 agent의 `tools[]`에 `ext__<id>__<tool>`로 실린다. 호출은 `extension_tools/call` → host queue → shell main handler이고, handler는 그 호출만 쓰는 agent 자격을 받는다. Gate `extension_tool`(`not_assigned`, `removed`), 묻지 않는다. harness agent는 `lophn ext call <name> --input '<json>'`. 편집기에 "Shell extensions" 칸, 명함 `diff.plus`에 `ext: <id>`.
  - 앱 slug `tab`, `browser`, `team`, `ext`를 예약했다.
- 저장 모양: ledger step `lophn-agent.sessions.spawned-by`(`sessions.spawned_by`, 옛 session은 null). 정의 칸 `extensions`는 새 optional 칸이다.

옮기기: ledger step이 자동으로 돈다. 정의 file은 그대로 읽힌다.

결정:
- host queue는 harness queue를 일반화하지 않고 같은 꼴로 새로 둔다. harness queue는 session마다 turn 입력을 담는 queue라 요청 종류를 실을 자리가 없다. (사람이 확인)
- 팀 상한은 root session 아래 열린 자손 수로 센다. core는 desk를 모른다. (사람이 확인)
- `team_changed`는 turn 준비 때 비교해 붙이고 queue에 넣지 않는다. 쉬던 session을 깨우지 않는다. (사람이 확인)
- TUI는 project workspace의 session만, 첫 turn 전·turn 중이면 `conflict`다. TUI hold는 탭이 있는 동안이다. (사람이 확인, agent)
- shell main이 extension tool 목록을 core에 올리고 core는 메모리에만 둔다. (사람이 확인)
- extension tool의 Gate 판정은 tool 정의가 아니라 호출 route 한 곳에서 한다. lophn runtime과 harness CLI가 같은 길을 거친다. (agent)

후속: 진짜 Electron 창에서 agent의 `tab open`·`team spawn` 탭과 진짜 harness CLI의 TUI resume은 사람이 아직 보지 않았다. TUI hold의 두 틈은 `project-docs/issues/coding-agent.md`.

## 사용자 package(`@me`) publish·catalog 결함 정리

```yaml
modules: [packages/base, packages/protocol, packages/core/apps, packages/core/main, packages/core/agent-workspaces, packages/cli]
checked: [architecture-app-call, architecture-package]
```

- 전:
  - publish한 bundle의 blob에 참조가 없어 7일 뒤 GC 대상이었다. 공개 판의 byte는 `<data>/sdk/@me/<part>/<version>` 설치 사본 하나뿐이었다.
  - `@me` package의 `permissions`는 정보일 뿐이었다. 소비 앱은 그 권한 없이 release를 낼 수 있었다.
  - 판 schema는 `1.0.0-beta`를 받았지만 ledger CHECK가 막아 내부 오류가 났다. 판 목록은 문자열 순서였다(`0.10.0`이 `0.9.0` 앞).
  - publish는 폴더 `package.json`의 name·version을 보지 않았다. description은 첫 publish 값에 고정됐다. `kind`, publish 입력 `key`는 쓰지 않는 칸이었다.
- 후:
  - bundle은 `package_version/bundle` blob(permanent)으로 같은 tx에서 등록된다. core가 뜰 때(`sdkInstallWiring.start`) catalog의 `@me` 판마다 설치 사본이 없거나 다르면 blob에서 다시 쓴다. 실패한 판은 `me_copy_skipped` 경고로 남기고 기동은 계속된다.
  - `package.publish`는 폴더의 `@lophn/cap-*` 의존이 요구하는 권한이 `permissions`에 없으면 `invalid_input`이다. `permissions`는 선언 permission 여섯 이름만 받는다. release 준비는 `@me` 의존의 정확한 판이 적은 권한을 소비 앱 선언에서 모두 요구하고, catalog에 없는 판은 `invalid_input`이다.
  - 판은 정확한 `x.y.z`만 받는다. 판 목록은 숫자 순서다(`compareVersions`, `packages/base`).
  - 폴더 `package.json`의 name·version이 입력과 다르면 `invalid_input`이다. description은 새 판을 낼 때 그 판의 값으로 바뀐다(옛 판 재시도는 바꾸지 않는다).
  - `kind`(catalog 값, register 입력, `PackageVersionRegistered` payload)와 publish 입력 `key`를 지웠다. `package.read` 설명은 `used_by`가 `@me`에만 있다고 적는다.
  - 앱 agent 지침: 내장 skill `publish-package`(내기와 쓰기 절차, 실패별 대처)를 더했다. app prompt는 package로 옮기거나 남의 package를 쓸 때 그 skill을 읽게 하고, home prompt는 사람이 정하면 code가 있는 앱의 lophn에게 넘기게 한다. 전에는 `package.publish` 설명과 `--help`뿐이었다.
- 저장 모양: blob 참조 field `package_version/bundle`이 늘었다. ledger 표는 그대로다.

옮기기: 이미 낸 판은 기동 때 설치 사본에서 `package.json`의 `file:` 재작성을 되돌려 bundle byte를 다시 만들고, sha256이 `bundle_hash`와 같으면 blob을 만들어 `register_version` 재시도로 참조를 붙인다. blob이 붙어야 하고 SQL만으로 안 되므로 schema step이 아니라 기동 단계에서 멱등으로 돈다.

왜: 설치 사본을 잃으면 공개 판을 되살릴 길이 없었고(사용자 data), 권한 누락이 실행 중 broker 거절로만 드러났다(사람, 2026-11-08, `reports/user-package-architecture.md`).

결정:
- 공개 판의 byte는 ledger blob이 지키고 설치 사본은 그 파생이다. 버린 길: "같은 내용으로 다시 publish"로 복구(앱 HEAD가 바뀌면 hash가 달라 불가). (사람이 추천을 받음)
- `@me` permission은 publish와 release 준비에서 강제한다. 버린 길: 칸 지우기(schema step이 들어 일이 비슷한데 얻는 것이 없다), 정보로 두기. (사람이 추천을 받음)
- description은 최신 판을 따른다. 버린 길: 다르면 `conflict`(설명 하나로 publish가 막힌다). (사람이 추천을 받음)
- prerelease는 받지 않는다. ledger를 넓히는 대신 protocol을 좁혔다. (agent)

후속: `project-docs/issues/app-call.md`(`@me`가 `@me`에 기대는 권한, 옮기기가 못 붙인 옛 판).

## 터미널: 다시 붙은 탭의 mouse, 이모지 폭, TUI 복사를 고친다

```yaml
modules: [packages/shell/renderer, packages/shell/terminal-host]
checked: []
```

- 전:
  - 창 reload나 project를 떠났다 돌아와 터미널이 다시 붙으면, mouse를 받는 TUI(Claude Code, OpenCode)에서 드래그·클릭·wheel이 모두 사라졌다. snapshot이 SGR mouse 인코딩을 빠뜨려 xterm이 X10 report를 `onBinary`로 냈고, lophn은 `onData`만 보냈다. xterm 자체 선택도 꺼져 있었다.
  - xterm이 Unicode 6 폭표라 이모지(🔥✅🚀)를 1칸으로 셌다. TUI는 2칸으로 그려 그 줄 뒤가 밀렸고, OpenCode 화면에 지워야 할 글자가 남았다.
  - snapshot을 새 view 크기로 써서 줄이 꺾일 수 있었고, 그 뒤 PTY 치수가 같으면 TUI가 다시 그리지 않았다.
  - TUI가 고른 글의 OSC 52 복사를 삼켜 Claude Code·OpenCode 안에서 드래그한 글이 clipboard에 가지 않았다.
- 후: host 화면이 mouse 인코딩과 커서 숨김을 따라가 snapshot에 붙인다. renderer는 0x80 아래 `onBinary`도 보낸다. 글자 폭은 renderer·host 모두 Unicode 11이다. snapshot은 PTY 치수로 쓴 뒤 칸에 맞추고 치수가 달라지면 PTY를 resize한다. 사람이 그 터미널에서 mouse를 뗀 뒤 첫 OSC 52 쓰기 하나를 clipboard에 쓴다.

- 폭표는 graphemes(Unicode 15)가 아니라 Unicode 11이다. OpenCode는 xterm이 grapheme mode(2027)를 모른다고 답하면 코드포인트 폭을 더하는데 그 값이 Unicode 11과 같다. VS16·ZWJ 이모지는 Claude Code(string-width)와 1칸 어긋날 수 있다. (agent)
- OSC 52는 쓰기만, mouse를 뗀 뒤 한 번만 받는다. 출력은 인터넷에서 온 글일 수 있어 아무 때나 clipboard를 바꾸게 두지 않는다. (agent)

후속: 없음.

## workspace마다 lophn, 모든 workspace에 같은 설정 층, workspace memory와 agent memory

```yaml
modules: [packages/protocol, packages/core/lophn-agent, packages/core/agent-workspaces, packages/core/main, packages/core/apps, packages/core/approvals, packages/core/jobs, packages/core/runs, packages/core/storage, packages/core/router, packages/cli, packages/shell/ipc, packages/shell/main, packages/shell/preload, packages/shell/renderer, packages/sdk, packages/design, tests, tools]
```

- 전:
  - 내장 lophn은 id `lophn` 하나였고, 정의 `<data>/agents/lophn.md`의 name·model·MCP·끄기·할당이 모든 workspace에 같이 걸렸다. Settings › Agents에 전역 lophn 편집이 있었다.
  - 사람 설정 층(지시 `LOPHN.md`, `extensions.json`의 MCP·skill 끄기, model)은 project만 가졌다. Home과 앱은 전역 층만 받았고, 앱 agent는 source의 `AGENTS.md`를 file tool로 읽으라는 prompt를 받았다.
  - session을 건너 남는 memory가 없었다.
- 후:
  - lophn은 workspace마다 하나다. id는 workspace에서 정해진다: Home `lophn_home`, project·앱 `lophn_<prj|app id>`. 정의는 `<data>/agents/<id>.md`이고 없으면 기본 정의다. handle은 모두 `lophn`이고 `{agent: "lophn", workspace}`로 부른다. workspace를 빼면 부른 쪽 workspace의 lophn이다. lophn은 그 workspace의 범위 agent처럼 목록·명함·call 정책·할당·MCP secret이 agent id로 나뉜다. protocol의 `LOPHN_AGENT_ID`가 없어지고 `lophnIdOf`, `isLophn`, `workspaceOfLophn`이 생겼다. `agents/card`가 `workspace`를 받는다.
  - migration(ledger step `lophn.split-per-workspace`와 같은 id의 data step)이 전역 `agents/lophn.md`를 Home과 모든 project·앱(archived 포함)의 lophn 정의로 복사하고 지운다. `sessions`, `jobs`, `runs`, `agent_calls`, `share_requests`의 `lophn` id, settings의 call policy 규칙, `secrets.json`의 `mcp.lophn.*`·`mcp-oauth.lophn.*`, shell layout 탭의 agent도 workspace의 lophn id로(여럿에 걸리면 모든 lophn으로) 옮긴다.
  - Settings › Agents의 lophn card와 편집이 없어졌다. 전역 `LOPHN.md` 편집은 남는다. lophn의 name은 workspace의 Agents 탭에서 바꾼다.
  - Home·project·앱이 같은 층을 갖는다. Home 그릇 자리 `<data>/home/`(`LOPHN.md`, `extensions.json`, `skills/`), 앱은 `<data>/apps/<app>/extensions.json`과 source의 `AGENTS.md`(지시 층 `app`)다. 지시 층은 global → home | project | app → agent다. route `projectExtensionSettings*`·`projectModel*`가 `workspaceExtensionSettingsRead|Change`·`workspaceModelRead|Change`(입력 `{workspace: "home" | prj id | app id}`)로 바뀌었다. Home 층 MCP OAuth owner는 `home`이다.
  - memory 둘: workspace memory `<그릇 자리>/memory.md`(그 workspace의 lophn이 쓰고 그 workspace의 agent가 받는다), agent memory `<data>/agent-memory/<agt_id>.md`(사람이 만든 agent마다). tool `agent.memory`(덧붙이기, 바꾸기)로만 쓰고 file tool 범위에는 없다. rewind가 되돌린다. 지시 block 뒤 `memory` block에 `~~~data`로 실리고 session 첫 turn에 고정된다(daemon 재시작과 Compact 뒤 다시 읽는다). 파일마다 8 KiB이고 넘치는 쓰기는 거절한다. notice는 없다. 내장 prompt(Home·project·앱)와 `update-apps`·`migrate-sdk` skill이 memory에 담을 것과 담지 않을 것을 말한다. `@lophn/agent` 1.6.0과 `migrate-sdk` 메모.
  - Agents 탭이 Home과 앱에서도 열린다. 그 workspace의 지시(Home `LOPHN.md`, 앱 source `AGENTS.md`, source가 없는 앱은 빈 칸), model, skill·MCP 끄기를 보고 고친다. Agents 탭에 workspace memory 칸, agent 편집기에 agent memory 칸이 있고 사람은 editor로 고친다(8 KiB 대비 크기, 다음 session부터 보인다). `skills/read` 입력이 `{workspace?: "home" | prj id | app id}`가 된다. 새 shell IPC로 memory 파일을 연다.

- 내장 lophn은 workspace마다 객체다. name, model, 본문, MCP, 끄기, extensions, apps, permissions, skip이 그 workspace의 것이다.
- handle은 모두 `lophn`이고 lophn 하나는 handle과 workspace의 짝으로 가리킨다. name은 사람이 workspace마다 바꾼다.
- workspace의 lophn은 그 workspace의 범위 agent처럼 돈다. Home lophn은 Home에서만 보인다. (agent)
- 전역 lophn과 `lophn` id로 저장된 것은 migration이 모든 workspace의 lophn으로 옮긴다. 사람이 그 뒤에 workspace마다 뺀다. (agent)
- Settings의 전역 lophn 편집은 없애고 전역 `LOPHN.md` 편집은 남긴다. (agent)
- 모든 workspace가 같은 층을 갖는다. project model 층은 workspace model 층이 된다.
- Home 층의 MCP OAuth owner 열쇠는 전역(`global`)과 다른 `home`이다. (agent)
- 앱 지시 층은 앱 source의 `AGENTS.md`다. template에서 오고 이미 그 역할을 하므로 앱에 한해 `AGENTS.md`를 지시로 읽는다. source가 없는 앱은 그 층이 없다.

- memory tool 이름은 `agent.memory`다. `memory`를 앱 slug 예약 목록에 더하면 `@lophn/declaration`과 `app-ui` 판이 줄줄이 오른다. (agent)
- 앱 agent 지침의 memory 습관은 `@lophn/agent` 1.6.0(minor) 메모로 알린다. `agent`는 다른 SDK가 기대지 않는 leaf라 pin 바꿈이 작다. 1.5.0을 pin한 앱은 SDK 업데이트가 있다고 보인다. (agent)
- model 출처 값 `project`는 이제 workspace 층(Home·project·앱)을 뜻하지만 이름은 그대로 둔다. 공개 SDK type `AcpSessionMeta.layer`에 실려 있어 바꾸면 SDK가 깨지는 변경이 된다. 화면 글만 "workspace default"다. (agent)
