# apps

## 왜
앱은 보는 사람이 없어도 돌고, 오래 쓸수록 가치가 쌓여야 한다. 코드를 읽지 않아도 쓰고, 바꾸고, 되돌릴 수 있어야 한다.

## 무엇을 약속하나

- **[I1]** 코드를 몰라도 앱이 무엇을 하는지 안다.
- **[I2]** 바꾼 앱은 실제 데이터에 쓰기 전에 미리 써 보고 고른다.
- **[I3]** 쓰던 앱은 내가 바꾸기 전에는 그대로이고, 새 판이 마음에 안 들면 이전 판으로 되돌린다.
- **[I4]** 두 번째 앱은 공용 SDK와 화면 재료를 써서 첫 번째보다 빨리 만들어진다.
- **[I5]** 앱은 내가 보지 않을 때도 정한 일(예: 매일 동기화)을 한다.
- **[I6]** 한 앱이 깨져도 다른 앱은 멀쩡하다.
- **[I7]** 내가 만든 앱의 기능(예: 캘린더에 일정 넣기)을 다른 앱과 agent가 MCP를 따로 만들지 않고 바로 쓴다.
- **[I8]** 탭이나 대화에 띄우려고 만든 앱은 패널과 카드로 보인다(예: rate limit 대시보드를 문서 옆에).
- **[I9]** 앱은 agent에게 보여 줄 화면 상태를 정하고, 민감한 칸은 숨긴다.

## 하지 않는 것
- 코드를 짜는 도구나 앱 마켓을 만들지 않는다.
- 옛 판으로 되돌리는 것을 이미 쌓인 데이터나 밖으로 나간 효과의 취소로 보이지 않는다.

## 잘되고 있다는 신호
- 두 번째 앱은 더 적은 일로 만들어진다.
- 쓰던 앱은 update 뒤에도 같은 동작을 한다.
