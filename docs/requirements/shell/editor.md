# shell/editor

문서를 같은 자리에서 읽고 고치는 편집기, 문서 탭·분할·정보 패널·저장 상태와 외부 변경 충돌의 표시를 맡는다; 디스크 쓰기·편집 세션 종료·버전 생성·충돌 판정은 documents/file-tracking과 documents/versions를 따른다.

## 요구

### 화면과 조작

**[R1]** 탭 닫기·파일 전환·읽기 전환·창 닫기·CommandOrControl+S를 documents/file-tracking의 편집 세션 종료에 연결하고 유휴 종료도 그 concern의 결과로 반영한다.
- 이유: 창·탭 조작이 마지막 편집을 빠뜨리지 않게 한다.
- 확인: 각 조작 뒤 마지막 편집이 누락되지 않고 종료 기록이 중복되지 않으며 유휴 2분의 실제 판정은 documents/file-tracking을 따른다.

**[R2]** 저장 상태는 디스크 저장 성공·버전 확정·형식 검사 실패를 서로 다른 상태로 보여 준다.
- 이유: 디스크 저장과 version 확정을 같은 성공으로 혼동하지 않는다.
- 확인: 디스크 저장 뒤 documents/file-tracking의 800ms 버전 처리와 documents/formats의 실패에서 디스크 성공을 버전 성공으로 표시하지 않는다.

**[R3]** 문서 탭 막대는 36px·탭 폭 120~220px·고정 탭 36px·좌우 여백 12px·아이콘 14px·간격 6px·닫기 영역 20px로 두고 focus 칸의 활성 탭 위에는 2px 표시를 쓰며 동명은 가장 짧은 상위 폴더로 구별한다.
- 이유: 여러 문서의 구별과 닫기 조작을 안정적으로 제공한다.
- 확인: 탭이 최소 120px까지 줄어든 뒤 가로 스크롤하고 활성 탭이 보이며 닫기 자리는 항상 유지된다.

**[R4]** 탭 제목은 파일 이름·tooltip은 문서 제목과 상대 경로로 보이고 tablist·tab·tabpanel 의미 및 좌우 화살표·Enter·Delete 조작을 제공하며 문서 제목이 사라지면 32px sticky 머리를 붙인다.
- 이유: 문서 이름과 읽는 위치를 키보드로 찾을 수 있게 한다.
- 확인: 키보드만으로 이동·열기·닫기가 가능하고 sticky 머리에 제목과 현재 절이 보인다.

**[R5]** 분할은 좌우 1칸 또는 2칸·최소 칸 폭 480px·경계 1px·잡는 영역 8px·focus 표시 2px로 두고 두 번 누르면 50:50이며 공간별 비율을 기억하고 좁아져도 분할 상태는 유지한 한 칸 보기로 전환한다.
- 이유: 좁은 창에서도 두 문서의 배치 선택을 잃지 않는다.
- 확인: 다시 넓히면 두 칸과 비율이 복원되고 위아래·3칸 분할은 없다.

**[R6]** 정보 패널은 320px·머리 36px·안 여백 16px·목록 행 32px·절 간격 20px에 정보·버전·컨텍스트 탭을 두고 기본 닫힘·공간별 열림과 마지막 탭 기억·CommandOrControl+Alt+B 조작을 제공한다.
- 이유: 문서 부가 정보가 본문을 상시 차지하지 않게 한다.
- 확인: overlay는 Escape·바깥 click으로 닫고 shell/design-system의 폭 예산에 따라 붙거나 뜬다.

**[R7]** Markdown 편집기는 CodeMirror 6으로 shell 안에서만 사용하고 두 번째 실제 소비자가 필요하기 전에는 SDK 공개 계약에 포함하지 않는다.
- 이유: 실제 재사용 수요 없이 앱 SDK에 편집기 계약을 고정하지 않는다.
- 확인: 앱 SDK에 CodeMirror 공개 API가 추가되지 않으며 shell의 문서 편집이 동작한다.

**[R8]** 읽기와 편집은 같은 기둥·읽기 폭·16px/28px 글꼴 및 제목·목록·인용·코드 스타일을 쓰고 전환 전후 첫 블록 위치 차이를 4px 이하로 유지한다.
- 이유: 읽기·편집 전환 때 읽던 위치를 잃지 않는다.
- 확인: e2e로 전환 전후 첫 블록 위치를 재어 4px 이하이다.

**[R9]** 편집 mode는 머리의 편집/읽기 버튼과 커서만 바꾸며 배경·테두리는 바꾸지 않고 Markdown 표시 문자는 커서가 해당 요소 안에 있을 때만 muted 글자로 보인다.
- 이유: 편집 mode가 문서 내용과 다른 화면처럼 느껴지지 않게 한다.
- 확인: 커서를 요소 밖으로 옮기면 원문 표지가 숨고 읽기·편집 배경이 같다.

**[R10]** 편집기의 인라인 코드·코드 블록은 고정폭과 muted 배경에 문법 강조 없이 그리며 인용 막대 2px·체크박스 16px·본문 최대폭 이미지와 16:9 loading skeleton·frontmatter key/value 두 열을 쓴다.
- 이유: Markdown 구조는 읽을 수 있게 하되 코드 장식이 글을 압도하지 않게 한다.
- 확인: 이미지 실패에는 아이콘과 alt가 보이고 코드·인용·속성이 정한 모양이다.

**[R11]** 찾기 줄은 36px·입력 28px, 형식 문제는 왼쪽 여백 24px의 아이콘 14px와 최대 200px 목록, 링크 선택은 320px popover·32px 행으로 그리고 저장 상태 변경은 screen reader에 polite로 전달한다.
- 이유: 찾기·문제·링크 조작과 저장 상태를 접근 가능하게 한다.
- 확인: 찾기·형식 문제·링크 고르기를 키보드로 조작하고 저장 상태를 screen reader로 듣는다.

**[R12]** 저장 버튼 없이 고침을 자동 저장 흐름에 연결하고 머리 메타 줄에서 저장 중·디스크 저장·버전 확정·검사 문제·연결 끊김·실패를 구별한다.
- 이유: 저장 단계의 실패를 정상 완료로 오인하지 않게 한다.
- 확인: 형식 실패와 연결 끊김이 정상 저장으로 표시되지 않으며 실제 저장은 documents/file-tracking을 따른다.

**[R13]** 버전 비교는 도구 줄 44px·바뀐 절 목록 220px·원문 13px/20px·옛/새 줄 번호 각 40px·기호 16px를 쓰고 변경 없는 연속 7줄 초과는 앞뒤 3줄만 남기며 나란히 보기는 본문 1,100px 이상·5,000줄 초과는 절 선택으로 제한한다.
- 이유: 큰 diff에서도 변경 범위를 먼저 찾을 수 있게 한다.
- 확인: 좁은 칸에는 한 줄 보기와 이유가 보이고 접힌 줄을 펼칠 수 있다.

**[R14]** 비교에는 +·− 기호를 색과 함께 쓰고 같으면 두 버전의 내용이 같습니다를 보이며 복원은 secondary 행동으로 두어 primary 버튼을 두지 않는다.
- 이유: 비교는 차이를 이해하는 화면이지 revert를 유도하는 화면이 아니다.
- 확인: 색 없이 차이가 읽히고 같은 버전에서 빈 상태가 보이며 복원 의미는 documents/versions를 따른다.

**[R15]** 문서 옆 notice는 높이 32px·아이콘 14px·아래 여백 12px에 가장 높은 우선순위 하나를 보이고 충돌 막대는 해결까지 유지하여 assertive로 전달하며 나머지는 polite·디스크 재읽기 안내만 3초 뒤 사라지게 한다.
- 이유: 외부 충돌을 짧은 안내로 놓치지 않게 한다.
- 확인: 외부 변경 충돌이 토스트처럼 사라지지 않고 해결 화면으로 이동한다.

**[R16]** 작업대 상단 경로는 focus 칸 활성 탭을 따르고 문서 머리는 제목 20px·메타 12px·편집 ghost 및 CommandOrControl+E·정보 패널·메뉴를 두며 notice 간격 12px·본문 간격 24px를 지키고 읽기 화면에 primary를 두지 않는다.
- 이유: 현재 문서와 focus 위치를 일관되게 안내한다.
- 확인: focus 칸을 바꾸면 경로가 바뀌고 정한 머리·본문 치수가 유지된다.
