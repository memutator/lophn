# 0.16.0

## 빠른 실행: hover로 바로 열기, 전역 값과 project 값, 앱 panel 여는 자리

```yaml
modules: [packages/shell/renderer, packages/core/config, packages/design]
checked: []
```

- 전: 앱 하나를 열려면 App 단추 → App ▾ menu의 App panel → 고르는 탭 → 앱 고르기였다. Browser·Terminal 단추는 빈 탭만 열었다. 빠른 실행 순서와 고정은 project의 layout `quick`에만 있어 Home·앱 place는 기본 순서였다. 옛 activity bar의 앱 panel 여는 자리(dock·float, `rail_apps.open`)는 UI 개편 때 빠졌다. New session ▾의 coding agent는 Claude Code·Codex·OpenCode로 고정이었고 명령어를 바꿀 수 없었다.
- 후:
  - Terminal · Browser · App 단추에 pointer를 올리면 목록이 뜬다: 즐겨찾기 coding agent, bookmark, 앱 화면과 모든 앱 panel 화면(icon과 이름). 줄을 누르면 바로 연다. 단추를 누르면 전처럼 탭을 연다(App은 고르는 앱 panel 탭).
  - Settings › Quick launch(새 항목): 전역 단추 순서와 켜고 끄기(줄마다 Switch), 고정할 앱 panel, 앱 panel 화면마다 여는 자리(Tab · Float).
  - Project settings › Quick launch: "Use the global quick launch" Switch. 끄면 그 project만의 순서·켜고 끄기·고정을 둔다(지금 전역 값에서 시작).
  - 앱 panel float을 옮기거나 크기를 바꾸면 그 화면의 자리·크기를 기억해 다음 float(빠른 실행, tab menu의 Float)이 거기서 열린다.
  - Settings › Coding agents 표에 Command(비우면 기본 명령어)와 Favorite(별) 열. 즐겨찾기가 Terminal hover와 New session ▾에 나온다.
  - 저장: core 선언 설정 `shell.quick_launch`, `shell.app_launch`, `shell.coding_agents`(`settings.json`). layout 파일 `quick`에 선택 필드 `hidden`(끈 단추 id)이 붙는다. 없으면 모두 켜짐이라 옛 파일은 그대로 읽힌다.
  - design `Popover`에 `hover` prop.

왜: 사람이 앱을 여는 길이 너무 길다고 했다. 앱 panel의 dock·float 정책은 개편 때 잃은 기능이다(사람 2026-11-02).

결정:
- project 값은 전역 값을 통째로 덮는다(합치지 않는다). (사람 2026-11-02)
- 이미 `quick`을 저장한 project는 "이 project만의 값"으로 남는다. Home과 앱 place는 덮어쓰기 칸이 없다. (agent)
- 여는 자리와 기억한 자리는 앱 panel 화면(`<app>:<surface>`)마다 전역 하나다. place마다 따로 두지 않는다. (agent)
- 여는 자리는 사람이 고르는 설정이고, 기억은 float 자리·크기만 한다. 마지막에 dock했는지 float했는지는 따라가지 않는다. (agent)
- 즐겨찾기의 기본값은 전에 고정이던 Claude Code·Codex·OpenCode다. (agent)
- 끈 단추는 순서에서 빼지 않고 `hidden`에 따로 둔다. 순서에서 빼면 `quickOrder`가 모르는 기본 단추를 끝에 다시 붙여 꺼지지 않는다. (agent)

## tab 줄 폭과 group 접기, split 칸의 stack

```yaml
modules: [packages/shell/renderer, packages/shell/main, packages/design]
checked: []
```

- 전: 고르지 않은 tab은 224px 고정 폭이고 고른 tab도 224px보다 좁아지지 않아 짧은 이름도 넓었다. 고르지 않은 group은 늘 아이콘만, 고른 group은 focus 반쪽만 이름을 보였다. 이미 split인 coding agent 터미널이 문서·URL을 또 열면 새 tab이 옆 칸을 차지하고 전 tab은 group에서 빠졌다. tab 줄에서 group 칸을 끌면 늘 group 통째(첫 tab, 대개 coding agent)가 끌려 tab 하나를 꺼내거나 넣을 수 없었다.
- 후:
  - tab은 이름 폭만큼이다(고르지 않은 tab의 긴 이름만 자른다). 줄이 넘치지 않으면 group도 모든 이름을 보이고, 넘칠 때만 고르지 않은 group부터 아이콘으로 접힌다.
  - split 칸 하나가 여러 tab을 돌려 본다(칸의 stack). 터미널 옆에 열기는 다음 칸에 쌓고 마지막 것을 보인다. tab 줄 group 칸에 칸의 tab이 모두 보이고(고르면 이름까지, 아니면 숨은 tab은 아이콘), 칸 머리의 ‹ n/m ›로 돌려 본다. ⋯의 Move out of pane이 tab 하나를 꺼낸다.
  - tab 줄 group 칸 안의 tab을 끌면 그 tab 하나가 움직인다. 다른 tab을 card 칸 가운데나 tab 줄 group 칸의 두 tab 사이에 놓으면 그 칸 stack의 그 자리에 들어간다. 칸의 빈 곳을 끌면 group 통째다.
  - 저장: layout 파일 leaf에 선택 필드 `stack`(온 순서, 보이는 tab 포함). 없으면 칸 하나라 옛 파일은 그대로 읽힌다.

왜: 사람이 짧은 이름 tab이 넓고, 공간이 남는데 group을 아이콘으로 접고, coding agent가 보낸 것이 빠지고, group의 tab 하나를 끌어 넣고 뺄 수 없다고 했다(사람 2026-11-02).

결정:
- 칸에 쌓인 tab은 tab 줄에 따로 칸을 두지 않고 group 칸 안에 그 칸 자리로 보인다. 개수 표시와 밑줄은 쓰지 않는다. (사람 2026-11-02)
- group 칸 가운데에 놓기는 swap이 아니라 그 칸에 쌓기다. group이 아닌 칸의 가운데는 그대로 swap이다. 옮기면 group이 풀리는 놓기는 막는다. (agent)
- 보이는 tab이 칸을 떠나면(닫기, float, 끌어 옮기기, Remove from split) 칸은 남고 stack의 이웃이 보인다. Unsplit은 숨은 tab까지 tab 줄에 내놓는다. (agent)
- 판을 올리지 않는다. `stack`은 선택 필드라 옛 파일이 그대로 맞다. (agent)

## 명령 결과가 model 한도를 넘으면 버리지 않고 파일로 두고 경로를 준다

```yaml
modules: [packages/core/lophn-agent, packages/protocol/lophn-agent, packages/core/main/agent-runtime]
checked: []
```

- 전: 내장 명령 결과는 24 KiB를 넘으면 배열 뒤쪽을 버리고 `omitted` 수만 남겼다. 앱 command 결과는 24 KiB를 넘으면 통째로 `result: null`과 "the result was too large to show"로 바뀌었다. 나머지를 볼 길이 없어, 앱 지침이 "command 결과는 작게"를 요구하고 앱이 스스로 범위를 줄였다(calendar `agenda` 62일).
- 후: handler는 전체를 돌려주고, 넘치면 runtime이 전체를 `<data root>/tool-results/<session>/<tool call>.json`에 쓰고 model에는 앞부분과 경로를 준다. 그 session의 file tool은 자기 결과 폴더만 읽기로 연다.

왜: 결과를 model에 맞게 줄이는 것은 agent runtime의 책임이다. 그 한도 때문에 앱의 기능이 깎이면 안 된다.

결정:
- 넘친 결과는 파일로 두고 경로를 준다(Claude Code가 큰 tool 출력을 파일로 두고 미리보기와 경로를 주는 것과 같다). (사람 2026-11-02)
- 스스로 창을 나누는 tool(file.read 등)은 이 길을 타지 않는다. 넘친 file.read를 다시 파일로 쓰는 고리를 막는다. (agent)
- 결과 폴더는 읽기 범위에 섞지 않고 따로 연다. 작업 폴더가 되지 않게 한다. (agent)

## 오른쪽 sidebar에서 Files 밖의 panel을 누르면 창이 비던 것

```yaml
modules: [packages/shell/renderer]
checked: []
```

- 전: project의 Files panel에서 Domains, Artifacts, Workflows, Scheduled jobs 중 하나를 누르면 `NotFoundError: removeChild` 예외가 나고 창 전체가 빈 화면이 됐다. 0.15.0에서 Files의 루트 선택을 머리 줄 `<h2>`에 portal로 넣었다. 다른 panel의 제목 문자열이 같은 `<h2>`에 들어가면서 portal의 노드를 지웠고, 그 뒤 Explorer unmount의 `removeChild`가 실패했다. error boundary가 없어 root가 통째로 내려갔다.
- 후: `<h2>`는 제목 문자열과 portal을 받는 `<span>`을 따로 갖는다. React가 자식을 그리는 element와 portal을 받는 element가 겹치지 않는다.

왜: 사람이 보고했다(2026-11-03). mock 모드 앱에서 네 panel 모두 재현했고 고친 뒤 양방향 전환이 예외 없이 된다.

## Explorer의 Copy Path가 복사하지 않던 것

```yaml
modules: [packages/shell/main/app-frame]
checked: []
```

- 전: shell 창의 모든 `navigator.clipboard.writeText`가 `NotAllowedError: Write permission denied`로 실패했다(Explorer의 Copy Path·Copy Relative Path, code block·markdown·table 복사). desktop 창과 overlay가 같은 default session을 쓰는데, overlay 보안이 그 session의 permission을 모두 거절했다(`75b1a6fbf`, 2026-10-04).
- 후: default session은 `lophn-shell://` page의 main frame이 요청하는 clipboard 쓰기(`clipboard-sanitized-write`)만 허락한다. clipboard 읽기와 나머지는 그대로 거절한다. 표는 `overlay-security_test.ts`가 지킨다.

왜: 사람이 보고했다(2026-11-03). 터미널은 이미 main IPC로 clipboard에 쓰므로 shell page에 새 능력을 주는 것이 아니다.

## Linux에서 Explorer의 Delete가 5초 걸리던 것

```yaml
modules: [packages/shell/main/desktop/wiring]
checked: []
```

- 전: Electron `shell.trashItem`이 KDE에서 `kioclient move <path> trash:/`를 띄웠고, 파일 하나에 5.2초 걸렸다.
- 후: Linux는 `gio trash`를 먼저 쓴다(같은 파일에 10ms). gio가 없거나 실패하면 `shell.trashItem`으로 넘긴다. 둘 다 못 버리면 전처럼 아무것도 지우지 않고 `unavailable`이다.

왜: 사람이 보고했다(2026-11-03).

결정:
- Reveal in File Manager가 느린 것은 고치지 않는다. lophn의 요청은 1ms에 끝나고, 그 뒤 xdg-desktop-portal이 이 기계의 `FileManager1` 이름을 가진 Nautilus를 깨우는 데서 걸린다. 앱이 아니라 기계 설정의 일이다. (agent)

## 왼쪽 sidebar: New session은 place 줄의 +, current 줄에 Rename·Stop, 설정 톱니는 hover 때만

```yaml
modules: [packages/shell/renderer]
checked: []
```

- 전: 맨 위에 New session 줄(▾ menu)이 있었다. 이 창 place 줄의 톱니(Project settings·App details)가 늘 보였다. current session 줄은 누르기 말고 할 수 있는 것이 없었다.
- 후:
  - New session 줄을 없애고 place 줄 오른쪽 끝에 +를 둔다. 이 place의 +는 늘 보이고 이 창에서 열며 오른쪽 클릭 menu로 lophn agent·coding agent를 고른다. 다른 place의 +는 hover·focus 때 보이고 route `startSession`으로 그 place에 가서 lophn 새 session을 연다.
  - 톱니는 + 왼쪽에 있고 place 줄에 hover나 focus가 있을 때만 보인다. 자리는 남아 이름 폭이 흔들리지 않는다.
  - 이 창 place의 current 줄(lophn session, 터미널. workflow는 빼고)은 오른쪽 끝 자리가 평소 상태 점이고 hover·focus 때 x(Stop)가 된다. 연필(Rename)은 그 왼쪽에 hover·focus 때 뜬다. 연필은 줄을 이름 칸으로 바꾼다(Enter·blur 확정, Escape 취소). 탭이 열려 있으면 탭 이름 바꾸기와 같은 길이고, 없으면 session 제목을 바꾸고 sidebar가 제목을 다시 읽는다. Stop은 그 session의 도는 turn을 멈추고 탭을 닫아 Recent로 보낸다. 터미널은 탭 닫기와 같다.
  - `AgentTabSource.stopSession(session)`: session의 running turn을 읽어 멈춘다.

왜: 사람이 요청했다(2026-11-03).

결정:
- x는 "멈추고 닫기"다. turn만 멈추면 탭이 열린 줄은 current에 남아 x를 눌러도 줄이 그대로이기 때문이다. (agent)
- x는 줄 전체 hover로 점에서 바뀐다(점 자리만 hover로 바꾸지 않는다). 탭의 저장 안 된 ●와 같은 방식이다. (사람 2026-11-03)
- Rename·Stop 단추는 이 창이 보이는 place의 줄에만 둔다. 다른 place의 탭은 그 place layout에 있어 이 창에서 닫지 않는다. (agent)
- 다른 place의 +는 기본 lophn만 연다. agent 고르기 menu는 이 place의 +에만 있다. (agent)
