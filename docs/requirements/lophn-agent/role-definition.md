# lophn-agent/role-definition

역할의 재사용 가능한 책임, 프롬프트, 읽기 범위 종류, 고정 tool 선택, 일별 model slot 용도와 기대 결과를 정의하며 실제 대상·주기·남길 문서는 lophn-agent/assignments에 둔다.

## 요구

### 책임과 범위

**[R1]** 역할 정의는 무엇을 왜 만들고 고칠지 판단하고 설명하는 책임의 재사용 단위로 두며 실제 대상·세션·진행 일·멈춘 이유·주기·남길 문서·run 한도·권한 예외·임의 실행 코드는 포함하지 않는다.
- 이유: 역할과 실제 assignment 및 harness 상태를 중복 정의하지 않는다.
- 확인: 같은 역할을 조회할 때 책임만 보이고 실제 상태와 대상은 lophn-agent/assignments에서 확인되는지 본다.
- 의도: lophn-agent#I1

**[R2]** 역할 이름·목적·사용할 상황은 각각 앞뒤 공백을 제외하고 1자 이상이어야 하며 하나라도 없거나 비면 등록을 거절한다.
- 이유: 사람이 고를 책임을 빈 이름이나 설명으로 만들지 않는다.
- 확인: 공백뿐인 이름·목적·상황을 제출하고 등록이 거절되는지 본다.
- 의도: lophn-agent#I1

**[R3]** 역할 이름은 내장 역할과 승인한 Operator 전체에서 앞뒤 공백과 영문 대소문자를 무시해 중복을 거절하며 같은 이름으로 기존 정의를 덮어쓰지 않는다.
- 이유: 표기 차이로 담당 역할을 혼동하지 않는다.
- 확인: Operator 이름의 대소문자·공백만 다른 등록이 기존 역할을 수정하지 않고 거절되는지 본다.
- 의도: lophn-agent#I1

**[R4]** 역할 프롬프트는 맡는 일·맡지 않는 일·정보를 해석할 관점·기대 결과의 네 설명을 비어 있지 않게 쓰고 제외나 결과가 없어도 없다고 명시한다.
- 이유: 모호한 프롬프트를 전권으로 해석하지 않는다.
- 확인: 네 설명 중 하나를 비운 정의는 등록되지 않고 결과 설명과 기대 결과가 일치하는지 본다.
- 의도: lophn-agent#I1

**[R5]** 읽기 범위 종류는 전체·앱 하나·컨텍스트 하나 중 책임에 맞게 정하며 실제 담당 대상은 lophn-agent/assignments에서 유효하게 지정하기 전에는 일하지 않는다.
- 이유: lophn-agent/roles/app-engineer에 따라 앱 담당과 컨텍스트 반복 책임을 구분한다.
- 확인: 없는 앱·컨텍스트의 assignment는 시작할 수 없는지 확인한다.
- 의도: lophn-agent#I1

**[R6]** 역할에는 API key·OAuth token·서버 인증·가격표·model 호출 매개변수와 역할별 model 덮어쓰기를 넣지 않으며 실제 provider·model은 lophn-agent/harness/provider와 lophn-agent/harness/model의 공통 설정을 쓴다.
- 이유: lophn-agent/harness/model에 따라 책임 정의에 인증이나 실행 설정을 복사하지 않는다.
- 확인: 역할 판을 조회해 인증·model 설정이 없고 일별 judgment·organizing 용도만 있는지 본다.
- 의도: lophn-agent/harness#I1, platform#I8

### tool과 정의 판

**[R7]** tool은 명시한 개별 동작 또는 묶음을 적용 시점의 개별 동작으로 고정해 선택하며 빈 선택은 0개이고 묶음에 새 동작이 생겨도 기존 역할 선택이 자동으로 늘지 않는다.
- 이유: 묶음 확장을 권한 확장으로 만들지 않는다.
- 확인: 묶음에 새 tool을 추가한 뒤 내장 역할 제품 갱신 또는 Operator의 새 승인 전 제공 목록이 그대로인지 본다.
- 의도: lophn-agent#I1

**[R8]** 프롬프트·skill·tool 선택의 설명은 현재 접근 범위를 늘리거나 판정을 생략하는 근거가 아니며 실제 호출은 lophn-agent/harness/tool-judgment의 현재 검사를 따른다.
- 이유: 글로 쓴 책임을 권한으로 취급하지 않는다.
- 확인: 범위 밖 tool 요청은 프롬프트에 허용 문구가 있어도 거절되는지 본다.
- 의도: lophn-agent#I1

**[R9]** 제품이 공급한 lophn·App Engineer·Context Engineer 정의는 사람이나 agent가 덮어쓰거나 삭제할 수 없고 자유 복사본도 만들지 않으며 다른 반복 책임은 승인한 구체적 Operator로만 만든다.
- 이유: 책임 경계를 역할 복사로 우회하지 않는다.
- 확인: 내장 세 역할 편집·복사 요청은 거절되고 Operator 초안은 승인 전 실행되지 않는지 본다.
- 의도: lophn-agent#I1

**[R10]** Operator 정의 재사용은 책임과 선택을 복사하되 다른 assignment의 실제 범위·세션·이력·approval request·부여 권한·인증을 복사하지 않는다.
- 이유: 재사용한 정의에 이전 사용자의 권한이 따라오지 않는다.
- 확인: 새 assignment가 별도 대상과 승인을 요구하고 과거 세션을 상속하지 않는지 본다.
- 의도: lophn-agent#I1, lophn-agent#I2

**[R11]** 정의 적용 전 필수 설명·값 종류·이름 중복·존재 참조·tool·확장·범위·handoff 제약을 검사하고 오류를 항목별로 설명하며 하나라도 어긋나면 전체 적용을 거절한다.
- 이유: 부분적으로 유효한 역할이 남지 않게 한다.
- 확인: 유효한 프롬프트와 잘못된 tool을 함께 제출할 때 어느 일부도 바뀌지 않는지 본다.
- 의도: lophn-agent#I1

**[R12]** 정의 변경은 전체를 새 판으로 적용하고 실패하면 이전 판 전체를 유지하며 과거 내용 복원도 과거 판을 덮지 않는 새 변경으로 처리한다.
- 이유: 시작한 run의 책임 근거를 안정적으로 유지한다.
- 확인: 변경 실패 뒤 이전 정의가 그대로이고 과거 판 적용 뒤 새 판이 남는지 본다.
- 의도: lophn-agent#I5

**[R13]** 정의의 생성·변경·사용 중단 근거는 결정한 사람·제안 주체·시각·이유·전후 전체 내용과 함께 보존하여 각 run에서 사용한 판을 확인할 수 있게 한다.
- 이유: 나중에 어떤 책임으로 일했는지 되짚을 수 있어야 한다.
- 확인: 실제 기록 보존과 조회는 platform/ledger와 lophn-agent/observability에 따라 과거 run에서 근거 판으로 이어지는지 본다.
- 의도: lophn-agent#I5

**[R14]** 변경된 정의는 다음에 시작하는 run부터 적용하고 이미 시작한 run은 시작 때 판을 유지하되 현재 범위 회수·assignment 멈춤은 옛 판을 이유로 미루지 않는다.
- 이유: 실행 근거 고정과 현재 권한 검사를 동시에 지킨다.
- 확인: 진행 중 변경 뒤 기존 판단 근거는 유지되지만 회수된 범위의 다음 호출은 막히는지 본다.
- 의도: lophn-agent#I1

**[R15]** 구체적 Operator 정의는 반복할 판단·필요 근거·비교 기준·갱신 조건·책임 밖을 명시하고 실제 범위·남길 문서·주기와 결합한 초안을 사람이 검토할 수 있게 한다.
- 이유: Operator 이름만으로 반복 책임을 승인하지 않는다.
- 확인: 초안의 책임을 읽고 무엇을 판단하고 언제 결과를 바꿀지 알 수 있으며 실제 결합은 lophn-agent/assignments를 따르는지 본다.
- 의도: lophn-agent#I1, lophn-agent#I2

## 열린 질문
- lophn-agent/role-definition#Q1 내장 세 역할을 사람이 편집하거나 복사할 수 있게 할까.

## 버린 것
- 독립·subagent·둘 모두 호출 용도 선택은 네 역할 모두 subagent를 쓰지 않으므로 제거했다.
- 내장 역할 자유 복사본을 기존·새 assignment에 연결하는 선택은 자유 복사본 자체가 없으므로 제거했다.
