# lophn 0.3.0

This release joins provider setup and model choice into one flow, lets apps use outside services and secrets, and makes coding agent hand-offs easier to follow.

## New
- Manage models window: turn models on or off for each provider, and connect a new provider from the same window. Models of a newly connected provider start turned on.
- Custom providers: when you connect one, choose its API (Chat Completions, Responses, or Anthropic Messages). lophn reads the provider's model list, you can refresh it, and you can add a model by name.
- Custom models: set a model's context limit, input and output types, reasoning effort levels, and prices in Manage models. The picker and the cost estimates use them.
- Default model: when you connect your first provider and no default model is set, lophn asks you to pick one, or you can skip.
- Settings has a Back button that returns you to the screen you opened it from.
- Apps can use built-in libraries for files, outside network calls, and secrets. An app can call an outside service you have turned on, including one on this computer. A saved secret is attached to the request, and the app never sees its value.
- App Engineer can publish app packages.
- An app that lophn creates can be handed to a coding agent right away.
- Operators can use the MCP servers you set on their edit screen.
- A coding session that has not started within five seconds shows "Check the terminal" in the waiting list.
- lophn and App Engineer can see the names and app APIs of your other apps.

## Changed
- The model picker only picks models. The favorite star and the connect line are gone, and the model in use stays visible even when it is turned off.
- The default model is set in Settings → Agents. The "Change defaults…" line is gone.
- Reasoning effort is chosen in the picker for models that support it.
- A reply can use up to 32,000 output tokens, within the model's own limit and a quarter of its context window. OpenAI-style models were limited to 4,096 before.
- Agents can call App Engineer, Project Manager, and Operators even before they have an open session.
- App Engineer marks a reported problem as resolved only after a fixed release is active.
- App changes are checked by example checks that App Engineer writes and lophn runs against the app, so a coding agent cannot grade its own work.

## Fixed
- Connecting a provider or changing the default model in Settings failed with an "invalid input" error.
- MCP servers saved for an Operator were never used.
- The Agents tab was cut off and could not scroll.
- The model fields in Settings, the Operator editor, and the chat picker stayed empty, because the model list never loaded.
- "No options for this model" appeared before any option was chosen.
- Custom provider models could not be selected by name.
- A ChatGPT account could pick a model that the account cannot use, and the turn then failed.
- Context chips sent with a message disappeared from the conversation, and resending a failed message dropped them.
- Turns on models with no known context limit failed with a context-limit error.
- Estimated cost counted cached input at the normal input price.
- The desktop app always showed the coding tool detection in Settings as unknown.
- App tests rejected apps that import their own packages, and rejected a rollback check for a write API that had nothing to undo.
- App Engineer could not publish app packages.
- Apps could not use outside network calls or secrets.
- A message from a coding agent to App Engineer was rejected, and open coding sessions showed as unknown.
- A coding agent could stop waiting when Claude Code asked for folder trust, with nothing shown on screen.
- Agents treated their own earlier replies as instructions from another agent.
