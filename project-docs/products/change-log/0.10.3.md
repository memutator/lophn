# 0.10.3

## 설치본에서 앱이 뜬다: package 의존을 package.json에 선언하고, 설치본 workspace를 선언에서 정한다

```yaml
modules: [packages/core/apps, packages/protocol, packages/sdk, tools]
checked: []
```

- 전:
  - `.deb` 설치본에서 모든 앱의 release 준비가 `handlers: exited before ready`로 끝났다. 앱 진입점이 `@lophn/cap-problem`을 이름으로 불러오는데 설치본 `platform/node_modules/@lophn`에 그 link가 없어, 앱 process가 `Cannot find package '@lophn/cap-problem'`로 바로 죽었다. preview 자식의 stderr는 버려서 log에 남지 않았다.
  - 원인: `tools/package-linux.ts`가 설치본 workspace를 `base`, `protocol`, `core`, `coding-agent`로 손으로 적었고, core의 `package.json`은 쓰는 `@lophn/*`를 선언하지 않았다. dev에서는 root workspace가 모든 package를 끌어올려 우연히 풀렸다. 진입점이 이름을 변수에 넣어 `import()`해 type check와 lint도 보지 못했다.
- 후:
  - 앱 진입점은 `createExceptionObserver`를 `@lophn/cap-problem`에서 정적으로 import한다. `check-deps`는 core 중 `apps/runtime/entrypoint`만 이 SDK를 쓰게 둔다.
  - 각 package의 `package.json`이 쓰는 workspace package를 선언한다(core, coding-agent, protocol, cap-problem, shell renderer, wireframes. shell preload는 `electron` peer). Biome `noUndeclaredDependencies`가 선언 없는 bare import를 막는다.
  - `package-linux`는 `package-lock.json`에서 core와 coding-agent의 `@lophn` 의존을 따라가 설치본 workspace를 정한다. 지금은 `base`, `coding-agent`, `core`, `protocol`, `sdk/cap-problem`이다.
  - `verify-linux-install`이 설치된 Electron의 Node로 앱 진입점을 import해 본다.
  - SDK 설치 사본은 vendor로 담은 package(`@lophn/protocol`)를 사본 `package.json` 의존에서 뺀다. cap-problem 사본은 전과 같은 모양이다.

왜: 사람의 `my-usage` 앱이 미리보기와 운영 배포 모두 뜨지 않았다. 설치본은 이 판에서 어떤 앱도 띄우지 못했다.

결정:
- 설치본 workspace 목록에 하나를 더하거나 진입점을 상대 경로로 바꾸지 않고, 선언을 정본으로 둔다. 손 목록은 선언과 다시 어긋난다. (사람)
- 상대 경로로 다른 package를 import하는 곳(core → base·protocol 등)은 이번에 바꾸지 않는다. 그 package도 이제 선언돼 설치본에 실리고, 바꾸면 범위가 크다. (agent)

후속: 설치본을 다시 만들어 깔고(`dpkg -i`), `my-usage` release를 다시 준비한다.

## place switcher를 Projects/Apps 두 묶음의 높은 줄로 바꾸고, 앱 place의 오른쪽 패널 모양을 앱마다 기억한다

```yaml
modules: [packages/shell/renderer, packages/design]
checked: []
```

- 전:
  - 상단 바 switcher는 이름과 chevron만 있었다. 열면 Recent 묶음과 전체 목록에 같은 place가 두 번 나왔다. 런처 카드는 폴더·창 아이콘 하나로 모두 같아 보였다.
  - 앱 place는 오른쪽 패널의 열림, 고른 탭, 보던 agent와 session을 mount 때마다 잃었다. project place는 layout file에 저장한다.
- 후:
  - trigger는 지금 place 이름과 chevron 한 줄이다. 목록은 Projects와 Apps 두 묶음이고 묶음 안은 최근에 연 순서다. Recent 묶음은 없다. 줄은 40px(일반 menu 줄 32px)이고 menu는 trigger 폭(192px 이상)을 따른다.
  - 목록 줄과 런처 카드(Projects, Apps, Archived)에 place 표식(`PlaceMark`)이 붙는다. 이미지가 있으면 그 이미지, 없으면 첫 글자와 id로 정한 8색 배경이다. project는 둥근 사각형, app은 원이다. 상단 바 trigger에는 표식이 없다.
  - 앱 place의 패널 열림, 고른 탭, details 탭, 보던 agent와 session을 앱마다 localStorage(`lophn.app-layout.<app>`)에 기억한다. manage pane은 저장하지 않고 새 session 요청은 저장값보다 먼저다.

왜: place가 몇 개뿐인데 목록이 중복되어 읽기 어려웠다. 앱과 project를 오가면 앱 쪽 화면이 매번 처음으로 돌아가 전환이 불편했다.

결정:
- 검색 입력은 두지 않는다. place가 적다. 버린 길: 검색 popover, 종류 라벨을 윗줄에 둔 두 줄 trigger(상단 바 36px 안에서 trigger가 42px가 되어 삐져나왔다), 분류 탭, 두 열, 타일, 항상 보이는 탭. (사람)
- 상태 점과 보조 문구는 넣지 않는다. (사람)
- `CatalogSource`의 항목에 `icon`(이미지 src)을 받을 자리만 두었다. core가 project와 앱의 이미지를 아직 주지 않아 지금은 모두 첫 글자 표식이다. (agent)
- 앱 place layout은 파일이 아니라 localStorage에 둔다. 폭(`panel-width.ts`)과 같은 방식이고 다른 기기와 맞출 값이 아니다. (agent)
- 앱 place에서는 place menu가 열려 있는 동안 앱 view를 숨긴다(`shown={!placeOpen}`). DOM menu가 native view 밑에 깔려 안 보였다. browser 탭이 menu가 열린 동안 native view를 숨기는 것과 같다. 같은 문제가 앱 위쪽 바의 Agent select에도 있을 수 있으나 이번에는 고치지 않았다. (agent)

후속: project와 앱이 이미지를 갖게 되면 `core-catalog.ts`가 `icon`을 채운다.

## 칸을 위아래로도 나누고 최대 6칸까지 둔다

```yaml
modules: [packages/shell/renderer, packages/shell/main, packages/shell/ipc, packages/design, tools]
checked: [architecture-workspace-layout, architecture-ui-kit, tool-wireframes, tool-worktree-prep]
```

- 전: 칸은 좌우로 최대 둘이었다. layout에는 왼쪽 칸 비율(`split_ratio`) 하나만 있었다. 칸 본문에 탭을 놓는 자리는 왼쪽·가운데·오른쪽이었다.
- 후:
  - 칸 배치가 tree(`layout`: `leaf` 또는 `{ dir: row|column, ratio, a, b }`)다. 칸은 최대 6개이고 좌우·상하로 나뉜다.
  - 탭을 칸 본문의 왼쪽·오른쪽·위·아래 가장자리에 놓거나, 탭 menu의 Split Right·Split Down, 단축키 `pane.split`(Ctrl+\\)·`pane.split-down`(Ctrl+Shift+\\)으로 그 칸 곁에 새 칸을 만든다. 경계는 칸 사이마다 하나이고 끌어서 비율을 바꾼다.
  - 칸이 비면 그 칸만 빠지고 나머지 배치는 남는다. 모든 칸이 최소 크기(폭 320, 높이 240)로 들어가지 않으면 focus 칸 하나만 보인다.
  - `pane.focus`는 1~6번 칸이다. 번호는 왼쪽·위에서 오른쪽·아래로 센다. 탭 안에서 연 문서는 다음 칸 끝에 열린다(끝이면 처음).
- 계약:
  - 바뀐 것: layout 파일 판 5 → 6. desk의 `split_ratio`가 `layout`이 되고 `panes`는 최대 6, `focused_pane`·`origin_pane`은 0~5. 판 5 파일은 읽을 때 올린다(`upgradeFromV5`).
  - 생긴 것: `pane.split-down` command, `renderer/workspace/layout-tree.ts`.
  - 없어진 것: `splitRatio`, `splitLayout`, Panes의 `bodyWidth` prop.

왜: VS Code처럼 화면을 위아래로도 나눠 보고 싶다는 요청(사람).

결정:
- 칸 배치를 중첩 tree로 저장한다. 칸마다 사각형을 저장하는 안은 경계 하나를 옮길 때 이웃 칸을 모두 다시 계산해야 해서 버렸다. (agent)
- 칸 최대 수는 6이다. 사람이 더 필요로 하는지 모르고 `pane.focus` 번호가 1~6이면 충분하다. 추천안으로 진행했다. (agent)
- 칸 최소 폭을 480에서 320으로 줄였다. 480이면 1500px 창에서 셋째 칸이 들어가지 않았다. (agent)

후속: 없음.
## 앱 화면과 artifact 화면을 `<webview>` guest로 옮기고, desk를 오가도 page를 지킨다

```yaml
modules: [packages/shell/main, packages/shell/renderer, packages/shell/ipc]
checked: [architecture-workspace-layout, architecture-browser-tab, architecture-annotation, architecture-appearance, architecture-keybindings, architecture-artifact]
```

- 전:
  - 앱 화면(app panel 탭, 앱 place 본문, 앱 card, 앱 전용 창)과 artifact 탭은 native `WebContentsView`였다. native view는 shell DOM 위에 그려져 floated 패널·menu·toast가 page 밑에 깔렸고, 피하려고 view 층(`appViewOrder`), cover로 view 줄이기(`useViewCover`, `createViewCovers`), bounds relay(`placement.ts`, `visibility.ts`, `frame-router.ts`, `renderer/app-frame/bounds.ts`), 앱 place menu가 열린 동안 화면 숨기기라는 장치가 쌓였다.
  - 앱 전용 창은 문서가 없는 빈 `BrowserWindow`에 native view 하나였다. `webviewTag`와 shell preload가 없어 단축키가 닿지 않았다.
  - desk를 떠났다 돌아오면 일반 browser 탭의 `<webview>`를 놓아 page를 url로 다시 load했다(`issues/workspace-layout.md`).
- 후:
  - 앱 화면과 artifact 화면이 browser 탭과 같은 창의 `<webview>` 그릇에 산다(`packages/shell/renderer/app-frame/webview-host.tsx`, kind 중립). project 창은 floats 층, detached 창·앱 전용 창은 본문, 앱 place는 `.content`다. 앱·artifact element는 `src`만 적고 첫 load 전까지 숨긴다. z-index 규칙은 그대로다(pane 화면 1, floated 화면 `--z-sticky + 2L+1`, 패널은 그 위).
  - main registry가 state에 `src`를 싣는다. 앱은 `lophn-app://<label>/<screen>/index.html?view_session=..&mount=<generation>`, artifact는 `lophn-artifact://<host>/<entry>?mount=<n>`이다. `acceptGuest(window, src)`가 그 창의 view이고 아직 안 쓴 src일 때만 1회 받고, `did-attach-webview`에서 guest를 그 view에 묶는다. 붙이기 판정은 `wiring/browser.ts`의 `will-attach-webview` 하나이고 `webview-guest.ts`의 `hardenWebviewAttach`가 kind별로 partition·preload·webPreferences를 강제한다. browser guest는 `lophn-*` src를 거절한다. 신원은 `byContents` 그대로라 app-ipc·annotate·app-call은 바뀌지 않는다. annotation screenshot은 guest `capturePage`다.
  - 앱 전용 창은 shell 문서 `#app-window=<app>/<release>/<screen>`(`packages/shell/renderer/app-frame/app-window.tsx`)이고 `webviewTag`·shell preload를 쓴다. 앱 하나에 창 하나이고 전역 palette·tray는 detached 창처럼 건너뛴다.
  - `<webview>`는 탭 key가 어느 desk의 layout에든 있는 동안 그대로 두고, 모든 desk에서 사라지거나 그 탭이 detached가 될 때만 지운다. desk를 오가도 page를 다시 load하지 않는다.
  - secret 입력 창의 입력 차단이 `hostWebContents`로 guest까지 본다.
- 계약:
  - 바뀐 것: `AppFrameViewState`·`ArtifactViewState`에 `src`가 생겼다. 앱 panel·artifact 탭의 Detach transfer가 `{ value: null, views: [] }`이고 받는 창이 다시 연다. `AppViews.moveViews`는 browser의 크기 준 popup과 DevTools만 옮긴다.
  - 생긴 것: kind 중립으로 옮긴 `<webview>` 그릇(`packages/shell/renderer/app-frame/webview-host.tsx`), `acceptGuest`·`bindGuest`·`dropGuest`, 앱 전용 창 route `#app-window=`, `renderer/app-frame/app-window.tsx`.
  - 지운 것: `app-frame/placement.ts`, `app-frame/visibility.ts`, `browser/frame-router.ts`, `renderer/app-frame/bounds.ts`, `useViewCover`·`createViewCovers`·`ViewCoversProvider`, cover 빼기, 앱 view 층. `app-frame/view-order.ts`는 overlay 층만 남는다. native relay는 `renderer/browser/native-bounds.ts`, `main/browser/native-bounds.ts`, `native-view.ts`, `view-order.ts`에만 있다.

왜: native view가 shell DOM 위에 그려져 menu·popover·floated 패널·toast가 앱 page 밑에 깔렸고, 그 우회 장치가 층·cover·bounds relay로 쌓였다. browser 탭은 같은 이유로 이미 `<webview>`를 쓰고 그 뒤로 겹침 문제가 없다. 앱 화면과 artifact 화면도 같은 그릇으로 모으면 장치가 하나로 줄고, 같은 변경에서 desk를 오갔다 돌아오면 browser 탭 page가 다시 load되던 결함이 닫힌다.

결정:
- 화면 그릇은 `<webview>`다. iframe은 preload의 isolated world, 앱별 partition, `sender.id` 신원을 잃고, remote UI는 앱이 자기 DOM·CSS component를 못 쓰게 한다. Electron은 `<webview>`를 권하지 않지만 browser 탭이 이미 그 위험을 지고 있어 새 위험이 아니다. (사람)
- Detach하면 앱 화면이 다시 load된다. browser 탭과 같다. 앱이 화면 상태를 URL이나 storage에 두면 잃는 것이 줄어든다. (사람)
- artifact 탭도 같이 옮긴다. 같은 겹침 문제를 갖고 있고, 남기면 앱 쪽 장치를 지우지 못한다. (agent)
- 붙이기 ticket은 `src` 하나이고 한 번만 쓴다. renderer가 적은 partition·preload·webPreferences는 버리고 registry가 정한 값만 쓴다. (agent)
- 앱 저장소 partition 이름(`persist:app-<app>:live`, `persist:app-<app>:preview-<bundle hash>`)을 바꾸지 않는다. 사람의 `~/.lophn` cookie·localStorage·IndexedDB가 이어져 migration이 없다. (agent)
- 앱 template `AGENTS.md`(lophn-managed 절)에 "다시 load되어도 잃으면 곤란한 화면 상태는 `localStorage`에 둔다"를 더했다. 새로 만드는 앱에만 들어간다(agent). URL query는 Detach 때 main이 새 `src`를 내므로 남지 않는다.
