## 탭 본문 오류 경계, gallery smoke check

```yaml
modules: [packages/shell/renderer, tools]
checked: []
```

- 전: 탭 본문을 그리다 component가 throw하면(Project settings 탭의 `Input needs a Field label`) 오류 경계가 없어 shell 창 전체가 빈 화면이 됐다. 같은 종류의 오류를 빌드 전에 잡는 check도 없었다.
- 후:
  - 모든 탭 본문(docked, 떠 있는 float, 전역 float, 떼어낸 창)을 `TabBoundary`가 감싼다. throw하면 그 탭 자리에 한 문장과 [Try again]이 뜨고(누르면 본문을 새로 mount) 오류는 console에 남는다. 창의 나머지는 그대로 동작한다. 탭 key가 바뀌면 경계도 새로 선다.
  - `npm run wireframes:smoke`가 gallery의 모든 page(337개)를 offscreen Electron 창에서 그려 보고 uncaught error·console error·빈 root가 있으면 실패한다. 30초쯤 걸리고 `check:full`에 든다(빠른 `check`에는 없다).
  - smoke가 처음 돌 때 agent 편집기 MCP 목록의 key 중복(project와 agent에 이름이 같은 server)이 걸려 key를 `layer/name`으로 고쳤다.

옮기기: 없음.

왜: Project settings 탭 하나의 오류가 창 전체를 비웠고(54b58e794), gallery를 눈으로 훑지 않으면 같은 오류를 못 잡았다(사람, 2026-11-07).

결정:

- smoke는 headless Chrome이 아니라 node_modules의 Electron을 쓴다. 따로 설치할 것이 없다. (사람이 브라우저 check를 허락했고, Electron 선택은 agent)
- 오류 문구는 앱 화면 경계(`AppErrorBoundary`)의 `common.error.show-failed`와 `common.button.retry`를 다시 쓴다. (agent)

## 앱 sidebar panel과 tray는 선언하면 나오고 사람이 끈다

```yaml
modules: [packages/core, packages/shell/renderer, tools]
checked: []
```

- 전: 설정 `shell.sidebar_panels`·`shell.tray`(`{app, screen}[]`)가 "켠 것"이었다. 앱이 `sidebar`·`tray` 자리 화면을 선언해도 사람이 Settings › Quick launch에서 Switch를 켜야 panel과 tray 항목이 나왔다.
- 후:
  - 설치된(보관하지 않은) 앱의 `sidebar` 자리 화면은 모든 workspace 종류의 오른쪽 sidebar에, `tray` 자리 화면은 tray에 선언하는 즉시 나온다.
  - 설정은 `shell.sidebar_panels_off`·`shell.tray_off`(같은 `{app, screen}[]`, 최대 20, 기본 `[]`)로 바뀌어 "끈 것"만 쌓는다. Settings의 Switch는 목록에 없으면 켜짐이고, 끄면 목록에 더하고 켜면 뺀다. 그룹 제목은 그대로이고 도움말만 "기본으로 나온다"로 바꿨다.
  - tray는 보일 항목이 하나도 없으면 아무것도 그리지 않는다(값도 읽지 않는다).

옮기기: data step `settings.places-default-on`(core `setting-declarations` wiring)이 `<root>/settings.json`의 옛 `shell.sidebar_panels`·`shell.tray`를 지운다. 켠 것이 이제 기본이라 잃는 것이 없고, 모르는 key 하나가 settings 전체를 거절시키므로 지워야 한다. 사람이 이미 켠 panel·tray는 그대로 나오고, 끄고 싶은 것은 다시 꺼야 한다. 다시 돌아도 같다.

왜: 앱이 자리를 선언했는데 사람이 따로 켜야 보이면 앱이 낸 sidebar 화면과 tray 값을 처음 쓰는 사람이 찾지 못한다(사람, 2026-11-07).

결정:
- 켜는 쪽(opt-in)이 아니라 끄는 쪽(opt-out)을 저장한다. 새로 설치한 앱이 목록 갱신 없이 바로 나온다. (사람)
- 옛 켠 목록을 "끈 목록의 보수"로 옮기지 않고 지운다. 설치된 앱 전체를 알 수 없는 data step에서 보수를 만들 수 없다. (agent)

후속: 없음.

## sidebar panel과 tray 화면이 열리지 않던 것을 고친다

```yaml
modules: [packages/shell/renderer]
checked: []
```

- 전: 앱의 `sidebar`·`tray` 화면이 오른쪽 sidebar와 tray popup에서 "Couldn't load …"로 열리지 않았다. 같은 앱의 `tab`·`panel` 화면은 열렸다. 또 창이 앱 화면 목록을 mount 때 한 번만 읽어서, core가 준비되기 전에 읽다 실패하거나 앱의 새 판이 활성이 되면 sidebar·tray·빠른 실행의 앱 목록이 창을 다시 열 때까지 낡았다.
- 후:
  - sidebar·tray가 화면을 앱의 활성 판에 고정해서 연다. 앱 화면 목록 read가 `release`를 같이 싣는다. 원인은 renderer가 `release` 없이 live view를 열어 main의 `checkOpen`이 `invalid_input`으로 거절한 것이다.
  - 화면 목록은 core가 (다시) ready가 될 때와 `AppViewChanged`(activation)가 올 때 다시 읽는다.

옮기기: 없음.

왜: 선언하면 나오게 한 sidebar·tray가 실제로는 빈 오류 화면이었다(사람이 설치본에서 봄, 2026-11-07).

결정:
- main이 판 없는 live open을 받아 활성 판으로 열게 하지 않고 renderer가 판을 준다. open 입력은 이미 판 고정이 규칙이고, 목록을 읽을 때 판을 함께 얻으므로 가장 작다. (agent)

후속: 설치본에서 tray·sidebar view가 만들어졌다가 닫힌다는 로그와 이 원인이 같은지는 확인하지 못했다(여기서는 view가 만들어지기 전에 거절된다).
