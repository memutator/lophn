# terminal-agent

터미널의 agent는 사람이 연 터미널 하나 안에서 지금 어떤 coding agent(harness)가 도는지, 그것이 무슨 상태인지 아는 층이다. 탭 icon, 탭 점, OS 알림이 이것만 본다. lophn session이 아니다. lophn은 그 agent에 메시지를 넣지 않는다. lophn agent로 쓰는 harness(runtime이 harness인 정의)는 이 층이 아니라 [coding-agent.md](coding-agent.md)의 "harness agent"다.

이 층은 터미널 한 개를 둘러싼 일도 함께 정한다. 터미널을 누가 열고 갖는지, 화면과 출력이 desktop 창과 폰에 어떻게 이어지는지, clipboard와 mouse, 진단 기록이다. 터미널(PTY)과 agent 상태와 알릴 계기가 모두 그 터미널을 가진 core에서 정해지기 때문에 같은 자리에 둔다.

## 문제

사람은 lophn 안 터미널에서 `claude`, `codex`, `opencode` 같은 coding agent를 쓴다. 그 agent가 일하는 동안 사람은 다른 탭이나 다른 창을 본다. 이 층이 없으면 어느 탭에서 무엇이 돌고, 끝났는지, 권한을 기다리는지 탭을 일일이 열어 봐야 안다. 다른 harness 관리 도구(herdr, orca, emdash, paseo)는 이미 icon, 상태, 알림을 보인다.

어려운 점이 몇 가지 있다.

- 상태를 화면 글자로 짐작하면 오판이 많다. 그렇다고 hook만 믿으면 hook이 없을 때 icon조차 없고, 설치를 물을 때를 모른다.
- coding agent는 사람의 터미널에서 도는 사람의 것이다. lophn session으로 만들면 `claude`를 띄울 때마다 session 행이 생긴다.
- 일부 harness는 TUI를 사용자당 하나인 background server에 붙여, hook이 이 탭의 환경이 아니라 server를 처음 띄운 환경으로 돈다.
- turn이 끝난 것만으로는 일이 끝난 것이 아니다. subagent가 돌 수 있고, 알림이 두 번 가거나 일찍 가면 믿을 수 없다.
- 사람이 보고 있는 탭에는 알릴 것이 없고, 창이 여럿이면 알림이 겹치면 안 된다.

## 목표와 비목표

- 목표: 탭마다 harness 종류와 상태(running, waiting, idle, unknown)를 알고 탭 icon과 점으로 보인다. 사람이 안 보는 사이 끝난 turn과 권한 물음을 알린다. 끝난 session의 identity를 남겨 다시 열 수 있게 한다.
- 목표: 터미널은 core가 열고 갖는다. desktop 화면과 폰은 같은 core route로 붙어 보고 친다. 창이 없어도 열리고 앱을 Quit해도 돈다.
- 목표: 상태와 알릴 계기의 결정은 터미널을 가진 core 한 곳이고, 알림을 어디에 띄울지는 shell main 한 곳이다.
- 비목표: 화면 글자를 읽어 상태를 짐작하지 않는다. transcript를 읽지 않는다. 사람 터미널의 agent에 메시지를 넣거나 lophn session으로 다루지 않는다. 상태를 disk에 저장하지 않는다.
- 비목표: Windows에서 foreground process 감지와 터미널 signal을 하지 않는다. hook이 harness와 상태를 알려 준다.
- 비목표: 사용자의 앱과 사람이 쓴 글은 공격자로 보지 않는다. 터미널 안의 process는 그 터미널의 상태를 꾸밀 수 있고 사람의 것이라 막지 않는다. 막는 것은 터미널 출력(인터넷에서 온 글)이 clipboard나 화면 밖으로 새는 일이다.

## 모델

```
화면·폰·agent ─ terminals/open ─▶ core: 터미널 key 발급, env LPN_TERMINAL_HOOK={socket,key}(+ browser bridge env, 사람의 login env)
                                  ─▶ PTY host(core의 자식. bash·zsh·fish·PowerShell 7·5.1의 시작 층으로 `claude`·`codex`·`opencode`·`omp`·`kilo`·`cline` 함수를 끼운다)
                                  └ tab이 있으면 그 project를 보이는 창에 터미널 탭(창이 없어도 터미널은 돈다)
PTY host ─ 250ms마다 foreground process argv(shell launch만), 바뀔 때만 ─▶ core tracker
           argv가 harness를 가리키면 그 harness(상태는 unknown). 이 실행에서 처음 본 harness면 hook 설치를 묻는다(HookInstallAsked)
harness(claude 등) ─ 전역 hook ─▶ lophn hook <harness> <event> ─ env가 없으면 바로 끝
                                    └ stdin JSON ─▶ hook endpoint(POSIX per-run 폴더의 unix socket, Windows named pipe)에 한 줄 {v:1,key,harness,event,payload}
core ─ key로 터미널을 찾고 hook을 신호로 바꿔 ─▶ tracker: running / waiting / idle / unknown
tracker ─ 바뀔 때 runtime.agent를 실어 TerminalRuntimeChanged ─▶ 화면: 탭 icon(harness vendor), X 자리의 점
        ├ 일 끝(main turn과 child가 다 끝나 1.5초 idle, 완료·실패)·권한 물음 ─▶ core attention(못 본 끝 unseen과 폰 push)
        └ 같은 계기 ─▶ TerminalAgentSignaled ─▶ shell main: 사람이 안 보고 있으면 desktop 알림(한 곳)
화면 ─ terminals/watch(lease) + snapshot{after_seq} ─▶ TerminalOutputAppended(날 출력)      화면 ─ terminals/input·resize ─▶ core ─▶ PTY
```

개념과 이름은 다음과 같다.

- **harness**: 터미널에서 도는 coding agent 제품. 25종을 알아본다(claude, codex, opencode, pi, omp, cursor, copilot, kimi, kiro, antigravity, grok, droid, amp, devin, qwen, qoder, hermes, muse, codebuddy, command-code, prime-agent, mimocode, cline, letta, kilo). 제품마다 hook 위치와 형식, 설치할 event, hook stdout, session id·이름·resume 규칙, 끊기 key를 한 표(harness adapter)가 정한다. hook 자리가 없는 harness(prime-agent)는 foreground 감지와 icon만 한다.
- **runtime.agent**: 터미널 runtime에 실리는 agent 값. harness, 상태, hook을 들은 적이 있는지(`hooked`), foreground인지, session id·제목·이름. 터미널 탭 이름은 runtime의 `tab_name`으로 함께 실린다.
- **상태 넷**: running, waiting, idle, unknown.
- **main turn과 child**: tracker는 터미널마다 main turn의 상태와 child(subagent) 집합을 따로 들고, 보이는 상태는 둘을 합쳐 계산한다.
- **unseen**: 사람이 아직 못 본 turn 끝이다. core가 들고(`attention.md`) 터미널은 `term:<탭>`으로 둔다. 탭 점(finished)과 알림 panel의 Finished 줄의 근거다. runtime.agent에는 실리지 않고 탭을 그리는 쪽이 core의 값을 더한다.
- **session identity**: hook이 session id를 알려 준 session의 harness, hook session id, folder, cwd, 첫 prompt, harness가 붙인 session 이름과 사람이 고정했는지, 시각.


**폰의 터미널 보기(terminal view).** 폰은 coding session의 터미널 화면을 있는 그대로 보고, 허락받은 기기는 그 터미널에 친다. 폰이 목록으로 보이는 것은 coding session의 터미널(`coding_sessions/list`에 나오는 것)과 폰이 연 터미널이지만, 기기는 그 기계의 어느 터미널이든 화면 사본으로 볼 수 있다(아래 "다른 기계의 터미널"). 터미널로 도는 coding session은 폰에서 열면 대화 대신 이 화면이 바로 선다(`remote.md`). 상태를 화면 글자로 짐작하지 않는다는 위 비목표와 상관없다: 이 화면은 사람이 보는 용도이고 상태 판정에 쓰지 않는다. 폰은 날 출력을 그리지 않고 core가 파싱한 화면 사본을 읽는다. 열기와 입력은 desktop 화면과 같은 `terminals/open`·`terminals/input`이다.
```
폰 ─ terminal_view/watch(lease 30초, 10초마다 갱신) ─▶ core ─ 250ms마다 PTY host의 headless 화면을 읽는다
폰 ◀─ TerminalScreenChanged{terminal, seq} ◀─ core(최신 화면 하나, 메모리)
폰 ─ terminal_view/snapshot ─▶ 화면 읽기      폰 ─ terminals/input(허락받은 기기만) ─▶ core ─▶ PTY
폰 ─ terminal_view/resize(lease를 쥔 폰만) ─▶ core ─▶ PTY 크기(폰 크기 표지)
폰 ─ terminals/open {project, key, tab} ─▶ core ─▶ PTY(그 project를 보이는 창이 있으면 탭도) ─▶ {terminal}
```
- **화면.** PTY host가 파싱한 화면(xterm)을 색·굵게·밑줄·반전과 폭 2칸 글자(CJK, emoji) 표지가 붙은 글 토막(run)의 줄로 읽는다. viewport 전체와 그 위 scrollback의 끝쪽 `tail`줄(0~500, 기본 100)을 매번 통째로 둔다. 줄 diff도 replay도 없다: core는 최신 화면 하나만 두고 느린 폰은 건너뛴다. 출력이 이어져도 첫 화면은 바로, 그 뒤는 250ms 간격으로 읽는다(초당 네 번까지). 터미널을 다시 만들면(재시작) `generation`이 오르고 `seq`는 그 안에서 화면마다 오른다.
- **보는 동안만.** 폰이 `terminal_view/watch`로 lease를 잡는 동안만(10초마다 갱신, core는 30초 안에 갱신이 없으면 거둔다) core가 화면을 읽는다. 터미널마다 lease가 하나라도 있는 동안이고 tail은 lease들의 최대다. 폰이 사라져도 lease가 저절로 끝난다. 화면이 바뀌면 core가 `TerminalScreenChanged {terminal, seq}`를 내고(내용 없이, 남지 않는 event) 폰이 `terminal_view/snapshot`을 다시 읽는다. 끝난 터미널의 화면과 lease는 core가 지운다.
- **크기.** PTY 크기는 마지막에 잡은 쪽이 이긴다(Paseo와 같은 규칙). 폰은 화면을 열 때, 사람이 화면을 누를 때, 크기를 쥔 동안 keyboard나 회전으로 자기 grid가 바뀔 때 `terminal_view/resize`로 자기 열과 줄 수를 잡는다. 그 터미널의 lease를 쥔 principal만 잡을 수 있다. core는 그 크기로 PTY를 바꾸고 runtime에 `remote_size`를 싣는다. desktop 탭은 칸에 맞추지 않고 그 크기로 그리며 "Sized for another device · Click to fit"을 보이고, 사람이 그 탭을 고르거나 누르거나 치면 `terminals/resize`로 칸 크기를 다시 잡는다(폰의 크기를 놓는다). lease가 모두 끝나면 core가 폰의 크기를 놓아 탭이 칸에 다시 맞춘다: 폰이 떠난 뒤 desktop 창의 터미널이 폰 폭으로 남지 않는다.
- **폰이 여는 터미널.** `terminals/open {project, key, tab}`은 core가 그 project 폴더에 터미널을 열고 그 터미널을 답한다. 창이 없어도 열린다. `tab`이 있으면 그 project를 보이는 창에 탭으로도 보인다. 같은 `key`의 다시 보낸 open은 같은 답이다.
- **입력.** 폰이 친 글은 core가 그 터미널의 지금 generation에 사람이 치는 것과 같이 PTY에 쓰고(끊기 key면 tracker가 사람이 친 입력으로 본다), 같은 `key`는 터미널마다 기억해 한 번만 친다.
- **입력은 기기마다 허락이다.** 기기의 `terminal_input`(명단 항목의 칸)이 켜져 있을 때만 `terminals/input`과 열면서 치는 `terminals/open {command|resume}`이 통하고, 꺼져 있으면 그 기기는 보기만 하고 빈 터미널만 연다. 값은 초대할 때 정한다: 사람이 Settings › Remote의 Add a device에서 새 기기의 터미널 입력(기본 켬)을 정하면 그 값이 초대장에 실리고(`roster/invite {terminal_input}`), 그 초대장으로 명단에 드는 기기가 그 값으로 시작한다. 바꾸면 새 초대장을 낸다. 그 뒤로는 My devices의 기기 줄 스위치로 기기마다 켜고 끈다(`roster/set_terminal_input`은 기기 route 목록에 없어 폰이 켤 수 없다). 같은 허락이 agent의 browser page를 멀리서 다루는 것(`page_view/input|control|open`, `browser-tab.md`)에도 걸린다. 허락은 core가 입력마다 동기로 본다: 켜고 끈 것과 기기를 끊은 것이 commit된 뒤 메모리 표가 바뀌므로 끄면 그 기기의 다음 입력부터 `forbidden`이다. `terminal_view/snapshot`의 `input`이 이 폰의 허락이고 폰은 입력 칸을 그릴지 정한다.

**다른 기계의 터미널.** 이 컴퓨터의 창은 명단의 다른 컴퓨터의 터미널과 coding agent를 desktop 탭 그대로 연다(`one-screen`). 탭의 기계 묶음이 그 기계의 통로를 주고, 받는 기계는 이 컴퓨터를 기기(`device:<이 컴퓨터의 id>`)로 본다.
```
이 컴퓨터의 탭 ─ machines/call ─▶ 그 기계: terminals/list, terminal_view/watch·snapshot·resize, terminals/open
이 컴퓨터의 탭 ◀─ machines/watch ◀─ TerminalScreenChanged{terminal, seq}, TerminalRuntimeChanged
이 컴퓨터의 탭 ─ terminals/input·restart·close(허락받은 기기만) ─▶ 그 기계 ─▶ PTY
```
- **화면은 사본이다.** 날 출력(`TerminalOutputAppended`)은 기계 사이 연결로 보내지 않는다. 한 기계에서 잰 값(core 둘, 30초 `yes`와 64 MiB): 날 출력을 넘기면 초당 53,000 묶음·6 MB까지 흘러 받는 기계가 이 컴퓨터에 준 기기 Gateway가 32초 동안 일곱 번 `slow_consumer`로 끊겼다. 그 끊김은 연결 전체를 닫아 그 사이 `machines/call` 140번 가운데 12번이 `unavailable`이었고 `StateChanged`는 p95 1.2초·최대 3.6초 늦었다. 화면 사본으로는 같은 쏟음에서 끊김 0, `TerminalScreenChanged`가 초당 4번 남짓(묶음 하나 최대 13 KB, 평균 37 KB/s), `StateChanged` p95 8 ms, `machines/call` p95 8 ms였다. 그래서 탭은 폰과 같은 화면 사본을 받아 같은 xterm에 다시 쓴다: `TerminalScreenChanged`의 seq가 받은 것보다 크면 `terminal_view/snapshot`을 읽어 화면을 비우고 쓴다. 사본의 scrollback은 200줄이다.
- **보기는 내 기기 모두다.** 그 기계의 어느 터미널이든(사람이 그 기계에서 연 것도) 본다. core가 연 터미널마다 terminal view가 알아 둔다.
- **치기, 다시 시작, 닫기는 이 컴퓨터의 터미널 입력 허락이다.** 받는 기계가 입력마다 본다(19). focus 검사는 없다: 그 검사는 이 컴퓨터의 capability를 지키는 것이고 다른 기계는 기기 허락만 본다. 허락이 없으면 탭은 보기만 남고 탭 위쪽 toast가 그 기계에서 이 컴퓨터의 터미널 입력을 켜라고 말한다. clipboard와 link 열기는 이 컴퓨터의 것이다.
- **크기.** 탭은 그 기계의 PTY 크기로 그린다. 사람이 그 탭을 고르거나 누르거나 치면 `terminal_view/resize`로 칸 크기를 잡는다(폰과 같이 마지막에 잡은 쪽이 이긴다). 이 탭이 잡은 크기를 쥐고 있는 동안은(그 기계가 알린 PTY 크기가 이 탭이 보낸 것이다) 창이나 칸의 크기가 바뀔 때도 칸에 다시 맞춘다: 탭을 막 붙일 때 칸이 아직 배치 전이라 작게 잡았어도 칸이 자리 잡으면 바로잡힌다. 다른 기기가 다른 크기를 잡았으면(그 기계가 알린 크기가 이 탭이 보낸 것과 다르고 `remote_size`다) 그 크기로 그리고 "Sized for another device · Click to fit"을 보이며, 사람이 누르거나 칠 때까지 맞추지 않는다.
- **그 기계에 터미널이 없으면 끝난 터미널이다.** 그 기계의 core가 다시 떠 PTY가 사라지면 다시 붙은 뒤의 `terminal_view/snapshot`·`watch`가 `not_found`를 낸다. 탭은 마지막 화면을 둔 채 끝난 터미널로 보이고(이 컴퓨터의 터미널이 끝난 것과 같은 줄), 다시 시작은 그 기계에 `terminals/restart`를 보냈다가 `not_found`면 같은 폴더에 새 터미널을 연다(허락이 없으면 `forbidden`이라 보기만 남는다는 toast가 뜬다). 입력이 다시 받아들여지면 그 toast는 사라진다.
- **이름 바꾸기는 이 컴퓨터의 터미널만.** 탭 이름을 core에 알리는 `terminals/name`과 저장한 session 이름 `terminals/saved_sessions`·`terminals/rename_saved`는 기기 route 목록에 없다. 그래서 다른 기계의 터미널 탭에는 이름 바꾸기가 없다(탭 줄, tab menu, sidebar 줄).
- **Finished 줄과 점은 그 기계의 runtime이 준다.** 다른 기계의 터미널은 그 기계의 `TerminalRuntimeChanged`(agent 상태와 `tab_name`)와 못 본 끝(`unseen`)으로 같은 Finished 줄과 탭 점을 만든다. OS 알림(`TerminalAgentSignaled`)은 아직 그 기계의 탭을 열지 않고 창만 앞으로 가져온다(그 터미널의 project를 이 컴퓨터가 모른다).
- **lease.** 사본의 lease key는 principal과 터미널이라 이 컴퓨터의 창들이 하나를 같이 쓴다. 그래서 탭을 놓아도 끄지 않고 30초 뒤 저절로 끝나게 둔다.

## 지키는 것

1. **무엇이 도는지는 foreground process나 hook이, 상태는 hook만 정한다.** 화면 글자를 읽지 않는다. foreground는 결정적인 사실이라 hook을 놓기 전에도 icon이 보이고 설치를 물을 때를 안다.
   - PTY host는 foreground process의 argv를 250ms마다 읽어 바뀔 때만 보낸다. Linux는 shell의 foreground process group을 `/proc`에서 읽어 그 cmdline을 쓴다. 앞 6개 인자만, 인자마다 32768자까지 싣는다. Hermes는 `python3 -I -c '<launcher code>'`로 돌고 표지(`hermes_cli.main`)가 7KB 가까운 code의 끝에 있어 인자를 짧게 자르면 못 알아본다. shell 자신이 foreground면 없다. 바뀌었는지는 argv를 이어 붙인 것으로 본다.
   - 다른 POSIX는 node-pty의 process 이름뿐이라 이름 하나만 싣고, node로 도는 CLI는 `node`로 보여 못 알아본다. hook이 오면 그때 harness를 안다. win32는 foreground가 없어 hook이 harness와 상태를 알려 준다.
   - core의 tracker가 argv로 harness를 고른다(실행 파일 이름, interpreter가 돌리는 script 이름, package 경로, code 표지 규칙). 맞으면 그 harness다. foreground가 알아보지 못하는 process로 바뀌면 agent가 떠난 것이다. 사람 터미널에서는 터미널 process의 끝이 agent의 끝이 아니고(shell이 남는다), Codex·OpenCode는 session 끝 hook이 없다.
   - **process가 정한 harness는 다른 harness의 hook이 뒤집지 못한다.** grok·devin·cursor는 `~/.claude/settings.json`의 hook을 기본으로 같이 읽어서 그 탭이 Claude의 hook을 받는다. 이것으로 탭이 Claude로 바뀌면 안 되므로, foreground(또는 띄운 쪽)가 정한 harness와 다른 harness의 hook은 버린다. foreground를 못 알아본 탭(예: macOS의 node)은 hook이 알려 주는 harness를 따른다. 그러려고 tracker는 harness가 process로 정해졌는지, hook이 알려 준 것인지를 둘로 센다.
2. **상태는 running, waiting, idle, unknown 넷이다.** 그 harness의 hook을 한 번도 못 들었으면 unknown이다. 권한 물음이 있으면 waiting이다. 그다음 main turn이 돌거나 살아 있는 child가 하나라도 있으면 running이다. 둘 다 아니면 idle이다.
   - main turn은 TurnStarted로 돌고 TurnEnded로 끝나며, TurnEnded는 권한 물음 수를 0으로 둔다. PermissionRequested는 waiting이고 수를 센다. PermissionResolved는 대기를 모두 푼다(0으로 둔다). 한 물음을 두 event로 알리는 harness가 있어 하나씩 줄이면 센 수가 남아 waiting이 계속 보인다. SessionEnded는 unknown이다. session 이름만 알리는 신호(SessionNamed)는 상태를 바꾸지 않고, 끊어서 내려간 unknown이나 첫 hook 전의 unknown을 되살리지도 않는다.
   - 도는 turn이나 물음 중에 사람이 단독 끊기 key를 치면 unknown으로 내리고 알리지 않는다. Claude Code처럼 끊어도 Stop을 보내지 않는 harness가 있다. 멈췄다고 하지 않고 모른다고 한다. 어느 key가 끊는지는 harness마다 다르다. 대부분 Esc와 Ctrl-C다.
   - 끊김을 hook으로 알리는 harness(opencode·kilo·mimocode, pi, omp, amp, grok, droid, cline, cursor, kimi, codex)는 끊기 key 칸이 비어 있어 key로 내리지 않는다. cursor는 `stop`의 `status: aborted`, kimi와 codex는 `Interrupt` hook, 나머지는 plugin 본문이 TurnEnded(interrupted)로 알린다. 이 key는 입력 지우기와 팝업 닫기에도 쓰여서, key로 내리면 turn이 도는데 상태만 unknown이 되고 다음 TurnStarted까지 돌아오지 못한다. wait·subagent로 길게 이어지는 turn은 몇 시간이고 점이 없다. Codex 0.150 미만은 `Interrupt` hook이 없어 끊으면 running에 남는다.
   - 끊김 신호가 없는 harness(claude, copilot, kiro, antigravity, devin, qwen, qoder, muse, codebuddy, command-code, letta, hermes, prime-agent)는 키로 내린다. 이 내림은 짐작이라 tracker가 `guessed`로 기억하고, 그 뒤에 PermissionResolved(PostToolUse 계열, 끊긴 tool은 내지 않는다)가 오면 turn이 안 끊긴 것으로 보고 running으로 되돌린다. TurnStarted·TurnEnded·SessionEnded가 오면 짐작은 풀린다. 진짜로 끊긴 turn에 동시에 끝난 tool의 늦은 hook이 오면 running에 남을 수 있다. 다음 TurnStarted나 TurnEnded에서 풀린다.
   - **child(subagent)의 시작과 끝도 hook에서 받는다.** Claude 꼴(claude, qwen, qoder)은 `SubagentStart`·`SubagentStop`을 ChildStarted·ChildEnded `{child: agent_id}`로 낸다. `agent_id`가 붙은 `PostToolUse`·`PostToolUseFailure`도 ChildStarted다. Start를 놓쳐도 child가 살아 있음을 안다. 다만 ChildEnded를 낼 길이 없는 harness(codex 등)에서는 child가 끝나지 않으므로 예전처럼 PermissionResolved로 둔다. `hook-agent-`로 시작하는 id(`type: "agent"` hook)는 `SubagentStop`을 내지 않으므로 child로 세지 않는다.
   - Claude `Stop` payload의 `background_tasks`에서 `type: "subagent"`이고 `running`·`pending`인 항목의 id는 TurnEnded의 `children`에 싣는다. shell, monitor, workflow, MCP task, teammate는 싣지 않는다. 늘 도는 dev server 때문에 영원히 running이 되면 안 되고, teammate id는 lifecycle `agent_id`와 맞지 않는다. OpenCode 계열 plugin은 하위 session의 `session.status`를 넘길 때 `sessionID`를 root로 바꾸고 `properties.lophn_child`에 하위 session id를 싣는다. busy·retry는 ChildStarted로, idle은 ChildEnded로 바뀐다.
   - **child 집합은 terminal마다 child id → 마지막으로 그 child의 신호를 들은 시각이다.** ChildStarted는 더하거나 시각을 고치고 ChildEnded는 뺀다. TurnEnded의 `children`이 있으면(Claude Stop payload에 `background_tasks` 배열이 있으면, 비어 있어도) 집합을 그 id들로 바꾼다. 그 목록은 그때 도는 background 일 전체이고, main turn이 끝날 때는 foreground subagent가 돌 수 없다. 그래서 SubagentStop이 Stop보다 먼저 도착하거나 끝난 child의 늦은 tool hook이 와서 남은 id가 다음 Stop에서 빠진다. `children`이 없으면(옛 Claude, 그 밖 harness) 집합을 그대로 둔다. SessionStarted, SessionEnded, 사람의 끊기 key, harness가 바뀌거나 떠남, 터미널 끝은 집합을 비운다. 끊기 key는 main은 끝났고 child만 돌 때도 받는다.
   - ChildStarted도 대기 중인 권한 물음을 푼다. subagent의 권한 물음을 허락하면 그 subagent의 tool hook이 ChildStarted로 온다. 키로 내린 짐작도 PermissionResolved처럼 되돌린다.
   - 근거가 끊긴 child가 영원히 running으로 남지 않게, 10분 동안 신호가 없는 child는 뺀다. timer는 터미널마다 하나다. 가장 오래된 child의 마지막 신호에서 10분 뒤에 깨어나 오래된 child를 거르고 다음 것으로 다시 건다. 다른 신호가 오지 않아도 빠진다.
   - background shell(dev server 등), monitor, workflow는 child가 아니다. 늘 도는 process 때문에 영원히 running이 되지 않게 하려는 것이다.
3. **터미널 능력은 lophn이 알린다.** shell env는 core가 읽은 사람의 login shell env(PATH 포함)다. core가 OS 서비스나 다른 process에서 떠도 터미널과 CLI는 사람의 환경을 받는다. 물려줄 때 token·secret 꼴 이름, `LOPHN_*`·`ELECTRON_*`, 내부 endpoint를 가리키는 값, 바깥 agent session이 자식 env에 넣은 표지(Claude Code·Codex의 `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CODEX_THREAD_ID` 등 16개)는 지운다. 표지를 물려받으면 그 안의 Claude Code가 자식 session으로 돌아 transcript를 저장하지 않는다. 단 사람의 일상 도구가 기대는 이름(`SSH_AUTH_SOCK`, `XAUTHORITY`, `GIT_AUTHOR_*`·`GIT_COMMITTER_*`의 NAME·EMAIL·DATE, proxy 변수 `HTTP_PROXY` 등 대소문자 둘)은 정확한 이름만 남긴다(이름 규칙에 걸려도, 값이 local port여도). `GIT_AUTHOR_TOKEN` 같은 다른 이름은 그대로 지운다. `COLORTERM`은 늘 `truecolor`로 덮는다. Claude Code(chalk)·Codex는 `TERM=xterm-256color`만 보면 256색으로 내려 자기 색을 근사한다. launcher나 agent에서 띄운 lophn은 `COLORTERM`이 없어 그렇게 됐다.
4. **`lophn hook`은 터미널을 가진 core에 보낸다.** env `LPN_TERMINAL_HOOK`의 socket에 한 줄을 쓰고 답 없이 닫는다. hook은 harness 안에서 동기로 돌아서 CLI는 1초 안에 끝내고, 실패해도 출력 없이 성공한다. env가 없으면 CLI를 띄우지 않고 끝난다. hook은 API route가 아니라 터미널마다 key가 있는 이 socket으로만 온다.
   - 개발 실행도 같은 launcher 본문을 쓴다. 저장소 실행의 core는 그 저장소의 dev CLI launcher(`<저장소>/.cache/dev-cli/lophn`, 없으면 CLI 없음)를 쓰므로 사람이 쓰는 진짜 harness가 개발 앱의 터미널에서 hook을 보낸다. 물려받은 `LOPHN_CLI`는 보지 않는다. 설치된 앱의 터미널에서 띄운 dev·test core가 그 값(설치된 CLI)을 쓰면 설치된 CLI가 dev data root에 설치본 core를 띄운다. 자세한 것은 [coding-agent.md](coding-agent.md)다.
   - key는 터미널 하나에 하나(64 hex)다. core는 모르는 key, 줄 상한(payload 64 KiB에 envelope 몫)을 넘는 줄, 틀린 모양을 조용히 버린다. POSIX socket은 0700 per-run 폴더 안 0600 file이고 Windows endpoint는 named pipe다. 폴더 준비를 먼저 확정하고 browser shim·listen을 기다리지 않는다. browser 준비가 실패해도 hook은 자기 endpoint를 열고, hook listen 성공 뒤에만 env/key를 발급한다. SID·DACL 검사는 더하지 않는다. 그 터미널 안의 process는 그 터미널의 상태를 꾸밀 수 있다. 사람의 것이라 막지 않는다.
   - CLI는 stdin을 1 MiB까지 읽고, 최상위 글 field(마지막 답, prompt)를 4,096자로 자른 뒤 payload가 64 KiB를 넘으면 버린다. 긴 마지막 답 하나가 turn 끝 신호째 버려지지 않게 하려는 것이다.
   - key는 터미널을 닫을 때 회수한다. shell이 스스로 끝나도 restart가 같은 env를 써서 남긴다.
5. **사람 터미널의 `codex`·`opencode`·`kilo`·`cline`은 그 탭의 private server로 돈다.** Codex(0.156+), OpenCode(2.x), Kilo, Cline(3.x)은 TUI를 사용자당 하나인 background server에 붙이고 turn과 hook을 그 server가 돌릴 수 있다. server는 처음 뜰 때 받은 env를 그대로 써서 hook이 이 탭의 `LPN_TERMINAL_HOOK`이 아니라 옛 값을 본다. Codex 문서도 shared client는 daemon을 시작할 때 물려받은 env를 쓴다고 적는다. 그래서 사람 터미널은 shell 시작 층이 함수를 정의해 `--no-daemon`(Codex), `--standalone`(OpenCode)을 붙이고, Kilo는 env `KILO_NO_DAEMON=1`, Cline은 env `CLINE_SESSION_BACKEND_MODE=local`(session을 hub daemon이 아니라 process 안에서 돌린다)로 부른다. 그러면 harness가 자기 server를 띄우거나 server 없이 돌아 hook이 탭의 env를 물려받는다.
   - 시작 층은 shell이 사용자 startup file을 모두 읽은 뒤에 함수를 정의한다. bash는 `-l`을 빼고 `--init-file`로 뜨며(`-l`이면 init file을 무시한다) login bash의 순서(`/etc/profile`, 그다음 `~/.bash_profile`·`~/.bash_login`·`~/.profile` 중 처음 있는 것)를 따라 한다. zsh는 `ZDOTDIR`을 우리 폴더로 줘 `.zshenv`만 먼저 읽히고, 그 안에서 사용자 값(없으면 unset)으로 돌린 뒤 사용자 `.zshenv`를 읽는다. 나머지 file은 사용자 자리에서 읽히고 함수는 첫 prompt 직전에 정의한다(PATH가 그때 완성된다). fish는 `--init-command`로 config 뒤에 source한다. PowerShell 7·5.1은 기존 `-NoLogo` 뒤 `-NoExit -Command ". '<init.ps1>'"`를 붙여 profile을 읽은 뒤 dot-source한다. 경로의 작은따옴표는 겹쳐 escape한다. `-NoProfile`이나 execution policy 우회는 없다. 그 밖의 shell(sh, dash, nu, cmd.exe 등)은 그대로다. init file이 없으면 시작 층 없이 원래 login shell로 띄워 사용자 rc를 하나도 잃지 않는다(bash는 없는 init file을 받으면 rc를 하나도 읽지 않는다).
   - 시작 층 file은 core가 켜질 때 per-run 폴더의 `shell-init/`에 쓰고(packaged의 asar 안 file은 외부 shell이 읽지 못한다) 폴더 경로는 env `LPN_SHELL_INIT`으로 터미널에 준다. POSIX는 공통 socket directory 아래 `core-<pid>/`, Windows는 `<data root>/run/core-<pid>/` 아래이고 Windows file은 UTF-8 BOM이 있다. file 준비나 hook listen이 실패하면 시작 층도 없다. Windows 실행 gate는 없다. 정책 때문에 `.ps1`을 읽지 못하면 hook endpoint는 남지만 wrapper는 없고, 정책을 자동으로 바꾸지 않는다.
   - 함수는 원래 명령(`command codex` 등)을 부르고 인자와 종료 상태를 그대로 둔다. 실행 파일일 때만 정의해서 사용자의 alias·function과 없는 명령은 건드리지 않는다. 호출마다 `--help`로 flag를 지원하는지 본다(옛 버전은 모르는 flag에 오류로 끝난다). Codex는 인자에 `--no-daemon`, `agents`, `queue`, `--remote`, `--remote=*`가 있으면 붙이지 않는다(shared server가 목적인 명령). OpenCode는 `--standalone`, `--server`, `--help`, `--version`, `--completions`가 있거나 첫 인자가 `run`·`mini`가 아닌 subcommand(`acp`, `api`, `serve`, `service` 등)면 붙이지 않고, `run`·`mini`는 subcommand 뒤에, TUI는 맨 앞에 붙인다. Kilo와 Cline은 flag가 아니라 env라 `--help`를 보지 않는다(모르는 판은 env를 무시한다). 공유 daemon을 다루는 명령인 `kilo daemon`·`kilo console`, `cline hub`는 env 없이 부른다.
   - PowerShell도 사용자의 alias·function은 두고 실제 Application만 감싼다. 찾은 native path를 보관해 call operator와 argument array로 실행하므로 재귀 호출하지 않는다. GUI 인자는 stdin JSON으로 보내고, Kilo·Cline env는 호출 뒤 원래 값/없음으로 복원한다. native 종료 상태를 유지하며 `Invoke-Expression`은 쓰지 않는다.
   - `claude`·`codex`·`opencode`·`omp` 함수는 첫 인자가 `gui`면 그 앞의 일을 하지 않는다. `gui`, `gui --resume <id>`, `gui --resume=<id>`만 받고(id는 `[A-Za-z0-9._-]` 200자까지, 그 밖은 사용법을 찍고 2로 끝난다) `{"resume":…}`를 `lophn hook <harness> lophn-gui`에 넘긴다. CLI가 친 곳의 cwd를 더해 그 터미널의 hook socket으로 보내고, core가 key로 그 터미널을 알아 GUI로 바꾼다([harness-gui.md](harness-gui.md)). 터미널 env에는 `LOPHN_*`가 없어서 CLI 경로는 core가 시작 층을 쓸 때 넣는다(개발은 저장소의 dev launcher, 설치본은 설치한 launcher, 둘 다 없으면 `lophn`). `claude`·`omp` 함수는 이 분기만 한다.
   - 터미널 탭 머리 단추와 ⋯ 메뉴의 "Open as chat"은 GUI를 아는 CLI가 탭에 있으면(hook만 온 탭도) 보인다. 그 CLI가 foreground가 아니거나 session id를 아직 알리지 않았으면 이유와 함께 끈다. GUI가 붙은 탭의 ⋯ 메뉴에는 "Open in terminal"이 있다.
   - **터미널 안에서 lophn을 부르는 code는 CLI 경로와 data root를 core에서 받는다.** 터미널 env에서 찾지 않는다(경로와 root를 알리는 `LOPHN_*`가 없다). project 터미널에는 core가 `LOPHN_WORKSPACE`(`{"project":"<prj>"}`)만 넣고, 사람 token의 `lophn tab open --url`이 탭을 놓을 workspace로 읽는다. dev CLI launcher는 `LOPHN_HOME`이 없으면 `~/.lophn`을 잡아 개발 앱이 아니라 사람의 실제 data root 쪽 앱으로 간다. 이것을 모르고 짠 일이 있었다(mistakes 이슈, 아래 결정). gui 요청처럼 그 탭을 알아야 하는 요청은 hook socket(key가 탭을 가리킨다)으로 보낸다.
6. **알림은 사람이 보고 있지 않을 때만이고, 알릴 계기는 core가, 어디에 띄울지는 shell main 한 곳이 정한다.** core의 tracker가 계기를 정한 순간 `TerminalAgentSignaled`를 내고 shell main이 그것을 듣는다. shell이 없으면(창 없이 도는 core) desktop 알림은 없고 폰 push만 간다. turn 끝(완료, 실패)과 권한 물음·질문만 알린다. 사람이 끊은 turn(interrupted), `/clear`, compact는 알리지 않는다. 터미널 안 coding agent와 lophn의 Agent 탭(lophn agent session)이 같은 규칙이다.
   - 터미널의 turn 끝 알림은 일이 다 끝났을 때 한 번 간다. TurnEnded가 알림을 기다리게 둔다. child가 남았으면 보내지 않고, 보이는 상태가 idle이 되면 1.5초 기다린다. 그 사이 다시 running이나 waiting이 되면 보내지 않는다. 다시 깨어난 main turn(TurnStarted)은 기다리던 알림을 지운다. 그래서 background agent가 끝나 main이 잠깐 깨는 경우에 알림이 두 번 가지 않는다. 상태는 늦추지 않고 바로 바꾸지만 계기(`TerminalAgentSignaled`, attention)는 이 알림과 같은 때 한 번 간다. 그래서 `unseen`도 그때 선다. 실패한 turn도 같다. 권한 물음은 늦추지 않는다.

     | 상황 | 알림 |
     |---|---|
     | 그 탭이 focus를 가진 창에 보인다 | 없음 |
     | lophn 창에 focus가 있는데 그 탭은 안 보인다 | 그 창의 toast(overlay notification). 누르면 그 탭을 고른다 |
     | lophn 창 어디에도 focus가 없다 | OS 알림. 누르면 그 탭이 있는 창을 앞으로 가져오고 탭을 고른다 |

   - 보고 있다는 것은 그 탭이 focus를 가진 창에서 고른(보이는) 탭이라는 것이다. 터미널은 shell main이 탭별 focus 표로, lophn session은 대화가 보이는 동안 renderer가 알리는 visible 신호로 안다. 대화를 그리는 곳(workspace 창(Home, project)의 Agent 탭, 앱 side panel)은 모두 그 신호를 보내야 한다. 하나라도 빠지면 그곳의 session은 보고 있어도 알림이 뜨고 Finished 줄이 지워지지 않는다. 앱 화면이 연 session은 예외다. 그 앱 view가 focus 창에 보이는 동안에도 보고 있는 것이고, turn 끝(완료·실패)은 아예 알리지 않고 Finished 점도 없다([app-call.md](app-call.md)의 "앱 화면의 agent session"). side panel처럼 마운트된 채 CSS로 숨는 칸은 실제로 보이는지를 넘긴다. 같은 창에 같은 session이 두 곳 보일 수 있어 수를 센다. 창이 여럿이어도 toast를 받는 창은 focus를 가진 창 하나라 한 번만 뜬다. detached 창에는 toast 표면이 없어 그 창이 focus를 가졌으면 OS 알림이다. headless는 OS 알림을 띄우지 않는다.
   - 누르면 main이 그 탭을 가진 창(모르면 마지막 focus 창, detached 제외)을 앞으로 가져온다. 터미널은 renderer에 그 탭을 고르라고 보내고(`TerminalReveal`, 터미널이 속한 project를 함께 보내 다른 project에 있어도 그 project로 이동해 탭을 고른다), Agent 탭은 그 창이 toast 행동 `session`을 돌려 탭을 연다(sidebar 줄과 같은 길). toast의 누름도 같은 길로 main이 처리한다.
   - 못 본 것(unseen)은 core가 든다(`attention.md`). tracker는 사람이 보고 있든 아니든 계기를 attention에 넘기고(터미널, harness, 제목, `waiting`·`finished`·`failed`, 일한 시간 `active_ms`) attention이 앞에 있는 host가 그 터미널(`term:<탭>`)을 보고 있는지로 서고 끈다. `active_ms`는 turn이 running이 된 때부터 끝까지에서 권한 물음을 기다린 시간을 뺀 것이고, 시작을 못 들었거나 waiting이면 모른다(null). tracker가 새 turn이 시작할 때(끝 알림을 기다리던 중 이어진 turn은 아니다)와 터미널이 끝날 때 그 표시를 지운다. 탭을 고르거나 창이 focus를 받으면 main이 보고 있는 것을 core에 다시 알려(`presence/report`) core가 끈다. desktop의 toast·OS 알림은 이전처럼 보고 있으면 없다.
   - lophn agent session의 toast·OS 알림은 core Bus event(`TurnEnded`, `TurnRequestOpened`, `QuestionAsked`)를 shell main이 직접 듣고 정한다. session이 lophn agent인지는 `session_snapshots/list`로 읽는다. 팀 자식의 요청과 질문은 부모가 풀므로 알리지 않는다. 터미널의 coding agent는 터미널 쪽 tracker가 알린다. event는 한 줄로 처리해 읽기가 끝나는 순서가 event 순서를 뒤집지 않는다. 못 본 끝(finished 점)은 core가 들고(`attention.md`) 창의 unseen store가 `unseen/list`를 읽는다. renderer의 sessions store가 이를 session 상태와 합쳐 Agent 탭에 finished 점을 준다. 권한 물음은 점을 켜지 않는다(waiting 점이 보인다).
   - 알림 본문은 hook payload가 직접 준 글만 쓴다. turn 끝 신호의 `message`에 마지막 답(실패면 오류 글)을 싣는다. claude 꼴·codex·droid·command-code·antigravity·grok·copilot는 `last_assistant_message`, kiro는 `assistant_response`다. 권한 물음은 `request.summary`(없으면 tool 이름)를 쓴다. plugin 형식(opencode 계열·pi·omp·amp)은 lophn이 놓은 plugin 본문이 마지막 답을 `lophn_message`로 실어 보낸다(끝까지 간 turn만, 4000자 상한, 못 읽으면 뺀다). cursor·hermes·cline·letta는 payload에 답이 없어 본문 없이 알린다. transcript는 읽지 않는다. 본문은 공백을 접어 160자에서 줄임표로 자른다(markdown은 그대로). 모르면 본문은 없다(폴더 이름으로 채우지 않는다).
   - 알림 글은 toast와 OS 알림이 같고, 글을 정하는 곳도 shell main 한 곳이다(`agent`, `workspace`, `body`). 제목은 누구인지에 어디인지를 붙인다. 터미널의 누구는 그 탭의 보이는 이름이다. 화면이 탭 이름이 바뀔 때마다 `terminals/name`으로 core에 알리고 core는 메모리에 두었다가 터미널이 끝나면 지운다. core는 그 이름을 runtime의 `tab_name`으로 실어(`TerminalRuntimeChanged`) 다른 창·workspace의 탭 이름도 모든 화면이 안다. `TerminalAgentSignaled`의 `name`이 이 이름이다. 모르면 harness 이름이다("<탭 이름> finished · 다운로드", "Claude Code finished · 다운로드", "lophn needs permission · <session 이름>", "Claude Code's turn failed · …"). 어디를 모르면 "Claude Code finished"다. main은 ICU formatter가 없어 `{agent}`·`{workspace}`만 손으로 채우고, 있을 때와 없을 때를 별도 key(`common.title.agent-*`, `…-in`)로 둔다. 본문은 마지막 답의 앞부분, 권한 물음의 요약, 실패 까닭이다. toast는 제목 앞에 그림을 단다(터미널은 harness 제품 아이콘, lophn agent는 그 agent의 profile. profile은 character의 shape·color나 이니셜이고 올린 이미지는 main이 읽을 주소가 없어 이름 첫 글자로 갈음한다). OS 알림에는 그림이 없다(harness 아이콘이 renderer 안의 svg뿐이다).
   - lophn agent 알림의 이름·얼굴·본문은 알릴 때마다 main이 core에서 읽는다. agent 이름과 profile은 `agents/read`의 `effective`, session 이름은 `sessions/read`의 `title`(없으면 제목에 어디를 붙이지 않는다), 끝난 turn의 답은 `TurnEnded.messages`를 뒤에서부터 `messages/body`로 읽어 글(text) 부분이 있는 첫 것, 실패는 `TurnEnded.error.message`, 권한 물음은 `TurnRequestOpened`의 subject(shell 명령, tool 이름, harness 요약), 질문은 `ask/read`의 첫 질문이다. 보고 있어 알리지 않을 때는 본문을 읽지 않는다.
7. **못 본 끝남은 알림 panel의 Finished 묶음에도 남는다.** 별도 기록 없이 core의 못 본 끝(`unseen/list`)과 터미널 runtime의 idle에서 줄을 만든다. 줄은 굵은 윗줄이 탭·session 이름, 작고 흐린 아랫줄이 누가 끝냈는지(coding agent 제품 이름, lophn agent 이름)다. core는 session 참조만 가지므로 lophn session 줄은 창이 session store의 agent로 그 정의(이름, avatar)와 session 이름을 읽어 그린다. 터미널 줄의 이름은 runtime의 `tab_name`이라 어느 창·workspace의 탭이든 같고, 탭을 그린 창이 이름을 알리기 전의 잠깐만 시작 폴더 이름이다. 창마다 waiting store가 `TerminalRuntimeChanged`를 모으고(창이 뜨기 전에 끝난 turn은 `terminals/list`로 읽는다), 줄을 누르면 toast와 같은 길로 탭을 고른다. 줄 오른쪽 끝의 [x]는 탭을 열지 않고 줄과 개수를 지운다. 터미널이든 lophn session이든 창이 core에 `unseen/dismiss`를 부르는 것이고 본 것과 같다. 권한·질문 같은 결정 요청에는 지우기를 두지 않는다. 탭을 보아 core가 unseen을 지우면 줄도 빠진다. 터미널이 끝나거나 host가 사라지면 tracker가 그 entry를 지우면서 unseen 표시를 지우고, 끝난 runtime이 `TerminalRuntimeChanged`로 모든 화면에 가 줄이 빠진다. 알림 단추의 개수는 대기 항목과 이 줄을 합한다.
8. **탭 점은 X 자리에 있다.** working은 숨 쉬듯 커졌다 작아지고 waiting, finished, ended는 멈춰 있다. 마우스를 올리거나 X에 keyboard focus가 가면 X로 바뀐다. reduced motion이면 움직이지 않는다. lophn agent 탭의 점도 같은 자리, 같은 규칙이다(working, waiting, finished, ended). floating 패널 머리, 최소화한 칩, detached 창 머리에도 같은 점이 있다. detached 창의 위 막대에는 점이 없고 icon만 있다.
9. **hook 설치는 묻고 놓는다.** 사람 터미널에서 harness를 foreground로 처음 알아본 때(core 실행마다 harness당 한 번) 설치 여부만 보고(`dry_run`), 없으면 core가 `HookInstallAsked`를 내고 그 터미널의 탭을 가진 창이 dialog로 묻는다(OS 창이 아니다. 답은 `coding_agents/hook_answer`, 결과는 `HookInstallFinished`. 창 고르기는 [coding-agent.md](coding-agent.md)). 붙은 shell이 없으면 묻지 않고 거절로 센다. shell이 붙어 있어도 그 터미널의 탭을 가진 창이 없으면 아무도 답하지 않고, shell 연결이 닫힐 때 거절로 센다(이 core 실행에서는 그 harness를 다시 묻지 않는다). 거절하면 이 실행에서는 다시 묻지 않고 기억하지 않는다. Settings › Coding agents의 [Install hooks]는 누른 것이 허락이라 묻지 않는다. 놓는 규칙은 [coding-agent.md](coding-agent.md)다. 놓거나 지운 뒤에는 공유 skill 사본을 hook이 놓인 harness에 맞춰 다시 맞춘다. 묻기나 놓기가 실패해도 터미널은 그대로 돈다.
   - 이 길에서는 harness가 이미 돌고 있고 harness는 hook을 시작할 때 읽어서(Hermes는 agent를 준비할 때 한 번) 그 실행에는 상태가 보이지 않는다. 그래서 성공 알림이 다시 시작하라고 한다. harness가 읽는 event가 늘면 이미 설치한 설정에는 그 event가 없다(예: Claude 꼴에 `SubagentStart`·`SubagentStop`이 늘었다). 그러면 dry_run이 `missing`으로 보고, 처음 알아볼 때 다시 묻고, Settings에는 [Install hooks]가 다시 보인다. 사람에게 묻지 않고 설정을 고치지 않는다.
   - Windows는 foreground가 없어 이 경로의 설치 dialog를 기대하지 않는다. 필요한 hook은 Settings의 [Install hooks]로 사람이 설치하며 자동 허락하지 않는다.
10. **상태는 메모리뿐이고 session identity만 저장한다.** running·waiting 같은 상태는 core 메모리에만 두고 runtime에 실어 `TerminalRuntimeChanged`로 낸다. 다시 붙은 화면은 `terminals/list`·`snapshot`의 runtime에서 읽는다. 터미널이 끝나면 지우고, restart한 shell은 다음 foreground나 hook에서 다시 안다.
    - hook이 session id를 알려 준 session의 identity는 core가 project마다 `<data root>/terminal-agents/sessions/<project>.json`에 저장한다(`terminals/saved_sessions`). 같은 session은 갱신하고 최대 50개이며 넘으면 오래된 것부터 뺀다. 저장한 것을 열면 core가 새 터미널을 열고(`terminals/open`의 `resume`) harness의 resume 명령을 친다. resume 규칙이 없는 harness(pi, amp, command-code, muse, codebuddy, prime-agent, mimocode)는 새 터미널만 연다. resume 명령은 core가 PTY에 바로 쓰므로 사람 입력의 자격 검사를 거치지 않고, id는 `[A-Za-z0-9._:-]`만 받아 따옴표가 필요 없다.
    - session id는 harness 표의 경로로 모든 hook event에서 읽고, 값이 바뀌면(`/clear`, resume) tracker가 session을 바꾸고 제목과 이름을 비운다. session 이름도 harness 표의 경로(claude 꼴은 `session_title`, OpenCode 계열은 `properties.info.title`, pi·omp는 plugin이 싣는 `session_name`)로 모든 hook event에서 읽는다. 경로가 빈 harness는 이름이 없고 첫 prompt가 제목으로 남는다. 이름은 runtime의 agent 값(`name`)으로 실리고 저장한 session 기록의 이름도 같이 고친다.
    - 사람이 탭 이름을 바꾸면 화면이 저장한 기록에 그 이름을 쓰고 고정(`pinned`, `terminals/rename_saved`)해, 이후 hook 이름이 덮어쓰지 않는다. 이름을 지우면 고정이 풀린다. 탭 이름은 사람 이름 > harness session 이름 > 터미널 제목(OSC 0/2, 앞의 spinner 같은 상태 글자는 지운다. coding agent가 도는 동안만, 일반 shell의 제목은 쓰지 않는다) > 자동 이름 순이고, workspace가 store 변경마다 모든 터미널 탭에 같은 계산을 적용해 그려지지 않은 탭도 hook 이름과 터미널 제목을 따른다. 이름의 출처가 사라진 동안은 탭이 기억한 그 session의 이름을 보인다(아래 결정). 터미널 제목은 core가 PTY 출력에서 읽어 runtime의 agent 값(`screen_title`)으로 싣는다. 창의 xterm은 제목을 읽지 않는다. sidebar 줄의 제목은 `name ?? 탭 이름`(저장한 줄은 `name ?? title`)이다.
11. **터미널 화면과 출력은 탭의 mount와 PTY의 수명을 나눈다.** PTY는 core가 열고 갖는다. 탭이 mount될 때 PTY를 열지 않는다: 열라는 요청(사람의 화면, 폰, agent의 `lophn tab open`)이 core에 오면 core가 열고, 그 workspace를 보이는 창이 있으면 탭으로 보인다. 창마다 한 번 본 terminal의 xterm·DOM·마지막 seq를 유지한다. 같은 project 안의 tab·pane·desk·float 전환은 DOM을 다시 붙이고 fit·focus만 한다. 숨은 terminal도 새 출력은 파싱하며, 보이지 않는 화면의 drawing만 쉰다. 탭을 닫거나 다른 창으로 옮기거나 project를 떠나면 view와 출력 lease를 놓는다.
    - **날 출력은 보는 쪽이 잡은 동안만 간다.** 화면은 `terminals/watch {terminal, watcher, on}`로 lease를 잡고(30초, 10초마다 갱신, key는 principal과 watcher) 처음 붙을 때 `terminals/snapshot {after_seq}`로 읽는다. PTY host는 새 출력을 16ms 또는 64Ki 문자 단위로 묶어 private pipe로 보내고, core는 그 터미널에 lease가 하나라도 있는 동안만 묶음 하나를 `TerminalOutputAppended`(남지 않는 event) 하나로 Bus에 낸다. lease가 없으면 core는 host의 화면만 유지한다. idle polling은 없다.
    - **seq로 잃거나 두 번 받지 않는다.** 화면은 받은 seq보다 큰 event만 이어 쓰고 다른 generation의 늦은 출력은 버린다. seq가 건너뛰거나 Gateway가 다시 열리면(`ready`) 마지막 seq로 `snapshot`을 다시 읽는다. back-pressure는 host의 묶기와 Gateway의 느린 연결 끊기(1 MiB)뿐이고 core는 터미널마다 queue를 두지 않는다. runtime이 바뀌면 lease와 상관없이 `TerminalRuntimeChanged`가 모든 화면에 간다.
    - 새 PTY의 ref는 주입한 IdSource로 만들고, 같은 PTY의 restart는 generation을 올린다. host가 사라졌다 새로 떠도 옛 ref를 새 PTY에 재사용하지 않아, 보관한 view와 늦은 입력이 새 shell에 섞이지 않는다.
    - 보이는 터미널은 focus와 상관없이 칸 크기를 PTY에 보낸다(`terminals/resize`). 사람의 키 입력과 restart만 focus 검사를 한다.
    - **focus 검사는 shell main에 남는다.** desktop 화면의 `terminals/input`과 `terminals/restart`는 shell main이 focus 검사를 한 뒤, 질의 응답은 그 창이 그 터미널을 보이는지 본 뒤 control `connect {client: shell}`이 준 capability를 실어 부른다. core는 살아 있는 capability만 받는다. 폰과 다른 기기는 capability 대신 기기의 터미널 입력 허락으로 치고 다시 띄운다(19). agent 자격은 터미널에 치지 못한다.
    - focus가 없는 xterm의 새 질의 응답은 `respond`로 보낸다. 사람의 입력은 focus 검사를 거치는 입력이다. `respond`는 focus가 아니라 "그 창이 보이는 터미널"을 본다: 창의 화면이 터미널에 붙을 때와 놓을 때 shell main에 알리고(`shell:terminal-shown`), shell main은 그 창이 보이지 않는 터미널의 응답을 core에 넘기지 않는다. `respond`는 agent의 human-input·interrupt 신호를 만들지 않는다. 이미 처리했던 출력을 처음 재생할 때는 질의 응답을 보내지 않는다(그 안의 옛 질의에 xterm이 답해 입력으로 PTY에 가지 않게 한다).
12. **다시 붙는 화면은 host가 파싱해 둔 화면 하나로 받는다.** 다른 창이나 새 renderer에 붙는 경우(project를 떠났다 돌아올 때, 창 reload, 앱을 다시 켬)는 PTY host가 들고 있는 화면을 한 번 받는다. PTY host는 raw 출력을 쌓지 않고 PTY마다 headless xterm으로 파싱해 두며, snapshot은 그 화면(scrollback 10,000줄, alternate screen, mode, cursor)을 직렬화한 chunk 하나를 마지막으로 파싱한 seq로 준다. 직렬화가 빠뜨리는 mouse report 인코딩(`?1006` 등)과 커서 숨김(`?25l`)은 headless 화면이 출력에서 따라가 덧붙인다. 빠지면 다시 붙은 xterm이 X10 report를 `onBinary`로 내 TUI가 mouse를 하나도 받지 못한다(renderer는 `onBinary`도 0x80 아래만 보낸다).
    - renderer는 view를 snapshot의 PTY 치수로 맞춘 뒤 재생하고, store entry의 `restored`를 올려 탭이 칸에 다시 맞추게 한다(치수가 다르면 탭이 PTY를 resize해 TUI가 다시 그린다). 재생 직후 그 자리에서 맞추면 막 붙은 칸이 배치 전이라 13x5 같은 치수로 PTY까지 줄였다. 그 seq 뒤 push만 이어 쓴다.
    - resize는 앞서 받은 출력을 옛 크기로 파싱한 뒤에 headless 화면에 건다. scrollback을 넘어 오래된 줄이 빠지면 `dropped_output`이 켜지지만 배너는 띄우지 않는다. 출력은 disk에 저장하지 않는다. pipe reader는 조각에서 newline을 찾고 완성된 줄을 한 번 join하며 UTF-8 decoder 상태를 유지한다.
13. **clipboard는 사람이 누른 키로만 쓴다.** Linux·Windows는 xterm의 key handler가 Ctrl+Shift+C(고른 글 복사, 없으면 아무것도 보내지 않는다)와 Ctrl+Shift+V(bracketed paste로 감싼 붙여 넣기)를 받고, macOS는 창 menu의 Cmd+C/V다. shell 창 session은 clipboard 쓰기 밖의 web permission을 거절해 `navigator.clipboard` 읽기가 안 되므로 OS clipboard는 복사·붙여 넣기 모두 shell main이 쓰고 읽는다(headless는 복사를 버리고 붙여 넣기는 빈 글이다). clipboard는 OS에 붙은 것이라 core로 가지 않는다.
    - mouse를 받는 TUI(Claude Code, OpenCode)는 스스로 글을 고르고 OSC 52로 clipboard에 쓴다. 출력은 인터넷에서 온 글일 수 있어, 사람이 그 터미널에서 mouse를 뗀 뒤 첫 OSC 52 쓰기 하나만 main으로 보내고(키를 누르면 거둔다) 읽기(`?`)에는 답하지 않는다. mouse를 받는 TUI 안에서 xterm 자체 선택은 Shift+드래그다.
    - xterm과 host 화면은 Unicode 11 폭표를 쓴다. 기본 Unicode 6은 이모지를 1칸으로 세어, 2칸으로 그리는 TUI의 줄이 밀리고 바뀐 칸만 다시 그리는 TUI 화면이 깨졌다.
14. **출력의 파일 경로와 `command`로 연 터미널.** 출력의 파일 경로(확장자가 있는 것, `:line[:col]`)는 shell을 시작한 폴더(`cwd_at_start`) 기준으로 풀어 부모 폴더를 읽어 그 이름의 파일이 있을 때만 link가 되고, Ctrl/Cmd-click하면 문서 탭으로 연다(자리는 [workspace-layout.md](workspace-layout.md)). shell이 `cd`한 뒤의 폴더는 모른다.
    - 열 때 `command`를 준 터미널(대화의 bash·sh·zsh 코드 블록 [Run in terminal])은 core가 shell 뒤에 한 번 넣는다. shell은 시작 층을 읽는 동안 친 글을 버리므로 첫 출력(prompt) 뒤 300ms 잠잠할 때(늦어도 5초) 친다. resume 명령도 같은 기다림을 거친다. 한 줄이면 Enter까지 쳐서 실행하고, 여러 줄이면 bracketed paste로 붙여 넣기만 한다. 줄바꿈·tab 밖의 제어 문자가 있는 글은 renderer가 단추를 두지 않고 `terminals/open`의 입력 schema(최대 8192자)가 거절한다.
15. **진단 기록은 글 내용을 싣지 않는다.** Settings › Diagnostics의 Trace(설정 `diagnostics.trace`, 기본 꺼짐)를 켜면 renderer가 터미널마다 모은 일을 0.5초마다 `shell:terminal-trace`로 보내고 main이 `<data root>/logs/terminal-trace.jsonl`에 덧붙인다. 10 MiB를 넘기 전에 `terminal-trace.1.jsonl`로 넘겨 둘만 남긴다. main은 설정을 처음 쓸 때 core에서 읽어 두고 `settings` 변경(`StateChanged`)이 오면 다시 읽는다(앱을 다시 띄우지 않는다). 꺼져 있으면 main이 false로 답해 renderer가 5초 동안 모으지 않다가 다시 묻는다.
    - 한 줄은 창(`win`), 시각(`t`), 탭 key, terminal ref와 일이다. TUI가 켜고 끈 DEC mode(mouse tracking·인코딩, focus 알림, alternate screen, bracketed paste, 동기 출력), RIS, pointer 누름·뗌(그때 xterm이 mouse를 TUI에 넘기는 중이었는지, 누른 자리 맨 위 요소, 터미널 밖에서 뗐는지), 뗀 뒤 xterm 선택이 생겼는지, focus·blur, fit·view resize, snapshot 재생(PTY 치수), active 바뀜, main이 거절한 입력, OSC 52, WebGL context 잃음. mouse 이동·wheel·PTY로 보낸 입력은 종류별 개수로 묶는다. 친 글과 출력 내용은 싣지 않는다(비밀번호·token이 지나간다). 간헐적인 mouse·화면 문제를 재현 없이 보려고 둔다.
16. **터미널 host 하나의 이상이 다른 터미널이나 core를 멈추지 않는다.** PTY host는 core의 자식이고 core와 수명을 같이한다. 요청 하나가 던지면 그 요청만 `host_lost`로 답하고 host는 계속 돈다. host는 core가 사라지거나(stdin이 닫힘, stdout 오류), SIGTERM, 요청 밖의 예외로 끝날 때 PTY 자식을 SIGHUP·SIGKILL까지 정리하고 끝난다(고아 PTY를 남기지 않는다). PTY를 띄우지 못한 원인은 stderr에 남는다(화면에는 `spawn_failed`만 보인다).
17. **host를 감독하는 core는 host가 답하지 않아도 기다리지 않는다.** host pipe 오류는 받아서 core가 끝나지 않게 하고, 요청은 10초 안에 답이 없으면 `host_lost`로 끝난다. host가 끝나면 code, signal, stderr 마지막 4 KiB를 로그 한 줄로 남긴다. 열기에 딸린 resume·command 줄을 친 것이 거절돼도 열기는 실패가 아니다(탭은 이미 열렸고 다시 치지 않는다). 붙여넣기 조각 하나가 거절되면 그 paste의 나머지는 보내지 않는다(닫는 bracketed paste 표지 없이 끝나거나 중간이 빠진 채 PTY에 들어가지 않게 한다).
18. **기기의 터미널 보기는 보는 동안만 화면을 읽고, 기기가 잡은 PTY 크기는 보는 동안만이다.** lease(30초)가 끝나거나 기기가 끄면 core가 화면 읽기를 멈추고 기기의 크기를 놓는다. 크기는 그 터미널의 lease를 쥔 principal만 잡는다. 기기는 그 기계의 어느 터미널이든 본다. 날 출력은 기계 사이 연결로 가지 않는다(다른 기계의 터미널도 화면 사본이다).
19. **기기(폰, 연결된 컴퓨터)의 터미널 입력은 사람이 컴퓨터에서 허락한 기기만 보낸다.** 허락은 core가 입력마다 보고(폰이 보여 주는 `input`은 안내일 뿐이다) 꺼진 기기는 `forbidden`이다. 열면서 치는 `terminals/open`의 `command`·`resume`과 `terminals/restart`도 입력이라 같은 허락을 본다(닫기는 허락받은 기기의 route 목록에만 있다). 허락이 없는 기기는 빈 터미널만 열고, `command`나 `resume`을 실은 열기는 터미널을 열기 전에 `forbidden`이다. 기기의 허락은 그 기계를 온전히 다루는 권한이라 보이는 터미널로 좁히지 않는다: 허락받은 기기는 그 기계의 어느 터미널에나 친다. 허락을 정하는 길은 초대장을 내는 것과 기기 줄의 스위치뿐이고 둘 다 desktop의 사람 자격이다. 기기 자격으로는 없다.
20. **터미널 화면은 가리지 않고 화면 사본은 event에 싣지 않는다.** 화면은 core 메모리의 최신 하나이고 폰은 `terminal_view/snapshot`으로 읽는다. 날 출력(`TerminalOutputAppended`)은 lease를 잡은 화면에만 가는 남지 않는 event다. 기록(ledger)에는 아무것도 남지 않는다.
21. **앱을 Quit해도 터미널은 돈다.** Quit할 때 도는 터미널이 있으면 "그대로 두기"(기본)와 "다 닫기"를 묻는다. 터미널이나 coding session이 열려 있는 동안 core는 스스로 끝나지 않는다. tray의 `Stop lophn`은 다 닫는다. 다시 켜면 탭이 살아 있는 터미널에 붙는다(12). core가 끝나면 PTY도 끝난다(16).
22. **OS에 붙은 것만 shell에 남는다.** focus 검사(11), 알림 띄우기(6), clipboard(13), 터미널의 link를 lophn browser 탭으로 여는 것이다. 나머지(PTY, tracker, hook 받기, 상태, 저장)는 core가 갖는다. shell이 없으면 알림은 폰 push만, 터미널의 link는 OS의 browser로 간다.

## 경계와 계약

- **hook 줄**: `lophn hook <harness> <event>`가 env `LPN_TERMINAL_HOOK`(`{socket, key}` JSON)의 endpoint에 쓰는 한 줄 `{v:1, key, harness, event, payload}`. 답이 없고 core가 연결을 닫는다. event 이름은 80자까지, payload는 64 KiB까지다. 탭을 GUI로 바꿔 달라는 요청은 같은 길의 event `lophn-gui`(`{cwd, resume?}`)이고 tracker가 아니라 harness GUI가 받는다. 이 env 이름이 `LOPHN_`이 아닌 것은 터미널 env가 바깥 `LOPHN_*`를 지우기 때문이다.
- **hook 신호**: harness마다 다른 hook event는 같은 신호 어휘로 바뀐다. SessionStarted, TurnStarted(prompt 한 줄), TurnEnded(outcome completed·failed·interrupted, 마지막 답이나 오류 글, `children`), PermissionRequested(tool, summary), PermissionResolved, SessionEnded, SessionNamed, ChildStarted·ChildEnded(`child`). 어느 신호에도 해당하지 않는 hook은 버린다.
- **터미널 route**(desktop 화면과 폰이 같이 쓴다, 사람 자격만): `terminals/list`·`snapshot`·`saved_sessions`(read), `terminals/open`·`close`·`restart`·`input`·`resize`·`watch`·`name`·`rename_saved`(memory). 실패의 이유는 `details.reason`(`no_folder`, `not_directory`, `unreadable`, `spawn_failed`, `kill_unconfirmed`, `host_lost`)이다. 기기 route 목록에 드는 것은 모든 기기의 `terminals/list`·`open`·`input`(입력은 허락받은 기기만 core가 받는다)과 허락받은 기기의 `terminals/close`·`restart`다. `terminals/restart`의 `shell_capability`는 기기가 아닌 부른 쪽에만 있다. 날 출력 route(`terminals/snapshot`·`watch`·`resize`)는 기기 목록에 없다.
- **runtime event**: 터미널 runtime(`TerminalRuntime`)에 `agent`(harness, state, hooked, foreground, session, title, name, screen_title), `tab_name`, `remote_size`가 실린다. 바뀔 때마다 `TerminalRuntimeChanged {runtime}`(subject `terminal:<ref>`)을 내고 같은 값은 다시 내지 않는다. 새로 뜨거나 다시 읽은 화면은 `terminals/list`로 한 번 읽는다. 끝났거나 모르는 터미널의 늦은 신호로 entry가 되살아나지 않는다.
- **날 출력 event**: `TerminalOutputAppended`(subject `terminal:<ref>`, payload는 host 묶음 하나 `{terminal_ref, generation, seq, chunk, dropped_output}`). `terminals/watch` lease가 있는 동안만이다.
- **알릴 계기 event**: `TerminalAgentSignaled {terminal, project, harness, kind(waiting·finished·failed), name, body}`(subject `terminal:<ref>`). hook 설치 물음은 `HookInstallAsked {request, terminal, harness, label, files}`와 `coding_agents/hook_answer`, 결과는 `HookInstallFinished`다. Settings › Coding agents는 `coding_agents/list`·`refresh`·`hook_status`·`install_hooks`·`uninstall_hooks`다.
- **shell에 남는 IPC**: `shell:terminal-input`·`shell:terminal-restart`(shell main이 focus를 본 뒤 capability를 실어 `terminals/input`·`restart`를 부른다), `shell:terminal-response`(그 창이 그 터미널을 보일 때만 `terminals/input {respond}`), `shell:terminal-focus`(focus 표), `shell:terminal-shown`(창이 보이는 터미널 표), `shell:terminal-link`(link를 어디에서 열지), `shell:terminal-copy`·`shell:terminal-paste`(clipboard), `shell:terminal-trace`(진단 묶음), 알림 누름의 `shell:terminal-reveal`(`TerminalReveal`). 터미널 열기·입력·크기·출력·탭 이름·저장한 session·agent 목록을 나르던 IPC는 없다(화면이 core route를 부른다).
- **저장 모양**: `<data root>/terminal-agents/sessions/<project>.json`(project마다 최대 50개, 원자 교체로 쓴다). 옛 자리 `<data root>/shell/agent-sessions/`는 data step이 옮긴다. 상태는 저장하지 않는다. 터미널 진단은 `<data root>/logs/terminal-trace.jsonl`(+ `.1`). 시작 층 file은 per-run 폴더의 `shell-init/`이고 이 폴더는 core 실행마다 새로 만든다.
- **설정**: `diagnostics.trace`(기본 꺼짐).
- **session lifecycle**: 앱이 터미널 coding agent도 session으로 보도록 core의 tracker가 지금의 집합(터미널, project, harness, 상태, hook이 알린 CLI session id와 제목, 터미널이 뜬 폴더, PTY shell pid, view `gui`|`tui`, handoff(`restart`·`shared`, handle도 GUI로 넘길 foreground TUI도 없으면 null), foreground(그 터미널의 foreground가 coding agent TUI인가))를 session lifecycle과 coding session 목록에 바로 준다. GUI view의 터미널은 handle이 진실이라 TUI agent가 없어도 줄이 선다. 앱이 그 session을 멈추면 core가 그 harness의 끊기 key를 PTY에 친다(key가 없는 harness는 `unavailable`). CLI 자신의 pid, process 목록, git 정보, process kill은 주지 않는다.
- **기기의 event**: 기기 Gateway가 보내는 터미널 event는 `TerminalScreenChanged`와 `TerminalRuntimeChanged`다. `TerminalOutputAppended`는 보내지 않는다.
- **폰의 터미널 보기**: 폰의 화면 사본 route는 `terminal_view/snapshot`(read)·`watch`·`resize`(memory), event는 `TerminalScreenChanged`다. 열기와 입력은 `terminals/open`·`terminals/input`이다. 입력 허락은 명단 항목의 `terminal_input` 칸이고(`remote.md`의 "내 기기 명단") 초대장(`roster/invite {terminal_input}`)이 처음 값을 싣는다. 바꾸는 `roster/set_terminal_input`과 `roster/invite`는 사람 자격만 부른다.
- **core와 shell 사이 link**: 창이 있어야 하는 것만 남는다. 요청 `tab_open`·`tab_close`·`tab_show`(터미널 탭은 target `{terminal: {terminal_ref}}`로 core가 연 터미널에 붙는다), `browser_call`, frame `hello`·`visible`·`response`·`report`. core가 shell에 시키던 터미널·coding 요청(`tool_call`, `terminal_interrupt`, `coding_*`, `terminal_stream`·`terminal_input`·`terminal_resize`·`terminal_open`), shell이 올리던 frame(`coding_report`·`coding_sync`·`coding_closed`·`terminal_screen`, `hello`·`visible`의 `tui`), 탭 target `coding`·`tui`, route `coding_sessions/wake`, `coding_sessions/list`의 `shell` 칸, `terminal_view/open`·`input`, `extension_tools/publish`, `terminal_sessions/signal`은 없어진다.
- **알림 모델**: core가 `TerminalAgentSignaled`로 계기를 내고, shell main 한 곳이 `{누구, 어디, 본문, 종류(finished·failed·permission)}`로 알림을 정하고, 보고 있는지에 따라 없음·toast·OS 알림 중 하나로 보낸다. 터미널 알림 누름은 `TerminalReveal`(터미널 ref와 project)로, lophn session 알림은 toast 행동 `session`으로 탭을 연다.
- **harness 표와 hook 설치**: 제품마다 hook 위치·event·stdout·session 규칙·끊기 key를 한 표가 정하고 설치 규칙은 [coding-agent.md](coding-agent.md)다. 설치 dry_run·dialog·결과 통지의 창 고르기도 거기에 있다.
- **harness GUI 전환**: 탭 머리 단추(`coding_sessions/switch`)와 `<harness> gui` 함수(hook socket)가 터미널을 GUI로 바꾸고 TUI로 되돌린다. GUI handle은 core 안 extension host에 있어 창과 상관없이 산다([harness-gui.md](harness-gui.md)).

## 결정

- **다른 기계의 터미널은 화면 사본으로 그린다.** 날 출력을 기기 Gateway로 넘기면 한 터미널의 쏟음이 그 연결을 `slow_consumer`로 끊고, 끊김은 연결 전체라 다른 event와 부르기가 같이 떨어졌다(모델의 "다른 기계의 터미널"에 잰 값). 사본은 core가 250ms마다 최신 하나만 두고 보는 쪽이 하나씩 당겨 쏟음과 상관없이 크기가 묶인다. 대가: 화면이 초당 네 번까지만 바뀌고 사본의 scrollback은 200줄이며 사본을 다시 쓸 때마다 scroll 자리가 맨 아래로 간다. 버린 안: 날 출력을 그대로 넘기기, 기기 연결에 터미널 전용 queue나 rate limit 두기(묶음을 버리면 결국 사본으로 맞춰야 한다). (agent, 잰 값으로)
- **session이 아니라 탭 상태다.** 사람이 자기 터미널에서 띄운 agent는 lophn의 대화가 아니고 lophn이 말을 넣지 않는다. session으로 두면 `claude`를 띄울 때마다 session 행이 생긴다. paseo도 터미널 탭의 agent를 chat agent와 나눠 상태 셋만 둔다. 실행 상태는 지금도 탭 상태다. identity만 저장해서 sidebar가 다시 열 수 있게 한다. (사람, 2026-10-26 / 2026-10-29)
- **터미널 coding agent는 sidebar의 Agents(정의)에 두지 않는다.** agent 정의와 열린 session을 나눈다. agent마다 session을 들여 쓰면 session이 생길 때마다 아래 agent가 밀리고 `+`를 찾기 어렵다. 터미널 coding agent는 Current(열린 session과 hook을 한 번이라도 보낸 터미널 agent)와 Recent(저장한 session)에 보인다. (사람)
- **foreground process로 무엇이 도는지 안다. 상태는 hook만 쓴다.** herdr와 같은 방식으로 무엇이 도는지 안다. hook만 쓰면 hook이 없을 때 icon이 없고 설치를 물을 때를 모르며 Codex·OpenCode가 끝난 것을 모른다. 상태까지 화면으로 짐작하는 herdr는 상태 오판 이슈가 많아 상태는 hook만 쓴다. (사람, 2026-10-26)
- **hook을 터미널을 가진 쪽이 받는다.** browser bridge가 이미 같은 꼴(터미널 env의 socket과 key)이다. orca·emdash(loopback POST), paseo(터미널마다 env token), herdr(unix socket)도 터미널을 가진 쪽이 받는다. 처음에는 터미널, 탭, focus, 알림이 모두 shell의 것이라 shell main이 받았다. 터미널을 core가 갖게 되며 hook도 core가 받는다.
- **터미널은 core가 열고 갖는다.** 창이 없어도 열리고, 폰과 agent가 연 터미널이 창에 기대지 않고, 앱을 Quit해도 일이 돈다. shell main이 PTY를 갖던 때는 core가 shell에 시키는 요청(`terminal_*`, `coding_*`)과 shell이 올리는 사본(`coding_report`, `terminal_screen`)이 같은 상태를 두 벌로 들었다. 같은 일을 하는 길을 둘로 두지 않으려고 화면은 route로만 붙고 OS에 붙은 것(focus 검사, 알림 띄우기, clipboard, link 열기)만 shell에 남는다. 터미널을 가진 쪽이 사람의 PATH를 모른다는 것이 shell에 둔 이유였는데 core가 login shell env를 읽어 그 이유가 없어졌다. (사람, 2026-11-17: 일은 core가 하고 shell은 화면 가운데 하나다 / agent: 나누기)
- **앱을 Quit해도 터미널은 돈다.** Quit은 화면을 끄는 것이고 일은 core의 것이다. 도는 터미널이 있으면 Quit이 "그대로 두기"(기본)와 "다 닫기"를 묻고, 어느 쪽이든 core는 남는다. 모두 끄는 길은 tray의 `Stop lophn`이다. 다시 켠 앱의 탭은 layout에 남긴 `terminal_ref`로 살아 있는 터미널에 붙고, 터미널이 없으면 새 shell을 연다. 버린 안: Quit이 터미널을 끝낸다(앞의 판. 폰과 agent가 연 터미널이 앱에 묶인다). (사람, 2026-11-17 / agent: 묻는 꼴)
- **탭의 자리(layout)는 화면마다 그대로 둔다.** core는 무엇이 열려 있는지(터미널, coding session)만 알고 그것을 어느 창, 어느 desk에 놓았는지는 화면이 저장한다. 탭이 `terminal_ref`를 지녀 다시 붙는다. 버린 안: layout을 core로 옮기기(쓰는 곳이 생길 때 한다). (사람, 2026-11-17)
- **날 출력은 Bus의 남지 않는 event로 싣는다.** renderer가 이미 쓰는 Gateway 하나로 가고, 놓쳐도 snapshot으로 맞추는 규칙(`event.md`)과 같아 새 연결이 필요 없다. 보는 화면이 없으면 내지 않는다(lease). 버린 안: 터미널마다 WebSocket, core의 터미널별 queue. (agent)
- **폰의 화면 사본 route는 그대로 두고 열기·입력만 `terminals/*`로 합친다.** 폰이 날 글자로 그리는 것은 이 범위 밖이고, 폰의 크기 잡기는 lease에 묶인 폰만의 규칙이다. (agent)
- **shell 함수로 끼운다.** 사람이 친 `codex`를 막거나 바꿔 부를 자리가 shell뿐이다. orca가 같은 방식(Codex shell function)이다. 공유 server를 쓰는 harness는 lophn 터미널에서 private server 옵션으로 띄운다. app-server protocol로 붙는 길은 하지 않는다. (사람, 2026-10-26)
- **Esc·Ctrl-C는 사람이 친 key로 보고, 끊김을 hook으로 알리지 않는 harness에만 쓴다.** 화면을 읽지 않고 입력을 본다. paseo가 같은 규칙이다. orca는 title 변화와 맞춰 보는데 그러려면 화면을 읽어야 한다. 이 key는 끊김이 아니라 입력 지우기일 수도 있어서, 키로 내린 상태는 짐작으로 기억하고 뒤따르는 PermissionResolved로 되돌린다. 끊김 hook이 있는 harness는 짐작할 필요가 없어 key를 보지 않는다. 버린 안: 모든 harness에서 key 판정을 지운다(Claude Code는 Esc로 끊어도 Stop을 안 보낸다). 각 harness가 실제로 끊김 hook을 내는지는 표와 payload를 읽는 코드, 공식 문서(cursor `stop.status`)로 가렸고 실행해서 확인한 것은 omp뿐이다. Codex 0.150 미만은 표가 판을 가르지 못해 감수한다. (agent, 2026-10-30)
- **main turn과 child를 따로 들고 합친다.** main turn이 끝나도 subagent가 돌면 일은 끝나지 않았다. child를 따로 세기만 하고 상태에 넣지 않으면(Paseo) main의 Stop마다 idle과 finished 알림이 나가고, background agent가 끝나 main이 다시 깨면 알림이 또 간다. Orca와 T3가 이렇게 합친다. 근거는 hook에서만 받고 화면 문구("Waiting for N background agents", herdr)는 읽지 않는다. background shell은 T3·herdr처럼 세지 않는다. 흔들림은 상태가 아니라 알림에서 흡수한다(Orca의 1.5초). herdr처럼 상태 전이를 미루면 화면 반응이 늦다. child가 남으면 finished를 보내지 않고 다 끝나 idle이 될 때 한 번 보낸다(T3). Stop의 `background_tasks`가 있으면 그것이 정본이다(Orca). Codex와 그 밖 harness의 child는 hook에 근거가 없어 지금 그대로다. (agent, 2026-11-04, harness-lab의 multi-harness session status 보고서)
- **보고 있으면 알리지 않고, 사람이 멈춘 것은 알리지 않는다.** orca(사람이 멈춘 turn은 news가 아니다), herdr(Done은 안 본 Idle)와 같다. (사람, 2026-10-26)
- **창에 focus가 있으면 toast, 없으면 OS 알림이다.** 터미널 안 coding agent와 lophn agent가 같은 규칙이다. 이전에는 터미널 agent는 lophn 창이 하나도 focus가 아닐 때만 OS 알림을 냈고, lophn agent는 창마다 toast를 띄워 창이 여럿이면 여러 번 떴다. (사람, 2026-10-26)
- **터미널의 계기는 순간으로 내고 attention이 알릴지·못 본 것인지를 정한다.** 폰 push와 `unseen`이 core에 있으므로 터미널의 대기와 끝도 core가 알아야 한다. 목록의 변화를 비교하면 상태 해석(child, debounce, 끊기 짐작)이 두 벌이 된다. 그래서 tracker가 해석을 끝낸 순간(권한 물음, 1.5초 debounce 뒤의 끝)을 attention과 `TerminalAgentSignaled`로 낸다. tracker가 shell main에 있던 때는 같은 순간을 `terminal_sessions/signal`로 올렸다. 대가: desktop의 못 본 끝이 1.5초 늦게 선다(전에는 바로 켜고 1.5초 안에 다시 running이 되면 껐다). 버린 안: report 변화 비교. (agent)
- **알림 결정은 renderer가 아니라 shell main 한 곳이다.** 창마다 renderer가 event를 보고 각자 toast를 띄우면 창이 여럿일 때 겹치고, 터미널은 shell main이 이미 focus를 안다. 계기는 core가 내도 띄우는 것은 OS에 붙은 일이라 shell에 남는다(폰의 push와 같은 근거). main이 "어느 탭이 어느 창에 보이는가"를 한 표로 들고 있으면 터미널과 Agent 탭이 같은 규칙으로 toast와 OS 알림 중 하나를 고른다.
- **알림 toast의 [View]는 다른 project의 터미널 탭으로도 간다.** lophn agent session 알림이 이미 그 session의 project로 가던 길(Route 시작값)을 쓴다. 터미널 reveal에 project를 함께 실어 Desktop이 그 project로 이동한 뒤 탭을 고른다. (agent)
- **Finished 줄은 두 줄이고 탭 이름이 굵은 윗줄이다.** 한 줄(`Claude Code / 탭 이름`)로 하지 않고 lophn 줄도 같은 순서로 맞췄다. 탭 이름의 정본은 이미 OS 알림 제목에 쓰던 메모리(지금은 core의 runtime `tab_name`)다. renderer끼리 이름을 나누는 새 길을 만들지 않았다. (사람 2026-11-04 / agent)
- **끝난 터미널의 Finished 줄은 원인을 고쳐 지운다.** [x]·Show가 아무것도 못 하는 것을 단추에서 고치지 않고, 끝난 소식이 구독한 창에만 가는 것을 고쳤다. 지금은 runtime이 바뀔 때마다 `TerminalRuntimeChanged`가 모든 화면에 간다. (agent, 2026-11-04)
- **탭 이름은 사람 이름 > harness session 이름 > 터미널 제목 > 자동 이름이다.** 처음에는 harness hook의 session 이름이 아니라 프로그램이 보내는 터미널 제목을 따랐다. OpenCode와 Claude Code가 이미 session 이름을 제목에 싣고 hook은 harness마다 이름 칸이 달라 깨지기 쉬웠기 때문이다. 이후 사람이 요청해 hook 이름을 제목 위에 두었다. 사람이 붙인 이름이 프로그램 제목보다 먼저다(VS Code, Ghostty, iTerm과 같다). 이름 바꾸기는 터미널 탭만이다. (사람, 2026-10-26 / 사람)
- **탭은 한 번 얻은 session 이름을 같은 session인 동안 기억한다.** 이름의 출처는 그때그때 사라진다. GUI 제목은 그 탭을 그린 동안만 있고, 터미널 제목은 TUI가 foreground일 때만 믿을 수 있고, 다시 뜬 TUI는 topic을 다시 내기 전까지 제품 이름("Claude Code")을 낸다. 전에는 그 순간 탭이 자동 이름(project 이름)으로 떨어졌고, 저장할 때 기억을 탭의 지금 이름에서 다시 만들어서 그 순간의 저장이 기억까지 지웠다. 이름을 쓰는 곳도 둘(작업대와 그려진 탭 화면)이고 규칙이 서로 달랐다. 지금은 규칙이 순수 함수 하나(`terminalName`)이고 순서는 사람 이름 > GUI 제목 > hook session 이름 > 터미널 제목 > 기억한 이름 > 제품 이름뿐인 터미널 제목 > 자동 이름이다. 기억은 탭 field로 두고 session id와 함께 layout에 저장한다(`agent_title`, `agent_session`). hook이 다른 session id를 알리면(`/clear`, 새 session) 버린다. (사람, 2026-11-10 / agent)
- **터미널 제목은 터미널을 가진 쪽이 PTY 출력에서 읽는다.** 처음에는 탭이 그려져 있을 때 그 창의 xterm이 읽어 창 메모리에 두었다. 그래서 창이 다시 뜨면(닫았다 열기, reload) 제목을 잊어 coding agent 탭이 자동 이름(project 이름)으로 떨어졌고, agent가 새 제목을 낼 때까지 탭을 골라도 돌아오지 않았다. 그 이름이 layout에 저장되며 저장해 둔 이름도 지웠다. agent 값은 바뀔 때만 push해서 다시 뜬 창은 탭을 그리지 않은 터미널의 agent도 몰랐다(sidebar 줄이 빠졌다). 제목을 터미널을 가진 쪽(지금은 core)이 읽어 runtime에 싣고, 창은 뜰 때 지금 값을 한 번 읽는다. (사람, 2026-11-10 / agent)
- **알아보는 harness의 범위는 orca, emdash, herdr 셋 가운데 둘 이상이 지원하는 것이다.** 한 곳만 지원하는 것은 넣지 않는다. Gemini CLI는 지운다(Google이 Antigravity로 옮겼고, 호환 장치를 남기지 않는다). OpenClaw는 비교한 도구 어디도 지원하지 않아 지운다(agent). hook이 없는 harness(prime-agent)는 foreground 감지와 icon만 한다. (사람, 2026-10-26 / agent)
- **Codex icon은 OpenAI 매듭이다.** Codex desktop app과 같다. (사람, 2026-10-26)
- **새 harness의 coding session 칸(`prompt`, `mcp`, `model_flag`)은 채우지 않는다.** 그 길은 막혀 있다. (agent)
- **새 hook event가 빠진 설정은 사람에게 묻지 않고 고치지 않는다.** 지금의 설치 화면이 다시 놓으라고 보이는 길(dry_run `missing`)을 쓴다. (agent)
- **다시 붙는 화면은 raw 출력 재생이 아니라 파싱한 화면 하나다.** raw를 상한(5MiB·LF 10,000개·chunk 10,000개)까지 쌓아 재생하던 때는 history를 한 번 쓰고 아래 viewport만 고쳐 그리는 TUI(omp는 초당 30여 chunk)가 몇 분 만에 상한을 채워 처음 그린 history를 밀어냈고 다시 붙은 화면이 비었다. 다시 붙을 때 보내는 양도 raw 수 MB에서 화면 하나(omp 7분 뒤 54KB)로 줄었다. 버린 안: 상한을 키우거나 chunk를 합친다(omp가 초당 20KB쯤 내므로 몇 분 늦출 뿐이다). renderer가 project를 떠나도 xterm을 살려 둔다(창 reload와 다른 창에서 여전히 raw를 재생한다). 대가는 열린 터미널마다 headless 화면 하나만큼 terminal-host 메모리를 더 쓰는 것이다. (agent)
- **xterm을 창마다 유지하고 출력은 push한다.** tab을 떠날 때 xterm을 버리면 돌아올 때 snapshot을 다시 받아야 하고 보이는 동안 polling(40ms)을 돌렸다. 같은 project 창의 이동에서는 xterm·DOM·seq를 유지하고 처음 한 번 lease를 잡은 뒤 묶음으로 받는다. 출력 일부가 없다는 배너는 없앴다. (agent)
- **글자 폭은 graphemes(Unicode 15)가 아니라 Unicode 11이다.** OpenCode는 xterm이 grapheme mode(2027)를 모른다고 답하면 코드포인트 폭을 더하는데 그 값이 Unicode 11과 같다. VS16·ZWJ 이모지는 Claude Code(string-width)와 1칸 어긋날 수 있다. (agent)
- **OSC 52는 쓰기만, 사람이 mouse를 뗀 뒤 한 번만 받는다.** 출력은 인터넷에서 온 글일 수 있어 아무 때나 clipboard를 바꾸게 두지 않는다. 읽기에는 답하지 않는다. (agent)
- **`COLORTERM`은 물려받은 값도 덮는다.** 무엇을 그릴 수 있는지는 lophn 터미널이 안다. `TERM_PROGRAM`은 정하지 않았다(물려받은 값, 예: `ghostty`, 이 남는다). (agent)
- **터미널 진단 기록은 이벤트 이름·mode·개수만 남긴다.** 친 글과 출력 내용은 싣지 않는다. 처음에는 env 하나로만 켜고 설정 화면에 두지 않았으나 지금은 Settings의 `diagnostics.trace`이고 기본 꺼짐이다. 재현이 어려운 문제를 볼 때만 켠다. (agent)
- **파일 경로의 상대 기준은 shell 시작 폴더다.** 버린 안: OSC 7로 지금 폴더를 받는다(shell 시작 층을 고쳐야 한다). (agent)
- **[Run in terminal]은 bash·sh·zsh만, 한 줄만 바로 실행한다.** 버린 안: 여러 줄도 바로 실행(줄마다 실행되어 중간 실패를 못 본다). (사람)
- **터미널 첫 열기 안내는 숨기지 않고 지운다.** 복원한 터미널은 기다리지 않고 볼 때 연다. (사람, 2026-10-26)
- **Windows: 인증은 기존 64 hex key만 쓴다.** SID·DACL 검사는 더하지 않는다. 경로가 한도를 넘으면 기능을 끄고 로그 한 줄만 남기며 pointer file·TCP로 우회하지 않는다. hook 준비는 browser shim·listen 성공과 분리한다. PowerShell은 사람의 실행 정책을 우회하지 않는다. Windows foreground·signal·TUI toggle·GUI adapter 전체 대응은 아직 범위가 아니다. (agent)
- **resume 규칙은 확인한 것과 못 한 것이 섞여 있다.** 이 컴퓨터의 `--help`로 확인한 것(claude, codex, opencode, omp, kiro-cli, agy, grok, devin, hermes, cline)과 herdr의 표에서 가져와 실행해 보지 못한 것(copilot, droid, qwen, qoder, cursor, kimi, kilo, letta)이 있다. (agent)
- **터미널 탭의 shell에 session 표지 `LOPHN_SESSION_ID=term:<탭>`을 넣는다.** 앱(process 감시)이 TUI CLI와 그 아래 process를 session에 잇는 키이고, 앱이 보는 session 목록의 id와 같다. 터미널 env는 `LOPHN_*`를 지우므로(물려받은 값은 쓰지 않는다) PTY를 띄울 때 그 터미널의 id로 직접 넣는다. 버린 안: shell pid 아래 process tree만으로 잇기(GUI view가 띄운 CLI는 extension host의 자식이라 닿지 않는다). GUI view의 CLI에는 harness-gui가 같은 값을 실어 띄우고, 앱이 보는 목록의 GUI 탭 행은 handle의 상태로 채운다(`harness-gui.md`, `workspace-session.md`). (agent)
- **터미널에서 lophn을 부르는 code는 CLI 경로와 data root를 터미널을 가진 쪽에서 받는다.** 이것이 적혀 있지 않아 개발 앱 터미널의 `lophn gui`가 사람의 `~/.lophn` 앱으로 가 사람의 data root에 개발 판 schema가 적용될 뻔한 일이 있었다(mistakes 이슈). 그 뒤 `lophn gui` 명령은 없어졌고 `claude gui`는 그 탭의 hook socket에 한 줄만 쓴다(core도 앱도 띄우지 않는다). (agent)

- **폰에 가는 터미널 화면은 PTY 그대로이고 가리지 않는다(redaction 없음).** 사람이 컴퓨터에서 보는 화면 그대로가 이 기능의 뜻이다. 화면은 색과 칸 위치가 있는 줄이라 글을 알려진 secret으로 바꾸면 칸이 밀려 TUI가 깨져 보이고, 줄바꿈과 run 경계에 걸친 secret은 어차피 놓친다(막은 것처럼 보이는 가짜 안전이 된다). 폰은 사람이 pairing한 사람 자신의 기기이고 연결은 Noise로 암호화된다. 대가: 터미널에 secret이 찍혀 있으면 폰에도 보인다. 화면은 core 메모리에 최신 하나만 있고 Bus event에는 실리지 않는다(`seq`만 알린다). ACP 대화 사본(`harness-gui.md`)은 lophn의 다른 대화 길과 같은 규칙으로 redaction을 거치므로 이 결정은 터미널 화면에만 해당한다. 버린 안: 화면 글을 redactor로 거르기. (agent)
- **폰에서 터미널에 치는 것은 기기마다의 허락이고 초대 때 정하며 기본은 켬이다.** 터미널에 치는 것은 사람의 shell과 coding agent TUI에 직접 치는 것이라 폰이 사람으로서 컴퓨터에서 명령을 돌리는 길이다. 승인 card를 거치지 않는다(TUI의 승인 물음도 글자 하나로 답한다). 그래서 보는 것과 치는 것을 나누고, 치는 것은 사람이 컴퓨터 앞에서 정한다. 처음에는 기본 꺼짐이고 Settings에서 기기마다 켜야 했는데, 그러면 컴퓨터 앞에 없는 사람이 터미널로 도는 session에 아무것도 치지 못해 폰으로 일을 이어 갈 수 없었다. 그래서 초대장을 낼 때 같이 정하고(기본 켬, 문구가 "이 기기가 사용자로서 명령을 돌릴 수 있다"고 말한다) 허락은 기기 행에 두어 잃어버린 기기 하나만 끌 수 있다. 이미 pairing한 기기는 바꾸지 않는다. 버린 안: 입력 없이 보기만(폰에서 TUI의 물음에 답할 길이 없다), 모든 기기에 한꺼번에 켜는 하나의 설정, 기본 꺼짐(앞의 판). (사람)
- **폰은 먼저 React Native의 styled text row로 터미널을 그린다.** WebView terminal(xterm.js)은 그 길이 못 쓸 때만 더한다. 이유: native module이 없이 되고 새 dev build가 필요 없다. 대가: 폭 2칸 글자는 fallback 글꼴로 그려지므로 폰에서 한글과 emoji의 폭을 한 번씩 재서 간격을 맞춘다. (agent)
- **폰이 PTY 크기를 잡고 마지막에 잡은 쪽이 이긴다(Paseo와 같은 규칙). 폰이 떠나면 desktop 탭이 자기 크기로 돌아간다.** 이유: 컴퓨터 폭 그대로의 화면은 폰에서 글자가 너무 작거나 줄마다 가로로 밀어야 해 읽을 수 없었고, TUI는 그린 폭에 맞춘 화면이라 폰 폭으로 다시 흐르지 않는다. 사람이 컴퓨터에서 그 탭을 고르거나 누르면 바로 다시 잡는다. 대가: 폰이 보는 동안 컴퓨터의 그 터미널이 좁다. 버린 안: 폰은 크기를 바꾸지 않고 Fit width와 100%(가로 scroll)만 두기(앞의 판), raw byte와 폰의 xterm으로 그리기(지금 snapshot 구조를 버려야 한다). (사람이 방향, agent가 규칙)
- **화면 갱신은 화면 전체를 core에 두고 바뀐 것만 알린다.** 최신 화면이 옛 화면을 대신하므로 row diff와 replay, backpressure queue가 필요 없다. event 이름은 `<Entity><과거형 동사>` 규칙에 맞춰 `TerminalScreenChanged`다. (agent)

- 터미널 coding agent를 lifecycle의 terminal session으로 본다. 처음에는 상태가 shell main의 tracker에 있어 shell main이 집합 전체를 core에 알렸다(`coding_report`). tracker가 core로 오며 사본 없이 원본을 바로 쓴다. (agent)

## 열린 것

- 탭의 CLI 아래에서 뜬 다른 harness process(Bash tool이나 `!`로 돌린 `claude -p`, 녹화 script)는 `LPN_TERMINAL_HOOK`을 물려받아 hook을 같은 탭으로 보내고, tracker는 새 session id를 `/clear`·resume처럼 그 탭의 session으로 받아 recent가 사람이 연 적 없는 session으로 찬다. 그 session이 도는 동안 GUI toggle이 엉뚱한 session을 열 수 있다. 추천은 `lophn hook`이 가장 가까운 harness 조상의 pid를 싣고 core가 PTY foreground group이나 GUI가 띄운 CLI일 때만 받는 것이다(issues의 "탭 CLI 안에서 띄운 다른 harness session이 그 탭의 session과 recent에 들어간다").
- `ChildEnded`를 낼 길이 없는 harness(Codex 등)의 child는 상태에 반영되지 않는다.
- Claude Stop payload의 `background_tasks` 항목 꼴과 id 일치(`background_tasks`의 id가 `SubagentStart`·`SubagentStop`의 `agent_id`와 같다)는 Claude Code CLI 2.1.316 bundle을 읽어 정했다. 실제 payload로 확인하지 않았다. 실제 model을 부르는 일이라 사람의 허락을 기다린다.
- 폰의 터미널 입력은 보낼 때마다 새 key라, 답을 잃고 다시 보내면 같은 글이 두 번 쳐진다(이슈 `phone-terminal-input-retry-types-twice`).
- 끊기 key 판정이 남은 harness는 tool이 없는 turn(긴 생성)에서 입력 지우기로 내려간 상태를 되돌리지 못한다. hermes는 `on_session_end`의 `interrupted`를 읽는 코드가 있으나 실제로 오는지 확인하지 못해 key 판정을 남겼다.
- hook 설치 물음은 그 터미널의 탭을 가진 창만 답한다. 폰이나 agent가 연 터미널처럼 그 탭을 보이는 창이 없으면 아무도 묻지 않은 채 shell 연결이 닫힐 때 거절로 세고, 그 core 실행에서는 다시 묻지 않는다. Settings의 [Install hooks]로는 놓을 수 있다.
- 이미 hook을 놓은 사람은 새 event가 생긴 판에서 [Install hooks]를 다시 누르거나 처음 물을 때 허락해야 child 상태 같은 새 기능이 보인다.
- macOS는 node로 도는 CLI를 hook이 올 때까지 알아보지 못한다. Windows는 foreground·signal이 없다. PowerShell 7·5.1에서 hook·시작 층·`claude gui`·알림·`$BROWSER` 중계는 실기로 확인했다(저장소 root의 Windows checklist). macOS도 실기로 돌리지 않았다.
- 개발 core가 연 터미널에서 사람이 친 `lophn`(PATH 앞의 dev launcher)은 `LOPHN_HOME`이 없어 사람의 `~/.lophn`으로 간다. 터미널 env는 바깥 `LOPHN_*`를 지우고 core는 data root를 넣지 않는다. hook과 `<harness> gui`는 탭의 socket으로 가 걸리지 않는다. 추천은 개발 core가 터미널에 자기 data root를 넣는 것이다(이슈 `dev-terminal-cli-reaches-real-root`).
- 다시 붙은 탭(앱을 다시 켬, 폰이나 agent가 연 터미널)에서 지난 출력의 한 줄이 빠지고 prompt가 두 번 보일 수 있다. 탭 칸과 PTY 치수가 다를 때 snapshot을 쓰는 순서와 xterm reflow가 맞지 않는 것으로 보인다(이슈 `terminal-reattach-reflow-drops-line`). 새 출력은 맞다.
- macOS 설치본은 packaging이 node-pty의 `spawn-helper`에 실행 bit를 주지만 실기로 돌려 보지 않았다. 없으면 core가 터미널을 띄우지 못한다(`spawn_failed`).
- core가 SIGKILL되거나 crash하면 extension이 띄운 CLI(자기 process group)가 남는다(이슈 `extension-cli-outlives-core-crash`). PTY host는 stdin EOF로 끝난다.
- 공유 daemon을 쓰는 harness의 새 판이 server 옵션 이름을 바꾸면 시작 층이 `--help`로 flag를 못 찾아 붙이지 않고, 그 탭은 hook이 옛 env를 본다.
- scrollback 10,000줄을 넘어 빠진 줄은 `dropped_output`만 켜고 알리지 않는다. 열린 터미널마다 headless 화면 메모리를 더 쓴다.
