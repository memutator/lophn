# 0.7.0

## 정해진 때 run을 돌리거나 workflow를 시작하는 job

```yaml
modules: [packages/protocol, packages/core/jobs, packages/core/apps, packages/core/runs, packages/core/workflows, packages/core/agent-roles, packages/core/main, packages/sdk, packages/design, packages/shell/renderer, tools, tests]
checked: [tool-check, architecture-testing, architecture-eval, architecture-activation, architecture-agent-call, architecture-place-session, architecture-agent-definition, architecture-annotation, architecture-browser-tab, architecture-artifact, architecture-workspace-layout, architecture-ui-kit, architecture-appearance, architecture-kinds, tool-context-review, tool-worktree-prep, tool-e2e, tool-dev, tests-support, tool-package-linux, tool-models-snapshot, skill-ui-design, skill-wording, tool-wording]
```

- 전:
  - 정해진 때 저절로 도는 일이 없었다. run은 사람(CLI, 화면)이 그때그때 시켰고, workflow instance는 사람만 시작했다.
  - 앱 tool을 부르는 쪽은 사람, agent, 앱 셋이었다.
- 후:
  - core에 job과 scheduler가 있다(`packages/core/jobs`, 동작은 `project-docs/architecture/job.md`).
    - job은 주기(`every`: `Nm`·`Nh`·`Nd`, `at`: 하루 단위일 때 local 시각), 할 일 하나(agent 호출 run, 앱 tool 호출 run, project의 `kind: agent` workflow instance 시작), 놓친 차례 정책(`run`·`hold`), `title`이다. cron 문법은 받지 않는다.
    - lophn(tray 포함)이 켜져 있을 때만 돈다. 놓친 차례는 몇 번이든 한 번으로 치고 수를 기록에 남긴다. 앞 차례가 아직 돌면 건너뛰고 `skipped(overlap)`로 남긴다. 자동 재시도는 없다.
    - `hold` job의 놓친 차례는 대기 목록의 hold card로 사람에게 묻는다([Start now], [Skip]).
  - job tool `job.create`, `job.update`, `job.delete`, `job.list`를 lophn, Project Manager, App Engineer가 받는다. agent는 자기가 만든 job만 고치고 지운다. 사람은 화면에서 모든 job을 보고, 켜고 끄고, 제목·주기·정책을 고치고, 지운다. 사람은 job을 만들지 못한다.
  - route: `job.create`, `job.update`, `job.delete`, `job.list`, `job_run.list`, `job.holds`, `job.decide_hold`와 machine만 받는 `job.claim_due`, `job_run.open`, `job_run.started`, `job_run.ended`. 남지 않는 event `JobChanged`. id 접두사 `job`, `jbr`.
  - 앱 호출의 부르는 쪽에 `program`(`{kind: "program", job, job_run}`)이 생겼다. job run의 tool 호출은 job을 만든 agent의 지금 할당(unattended)과 그 agent의 tool 목록에 뜰 tool인가(공개 tool이거나 맡은 domain의 tool)로 판정하고, 막히면 invocation을 `denied`로 남긴다. SDK `AppToolCaller`와 앱 process의 caller 검사도 이 종류를 받는다.
  - run 기록에 `job` 칸, workflow instance의 `started_by`에 `{kind: "job", job}`이 생겼다. 화면은 job이 연 run 줄과 job이 시작한 instance 줄에 job 제목을 보인다.
  - 화면: Settings › System › Scheduled jobs(모든 job과 기록), project 창 activity bar의 Scheduled jobs panel(그 project와 걸린 job), 대기 목록의 hold card.

왜: 사람이 lophn agent에게 일을 시키는 길이 그때그때의 화면과 CLI뿐이라, 10일마다 폴더를 옮기거나 매주 workflow를 시작하는 일을 맡길 수 없었다(`project-docs/products/roadmap/headless-schedule.md`).

결정:
- 놓친 차례 정책은 job마다 둔다: `run`(켜지면 한 번)과 `hold`(사람에게 묻는다). (사람, 2026-10-20)
- 놓친 차례는 몇 번이든 한 번으로 치고, 앞 차례가 돌면 이번 차례를 건너뛴다. 꺼 둔 job을 다시 켜면 그때부터 새로 세고 놓친 것으로 치지 않는다. (agent, planner)
- program은 약하게 둔다. job은 workflow instance의 끝을 판정하지 않고 instance 상태만 읽는다. 끝나지 않은 instance가 이어지면 건너뛴 기록이 쌓이고 사람이 화면에서 본다. (사람, 2026-10-22)
- job이 부른 agent도 job tool을 받아 job을 만들 수 있다. 막지 않고, 고치기는 만든 agent만 하며, 사람은 모든 job을 화면에서 본다. (agent, planner)
- job 화면의 자리는 Settings › System이고, project 창 activity bar에도 그 project와 걸린 job만 보이는 panel을 둔다. hold card는 앱과 project를 짧은 id로 보인다. (사람, 2026-10-22)
- 서머타임: 없는 시각은 시계가 건너뛴 직후(02:30이 없으면 03:00), 두 번 오는 시각은 첫 번째 한 번만 돈다. `at` 없는 `Nd`는 고정 길이라 local 시각이 밀린다. (agent)
- `revision`·`compare`를 두지 않는다. job을 동시에 고치는 쪽이 사람 화면과 agent 정도라 마지막 쓰기가 이긴다. (agent)
- 앞 차례가 도는지는 `job_runs` 표 하나로 판정하고 다른 module의 표를 SQL로 읽지 않는다. 그래서 workflow를 시작한 job run은 scheduler가 바퀴마다 instance 상태를 읽어 닫는다. (agent)
- 앱 호출의 부르는 쪽을 "사람 caller + run id"로 얼버무리지 않고 `program`을 wire에 더했다. invocation 기록과 rewind 화면이 job이 한 호출을 가려 보인다. (agent)
- job tool 입력의 자유 JSON 칸은 `z.json()`이라 tool의 JSON Schema에 `$defs`/`$ref`가 처음 들어간다. 진짜 Anthropic으로 Project Manager tool 묶음을 보내 받아지는 것을 확인했다. OpenAI는 key가 없어 돌리지 못했다(adapter는 `strict`를 켜지 않는다). (agent)
