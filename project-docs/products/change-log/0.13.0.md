# 0.13.0

## activation이 실패한 이유가 agent에게 간다, 앱 source와 겹치는 경로 규칙을 지웠다

```yaml
modules: [packages/core/apps, packages/core/router, packages/protocol]
checked: []
```

- 전:
  - 앱 grant를 만들 때 앱 source를 감싸거나 그 안인 `fs.read`·`fs.write` 경로를 `forbidden("path covers an app source")`로 거절했다. 이 검사는 activation의 마지막 commit(`activation.complete`)에서만 돌아서, 선언 검사와 사람의 동의, 새 앱 준비 확인을 다 지난 뒤에 떨어졌다. `~/.lophn`을 읽겠다는 선언은 그 안에 앱 source가 있다는 이유로 늘 거절됐다.
  - complete가 거절되면 실패 기록은 `commit_rejected: the new release was not adopted`뿐이었다. 거절 message는 버려졌다.
  - 동의가 필요한 activation은 `release.activate`가 `waiting_consent`를 돌려주면 끝이었다. 동의 뒤의 결과는 아무도 agent에게 알리지 않았다. 사람은 동의를 눌러도 대화에서 아무 말도 듣지 못했다.
- 후:
  - source와 겹치는 경로 규칙을 지웠다. `~/.lophn`을 지키는 장치는 사람의 동의 화면뿐이다.
  - complete가 거절되면 summary에 거절 message를 붙인다(`the new release was not adopted: <message>`).
  - `release.activate`가 기다리지 않은 시도(동의 뒤, 2분 기다림 상한 뒤, 재시작 뒤 이어받음)가 active나 failed로 끝나면 driver가 새 machine command `activation.report`를 부른다. 이 command는 release를 만든 agent session(`created_by`)에 새 notice 종류 `activation_finished`로 결과를 넣는다. 실패면 code, summary, 이전 release가 다시 도는지가 들어간다. Router의 `RouteInput`이 `notice`를 싣는다.

왜: mahas 앱의 release 6·7이 사람이 동의한 뒤에도 매번 `commit_rejected`로 떨어졌는데, 사람도 agent도 이유를 들을 길이 없었다.

결정:
- 앱 source와 겹치는 경로 규칙은 지운다. 사람이 정했다. 막아야 하는 것은 앱 code 쓰기와 data root(`secrets.json`, 다른 앱 data)인데 이 규칙은 그것을 정확히 막지 못하고, source가 마침 안에 있는 경로만 막았다. data root를 지키는 규칙은 아직 없다.
- 결과는 release를 만든 session에 알린다. 동의 표에는 부른 session이 없고, release를 만든 session과 activate를 부른 session은 보통 같다. 버린 길: 동의 표에 session을 더하기(schema migration이 필요하다). (agent)

후속: 없음.

## 화면 색·단추 일관성: Ink는 무채색, danger는 채운 빨강, 글자 단추에 행동 아이콘, 단추 묶음은 오른쪽

```yaml
modules: [packages/design, packages/shell/renderer, tools]
checked: []
```

- 전:
  - 기본 accent Ink에서 primary 단추는 검정·흰색인데 focus 테두리·고른 탭 강조선·selection·내 말 bubble은 파랑이라 primary 색이 둘로 보였다. 몇몇 강조선과 marker(tab strip, sidebar, tree, 진행 띠)는 `--color-text-*`나 `--color-focus`를 써서 accent를 바꿔도 따라오지 않았다.
  - `Button`의 `danger`는 빨간 글자 테두리 단추였다. 승인 카드의 Deny도 danger였고, 지우기 확인 중 몇은 primary였다.
  - 글자 단추 176개 중 142개가 아이콘이 없었다. 저장·취소 순서와 묶음 위치가 화면마다 달랐다(Save가 왼쪽, Settings 줄 단추가 칸 왼쪽).
- 후:
  - Ink preset의 `color.focus`·`color.selection`·`color.ink.soft`가 회색이다. 다른 accent는 그대로다. 주 행동·고른 것·켜진 것의 표시는 모두 `--color-ink-background`, `--color-focus`는 focus ring·입력칸 focus 테두리·drop 자리에만 쓴다.
  - 새 token `color.danger`(background·text·hover). `danger` 단추는 채운 빨강에 흰 글자다. 되돌릴 수 없는 일을 실제로 하는 단추(지우기 확인, Rewind, 연결 끊기, 값 지우기)에만 쓰고, Deny·Skip은 secondary다.
  - renderer `icons/action.ts`의 `actionIcons`로 같은 동사에 같은 아이콘을 붙인다. Cancel·Close 같은 닫기 단추만 글자뿐이다. `retryIcon`(chrome)을 지우고 `actionIcons.retry`로 합쳤다.
  - 단추 묶음은 오른쪽 끝, 닫기가 먼저고 주 단추가 오른쪽 끝이다.

왜: 사람이 Ink에서 파란 강조를 보고 accent가 blue라고 알았다. 색 역할과 단추 모양이 화면마다 달라 일관성이 떨어졌다.

결정:
- Ink에서는 focus도 무채색이다. 버린 길: focus만 파랑으로 남기기(화면에 accent가 둘로 남는다). (사람)
- bookmark 줄의 Remove는 바로 지우지만 secondary(휴지통 아이콘)다. 줄마다 채운 빨강이 서면 과하다. (agent)
- 탭 줄 resizer·칸 divider·drop 표시는 끌기 신호라 `--color-focus`로 둔다. (agent)
- 켠 토글(`aria-pressed`)은 `Button`·`IconButton`이 variant와 상관없이 selection 바탕에 accent 테두리로 그린다. effort 고르기와 도구 막대 토글이 같은 모양이다. (agent)
- design `Toast`의 action이 `icon`을 받는다. 파일 충돌 toast(Compare·Use disk·Keep mine)와 domain Undo에 붙였다. 앱이 준 label에는 붙이지 않는다. (agent)
- Workflow Stop은 instance를 `stopped`로 닫아 되돌릴 수 없으므로 danger다. (agent)
- `actionIcons.rewind`는 기록을 그 시점으로 되돌리기(History), `actionIcons.reset`은 기본값으로 되돌리기·Undo(Undo2)다. (agent)

후속: 없음.
