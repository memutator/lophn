# problems

## 왜
앱이 조용히 깨지거나 agent의 “고쳤다”는 말만 남으면 사람은 같은 문제를 다시 설명하고 직접 확인해야 한다.
발생 당시의 증거와 수리의 근거를 이어 두어, 고치는 동안 사람이 덜 끼어들게 한다.

## 무엇을 약속하나

- **[I1]** 앱이 깨지면 내가 알기 전에 lophn이 먼저 모은다.
- **[I2]** 나도 [문제 알리기]로 알릴 수 있고, 그때의 증거가 안전하게 남는다.
- **[I3]** 같은 문제는 하나로 묶이고, 원인 가설과 담당이 보인다.
- **[I4]** "고쳤다"는 주장과 실제 테스트 결과를 구별해 남긴다.
- **[I5]** 문제는 고침이 확인됐거나 내가 확인했을 때만 닫히고, 다시 생기면 다시 열린다.
- **[I6]** 보고 경로가 빠진 앱은 release되지 않는다.
- **[I7]** 같은 보고가 쏟아져도 묶이고 사라지지 않는다.

## 하지 않는 것
- agent나 앱의 완료 주장, 조용한 기간, 보고 경로 삭제만으로 문제를 닫지 않는다.
- 비슷한 보고를 같은 원인의 증명으로 삼지 않는다.
- 진단과 테스트를 핑계로 secret·운영 데이터·사람 파일의 접근을 넓히지 않는다.

## 잘되고 있다는 신호
- 내가 알아채기 전에 앱의 이상과 당시 증거가 남는다.
- 다음 수리에서 지난 시도와 실제 테스트를 다시 설명하지 않아도 된다.
- “고쳤다”와 “확인했다”가 다르게 보이고, 재발해도 지난 근거를 잃지 않는다.
