# lophn 0.7.0

This release adds scheduled jobs, which run an agent task or start a workflow on a timer while lophn is open. It also fixes several smaller bugs.

## New
- Scheduled jobs. Ask lophn, Project Manager, or App Engineer to create one. A job can run an agent, call an app tool, or start a workflow, every N minutes, hours, or days, or at a set local time each day.
- Jobs run only while lophn is open, including when it is in the tray. A missed run counts once, however many were missed. A run is skipped and recorded as skipped if the previous run of that job is still going. Jobs are not retried automatically.
- Each job has a missed-run setting. "Run once" runs the job once when lophn is back. "Hold" waits for you: a Hold card in the waiting list offers Start now and Skip.
- Settings › System › Scheduled jobs lists all jobs and their run history. The project window's activity bar has a Scheduled jobs panel for the jobs that involve that project.
- On screen you can turn a job on or off, change its title, schedule, and missed-run setting, and delete it. You cannot create a job on screen; ask an agent to do it.
- Agents can change or delete only the jobs they created. App tool calls made by a job are checked against the creating agent's current assignment, and blocked calls show as denied.
- Run history and workflow instances show the job that started them.

## Changed
- The attach (+) button in the chat input is removed. It did nothing.

## Fixed
- A Hold job that came due while the computer was asleep now asks before it runs. Before, it ran without asking.
- After the computer wakes, due jobs run within about a minute. Before, they could wait up to an hour.
- A job run whose end could not be recorded stayed "running" until the next launch, which skipped all of that job's later runs. It now closes on a later check.
- An MCP server turned off during a session can no longer be called by the agent. Before, a turn already running could keep calling its tools.
- When you reject a shell command and give a reason, the agent now receives your reason. Before, it only received "the person rejected this tool call".
- When app release preparation fails because an app's handlers do not match its tools, the message names the tools that differ.
- Packages added to an app's configuration now resolve when the app's check and test run.
- A URL opened from a terminal in another workspace now opens as a browser tab in that workspace, and the view switches to it. Before, it opened in the system browser.
- In the graph diagram, a loop-back edge that spans more than one step no longer runs behind the steps in between.
