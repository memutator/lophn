# 0.15.0

## declaration check가 옛 SDK가 깔린 node_modules를 원인으로 짚는다

```yaml
modules: [packages/core/apps]
checked: []
```

- 전: `declaration.check`는 앱 source의 `node_modules`나 `.lophn/sdk`가 아예 없을 때만 `npm install`을 안내했다. source의 `package.json`이 agent 밖(git, coding agent)에서 새 SDK 판으로 바뀌고 `node_modules`가 옛 판을 가리키면, 맞는 `lophn.ts`가 `declaration unknown field operations` 같은 선언 오류로 보였다. command-surface 전환 때 Mahas의 lophn agent가 이 오류를 보고 release를 포기했다. release 준비는 HEAD의 `package.json`으로 새로 깔아서 됐을 것이다.
- 후: `declaration.check`는 평가 전에 `package.json`의 `file:.lophn/sdk/...` 의존마다 `node_modules`가 실제로 가리키는 곳을 대고, 다르면 무엇이 무엇을 원하고 무엇이 깔렸는지와 `npm install`을 돌려준다. 없을 때의 안내도 이것으로 합쳤다.

왜: 검사는 source의 `node_modules`로, release 준비는 HEAD로 돈다. 둘이 어긋난 것을 agent가 볼 길이 없어 선언 오류로 읽었다.

결정:
- 자동 `npm install`이나 staging 평가 대신 어긋남을 짚는 오류만 낸다. 가장 단순하고 agent가 바로 고칠 수 있다. (사람)

## 앱이 skill을 내놓고 할당으로 다른 agent에게 준다

```yaml
modules: [packages/core/approvals, packages/core/apps, packages/core/lophn-agent, packages/core/agent-places, packages/core/main, packages/protocol, packages/coding-agent, packages/cli, packages/shell/main, packages/shell/renderer, packages/sdk]
checked: []
```

- 전:
  - 앱이 내놓은 command를 다른 agent가 알 길이 없었다. lophn agent의 place 정보에는 자기 domain의 command만 실렸고 coding agent에게는 아무 길이 없었다.
  - 할당(agent가 쓸 앱과 뺀 command)은 ledger 표 `agent_assignments`라 손으로 보거나 고칠 수 없었다.
  - 지침 파일은 `LOPHN.md`뿐이었다. skill은 내장, 등록 폴더, `~/.lophn/skills`, domain 폴더에서만 발견했고 frontmatter는 줄 단위로 읽어 `description: >` 같은 YAML 꼴은 말없이 빠졌다. agent 정의 `skills`는 받을 이름 목록이라 한 place의 편집 화면이 다른 place의 skill을 빼 버렸다.
- 후:
  - 앱이 내놓기: 선언에 `skills: [{name, public, commands}]`가 생겼다(`@lophn/declaration`, `@lophn/app-ui` 2.1.0. 이미 있는 앱은 2.0.0 그대로 돈다). skill 본문은 앱 source의 commit 파일 `.lophn/skills/<name>/SKILL.md`이고 template `.gitignore`는 `.lophn/sdk/`만 뺀다. release 준비는 선언한 skill 폴더가 commit에 있는지 보고, 공개 skill을 지우는 release는 막지 않고 `removed_public_skills`에 skill과 받던 domain을 싣는다.
  - 받기: 앱을 할당받은 agent는 그 앱 active release의 public skill도 받는다. core read `app.skills`가 bundle에서 읽고, 목록, `skill.read`, `/` 메뉴, Agents 탭 개수가 같은 규칙을 쓴다. 층은 내장 < 공유 < 전역 < project·app < domain이고, 공유받은 skill은 `skills_off`로 끈다. 공유받은 skill을 적는 칸은 따로 없다.
  - 청하기와 승인: 앱 place의 agent가 `lophn app share --agent <이름>... [--coding-agents] --reason <글>`로 요청을 연다. 앱마다 열린 요청 하나가 `share_requests` 표에 남고(turn이 끝나도 남는다), 사람이 대기 목록에서 승인하면 받을 agent의 정의 `apps`에 앱 slug가 들어간다. coding agent를 골랐으면 commit 뒤 설정 `coding-agent.shared_apps`에도 더한다. 거절하면 아무것도 바뀌지 않는다.
  - coding agent: `lophn harness sync-skills`가 `shared_apps`의 public skill을 hook이 놓인 harness의 skill 폴더(Claude Code `.claude/skills`, Codex·pi `.agents/skills`, OpenCode `.config/opencode/skills`)에 복사한다. 폴더마다 `.lophn-shared` 표시를 두고 표시가 있는 것만 덮고 지운다. shell main이 core 준비, activation, 그 설정이 바뀔 때, hook 설치·삭제 뒤에 부른다. `harness uninstall`은 lophn이 쓴 사본도 지운다.
  - 할당 저장: agent 정의 파일의 `apps`(앱 slug)와 `permissions.deny`(`lophn(<domain> <command>)`)로 옮겼다. `assignment.get/set`은 그대로이고 `revision`은 `{apps, deny}`의 hash다. 두 칸은 `mcp_servers`, `skip`처럼 사람만 쓴다(`agent.create`·`agent.update`가 `forbidden`). 옛 표의 schema step은 남고 새 data root에는 빈 표가 남는다. 이미 쓰던 data root는 data step `agents.skills-off`와 `approvals.assignment-file`이 이 순서로 옮긴다.
  - 지침과 skill 자리: 전역과 project 지침은 `LOPHN.md`가 없으면 `CLAUDE.md`를 읽는다(`AGENTS.md`는 읽지 않는다). project 첫 폴더와 앱 source의 `.lophn/skills`가 skill 발견 자리에 더해졌고, `SKILL.md` frontmatter는 YAML로 읽는다(YAML이 못 읽는 옛 머리만 줄 단위로 읽는다). agent 정의 `skills`는 `skills_off`(끈 이름)로 바뀌었다.
  - 지침: 내장 skill `design-app`과 앱 template `AGENTS.md`가 새 기능마다 "다른 agent에게 쓸모 있나, 누구에게"를 묻고, 쓸모 있으면 skill과 `lophn app share`로 제안하라고 한다.

왜: 앱이 만든 기능은 사람이 아는 다른 agent(lophn agent, 터미널의 coding agent)가 쓸 때 가장 값지다. 그런데 부를 수 있게 하는 할당과 알게 하는 skill이 따로 놀면 둘이 어긋난다. 할당을 사람이 읽고 고치는 파일로 옮기면서 한 번의 승인으로 부르기와 알기가 같이 가게 했다.

결정:
- 앱 skill 공유는 할당에 붙인다. 앱을 할당받은 agent가 그 앱의 public skill도 받고, 공유 skill을 적는 칸을 agent 정의에 따로 두지 않는다. 따로 두면 아는 것과 부를 수 있는 것이 두 칸으로 갈라져 어긋난다. (사람)
- 공유 skill의 원본은 domain 폴더가 아니라 앱 source `.lophn/skills`이고 release와 같이 봉한다. CLI를 바꾸는 commit에 skill이 같이 들어간다. (agent)
- 지침 파일은 `LOPHN.md`, 없으면 `CLAUDE.md`다. `AGENTS.md`는 읽지 않고 `LOPHN.md`를 옮기는 migration도 없다. lophn은 본질적으로 coding agent가 아니다. 앱 지침 층은 만들지 않는다(앱 agent는 지침이 시켜 `AGENTS.md`를 file tool로 읽는다). (사람, agent)
- project 설정과 skill은 project 폴더의 `.lophn/`에 둔다. 공용 자리 `.agents/skills`, `~/.agents/skills`는 읽지 않는다. 이 계획에서 project `skills_off`는 지금 자리(`extensions.json`)에 둔다. (사람, agent)
- lophn agent는 bundle을 참조하고 coding agent에게만 사본을 둔다. 사본은 동기화가 틀릴 길만 늘리고, coding agent는 자기 skill 폴더만 읽는다. core는 data root 밖을 쓰지 않으므로 `lophn harness` 쪽 코드가 core에서 읽어 쓰고 shell main이 부른다. session 시작 hook은 core를 부르지 않아 쓰지 않는다. lophn이 쓴 사본에는 표시 file을 두고 그것만 덮고 지운다. (agent)
- 할당 route(`assignment.get/set`), Grants 탭, `assignmentGet`을 부르는 곳은 그대로 두고 저장만 옮긴다. ledger를 바로 읽던 동기 reader(앱 호출 gate, 사용 관계, 판정)는 `AgentDirectory`를 거친다. (agent)
- 할당에서 뺀 command는 `permissions.deny`에 `lophn(<domain> <command>)`로 적는다(`<command>`는 argv 낱말). 다른 규칙은 이 변경에서 쓰지 않는다. `apps`는 앱 slug 목록이다. slug는 앱을 만들 때 정해지고 바뀌지 않는다. (agent)
- 공유 요청은 앱마다 열린 요청 하나이고 사람만 결정한다. 승인이 agent 정의 `apps`를 쓰는 길은 사람의 할당 쓰기와 같다. agent가 할당을 직접 쓰는 길은 없다. (사람, agent)
- `agent_assignments` 옮김과 `skills` → `skills_off` 옮김은 둘 다 data step이고 `skills-off`가 먼저 돈다. 옛 표의 schema step은 이미 적용한 ledger가 id를 기록하고 있어 지우지 않고, 새 data root에는 빈 표가 남는다. `skills_off`는 옮길 때 발견되는 후보 가운데 `skills`에 없던 것을 적어 받는 skill이 같게 한다. (agent)
- `@lophn/declaration`은 `skills` 칸이 생겨 2.1.0으로, 그것에 기대는 `@lophn/app-ui`도 2.1.0으로 올렸다. `skills`는 없어도 되는 칸이라 이미 있는 앱은 2.0.0 그대로 돈다. (agent)
