# 0.23.0

## 판을 올린 뒤 터미널 탭이 사용자 rc를 읽는다

```yaml
modules: [packages/core, packages/shell/terminal-host]
checked: []
```

- 전: 판이 바뀌어 shell이 옛 core를 멈추면, 옛 app supervisor가 정지하며 공통 socket 폴더를 통째로 지웠다. 그 안의 새 shell `shell-<pid>/`(shell-init, hook·bridge socket)도 같이 사라져 bash 탭이 `--init-file`로 없는 file을 받고 `~/.profile`·`~/.bashrc`를 하나도 읽지 않았다(PATH, nvm, 색, `claude gui` 함수가 빠짐).
- 후: supervisor는 정지할 때 아무것도 지우지 않는다(낡은 앱 socket은 새 자식 전에 지운다). 터미널 host는 bash·zsh init file이 없으면 시작 층 없이 원래 login shell로 띄운다.

- 후: `BUILTIN_SKILLS`에 `publish-package`(app, 끌 수 없음, menu 아님)를 선언했다. 앱 workspace의 agent가 읽는다.

## pin한 tray popup이 workspace를 옮겨도 다시 그려지지 않는다

```yaml
modules: [packages/shell/renderer]
checked: []
```

- 전: workspace를 옮기면 Tray가 새로 mount되며 pin한 popup을 다시 열었다. popup이 잠깐 사라졌다 나타나고 앱 화면이 다시 load됐다.
- 후: 열린 popup은 창 하나의 store에 있고 workspace 밖 layer가 그린다. pin한 popup은 그대로 떠 있고 앱 화면도 그대로다. 앱 화면이 받은 workspace는 연 때 것이다.

## 떠 있는 탭이면 무엇이든 모든 workspace의 전역 float이 된다

```yaml
modules: [packages/core/main, packages/shell/main, packages/shell/renderer]
checked: []
```

- 전: 전역 float(workspace를 바꿔도 남는 떠 있는 패널)은 앱 panel 화면만 됐다. float bar의 globe 단추도 앱 panel float에만 있었다. 저장 파일 `shell/global-floats.json`은 `{ schema_version: 1, floats: [{ app, screen, rect, minimized, pinned? }] }`였다.
- 후: noDetach가 아니고 layout에 저장할 수 있는 탭(터미널, browser, Agent, 파일, artifact, 앱 panel 등)의 desk float은 모두 globe 단추로 전역 float이 되고, 전역 float은 "이 desk로"로 돌아온다. 전역 float은 탭이 나온 workspace를 지니고 그 workspace의 통로로 그려진다(터미널은 cwd와 PTY, Agent는 그 workspace의 agent). workspace를 바꿔도 다시 mount되지 않는다. 옮기는 순간 webview는 한 번 다시 load된다. 이동은 kind의 `transfer`/`receive`를 같은 창 안에서 직접 부른다. 저장은 `{ schema_version: 2, floats: [{ workspace, tab(kind의 toStored 값), rect, minimized, pinned? }] }`이고 재시작 때 `fromStored`로 되살린다(터미널은 layout 복원과 같다). 모르는 kind·틀린 탭은 그 float만 빠진다. 앱이 지워지면 그 앱의 화면 float과 그 앱 workspace에서 온 float이 닫힌다.
- 돌아오는 자리: `anyWorkspace`인 kind(앱 panel, browser, 파일)는 어느 workspace의 desk로도 돌아온다. 터미널·Agent·artifact·search·workflow는 나온 workspace의 desk로만 돌아온다(그 단추는 다른 workspace에서는 없다). browser의 native popup은 전역 float이 되지 않는다(`noGlobal`). 앱 panel은 전과 같다(workspace를 주지 않고, 같은 앱·화면은 float 하나).
- 마이그레이션: core의 data step `shell.global-floats-tabs`가 판 1 파일을 앱 panel 탭(workspace Home)의 판 2로 옮긴다.

왜: 터미널이나 browser 같은 탭도 workspace를 오가며 계속 보고 싶다.

결정:
- 전역 float은 탭이 나온 workspace의 host로 그린다. 버린 길: workspace 없이 그린다. 터미널의 cwd, Agent의 workspace, 파일의 folder가 그 workspace의 것이라 뜻이 없다. (agent)
- 전역 float 본문이 여는 탭(파일 링크, popup)은 같은 workspace의 새 전역 float이 된다. 버린 길: 지금 창의 desk에 연다. 다른 workspace의 창이면 탭이 그 창에서 렌더되지 않을 수 있다. (agent)
- 전역 float의 제목 줄은 본문의 slice 없이 아이콘과 점을 읽는다. 그래서 Agent의 profile 아이콘과 상태 점은 없다. (agent)

후속: 개발 data(`.dev-data`)의 `shell/global-floats.json`은 다음 기동에 data step이 옮긴다. 터미널을 전역 float으로 올리면 그 project layout에서 빠져, 다른 workspace sidebar가 layout만 보고 아는 coding agent 터미널 표시(`harness`)는 그 동안 보이지 않는다.

## 설치한 앱에서도 log가 남고, trace 토글과 agent loop span이 생겼다

```yaml
modules: [packages/base, packages/core/diagnostics, packages/core/config, packages/core/main, packages/core/lophn-agent, packages/protocol, packages/shell/main, packages/shell/ipc, packages/shell/renderer, packages/design, tools]
checked: []
```

- 전: core의 구조화 log는 stderr로만 나갔다. 설치한 앱은 core를 띄울 때 stderr를 버려서(`stdio: ignore`) 모든 core log(`api handler_threw`, `config_ignored`, agent runtime의 `child_stderr` …)가 사라졌고 `npm run dev`에서만 보였다. agent loop(turn, model call, tool call)에는 span이 없었다. 터미널 trace는 `LOPHN_TERMINAL_TRACE=1`로 띄워야 했고 file 크기에 한도가 없었다. `LOPHN_TELEMETRY`는 `off|console|otlp`였다.
- 후:
  - core log가 늘 `<data root>/logs/core-{0..4}.jsonl`(10 MiB x 5, 0600)에 JSON 한 줄씩 남는다. info부터이고 stderr 출력은 그대로다. 쓰기는 비동기 queue(1 MiB)이고 넘치면 버리고 `log records_dropped` 한 줄로 개수를 남긴다. 알려진 secret 원문도 이제 log에서 지운다(전에는 `useRedactor`를 아무도 부르지 않아 pattern·key 이름 규칙만 적용됐다).
  - agent runtime child는 JSON log를 stderr로 내고(debug와 span 줄까지 늘), core가 줄마다 받아 record 모양이면 시각·service·trace id를 두고 글과 fields만 redaction해 같은 file에 싣는다. 모양이 아닌 줄은 `agent-runtime child_stderr`로 싣는다.
  - 새 설정 `diagnostics.trace`(boolean, 기본 `false`)와 Settings › Diagnostics의 Trace 토글. 켜면 core와 child의 debug log와 span 줄(span 하나가 한 줄, `component=trace`)이 core log file에 남고, shell main이 터미널 trace(`logs/terminal-trace.jsonl`)를 쓴다. 앱을 다시 띄우지 않고 바로 적용된다. 이벤트 이름·id·시간·크기만 싣고 친 글, 터미널 출력, prompt, model 답은 싣지 않는다.
  - agent loop span: `agent.turn`(turn마다 새 trace) 아래에 `agent.model_call`(시도마다, provider로 나가는 HTTP span이 그 아래)과 `agent.tool_call`(tool 호출마다). attribute는 `lophn.session`·`lophn.turn`·`lophn.model_call`·`lophn.tool_call` id, provider·model 이름, 종류, outcome, token 수, tool 이름뿐이라 log 한 줄을 ledger의 `model_calls`·tool call 행과 이어 읽을 수 있다. 자세한 것은 `architecture/observability.md`.
  - `LOPHN_TELEMETRY`는 `off|otlp`다. `console`을 없앴다(trace 토글이 대신한다). `otlp`인데 endpoint가 틀리면 `console`이 아니라 `off`로 내린다(warn 한 줄 그대로). `LOPHN_TERMINAL_TRACE`는 없어졌다.
  - 터미널 trace file은 10 MiB를 넘기 전에 `terminal-trace.1.jsonl`로 넘겨 둘만 남긴다.
- 저장 모양: 새 설정 key `diagnostics.trace`(기본값이 있어 옮길 것 없음). 새 file `logs/core-N.jsonl`. IPC `shell:terminal-trace`의 응답 false의 뜻은 같고 renderer가 5초 뒤 다시 묻는다.

옮기기: 없음(기본값이 있다).

왜: 설치한 앱에서 사람이 쓰다 겪는 문제를 나중에 볼 수 있어야 한다. 서버도 실사용자도 없는 프로토타입이라 내보내기·업로드 없이 file에 남기는 데까지만 한다.

결정:
- 늘 기록(info부터)과 trace(debug·span)를 나눈다. info 이상은 양이 적어 늘 남기고, 양이 많은 debug·span은 사람이 켠 동안만 남긴다. 버린 길: 시작 env로 켜기(설치한 앱은 env를 줄 수 없고 껐다 켜야 한다). (agent)
- child는 늘 debug·span을 stderr로 내고 core가 trace 설정으로 거른다. child에 설정을 따로 알리는 길이 없어도 바로 적용된다. 버린 길: child에 설정 변경을 보내기. (agent)
- shell main은 trace 설정을 SettingsChanged로 미리 읽지 않고 처음 쓸 때 읽고 알림이 오면 다시 읽는다. core가 아직 안 떠도 시작 순서를 따지지 않는다. (agent)
- 내보내기, 폴더 열기 단추, OTLP 변경(`console` 제거만)은 하지 않았다. (사람)

후속: 없음. 설치한 앱에서 log file이 실제로 생기는지는 packaged 앱으로 아직 보지 않았다.

## 도는 turn이 대화 화면에서 끝난 것으로 보이던 것을 고친다

```yaml
modules: [packages/core/main]
checked: []
```

- 전: ACP snapshot이 지금 turn을 `state_seq`가 가장 큰 turn으로 골랐다. 새 turn은 ledger head를 `state_seq`로 받고 turn 시작·끝은 ledger event가 아니라서, 앞 turn이 끝난 뒤 event 없이 새 turn이 시작되면 두 turn의 값이 같았고 먼저 읽힌 끝난 turn이 뽑혔다. 그동안 화면은 turn이 끝난 것으로 보아 Working 표시와 멈춤 단추가 없고 Esc도 멈추지 않았다.
- 후: 도는 turn이 있으면 그것이, 없으면 가장 늦게 시작한 turn이 지금 turn이다.

## agent가 artifact를 탭으로 열어 보고 다룬다

```yaml
modules: [packages/protocol, packages/core/host-queue, packages/core/main, packages/core/agent-workspaces, packages/cli, packages/shell/main, packages/shell/renderer]
checked: []
```

- 전: agent는 artifact를 file로 쓰고 path를 말할 뿐 화면을 볼 길이 없었다. 앱은 `lophn preview start` 뒤 `lophn browser snapshot|screenshot|act`로 preview 탭을 보고 다뤘지만 artifact 탭은 core의 탭 표에 없어 `browser *`가 닿지 않았다.
- 후: `lophn tab open --artifact <name>`이 자기 workspace(project·앱, 사람 token은 `--workspace`나 `LOPHN_WORKSPACE`)의 artifact를 host 탭으로 연다. home이면 `invalid_input`, 입구 `index.html`이 없으면 `not_found`이고 artifact마다 탭은 하나다. 그 탭에 `lophn browser snapshot|screenshot|act|evaluate|logs|wait`가 preview 탭처럼 닿고(navigate는 `invalid_input`) 탭 머리에 [Take control]이 선다. 내장 skill `write-artifact`에 "Check it on screen" 절을 더했다.
