## 앱 sidebar panel과 tray는 선언하면 나오고 사람이 끈다

```yaml
modules: [packages/core, packages/shell/renderer, tools]
checked: []
```

- 전: 설정 `shell.sidebar_panels`·`shell.tray`(`{app, screen}[]`)가 "켠 것"이었다. 앱이 `sidebar`·`tray` 자리 화면을 선언해도 사람이 Settings › Quick launch에서 Switch를 켜야 panel과 tray 항목이 나왔다.
- 후:
  - 설치된(보관하지 않은) 앱의 `sidebar` 자리 화면은 모든 workspace 종류의 오른쪽 sidebar에, `tray` 자리 화면은 tray에 선언하는 즉시 나온다.
  - 설정은 `shell.sidebar_panels_off`·`shell.tray_off`(같은 `{app, screen}[]`, 최대 20, 기본 `[]`)로 바뀌어 "끈 것"만 쌓는다. Settings의 Switch는 목록에 없으면 켜짐이고, 끄면 목록에 더하고 켜면 뺀다. 그룹 제목은 그대로이고 도움말만 "기본으로 나온다"로 바꿨다.
  - tray는 보일 항목이 하나도 없으면 아무것도 그리지 않는다(값도 읽지 않는다).

옮기기: data step `settings.places-default-on`(core `setting-declarations` wiring)이 `<root>/settings.json`의 옛 `shell.sidebar_panels`·`shell.tray`를 지운다. 켠 것이 이제 기본이라 잃는 것이 없고, 모르는 key 하나가 settings 전체를 거절시키므로 지워야 한다. 사람이 이미 켠 panel·tray는 그대로 나오고, 끄고 싶은 것은 다시 꺼야 한다. 다시 돌아도 같다.

왜: 앱이 자리를 선언했는데 사람이 따로 켜야 보이면 앱이 낸 sidebar 화면과 tray 값을 처음 쓰는 사람이 찾지 못한다(사람, 2026-11-07).

결정:
- 켜는 쪽(opt-in)이 아니라 끄는 쪽(opt-out)을 저장한다. 새로 설치한 앱이 목록 갱신 없이 바로 나온다. (사람)
- 옛 켠 목록을 "끈 목록의 보수"로 옮기지 않고 지운다. 설치된 앱 전체를 알 수 없는 data step에서 보수를 만들 수 없다. (agent)

후속: 없음.

## sidebar panel과 tray 화면이 열리지 않던 것을 고친다

```yaml
modules: [packages/shell/renderer]
checked: []
```

- 전: 앱의 `sidebar`·`tray` 화면이 오른쪽 sidebar와 tray popup에서 "Couldn't load …"로 열리지 않았다. 같은 앱의 `tab`·`panel` 화면은 열렸다. 또 창이 앱 화면 목록을 mount 때 한 번만 읽어서, core가 준비되기 전에 읽다 실패하거나 앱의 새 판이 활성이 되면 sidebar·tray·빠른 실행의 앱 목록이 창을 다시 열 때까지 낡았다.
- 후:
  - sidebar·tray가 화면을 앱의 활성 판에 고정해서 연다. 앱 화면 목록 read가 `release`를 같이 싣는다. 원인은 renderer가 `release` 없이 live view를 열어 main의 `checkOpen`이 `invalid_input`으로 거절한 것이다.
  - 화면 목록은 core가 (다시) ready가 될 때와 `AppViewChanged`(activation)가 올 때 다시 읽는다.

옮기기: 없음.

왜: 선언하면 나오게 한 sidebar·tray가 실제로는 빈 오류 화면이었다(사람이 설치본에서 봄, 2026-11-07).

결정:
- main이 판 없는 live open을 받아 활성 판으로 열게 하지 않고 renderer가 판을 준다. open 입력은 이미 판 고정이 규칙이고, 목록을 읽을 때 판을 함께 얻으므로 가장 작다. (agent)

후속: 설치본에서 tray·sidebar view가 만들어졌다가 닫힌다는 로그와 이 원인이 같은지는 확인하지 못했다(여기서는 view가 만들어지기 전에 거절된다).

## 앱의 `useTabHead` 머리 줄이 lophn이 감싸는 모든 프레임에 그려진다

```yaml
modules: [packages/shell/renderer, packages/sdk, packages/core, tools]
checked: []
```

- 전: 앱 화면이 `useTabHead`로 올린 머리 줄(경로, 탭, 상태 글, 단추, ⋯ 메뉴)은 앱 화면 탭과 dock한 앱 panel 탭에서만 그려졌다. tray popup, 앱 sidebar panel, float, 세션 카드에서는 `useTabHead`가 false를 돌려줘 앱마다 자기 머리 줄을 따로 그렸다.
- 후:
  - tray popup(제목과 pin 사이), 앱 sidebar panel(머리 줄의 단추 자리), 앱 panel float(desk float과 전역 float의 bar, 제목과 pin·minimize·dock·close 사이), 세션 앱 카드(크롬 줄 끝)도 같은 `CardHeadSpec`을 `HeadControls`로 그리고 단추·메뉴 누름을 같은 event로 앱에 돌려준다. 이 자리들에서 `useTabHead`는 true다. ← →(`nav`)는 탭에만 있다. 앱 전용 창과 detached 창만 머리 줄이 없다.
  - `@lophn/app-ui` 2.6.0(minor, API 변화 없음). `useTabHead` guide, `design-app` skill, 앱 template `AGENTS.md`가 "자기 머리 줄을 그리지 않는다. 상태 글과 주 행동은 `useTabHead`로"로 바뀌었다. `migrate-sdk/app-ui-2.6.0.md`가 지침 diff(`## Instruction diff`)와 옮기는 법을 싣는다. 이 diff를 싣는 것이 이제 지침이 바뀌는 판의 메모 규칙이다(AGENTS.md).
  - gallery의 `shell-tray`와 `shell-sidebar-app-panel`이 상태 글 하나와 단추 하나를 올린 머리 줄을 보인다.

옮기기: 없음(앱 data 변화 없음). 앱은 migrate-sdk 메모를 따라 자기 머리 줄을 지운다. 안 옮겨도 깨지지 않고 머리 줄이 겹쳐 보일 뿐이다.

왜: 앱이 자기 머리 줄을 그리면 자리마다 모양이 다르고 lophn의 머리와 겹친다. lophn이 그리면 앱은 글과 id만 올린다(사람, 2026-11-07).

결정:
- 머리는 앱이 아니라 lophn이 모든 프레임에서 그린다. (사람)
- 새 그리는 곳을 만들지 않고 탭의 `CardHeadSpec` 길을 그대로 쓴다. 프레임마다 `CardHeadContext`를 달고 spec을 자기 줄에 `HeadControls`로 그린다. 좁은 자리도 접거나 줄이지 않고 가운데가 먼저 줄어든다. (agent)
- `@lophn/app-ui`를 2.6.0으로 올린다(guide가 패키지에 들어 있고, 지침이 바뀌어 앱 agent에게 알려야 한다). `supported_from`은 그대로다. (사람)

후속: 앱 전용 창의 머리 줄은 없다. 좁은 자리에서 ⋯ 앞 단추를 메뉴로 접는 것은 하지 않았다.

## 앱 view 열기에서 live의 `release`가 type으로 필수가 된다

```yaml
modules: [packages/shell/renderer]
checked: []
```

- 전: `AppViewOpen`의 `release`가 mode와 상관없이 optional이라 판 없이 live view를 여는 호출이 compile을 통과했고 main의 `checkOpen`이 실행 때 `invalid_input`으로 거절했다(sidebar·tray가 그렇게 깨졌다).
- 후: `appViewOpenSchema`가 `mode`로 가르는 union이다. live는 `release` string이 필수이고 preview만 null일 수 있다. `EmbeddedView` props도 같은 union이라 판 없는 live 열기는 compile error다. main의 규칙은 그대로다. 판을 싣지 않은 세션 앱 카드는 앱의 지금 판을 읽어 그 판으로 연다(채택된 판이 아직 없으면 "unavailable" 안내). 전에는 이 카드가 판 없이 열려 거절됐다.

옮기기: 없음.

왜: 같은 실수가 두 자리에서 나와 사람이 "Couldn't load"를 봤다(사람, 2026-11-07).

결정:
- 런타임 규칙을 바꾸지 않고 type으로 막는다. (사람)

후속: 없음.

## SDK 판이 바뀌어도 SDK 업데이트 감지, tray popup 머리는 icon 단추만

```yaml
modules: [packages/core, packages/protocol, packages/shell, packages/sdk, tools]
checked: []
```

- 전: 앱 없는 `sdk_update_needed` 줄(감지)은 제품 판이 바뀐 기동에서만 돌았다. 제품 판이 같은 채로 설치 SDK 판만 바뀌면(개발에서 SDK를 올린 경우) 감지가 돌지 않았다. tray popup 머리는 앱의 `useTabHead` status·경로·탭·단추·⋯ 메뉴를 다 그려 좁은 popup에 글이 많았다.
- 후:
  - `core_meta`의 `sdk_versions`(설치 SDK part → 가장 높은 판)를 `product_version` 옆에 적고 기동마다 견준다. `notices.observe_version`이 `sdks`를 받아 `sdks_changed`를 돌려주고, 제품 판이나 SDK 판 중 하나가 바뀌면 같은 감지(같은 줄, 같은 key, 같은 params)가 돈다. 키 값 표라 migration은 없다. 기동 중에 쓴 줄은 toast가 없는 것은 그대로다(`issues/shell.md`).
  - `useTabHead` 단추에 `icon`(refresh, add, open, edit, delete, copy, run, stop, download)이 생겼다. 모르는 이름은 버리고 글 단추다. tray popup 머리는 단추만 icon 단추(label은 tooltip)로 그리고 status·경로·탭·⋯ 메뉴는 그리지 않는다. `icon`이 없는 단추는 작은 글 단추다. 다른 프레임은 머리를 그대로 두고 icon을 label 앞에 붙인다.
  - `@lophn/app-ui` 2.7.0(minor). `useTabHead` guide, `design-app` skill, 앱 template `AGENTS.md`에 "tray 머리는 단추만 icon으로, 한눈에 필요한 한두 개에 `icon`을 주고 앞에 둔다"가 더해졌다. `migrate-sdk/app-ui-2.7.0.md`가 지침 diff를 싣는다.
  - gallery `shell-tray`가 새로 고침 icon 단추 하나만 보인다.

옮기기: 없음(표 모양 그대로, 앱 data 변화 없음). 앱은 안 옮겨도 깨지지 않는다. tray 화면의 status는 popup에서 보이지 않게 된다.

왜: SDK 판만 바뀐 기동에서도 앱이 옮길 것이 생기는데 알림이 안 떴다. tray popup은 한눈에 보는 곳이라 머리에 단추만 있으면 된다(사람, 2026-11-07).

결정:
- 감지 신호는 제품 판 marker 옆 같은 표에 둔다. 새 표나 data root 파일을 만들지 않는다. (agent)
- `icon`은 이름 목록이고 lophn이 자기 icon으로 그린다. 앱이 그림을 싣지 못한다. 목록은 `renderer/icons/action.ts`에 있는 동사만 쓴다. (agent)
- `@lophn/app-ui`를 2.7.0으로 올린다(지침이 바뀌어 앱 agent에게 알려야 한다). `supported_from`은 그대로다. (사람)

후속: 없음.
