# documents/series

매주 쓰는 보고나 번호 붙은 실험처럼 이어지는 문서를 context 계약의 series 자료가 가진 경로 pattern 하나로 정의하고, pattern에 맞는 프로젝트 파일의 순서와 다음 이름 계산을 맡는다; pattern을 담는 계약은 documents/contexts, 파일은 documents/projects를 따른다.

## 요구

### pattern과 멤버

**[R1]** 이어 쓰는 문서 묶음은 context 계약의 series 자료가 가진 경로 pattern 하나로 정의하며 pattern 말고 따로 등록하거나 저장하는 묶음, 묶음 이름·제목·설정은 없다.
- 이유: 묶음을 따로 등록하면 계약과 어긋나는 두 번째 정본이 생기고, 파일 이름이 이미 묶음을 말하고 있다.
- 확인: `reports/weekly-{n}.md` pattern을 가진 계약만으로 주간 보고 묶음이 정의되고, 묶음을 만들거나 고치는 별도 화면·command가 없다.
- 의도: documents#I5

**[R2]** pattern은 프로젝트 폴더 기준 상대 경로이며 파일 이름 칸에 번호 자리 `{n}`·`{major}`·`{minor}`·`{patch}` 중 정확히 하나를 가지고 `*`는 파일 이름 칸에서만 쓴다.
- 이유: 번호 자리가 없거나 둘이면 어느 숫자가 순서인지 정할 수 없다.
- 확인: `reports/weekly-{n}.md`와 `eval/experiments/exp-{n}-*.md`는 받아들이고, 번호 자리가 없거나 둘인 pattern·폴더 이름 칸의 번호 자리나 `*`·`..`이나 절대 경로·번호 자리 바로 옆의 숫자나 `*`는 계약을 저장할 때 거절된다.
- 의도: documents#I5

**[R3]** 멤버는 pattern에 맞는 프로젝트 파일 전부이며 번호 자리가 잡은 글자가 key이고, 맞지 않는 파일은 멤버가 아니며 파일을 만들거나 지우거나 옮기면 멤버가 그대로 따라 바뀐다.
- 이유: 파일은 사람이 밖에서도 만들고 옮기므로 멤버를 따로 기억하면 어긋난다.
- 확인: `reports/weekly-{n}.md`에서 weekly-1.md·weekly-2.md가 멤버이고 weekly-2026-09-28.md와 notes.md는 멤버가 아니며, weekly-3.md를 만들면 멤버가 셋이 되고 지우면 다시 둘이 된다.
- 의도: documents#I5, documents#I1

### 순서

**[R4]** 멤버 순서는 key의 숫자를 수로 비교한 자연 순서이며 같으면 key 글자, 그래도 같으면 경로 순이고 OS locale에 따라 바뀌지 않는다.
- 이유: 글자 순서로는 exp-010이 exp-002 앞에 와서 "마지막 문서"를 잘못 고른다.
- 확인: exp-002·exp-009·exp-010과 0.2·0.9·0.10을 섞어 놓고 locale을 바꿔도 exp-002, exp-009, exp-010과 0.2, 0.9, 0.10 순서이고, 같은 key를 가진 exp-001-a.md와 exp-001-b.md는 경로 순으로 이어진다.
- 의도: documents#I5

### 다음 이름

**[R5]** 다음 이름은 pattern과 지금 있는 파일 목록만으로 매번 계산하며 어디에도 저장하지 않고, 계산 근거가 된 마지막 멤버와 계산한 이름이 이미 멤버에 있는지를 함께 알려 준다.
- 이유: 다음 이름을 읽었다는 것과 새 문서를 만들었다는 것은 다르고, 저장한 값은 사람이 밖에서 파일을 만들면 틀려진다.
- 확인: 다음 이름을 두 번 읽어도 파일이 생기지 않고 같은 결과가 나오며, 사람이 밖에서 weekly-3.md를 만들면 다음 읽기는 weekly-4.md를 돌려주고, 감소 규칙으로 이미 있는 이름이 나오면 이미 있음 표시가 붙는다.
- 의도: documents#I5

**[R6]** 처음 key는 사람이 직접 정하며 멤버가 없으면 다음 이름은 빈 제안이고, pattern의 `*` 자리는 계산하지 않고 `*`로 남겨 쓰는 쪽이 채우게 한다.
- 이유: 처음 번호나 날짜를 임의로 만들면 사람이 기대한 묶음과 어긋나고, 이름 뒤쪽 글은 규칙으로 정할 수 없다.
- 확인: 파일이 없는 pattern은 빈 제안을 돌려주고, `exp-{n+1:03}-*.md`에서 exp-010-x.md가 마지막이면 exp-011-*.md를 이름이 덜 정해진 제안으로 돌려준다.
- 의도: documents#I5

**[R7]** 번호 규칙은 정수 증가·감소, major·minor·patch 변경, 최대 4자리 0 채움(채움을 적지 않으면 마지막 멤버의 자리 수를 따른다)이며 P001→P002, 0.2→0.3, 0.2→1.0, 0.2.1→0.2.2, v1→v2를 같은 결과로 계산한다.
- 이유: 이전 제품에서 실제 지원한 규칙의 뜻을 그대로 보존한다.
- 확인: `P{n+1:03}.md`에서 P001.md 다음은 P002.md, `weekly-{minor}.md`에서 0.2 다음은 0.3, `weekly-{major}.md`에서 0.2 다음은 1.0, `weekly-{patch}.md`에서 0.2.1 다음은 0.2.2, `v{n+1}.md`에서 v1.md 다음은 v2.md, `exp-{n}-*.md`에서 exp-009-x.md 다음은 exp-010-*.md이고, 5자리 채움이나 읽을 수 없는 규칙은 계약을 저장할 때 거절된다.
- 의도: documents#I5

**[R8]** 마지막 멤버로 규칙을 계산할 수 없으면 오류 대신 빈 제안을 돌려주고, 날짜가 든 이름은 번호 pattern의 멤버가 아니므로 자동 번호를 꾸미지 않는다.
- 이유: 잘못된 이름을 만들어 저장하게 하는 것보다 사람이 정하게 하는 쪽이 낫다.
- 확인: 계산 결과가 안전한 정수 범위를 넘으면 빈 제안이고, `weekly-{n}.md` 폴더에 weekly-2026-09-28.md만 있으면 멤버가 없으므로 빈 제안이다.
- 의도: documents#I5

### 쓰는 쪽

**[R9]** Operator나 다른 lophn agent는 context 도구로 다음 이름을 읽고 일반 프로젝트 파일 하나를 써서 이어 쓰며, 이름을 읽는 것만으로는 파일이 생기지 않고 문서마다 판이 따로 남지 않는다.
- 이유: 반복 문서를 이어 쓰는 일이 사람의 이름 짓기 없이 되어야 하고, 문서는 사람이 여는 평범한 파일이다.
- 확인: agent가 다음 이름을 읽고 그 경로에 파일을 쓰면 멤버가 하나 늘고, 읽기만 하면 늘지 않으며, 이미 있음 표시가 붙은 이름은 agent가 덮어쓰지 않고 다른 이름을 정한다; 도구 모양은 documents/contexts와 lophn-agent 쪽 문서를 따른다.
- 의도: documents#I5, documents#I1

**[R10]** pattern 말고는 멤버·순서·다음 이름을 어디에도 기억하지 않으며 읽기는 변경 기록을 만들지 않고, 검색 색인 같은 파생 저장소를 지워도 결과가 같다.
- 이유: 파일 목록이 정본이므로 기억해 둔 사본이 있으면 어긋난다.
- 확인: 파생 저장소를 지운 뒤에도 같은 멤버·순서·다음 이름을 얻고, 읽기 전후 변경 기록 수가 같다.
- 의도: documents#I5

## 열린 질문

## 버린 것

- 묶음(series) 등록과 이름·제목·문서 format·정렬 기준·다음 규칙 설정은 버렸다; pattern이 계약 안에서 묶음을 정의한다.
- 묶음 ID와 자리·이름으로 조회하는 주소는 버렸다; 묶음은 계약의 자료이고 멤버는 파일 경로로 부른다.
- series 화면과 묶음 목록·상세·목차는 버렸다; 멤버는 context 검색과 문서 탭에서 보인다.
- 가족 보관·해제, 보관 상태는 버렸다; 묶음을 따로 두지 않으므로 정리할 것이 없다.
- draft와 template 기반 작성 값 보존은 버렸다; 쓰는 쪽이 일반 파일을 쓴다.
- key 예약과 제거된 key 재사용 금지는 버렸다; key는 파일 이름에서 읽는 값이다.
- 같은 format과 같은 자리를 멤버에 강제하던 검사는 버렸다; pattern에 맞는 파일이 멤버다.
- format이 선언한 정렬 값과 정렬 방향은 버렸다; 순서는 key 자연 순서 하나다.
- ledger 행과 묶음 변경의 주체 기록은 버렸다; 저장하는 것이 없다.
- 묶음 영구 삭제 요구는 버렸다; 지울 묶음이 없다.
- 멤버의 문서 version(첫 version·새 version)은 버렸다; 문서는 판 없는 프로젝트 파일이다.
- lophn agent의 series 읽기 통로(옛 R9)는 context 도구로 바뀌었다; 다음 이름 읽기는 R9가 맡고 도구는 lophn-agent 쪽이 정한다.
- coding agent의 묶음 등록·멤버 저장 도구는 버렸다; coding agent는 context를 쓰지 않고 파일을 직접 만든다.
- 날짜·주차 다음 이름 규칙은 이번에서도 뺐다; 날짜 이름은 번호 pattern에 맞지 않으므로 멤버가 아니다.
- Operator가 묶음의 다음 독립 문서를 만들지 못하게 한 제한은 풀렸다; Operator는 다음 이름을 읽고 새 파일을 쓸 수 있고, 쓸 수 있는 범위는 lophn-agent/roles/operator를 따른다.
