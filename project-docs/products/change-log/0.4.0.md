# 0.4.0

## 탭을 workspace 위에 띄우고 상단 bar로 접음

```yaml
modules: [packages/shell/renderer, packages/shell/main, packages/shell/ipc, packages/design]
checked: [architecture-ui-kit, architecture-annotation, tool-worktree-prep, tool-dev, tool-package-linux, skill-ui-design, skill-wording, tool-wording, boundary-catalog]
```

- 전: 탭은 pane(최대 둘)의 탭 줄에만 있었다. 셋을 같이 보려면 하나를 탭 뒤에 숨겨야 했다. native view(app panel)끼리는 쌓는 순서가 없었고, `EmbeddedView`가 unmount되면 view를 닫았다.
- 후:
  - 모든 탭 kind가 docked, floated(workspace 위에서 옮기고 크기를 바꾸는 패널), minimized(상단 bar의 `[icon 제목]` span)를 오간다. 탭 menu의 Float, 패널 bar의 Minimize·Dock·Close, span(누르면 접기 전 자리로, right-click의 Restore·Dock·Close, 넘치면 `+N` menu), palette의 Float tab·Dock panel·Minimize panel로 한다. 기본 단축키는 없다.
  - `layout.json`이 판 2다. `layout.floats`(최대 20, `{tab, rect, minimized, origin_pane}`)에 floated와 minimized 탭을 저장하고 되살린다. `TabItem.transient`(popup용) 탭은 저장하지 않는다. 판 1 파일은 읽지 않고 새로 만든다.
  - native view가 pane view < floated view(floats 순서) < overlay로 쌓인다. `setViewBounds`에 `layer`가 생겼다. DOM 패널이 아래층 native view 위에 뜨면 cover로 native view를 줄인다.
  - app panel view는 Float·Dock·접기에서 닫히지 않고 다시 쓰인다. 탭이 layout에서 사라질 때 닫는다.
  - design kit에 `FloatPanel`(`@lophn/ui/overlay`)이 생겼다.
  - focus는 칸과 패널 중 한 곳에만 있다. 맨 위 패널은 bar 위 강조선으로 보이고, terminal은 focus인 쪽만 입력을 받는다.
  - plain terminal과 app panel 탭이 `title`을 저장해, 다시 띄워도 탭·패널·span의 이름이 비지 않는다.

왜: terminal을 보면서 editor와 app을 같이 보고, browser popup(계획 `browser-tab`)이 뜰 자리를 만든다.

결정:
- 탭 하나는 pane이나 floats 중 한 곳에만 있다. editor session과 terminal 입력이 하나뿐이기 때문이다. (agent)
- 기본 단축키를 두지 않는다. Ctrl+Alt+Arrow는 GNOME에서 workspace를 바꾼다. (사람)
- DOM 패널이 native view 위에 뜨면 cover로 줄인다. 버린 길: 마지막 capture 그림 보이기(page가 멈춘다), DOM 패널을 native view로 띄우기(패널마다 renderer 하나). (agent)
- floats는 판 2에 `floats`만 더한다. `detached`는 계획 `workspace-detach`가 더한다. (agent)

후속: 개발 data의 `.dev-data/shell/layout.json`이 판 1이면 읽히지 않고 새로 만들어진다. detached 창은 `workspace-detach`가 한다.

## workspace에서 web page를 browser 탭으로 연다

```yaml
modules: [packages/shell/main, packages/shell/renderer, packages/shell/ipc, packages/shell/preload, packages/design, tools]
checked: [architecture-ui-kit, architecture-appearance, tool-dev, tool-package-linux, tool-worktree-prep, tool-check, skill-ui-design, skill-wording, tool-wording]
```

- 전: web page를 여는 탭 kind가 없었다. link와 로그인은 OS browser로 넘어갔다.
- 후:
  - 새 탭(+) menu의 Browser가 빈 주소 칸으로 열린다. toolbar에 뒤로, 앞으로, 새로 고침, 주소 칸(scheme이 없으면 `https://`, localhost·127.0.0.1은 `http://`), 별, bookmark menu, Open in browser, ⋮가 있다. 다시 열면 같은 URL을 load한다.
  - page는 `<webview>`라 menu, popover, floated 패널이 그 위에 겹친다. Float·Dock·접기에도 page가 다시 load되지 않는다.
  - 클릭 뒤 5000ms 안의 popup만 연다. 크기 준 popup(OAuth 로그인)은 opener를 지킨 채 floated 패널로 뜨고, dock하면 같은 주소의 보통 탭이 된다. 크기 없는 popup(`target=_blank`)은 연 탭 바로 뒤에 새 탭으로 열린다. 입력 없는 popup은 막고 탭에 알린다. page가 `window.close()`를 부르면 탭이 닫힌다.
  - navigation은 http/https(localhost, 사설 IP 포함)와 `about:blank`만, subframe은 `data:`·`blob:`·`about:`도 받는다. `file:`, `lophn-*:`, `javascript:` 등은 막는다. `mailto:`·`tel:`은 클릭 직후에만 OS로 넘긴다.
  - 모든 browser 탭과 project가 persistent session 하나를 같이 써서 로그인이 남는다. permission은 clipboard write만 허락한다. download는 클릭 직후에만 저장 dialog를 띄운다. UA와 client hints에서 Electron·앱 이름을 뺀다.
  - DevTools(⋮ Inspect)는 탭 안 page 오른쪽에 붙어 뜨고, 경계 막대로 크기를 바꾼다. 아래, floated 패널, 따로 뜬 창으로 옮겨도 다시 열지 않는다.
  - bookmark: 별이나 Ctrl/Cmd+D로 더한다. 별 popover에서 이름을 고치거나 지운다. toolbar menu, 빈 새 탭 목록, Ctrl+K palette, Settings › Browser 목록에서 연다. 모든 project 창이 `<dataRoot>/shell/bookmarks.json` 하나를 같이 쓰고, 깨진 파일은 덮어쓰지 않고 오류로 보인다.
  - 탭과 bookmark 목록에 page favicon이 보인다.
  - Settings에 Browser pane이 생겼다: bookmark 목록(고치기, 지우기)과 Clear browsing data(확인 뒤 cookie·storage·cache를 지우고 열린 page를 다시 load한다).
  - floated 패널 위쪽 가장자리의 회색 선을 지워 강조선만 보인다.
- 계약:
  - 생긴 것: shell IPC `ipc/browser.ts`(navigate, command, adopt, clear-data, devtools open·close·window, bookmarks list·add·update·remove, push state·event·bookmarks-changed)와 preload `window.lophnBrowser`. 탭 kind `browser`(layout `{key, url}`), renderer 전용 transient kind `browser_devtools`. overlay choice의 `image`(data URL). design `Palette` item의 `image`. `TabHost.openFloat(tab, size?)`, `TabHost.viewKeeps`, `openTabIn`의 `after`. project 창의 `webviewTag`.
  - 바뀐 것: overlay `menu`·`popover`가 창 본문 전체를 덮는다(`fullBody`). 앱 view와 browser native view가 창마다 하나인 층 순서(`windowViewOrders`)를 같이 쓴다. floated 패널 z-index가 층 번호 × 2다. `ViewKeeps`의 state가 kind와 상관없다. layout의 atomic write를 `workspace/atomic-file.ts`로 나눴다.

왜: terminal에서 dev server를 띄우거나 로그인할 때 lophn 창과 OS browser를 오가야 했다.

결정:
- browser는 새 탭 kind이고 terminal·editor와 같은 pane에 들어간다. 크기 준 popup은 floated 탭으로 연다. bookmark를 둔다(사람).
- 보통 탭은 `<webview>`, 크기 준 popup과 DevTools만 native view다(사람, 2026-10-19). native view는 DOM 위에 그려져 menu·패널이 page 밑에 깔렸다. 표준 Electron에는 popup contents를 `<webview>`에 넣는 길이 없다(ChatGPT desktop은 고친 Electron으로 한다). dock한 popup은 같은 주소의 `<webview>`로 다시 연다(사람).
- DevTools는 Chrome처럼 탭 안에 붙고 floating·분리를 고른다(사람). `<webview>`는 DevTools를 담지 못해 native view에 붙이고, 자리를 바꿀 때 view를 옮긴다(실험).
- favicon을 보인다(사람). roadmap의 "favicon 하지 않는다"를 뒤집었다. main이 page session으로 받아 data URL로 싣는다(agent).
- toolbar menu는 overlay로 띄운다. 별 popover는 `<webview>` 탭에서 이름 칸을 둔다(사람).
- 규칙은 rea `desktop-embeded-browser`를 TS로 옮겨 짰고 dependency로 넣지 않았다. partition은 persistent 하나다. localhost·사설 IP를 막지 않는다. tab cap, site list, capability 승인, storage mode는 두지 않는다(agent).

후속: terminal이 여는 URL과 Ctrl-click link를 browser 탭으로 보내는 `$BROWSER` bridge와 link를 열 곳 설정은 계획 `browser-bridge`다. 열린 이슈: `project-docs/issues/shell.md`(page에 focus가 있으면 Ctrl+W·Ctrl+Tab이 듣지 않는다), `project-docs/issues/browser-tab.md`.

## terminal이 연 URL과 Ctrl/Cmd-click한 link가 browser 탭에 열림

```yaml
modules: [packages/core/config, packages/design, packages/shell/ipc, packages/shell/main, packages/shell/preload, packages/shell/renderer, packages/shell/terminal-host, tools]
checked: [architecture-workspace-layout, architecture-ui-kit, architecture-appearance, tool-check, tool-worktree-prep, tool-dev, tool-package-linux, skill-ui-design, skill-wording, tool-wording]
```

- 전: terminal의 프로그램이 연 URL(`gh auth login --web`, `python3 -m webbrowser`)은 OS browser로 갔다. terminal에 보이는 URL은 눌러도 아무 일이 없었다.
- 후:
  - project 창의 shell 탭(Linux·macOS)은 env에 `BROWSER`(앱이 켤 때마다 per-run 폴더에 쓰는 shim)와 `LPN_BROWSER_BRIDGE`를 받는다. 프로그램이 `$BROWSER <url>`을 부르면 browser 탭이 열려 선택된다. pane이 둘이면 terminal 반대쪽 pane, 하나면 terminal 바로 뒤, terminal이 floated이면 focus pane이다.
  - terminal에 보이는 http/https 주소를 Ctrl/Cmd-click하면 같은 규칙으로 browser 탭에 연다. 그냥 click은 text 선택이다.
  - Settings › Browser에 Links 구역: Web links와 Local links(localhost, `.local`, 사설 IP)를 각각 Browser tab 또는 System browser로 연다. 기본은 둘 다 Browser tab이다.
  - 탭을 열 수 없을 때(Settings·app space 화면, detached 창 안 terminal, coding 탭, 설정이 System browser, `http`·`https`가 아니거나 userinfo가 든 URL)는 OS browser로 간다. 사용자가 앱 env에 `BROWSER`를 두었으면 shell 탭은 그것을 그대로 쓴다. socket 경로가 너무 길거나 Windows이면 bridge가 꺼지고 지금처럼 OS browser다.
  - gallery: `browser-bridge-pane`, `browser-bridge-one-pane`, `settings-browser-links`, `settings-browser-links-system`.
- 계약:
  - 생긴 것: shell IPC `shell:terminal-link`, `shell:terminal-bridge-ack`(invoke), `shell:terminal-bridge-open`(push)과 `TerminalApi.openLink`·`ackBridgeOpen`·`onBridgeOpen`. terminal host `open` 요청의 `env`(restart도 같은 env). core 선언 설정 `shell.browser.web_links`·`shell.browser.local_links`(`browser_tab` | `system_browser`). socket protocol `{v:1,key,url}` 한 줄 → `{"result":"pane"|"declined"}` 한 줄. renderer 의존성 `@xterm/addon-web-links@0.12.0`.

왜: `vite`와 `gh auth login`을 하며 lophn 창과 OS browser를 오가지 않게.

결정:
- 범위는 shell 탭이다. coding 탭은 app space 패널에 붙어 browser 탭을 열 pane이 없다(agent).
- renderer가 탭을 연 뒤 ack해야 `pane`이고, 1500ms 안에 없으면 `declined`로 shim이 OS browser로 연다. URL이 조용히 사라지지 않게(agent).
- key는 terminal 탭마다 main이 발급해 host `open`이 성공하면 묶고 탭을 닫으면 버린다. 비교는 `Map` 조회다(socket이 0700 폴더 안 0600 file이다)(agent).
- per-run 폴더는 data root 아래가 아니라 core socket 폴더 규칙(`XDG_RUNTIME_DIR`)을 따른다. unix socket 경로 104 byte 한도 때문이다(agent).
- link 설정은 renderer가 밀지 않고 main이 요청마다 core에서 읽는다(agent).
- bridge는 `desktop/main.ts`가 아니라 `wiring/coding.ts`가 만든다(agent).

후속: coding 탭의 bridge, detached 창 안 terminal의 bridge, host가 죽은 뒤 다시 시작한 shell의 bridge는 `project-docs/products/roadmap/browser-tab.md`의 "남은 bridge 일"이다.

## 탭을 OS 창으로 떼고 다시 붙임

```yaml
modules: [packages/shell/renderer, packages/shell/main, packages/shell/ipc, packages/shell/preload, packages/design, tools]
checked: [architecture-annotation, architecture-browser-tab, architecture-coding-agent, architecture-appearance, architecture-ui-kit, skill-ui-design, skill-wording, tool-wording, tool-check, tool-dev, tool-worktree-prep, tool-package-linux]
```

- 전: 탭은 docked, floated, minimized뿐이었다. 화면이 둘이어도 탭 하나를 다른 모니터로 옮길 길이 없었다.
- 후:
  - 탭 menu의 Detach와 floated 패널 bar의 [Detach]가 탭 하나를 OS 창 하나(detached)로 뗀다. 창 위 bar에 탭 icon·제목, [Dock], 창 단추가 있다. [Dock]과 창 닫기(×)는 같은 일이고 탭은 project 창 focus pane 끝에 docked로 돌아온다. 탭을 닫으려면 탭 안의 닫기를 쓴다. 단축키와 palette 명령은 없다.
  - 옮겨도 산다: terminal PTY(새 창이 지난 출력을 다시 그리고 입력을 받는다), editor의 마지막 고침(보내기 전에 디스크에 쓴다. 못 쓰면 옮기지 않는다), agent composer draft, app panel과 browser 크기 준 popup의 page(view를 닫지 않고 옮긴다. `window.opener`가 남는다). 보통 browser 탭은 새 창에서 같은 url로 다시 load되고 로그인은 남는다. 그 탭의 DevTools는 닫힌다.
  - detached 창에서 연 새 탭은 project 창에 docked로 열린다. detached 창 안에서 크기 준 popup이 열리면 또 하나의 detached 창이 된다.
  - 이미 떼어 둔 탭을 여는 길(파일 열기, 대기 목록의 [Answer in terminal] 등)은 그 창을 앞으로 가져온다.
  - project 창을 닫거나 다른 공간으로 가면 그 창의 detached 창도 닫히고 다시 열면 같은 자리·크기로 돌아온다(화면 밖이면 지금 화면 안으로 당긴다). 앱을 끄고 다시 띄워도 그렇다. 이때 terminal은 PTY에 다시 붙지 않고 agent draft는 비어 있다(재시작과 같다).
  - `layout.json`이 판 3이다. `layout.detached`(최대 20, `{tab, bounds}`)를 저장한다. 판 2 파일은 읽지 않고 새로 만든다.
  - gallery에 `new-detached-terminal` page가 생겼다.
- 계약:
  - 생긴 것: shell IPC `ipc/detached.ts`(open, focus, close, take, dock, changed, open-tab, remove, push event: docked·changed·open-tab·closed·opened·moved·dock-request)와 preload `window.lophnDetached`. `TabKindDef.transfer`/`receive`/`noDetach`, `TabTransfer`, `slimDetachedTab`. layout model의 `detachTab`, `openDetachedTab`, `attachDetached`, `closeDetached`, `isDetached`. `EditorSessions.flush`, `TerminalStore.adopt`, `DraftStore.entries`, `ViewKeeps.lookup`/`track`, 앱 view와 browser registry의 `move`, `AppViews.owns`/`moveViews`. renderer route `detached`(`#detached=<key>`).
  - 바뀐 것: `findTab`·`allTabs`·`mapTabs`가 detached를 본다. `openDesktopWindow(ctx, start?)`가 hash와 bounds를 받는다. tray와 전역 palette 키는 detached 창을 고르지 않는다.

왜: 화면이 둘인 사람이 terminal이나 browser를 다른 모니터에 두고 쓴다.

결정:
- 순서는 transfer → main이 창을 만들고 view를 옮김 → 성공했을 때만 layout을 바꾼다. 어느 단계가 실패해도 탭은 그 자리에 있다. editor flush가 실패하면 알리지 않고 옮기지 않는다(저장 실패는 파일 탭이 이미 보인다). (agent)
- 보통 browser 탭은 옮기지 않고 다시 load한다(사람, `browser-tab`의 `<webview>` 결정의 결과). popup·DevTools만 native view라 옮긴다. (agent)
- detached 창은 탭 하나만, ×는 dock, 앱을 끄는 중에는 dock하지 않는다(다음 실행에 돌아온다). (agent)
- project 창 renderer가 detached까지 layout 전체를 갖는다. detached 창은 main을 거쳐 탭 하나를 받는다. (agent)
- detached 창 안 popup은 features 크기를 따르지 않고 기본 창 크기다. 그 창에서는 DevTools를 floated 패널로 둘 수 없다. (agent)
- 창을 여럿 띄우는 Electron test는 만들지 않았다. 위험 test는 layout(`model_test.ts`의 detach·attach)과 editor transfer(`editor/transfer_test.ts`) 둘이다. (agent)

후속: 개발 data의 `.dev-data/shell/layout.json`이 판 2면 읽히지 않고 새로 만들어진다. 열린 이슈: `project-docs/issues/workspace-layout.md`.

## app panel·browser 탭 page에 focus가 있어도 탭 단축키가 shell에 닿는다

```yaml
modules: [packages/shell/ipc, packages/shell/main]
checked: []
```

- 동작:
  - 바뀐 것: 작업대 단축키 표의 `tab.next`·`tab.prev`·`tab.close`·`tab.reopen`·`tab.move-left`·`tab.move-right`가 모든 OS에서 `main`이다. app panel·browser 탭 page에 focus가 있으면 main이 그 키를 삼키고 shell renderer로 보낸다. `<webview>` guest의 키도 `hostWebContents`로 창을 찾아 palette·launcher chord까지 닿는다.

결정:
- 위 키는 page가 받지 않는다(Chrome과 같다). (agent)
- Linux·Windows에서 shell renderer 자신의 키는 main이 삼키지 않는다. 터미널의 Ctrl+W를 shell로 보내야 해서다. (agent)

## 접어 둔 app panel, 뜨자마자 옮긴 popup, docked page 옆 경계의 버그 셋을 고침

```yaml
modules: [packages/shell/renderer]
checked: [architecture-workspace-layout, architecture-browser-tab]
```

- 전: 접어 둔 app panel을 다시 펴면 접을 때의 view state가 보였다. 크기 준 popup이 뜬 직후 Dock·Float하면 그 탭이 오류 화면이 됐다. browser page 옆 pane 경계의 잡는 띠가 page 쪽 절반이 page 밑에 깔렸다.
- 후:
  - 보관 중인 app view도 main이 미는 state(unresponsive, crashed, 연결 끊김)를 받아, 다시 펴거나 Detach할 때 최신 state를 보인다.
  - popup의 adopt 답 전에 다시 mount한 탭은 같은 adopt를 기다려, 거절 없이 popup을 이어 쓴다.
  - 경계 잡는 띠가 docked browser page 위에 그려지고 floated 패널은 여전히 그 위에 그려진다. floats 층은 stacking context가 아니다.

## detached 창의 알려진 틈 넷을 고침

```yaml
modules: [packages/shell/renderer, packages/shell/main, packages/shell/ipc]
checked: [architecture-browser-tab]
```

- 전: detached 창에서 같은 agent의 새 대화가 이미 있는 대화를 앞으로 가져왔고, DevTools를 floated로 옮기면 DevTools가 사라졌고, 크기 준 popup이 960×600으로 떴고, project를 떠났다 돌아오면 detached terminal이 PTY에 붙지 못했다.
- 후:
  - agent 새 탭의 key는 floated·detached 탭까지 보고 고른다. detached 창이 연 새 탭이 project 창의 다른 session 탭과 key가 겹치면 project 창이 새 번호로 연다.
  - detached 창의 browser 탭은 DevTools 자리 menu에 floated가 없다.
  - detached 창 안의 popup은 opener 창 가운데에 features 크기로 뜬다(화면 작업 영역 안으로 당긴다). detached 창만 최소 크기가 320×240이다.
  - 같은 실행 안에서 project를 떠났다 돌아오면 detached terminal이 같은 PTY에 다시 붙는다. 앱을 다시 띄우면 붙지 않는다.
- 계약: IPC `detached-changed`에 선택 칸 `resume`이 생겼다. `TabKindDef.resume`(terminal만 선언). `Workspace`와 `DetachedTab`의 TabHost slice는 `useTabHostSlices` 하나로 만든다(동작 같음, detached 창의 `openPath`는 이제 열린 파일을 먼저 본다).

왜: `project-docs/issues/workspace-layout.md`에 올려 둔 detached 틈이다.

결정:
- terminal의 PTY 참조는 detached 창이 알려 main이 든다. 떠날 때 창을 dock시키는 안은 창이 돌아오지 않아 고르지 않았다. 디스크에는 쓰지 않는다. (agent)
